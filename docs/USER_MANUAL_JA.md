## 1. はじめに

OpenFocus は、研究者、エンジニア、画像処理の専門家のために作られた、プロ向けの
多焦点画像融合デスクトップアプリケーションです。高度な位置合わせと融合アルゴリズムを
使って多焦点画像シーケンスを処理し、被写界深度全体にピントが合ったオールインフォーカス
画像を生成します。

### 主な機能

- **多焦点画像融合**：ピント位置の異なる複数の画像を 1 枚の全焦点画像に合成します
- **10 種類の融合アルゴリズム**：StackMFF V1/V2/V3（深層学習）、OpenFocus A/B/C、ガイドフィルタ、DCT、DTCWT、GFG-FGF、および位置合わせ専用モード
- **画像の位置合わせ**：OpenFocus（高速）、ECC、ホモグラフィから 1 つを選び、ずれ・回転・拡大縮小・遠近の変化を補正します
- **自動背景**：スタックで乱れた背景を実際の1フレームに置き換え、どのフレームにもきれいに写っていない場所を表示
- **ワイプ比較ビュー**：A/B の仕切り表示で位置合わせを点検し、結果を比較できます
- **ソース固定レタッチ**：結果を生成したフレームから描画し、ソース/復元/露出ブラシ、ストローク単位の undo、レイヤー付き TIFF 書き出しを利用できます
- **プロジェクトファイル**：入力参照と再現可能な処理設定を保存します（結果の画素は別途書き出し）
- **処理テンプレート**：融合・位置合わせ・リソース設定を保存し、読み込み済みの任意のスタックへ再適用できます
- **マルチページ TIFF**：1 ファイルの Z スタックをページ単位で読み込み、また 1 ファイルに書き出せます
- **深度マップ**：画素ごとの焦点位置、物理 Z 校正、3D 曲面、OBJ 書き出し
- **スケールバー**：メタデータの自動較正または手入力に対応した論文品質のスケールバー
- **バッチ処理**：複数フォルダ、グループ融合、位置合わせのみ／融合／位置合わせ済み保存の 3 つの出力モード
- **クラッシュからの自動復元**：クラッシュ後、直前の作業セッションの復元を提案します
- **多言語対応**：English、中文、日本語、Español、Deutsch、Français、Русский、한국어、Português、Italiano、Nederlands、Polski の 12 言語。システム言語を自動検出します
- **ヘッドレス CLI**：スクリプト処理、レシピの再利用、レタッチの再生、CI 連携に対応
- **Agent から操作可能**：トークン保護されたローカルチャネルで実 GUI を操作できます（コマンド、ウィジェットパス、実際のマウス・キーボードイベント）
- **柔軟な書き出し**：個別画像、フォルダ、マルチページ TIFF、GIF アニメーションとして保存できます
- **画像の変換**：画像スタックの回転、反転、サイズ変更
- **ラベル**：ソーススタック、位置合わせ済みスタック、特定の出力に、フレーム番号を生成できる管理可能なテキストラベルを追加できます
- **設定の保持**：環境設定、言語、最近開いたスタックは再起動後も維持されます

### 対応入力形式

- 画像ファイル：JPG/JPEG、PNG、BMP、TIFF、WebP などの一般的な形式
- 動画ファイル：MP4、AVI、MOV、MKV、WMV、FLV、WEBM（自動的に画像シーケンスへデコードされます）
- 連番画像を含むフォルダ
- カメラの RAW ファイル（DNG、CR2/CR3、NEF、ARW、RAF、ORF、RW2 などの一般的な
  RAW 形式）。デコードには `rawpy`（LibRaw）を使用します。これは
  `pip install openfocus` でインストールされ、Windows/macOS のビルドにも同梱されています

透明 PNG スタックは、デスクトップ、デスクトップのバッチ処理、CLI でグループ融合なしに
融合できます。各フレームは同じ寸法・ビット深度・同じアルファマスクを持つ 8bit または
16bit PNG で、マスクは 1 つの空でない矩形の外側が 0、内側が一定の非ゼロ不透明度である
必要があります。一定不透明度の半透明は許可されます。可視矩形だけを独立して融合するため、
隠れた色がフォーカス測定やタイル境界に影響しません。PNG 出力は元のキャンバスと不透明度を
保ち、隠れた出力色は 0 になります。デスクトップのソース/結果ビューは透明部分を市松模様で
表示します。

原寸で読み込み、位置合わせなし、クイックプレビューと ROI をオフにしてから、PNG として
描画・保存してください。バッチでは融合手法と PNG 出力が必要で、位置合わせ済みスタックは
保存できません。透明データでは、位置合わせ、サイズ変更/縮小、ダスト補正、深度マップ、
比較、レタッチ、ラベル、スケールバーは使えません。矩形の寸法を変える融合手法は拒否されます。
グラデーションやぼかしのあるマスク、フレームごとに異なるマスク、透明 TIFF 入力、GIF や
マルチページ TIFF を含む PNG 以外の出力は未対応です。CLI も透明入力のセンサー補正と
深度マップを拒否します。CLI 例：
`python main.py --input ./png-stack --output ./result.png --method guided_filter --align none`。

### 対応出力形式

**名前を付けて保存**では、通常の TIFF は結果を単一画像として保存し、レイヤー付き TIFF はソースフレームをレイヤーとして含みます。Linear DNG は常に表示されますが、保存には、カメラ較正を備えた、調整が焼き込まれていないカメラリニアの結果が必要です。

- 個別画像：JPG、PNG、BMP、TIFF、WebP
- 画像シーケンス：フォルダとして保存
- アニメーション：GIF 形式

## 2. 使い始める

### アプリケーションの起動

インストール後、次のいずれかの方法で OpenFocus を起動します。

1. **Windows（実行ファイル）**：OpenFocus のショートカットまたは実行ファイルをダブルクリックします
2. **macOS**：DMG の `OpenFocus.app` を Applications に移してダブルクリックします。未公証版は右クリック →「開く」を選びます
3. **Linux**：デスクトップ版は提供していません。pip パッケージを入れて `openfocus` コマンドを使ってください
4. **Python ソース**：有効化した conda 環境で `python main.py` を実行します

最新版は [OpenFocus 公式サイト](https://openfocus.top/#download) から入手してください。
同じファイルと旧バージョンは [GitHub Releases](https://github.com/Xinzhe99/OpenFocus/releases)
にもあります。ターミナルからもインストールできます。

```bash
# macOS（Apple Silicon、~/Applications へ）または Linux（ヘッドレス CLI）
curl -fsSL https://openfocus.top/install.sh | sh -s -- --dry-run
curl -fsSL https://openfocus.top/install.sh | sh
```

```powershell
# Windows PowerShell
irm https://openfocus.top/install.ps1 | iex
```

起動すると、ライトテーマのメインウィンドウが表示されます（初回起動時にウェルカム
ダイアログで変更できます）。

### クイックスタートの流れ

1. 画像シーケンスを読み込みます（ファイル → フォルダを開く、またはドラッグ＆ドロップ）
2. 右パネルで融合設定を構成します
3. **位置合わせ** のドロップダウンから**1 つだけ**選びます（既定は ECC）
4. 必要ならカーネルサイズを調整します
5. *（任意）* **レンダリング設定**を開き、**クイックプレビュー** にチェックを入れると、縮小した下書きで先にパラメータを試せます
6. 「**レンダリング開始**」をクリックして処理を開始します
7. 結果を書き出します

## 3. メイン画面の概要

OpenFocus の画面は 3 つの主要エリアで構成されています。

### 左パネル：画像表示エリア

ウィンドウ左側では画像が分割表示されます。

- **ソース画像パネル（上）**：入力画像シーケンスを表示します
- **結果画像パネル（下）**：融合または位置合わせの結果を表示します
- **ナビゲーションスライダー**：各パネルの下のスライダーでフレームを切り替えます
- **画像情報ラベル**：現在のフレーム位置と画像サイズを表示します

パネル間のスプリッターをドラッグすると、表示領域の大きさを変更できます。

### 右パネル：コントロールパネル

右パネルには設定項目が縦に並んでいます。

1. **融合設定**：融合アルゴリズムとカーネルサイズを選択します
2. **位置合わせ設定**：ドロップダウンから位置合わせ手法を 1 つ選びます（なしも可）
3. **実行ボタン**：レンダリング開始のほか、デフォルトに戻す、**レンダリング設定**、全手法のレンダリングがあります。設定ダイアログではクイックプレビュー、フレーム順、露出の一致、明るさのドリフト除去、出力のシャープ化を設定します
4. **ソース画像リスト**：読み込んだ画像をファイル名付きで一覧表示します
5. **出力リスト**：生成された結果を一覧表示します

### メニューバー

画面上部のメニューバーからすべての機能にアクセスできます。

- **ファイル**：読み込み／書き出し、プロジェクト、処理テンプレート、スタック保存、最近使ったファイル
- **編集**：画像の変換、結果のレタッチ、画像ファイルのレタッチ、元に戻す／やり直す
- **ツール**：画像を合成、バッチ処理、手法の比較、深度マップ、ダストマップ（フラットフィールド）、スケールバー、ラベル
- **設定**：詳細設定（パフォーマンス、位置合わせと位置合わせ診断、センサー補正、出力命名、AI、起動）、GPU アクセラレーション、テーマ、言語
- **ヘルプ**：ユーザーマニュアル、環境情報、フィードバック、アップデート確認、ログフォルダー

**ツール → 画像を合成…** は、融合済みの顕微鏡領域やカメラパノラマを扱う
独立したワークスペースを開きます。現在のスタックは変更しません。
**プロジェクトアシスタント**タブで読み込み・位置合わせ・コントロールポイントを、
**元画像**タブで一覧・グリッド・手動配置を、**パノラマエディター**タブで継ぎ目・
ブレンド・露出/色・出力・投影・カメラ・HDR の設定とプレビュー表示を管理します。
**ファイルを追加…**、**フォルダを開く**、**結果を追加…** で現在のセッションの
選択結果をコピーするか、ファイルやフォルダを一覧またはキャンバスへドロップします。
フォルダ読み込みは直下の対応ファイルのみで、サブフォルダは走査しません。自然な
ファイル名順で並べ、重複パスを無視し、マルチページ TIFF はページごとに追加します。
画像を選んで Delete / Backspace を押すとワークスペースから外れ、ディスク上の
ファイルは削除されません。

**自動整列** は有界のサムネイル上で共通特徴を探し（マスクと透明ピクセルは無視）、
接続した重なりごとに合わせます。平面モードでは回転・倍率・平行移動を推定し、
パノラマモードではカメラとレンズモデルも推定します。共通特徴が足りない画像は
「未対応」と表示されます。平面モードではドラッグするか X/Y にピクセル座標、倍率（%）、
回転角度（度）を入力します（既知のステージ座標を含む）。特徴のない非重複領域の
位置を画像内容だけから推定することはできず、自動照合は物理的な校正ではありません。
既知のステージグリッドでは行数・列数・撮影順・方向・開始角・推定重なり率を設定し、
**グリッド配置を適用** を押します。セル数は画像数と一致し、グリッド配置は平面
モードでのみ使えます。設定を変えただけでは現在位置は動かず、適用すると置き換えて
対応付けを消去します。平面モードでは保存前にすべての重なりを確認し、X/Y・倍率・回転を調整して
ください。

**コントロールポイント** は2つのプレビューを持つ編集画面を開きます。画像 A と B を
選び、両方のプレビューで同じ特徴をクリックして **ポイントの組を追加** を押します。
プレビューとマーカーは拡大縮小されますが、保存される座標は元画像のネイティブ
ピクセルです。表には各有効状態、画像、A/B 座標、手動/自動の出所、ピクセル残差が
並びます。座標を修正し、疑わしい点の**有効**を外すか、**選択項目を削除**、
**誤差の大きい上位10%を削除**、**隣接しない画像の組を削除** を使います。
**最適化** は有効な組をすべて当てはめ、有効ポイント数、弱い組、未接続画像、
p95 ピクセル残差を報告します。1組を拘束するには少なくとも4つの有効ポイントが
必要です。手動編集で自動ポイントは消えません。繰り返し模様、視差、標本の動きを
確認してください。コントロールポイントの編集だけでは新しい全体プレビューは
作られません。編集または最適化の後に **合成プレビュー** を押して確認してください。

**元画像マスク** は1枚の元画像解像度のマスクを編集します。半径は元画像のピクセル
単位です。**除外** は赤く塗り、**含める** は元に戻します。**マスクをクリア** で
下地を消し、**マスクを読み込む…** は元画像と寸法が完全に一致する PNG（アルファ、
グレースケール、BGR）またはアルファなし TIFF（グレースケール、BGR）を1枚読み込みます。
**適用** でストロークを
確定し、**キャンセル** で元のマスクを保ちます。除外したピクセルは継ぎ目、特徴
照合、出力ピクセルに使われません。マスクまたは RGBA の元画像があると出力で
透明度を利用できます。

**パノラマエディター** が実際のブレンドを制御します。**最適な継ぎ目を検索** では、
**画像内容による継ぎ目（DP）** が内容に沿って継ぎ目を探し、**グラフカット** は
現在の OpenCV ビルドが提供する場合のみ表示され、**フェザリング** は内容継ぎ目の
検索を行いません。継ぎ目の精度 1/2/4/8、遷移幅の半分、色または色とグラデーションの
コスト、重なりのループ調整で検索を調整します。フェザリングでは精度・コスト・
ループ調整は無効です。**ブレンド** は実際のマルチバンドピラミッド（1～7 階層、
既定5）、フェザリング、重なりなしの硬い選択です。**露出と色** はオフ、露出補正、
カラーバランス、局所ゲイン場から選び、**線形光でブレンド** を任意で有効にします。
パノラマモードでは画像ごとのレンズ項目を設定できます：ヨー、ピッチ、ロール、
水平画角、放射歪み a/b/c、レンズ中心のX/Yシフト。周辺減光 k1～k3 と秒単位の
露出時間（0 は利用可能なファイルのメタデータを使用）は選択中の任意の画像に使えます。
これらはユーザー入力または推定値であり、画像から物理的に校正された値ではありません。

**投影法** は、アフィン X/Y/倍率/回転を使いグリッドに対応する
**顕微鏡の平面画像合成** か、各元画像をカメラのヨー・ピッチ・ロール・画角・
レンズモデルで写す **直線投影パノラマ**、**円筒投影**、**正距円筒投影** を選びます。
パノラマの縮尺はピクセル/ラジアンで、**画角を最適化** によりカメラ画角を調整
できます。直線投影が地平線を越える場合や円筒投影が極に達する場合はエラーになる
ため、そのような場面では正距円筒投影を選びます。**HDR／露出融合** では、
**露出融合** が同じ場面を異なる露出で連続撮影した完全なブラケットを融合し、
**HDR（Debevec + Reinhard）** は応答を校正してトーンマップします。ブラケット内の
連続露出枚数、露出時間（0 は利用可能なファイルのメタデータ）、露出融合の幅/目標輝度
または HDR 露出スケール/白色点を設定します。Debevec は全元画像に正の露出時間と
露出補正オフが必要です。HDR と線形光ブレンドは併用できず、不完全なブラケットや
互換性のない測光の組み合わせはエラーになります。

**合成プレビュー** は現在のグローバル計画を取得し、有界のプレビュー（長辺最大
1024ピクセル）を描画します。**継ぎ目を表示**、**画像番号を表示**、
**除外領域を表示** は選択したラベルとマスクを重ね、選択したコントロールポイントは
マーカーで示されます。元画像の不透明度はワークスペースのプレビューだけに影響し、
書き出しのブレンドには入りません。平面モードでは X/Y、倍率、回転が実際の配置を決めます。
未対応のパノラマ画像は、カメラのヨー、ピッチ、ロール、画角を調整して配置します。
プレビューの不透明度はインポートや配置変更後も保持されます。元画像、配置、マスク、
コントロールポイント、エディター設定の変更は計画を無効にするため、編集や最適化の
後は再度 **合成プレビュー** を押してください。保存時に現在の計画を再利用するのは、
元画像と設定が変わっていない場合だけです。それ以外は計画と描画をやり直します。
出力では自動・8ビット・16ビット（自動は16ビットの元画像または HDR があれば
16ビット、それ以外は8ビット）、0.01～10 の出力サイズ、正規化クロップ、
自動/オン/オフの透明度（自動はパノラマ投影、マスク/RGBA 元画像、
未覆いのキャンバスで有効）、カラープロファイル方針を選びます。自動は共通
プロファイルを保持し混在プロファイルを sRGB に変換、sRGB は変換、最初の
プロファイルを保持は画素を変換せず最初のタグを複製、プロファイルなしはタグを
省きます。このバックエンドは混在する16ビットプロファイルを変換できないため、
最初のプロファイルを保持するかプロファイルなしを選んでください。8ビットへの
暗黙の低減は行いません。**元画像の EXIF を保持** は最初の元画像のカメラ・レンズ・
露出・日付・GPS の EXIF をサニタイズして埋め込み、画素配置タグを捨てて向きを
リセットします。TIFF または PNG で保存します。TIFF はディスク上のタイル合成と
ストリップ書き込み（1ストリップ目標4 MiB、最低でも出力1行分）、必要に応じて
BigTIFF を使い、大きな PNG は行帯でエンコードします。一時領域と出力先の十分な
ディスク容量とメモリを確保してください。フルサイズ出力はディスクへストリームされ
ますが、計画とプレビューはメモリを使います。共通特徴または手動ポイントが必要で、
画像だけから物理的な縮尺は推定しません。処理中は元画像と設定が固定されます。
**キャンセル** を使い、終了を待ってください。

## 4. 画像と動画の読み込み

### 画像フォルダを開く

1. **ファイル → フォルダを開く** を選ぶか、`Ctrl+O` を押します
2. 画像シーケンスが入ったフォルダを選択します
3. 読み込み倍率のダイアログが表示されるので、倍率を選びます（100% = フル解像度）
4. OK をクリックすると画像が読み込まれます

このダイアログで **今後は確認しない** にチェックを入れると、以降は確認なしで
選択した倍率で読み込みます。**設定 → 詳細設定 → 起動と更新 → 読み込み時に縮小率を確認**
でプロンプトを再び有効にできます。読み込み後のスタックも **編集 → サイズ変更** で後から
縮小できます。

ソフトウェアは自動的に次の処理を行います。
- 画像ファイルを検出し、ファイル名で並べ替えます
- 最初の画像をソースパネルに表示します
- ソース画像リストにすべてのフレームを並べます

### 動画ファイルを開く

1. **ファイル → 動画を開く** を選ぶか、`Ctrl+Shift+O` を押します
2. 動画ファイル（MP4、AVI、MOV、MKV、WMV、FLV、WEBM）を選択します
3. 動画は自動的に個々のフレームへデコードされます
4. 各フレームが画像スタックの一部になります

### プロジェクトファイル

ファイル → プロジェクトを保存 は、入力参照と再現可能な設定を `.ofproj` に保存します。
正確なフレーム順（TIFF ページと重複フレームを含む）、除外フレーム、回転／反転、読み込み
倍率、手法ごとの描画パラメータ、ラベル、スケールバーのスタイル、現在のフレームが含まれ
ます。結果やレタッチの画素は保存されないため、別途書き出す必要があります。ソースファイル
から再構築できない処理は、先に新しい入力スタックとして保存してください。

ファイル → プロジェクトを開く は、記録されたフレームを再構築してから現在のスタックを
置き換えます。ソースが移動している場合は新しいソースルートを選び、旧／新パスの対応を
すべて確認します。移動後の参照を残すには、プロジェクトをもう一度保存してください。未保存
の変更がある間はタイトルバーにプロジェクト名と `*` が表示され、終了や別プロジェクトの
読み込み前に確認されます。保存しても結果画像の未書き出し保護は解除されません。

### 処理テンプレート

処理テンプレートは設定だけを運び、ソースパスは含みません。**ファイル → 処理テンプレートを
保存…** は `.oftemplate` を書き出し、現在の融合手法とパラメータ、位置合わせ手法と
パラメータ、手法ごとの明るさオプション、スレッド数、タイル設定、位置合わせのダウン
スケール幅、StackMFF AI バッチサイズ、シャープ化、逆順、センサーノイズ除去フラグを
記録します。欠陥マスクのパスは意図的に保存しません。

**ファイル → 処理テンプレートを適用…** は、すでに読み込んだスタックへこれらの設定を
適用します。現在のソースは置き換えません。選択画面は `.ofproj` プロジェクト（ソースを
要求せず設定だけを抽出）と、プロジェクト設定を含むレシピ `.json` も受け付けます。
適用するとプロジェクトは変更済みになり、アルゴリズムのパラメータやリソース設定が
変わる可能性があるため、描画前に右パネルを確認してください。レシピは引き続きヘッド
レス形式で、欠陥マスクのパスと指紋を含みます。

### サンプルスタック

ウェルカムダイアログには **サンプルスタックを読み込む** が用意されています。実際に
撮影されたフォーカススタックから 6 枚の写真が同梱されているので、手持ちの画像が
なくてもすぐに一連の作業を試せます。インストールの確認にも便利です。

### 鮮明度カーブ

ソースのナビゲーションスライダーの上に、フレームごとの鮮明度（正規化済み）を示す
小さなカーブが表示されます。ピントの外れたフレームは赤い点付きの谷として現れます。
カーブ上の任意の位置をクリックするとそのフレームへ移動し、ホバーするとフレーム番号が
表示されます。

### マルチページ TIFF スタック

顕微鏡ソフトウェア（ZEN、NIS-Elements、ImageJ/Fiji）は、Z スタック全体を 1 つの
マルチページ TIFF ファイルとして書き出すことがよくあります。OpenFocus はそのような
ファイルの各ページを画像スタックの 1 フレームとして読み込みます。ファイルをドロップ
または開くだけでスタックが完全な状態で現れます（フレーム名は `<file>_page_001` などに
なります）。1 ページの TIFF は従来どおりに動作します。逆方向も可能です。
**ファイル → スタックを保存 →（位置合わせ済み / 入力）→ マルチページ TIFF として保存**
で、スタック全体を 16-bit 深度を保ったまま 1 つの `.tif` に書き出します。

### スケールバー（論文用図版）

選択した対象に有効なメタデータがない場合は、手動較正が選択され、有効なピクセルサイズの入力を待ちます。

**ツール → スケールバー…** では、書き出し画像に焼き込むスケールバーを設定します。
較正方法はダイアログで明示的に選びます。**画像メタデータを使用** は ImageJ の
`unit=micron` 規約、OME-TIFF の `PhysicalSizeX`、明示的なセンチメートル解像度単位を
読み取るため、マルチページ TIFF を含む顕微鏡スタックは自動で較正されます。**手動較正**
の値は**元の画素**単位で入力し、現在の読み込み／縮小倍率に換算して描画されます。
0.5 µm/元画素は 50% 読み込みで 1 µm/作業画素になります。プリンタ解像度（72/300 dpi
など）は意図的に較正として扱いません。ダイアログには元の値、読み込み倍率、実際の描画値
が表示され、隅または任意の割合位置、色（自動は背景に応じて反転）、フォント、サイズ、
太字、文字揃えを選べます。プレビューはライブで更新されます。適用は 1 回の undo 可能な
編集として確定し、キャンセルすると以前の較正が残ります。

有効にすると、すべての書き出し（単一画像、フォルダスタック、マルチページ TIFF、GIF、バッチ処理）に
論文スタイルのバーが付きます。長さは 1-2-5 系列
の丸めた値（画像幅の約 12%）で、読みやすい縁取り文字を添えます。バーと文字は常に同じ
距離を示し、画像が小さすぎて読みやすく収まらない場合は、表示と異なる短いバーを描かず
に明示します。CLI では `--scale-bar`（自動較正）と `--scale-um <µm/px>` を使います。

**ツール → スケールバー → スケールバーを削除** から再度削除できます。*ソーススタック
から*／*結果から* はダイアログの「適用先」を残った側に絞り、*すべてから* はバーを
完全にオフにします。両方のキャンバスと A/B ワイプはすぐに再描画され、もともとバーの
ない側を削除しても設定は変わりません。履歴出力はそれぞれの較正とスタイルを保持し、
別のソーススタックを読み込んでも新しいスタックの設定は適用されません。

### 深度マップ（フォーカス位置）

**ツール → 被写界深度マップ…** は、選択した手法（DCT、DTCWT、GFG-FGF、
OpenFocus B/C、StackMFF V2/V3）の活動度指標からフォーカス位置を推定します。実測した
表面でも、融合画像の各画素の正確な出所でもありません。現在チェックしたフレーム、または
選択出力に記録されたソースを選べます。出所の記録がない場合に現在のスタックで代用する
ことはありません。計算、テクスチャ、書き出しは同じソースのスナップショットに結び付きます。
StackMFF V1 には深度マップがありません。透明 PNG スタックは GUI でも CLI でも深度
マップを作成できません。

対応する 7 手法では明示的に**計算**を押す必要があります。ダイアログを開く、指標・ソース・
位置合わせを切り替える、パラメーターを編集するだけでは計算は始まりません。編集欄は
指標の選択欄のすぐ下にあります。DCT メディアン核と GFG 初期核は 1〜51 の奇数（既定 7）、
B は半径と平滑化（既定 8、4）を指定します。C は半径を使わず、平滑化の既定値は 4 です。
DTCWT の分解レベルはソースのパラメーターで初期化され、ここでローカルな編集値として変更できます。
StackMFF V3 には数値の核ではなく、独自の AI 出力モード（既定のソフト合成、または
ハード選択）と説明が表示されます。ソフト合成は確率で加重した連続的なフレーム位置、
ハード選択は画素ごとに最も確率の高いフレームを使います。どちらも物理的な距離では
ありません。
編集値は対応する出力のパラメーター、またはメイン画面に記憶された手法の値から初期化し、
このダイアログを開いている間はソースと手法ごとに保持します。メイン画面、プロジェクト、
記録済み出力の設定には書き戻しません。

計算設定を変えると以前の 2D マップに**現在の結果ではない**と表示し、3D 曲面を消去します。
カラー・生データ・物理深度・OBJ を含むすべての書き出しは、新しい計算が成功するまで無効です。
実行中の処理は協調的にキャンセルします。終了後は再び**計算**を押してください。後続処理の
予約や自動再開はありません。計算ボタンは常に表示し、計算・キャンセル・モデル書き出し中は
無効になります。

- **カラーマップ**：グレースケール（論文標準）に加え、15 種類の科学用パレット
  （Turbo、Viridis、Magma など）と独自の配色を選べます。*カスタム配色を新規作成…*
  では任意の数のカラーストップからグラデーションを作成できます（ストップを
  ダブルクリックすると位置と色を編集できます）。独自配色は保存され、ドロップダウンに
  表示されます。
- **反転 / ガンマ / スムージング**：深度軸を反転し、トーンを再調整し（ガンマ < 1 で
  低いインデックスが明るくなります）、エッジ保持処理で斑点を除去します。
- **重ね合わせ**：座標範囲が一致する関連出力に限り、2D マップを任意の不透明度で
  重ねて表示できます。
- **書き出し**：カラー版は PNG/JPEG/TIFF/BMP に対応します。16bit 生データ TIFF は
  正規化したフォーカス位置を 0〜65535 に符号化します。無損失の浮動小数点データでも
  物理距離でもありません。生データには JPEG/BMP を使えません。
- **インデックス TIFF と代替画像 TIFF**：インデックスは現在の深度推定を符号なし
  16bit のフレーム番号として保存します。1〜N は深度計算に実際に使ったフレーム順
  （位置合わせ・並べ替え後）を指し、0 は無効画素です。最大 65,535 フレームに対応し、
  小数の推定位置は最も近いフレームに丸め（ちょうど半分は切り上げ）、代替画像は各有効
  位置で対応する深度入力フレームの画素を選び、無効領域を 0 にします。入力に 16bit が
  含まれる場合、8bit 値は 257 倍して 16bit にします。どちらも深度マップの ROI を使います。
  インデックスは推定した焦点位置であり、融合結果の真の画素出所ではありません。
- **物理深度**：Z の開始値、正のステップ、単位、取得方向を入力し、元の取得順序を確認
  します。除外フレームの間隔は保持されます。Float32 TIFF はマイクロメートル、欠損部の
  NaN、ソースメタデータを保存します。物理 OBJ には XY 較正も必要で、物理 Z は 1:1 です。
  現在のスタックと選択した出力の間で切り替えると、フレーム名とインデックスが同じでも
  確認済みの取得順序が解除されるため、書き出す前に再確認してください。
- **3D モデル / 3D テクスチャ**：メッシュ長辺の頂点数は既定 600 です。開くたびに
  **自動（実際の色）**が選ばれます。関連出力の識別情報と座標範囲/ROI が完成したマップに
  一致するときだけその出力を使い、それ以外は完了した計算の最初の参加フレームを、
  位置合わせ後の実際の順序で使います。採用した出力名またはフレーム名が表示されます。
  対応出力、指定した参加フレーム、**深度の疑似カラー**も明示的に選べます。使える画像が
  なければその旨を表示します。3D プレビューと OBJ のテクスチャ PNG は同じ画像を使います。
  2D マップには独自の配色と重ね合わせ設定があり、配色やガンマの変更で実際の写真の色は
  変わりません。疑似カラーテクスチャを選んだ場合だけ配色・ガンマ・反転に追従します。
  静止プレビューと書き出しは同じサンプリング済み高さ場を使い、隠れた追加平滑化はしません。
  相対的な起伏は画像単位の可視化です。
- **モデル書き出し**：OBJ、MTL、テクスチャ PNG、JSON メタデータは 1 つのファイル群です。
  まとめて保管してください。書き出しはバックグラウンドで実行されます。競合は全メンバーに
  ついて確認し、準備はステージングされ、キャンセル時は既存ファイルを残し、コミット失敗時は
  置換をロールバックします。モデルを保存しても親の融合画像は書き出されず、その未書き出し
  保護も解除されません。

計算は進捗とキャンセル付きでバックグラウンド実行されます。AI 手法は AI 融合と同じ
省メモリのタイル処理を再利用するため、深いスタックでも動作します。CLI では
`--depth-map [path]` と `--depth-colormap` で同等の操作ができますが、書き出されるのは
カラー版だけです（既定 `<output>_depth.png`）。上記の対応手法に限られ、透明または
グループ入力では拒否されます。GUI はさらに生データ、フレームインデックス、代替画像、
物理深度、3D モデルを書き出せます。

### クラッシュ時の自動復元

OpenFocus は作業セッション（スタック、設定、ラベル、現在のフレーム）のスナップショット
を常時保持しています。クラッシュ、電源断、強制終了などでアプリケーションが
予期せず終了した場合、次回起動時にそれを検出し、**セッションを復元** を提示して
まったく同じ状態に戻せます。正常終了時にはこのプロンプトは表示されません。復元データは
設定と同じ場所に保存されます（ポータブル版では実行ファイルの隣に置かれるため、
持ち運べます）。

### 最近使ったファイル

開いたスタックはすべて **ファイル → 最近使ったファイル** に記録されます（最大 8 件）。
項目はサブメニュー内で番号付きになりますが、グローバルなショートカットはありません。
項目をクリックすると開き直し、同じスタックを開き直すと先頭に移動します。ファイルが
存在しなくなった項目は確認のうえ削除でき、**履歴をクリア** でメニューが空になります。

### ドラッグ＆ドロップ

フォルダをアプリケーションウィンドウに直接ドラッグして画像を読み込むこともできます。
既存のスタックにさらにファイルをドロップすると、サイズ確認のうえ追加されます。

### EXIF の向き

EXIF の Orientation タグを持つカメラの JPEG/TIFF ファイルは、読み込み時に自動で
回転・反転補正されるため、縦位置の写真も正しい向きで読み込まれます。

### 16-bit 画像

16-bit の PNG/TIFF 入力は自動的に検出され、処理の全工程で保持されます。融合は
フル深度で実行され、結果は 16-bit PNG/TIFF として保存できます（JPG/BMP への
書き出しは 8-bit に変換されます。これらの形式は 16 bit を保存できないためです）。

カメラ RAW ファイルは 16-bit（カメラのホワイトバランス、sRGB ガンマ）に現像され、
自動明るさ調整は無効になります。こうすることでスタック内のすべてのフレームが同じ
露出マッピングを受けます。フレームごとの自動露出ではフレーム間で明るさがちらついて
しまいます。16-bit データを保つには TIFF または PNG で保存してください。

### カラープロファイル

すべてのソースフレームが同じ RGB ICC プロファイルを持つ場合、単体の PNG、TIFF、
JPEG、WebP 書き出しはそのプロファイルを保持します。混在している、または未設定の
スタックは ICC プロファイルなしで書き出されます。OpenFocus はプロファイルを保持する
だけで、ソース画素を共通の色空間へ変換したり、プレビューをカラーマネジメントしたり
はしません。混在プロファイルの画像は、読み込む前に共通の色空間へ変換してください。
RAW 入力は sRGB に現像され、カメラのプロファイルは継承しません。

マルチページ TIFF は、ファイル内のすべてのページが同じ有効な RGB プロファイルを
持つ必要があります。そうでない場合、そのフレーム群は未設定として扱われます。動画の
フレームも未設定です。追加したフレームと、ある描画で実際に選ばれたフレームがその
結果のプロファイル判断に加わり、プロファイルは以降の書き出しのために結果と共に
保持されます。

### スタックのクリア

読み込んだ画像をすべて削除するには、**ファイル → スタックをクリア** を選ぶか、
`Ctrl+W` を押します。

## 5. 画像の表示とナビゲーション

### 画像スタック内の移動

- **スライダー**：ソースパネルの下のスライダーをドラッグしてフレームを切り替えます
- **ファイルリスト**：右パネルのソース画像リストで任意のファイル名をクリックします
- **キーボード**：グローバルな前／次フレームのショートカットはありません。ソース画像
  リストにフォーカスを移し、↑／↓ キーで選択を移動してください

### 類似フレームの確認

ソースリストの見出し下にある **フレームを確認** をクリックすると、画素がほぼ同じ
隣接フレームを見つけられます。分析中はボタンが **確認を中止** に変わります。各候補には
基準フレームと差分が表示されるので、両方を確認してからソースのチェックボックスで
フレームを融合から除外してください。候補がチェックを変更したり、ファイルを削除したり
することはありません。この保守的な比較は類似フレームを見逃すことがあり、小さな合焦
領域だけの変化は平均化されません。スタックが変わると結果は破棄されます。候補フレームと
その基準フレームの両方が含まれる場合だけ表示され、チェックを変えると即座に更新されます。

### ズームとパン

- **ズームイン／アウト**：ソースまたは結果上でホイールを回します。`Ctrl` を押したままでも操作できます
- **拡大鏡**：左ボタンを押し続けます。ホイールで倍率、`Ctrl` + ホイールで四角の大きさを変更します。大きさは各パネルで個別に保存されます
- **ウィンドウに合わせる**：中央ボタンをクリックします
- **パン**：右ボタンでドラッグするか、スペースを押しながら左ボタンでドラッグします

大きなソース画像では、拡大鏡は原寸の 100% から始まります。百分率は元画像の 1 画素に対応するデバイス画素数を示し、メイン表示は 800% まで拡大できます。JPEG・RAW スタックは、利用可能ならサイズを制限したプレビューで開きます。細部の確認が必要になると、バックグラウンド処理が元の画素を読み込み、表示領域だけをビューに渡します。選択中の原画像は再確認用に保持され、切り替えやクリアで解放されます。最初の原画像デコードには十分な RAM が必要で、プレビューを開くより時間がかかる場合があります。

### 同期ナビゲーション

ソースパネルで移動すると、対応する結果フレームがあれば結果パネルにも表示されます。

## 6. ワイプ比較ビュー

ワイプ表示は 2 枚の画像を 1 つのフレームに重ね、ドラッグ可能な縦の仕切りで分けます。
これにより、位置ずれや画質の差が仕切りの左右で直接見比べられます。

### ワイプビューを開く

1. 少なくとも 1 つの結果（融合または位置合わせ）をレンダリングします
2. 結果パネルのタイトルバー右上にある **ワイプ** トグルを押します
3. 結果エリアが比較ビューに切り替わります。もう一度 **ワイプ** を押すと戻ります

### 表示の読み方

- **A 側（仕切りの左）**：ソースフレーム。既定ではソースパネルのスライダーに追従します
- **B 側（仕切りの右）**：直近のレンダリング結果
- **白い仕切り＋丸いハンドル**：左右にドラッグして分割位置を移動します
- 仕切りをまたいで大きくずれるエッジをドラッグすると、並列パネルでは見えにくい
  位置合わせの誤差が浮かび上がります

### 比較対象の選択

比較ビュー下部のバーには、左右それぞれのグループがあります。

- **A 側** — **ソースに追従**（既定）にチェックを入れるとソースパネルのスライダーに
  追従し、外すと A 側を任意のフレームに固定できます（専用スライダー付き）
- **B 側** — **最新の結果**（既定）にチェックを入れると常に最新のレンダリングを表示し、
  外すと専用スライダーで出力履歴をたどれます

両側ともリアルタイムに更新されます。新しいレンダリング、ソーススライダーの移動、
フレームの削除がすぐに反映されます。

### ズームとパン

比較ビューは両方の画像で 1 つの変換を共有します。

- **ズーム**：マウスホイール（カーソル位置を中心に拡大縮小）
- **パン**：仕切り以外の任意の場所をクリック＆ドラッグ
- **リセット**：ダブルクリック

ワイプモードと ROI モードは同じ結果パネルを使うため、一方に入ると他方は終了します。
スタックをクリアした場合もワイプモードは終了します。

## 7. 画像の位置合わせ

画像の位置合わせは、画像スタック内のフレーム間の空間的なずれを補正します。画像に
わずかなずれや遠近の変化がある場合に不可欠です。

### 位置合わせ手法

#### ECC（拡張相関係数）

- 相関に基づいて最適な位置合わせを最適化で求めます
- 微妙なずれに適しています
- サブピクセル精度を提供します
- ホモグラフィより低速ですが、より高精度です

#### ホモグラフィ

- 特徴点マッチング（SIFT/ORB 特徴量）に基づきます
- 大きな幾何変換に対応します
- 初期の位置合わせは ECC より高速です
- 遠近の変化が大きい画像に適しています

#### OpenFocus（高速）

- 有界相似変換（並進＋回転＋拡大縮小）と自動裁ち落としを行います。
- 画像差分をサンプリングして有界相似変換を探索し、Lanczos 補間で画像を変換します
- 移動の探索範囲は既定でフレームサイズの 3% です。CLI の `--align-shift-limit` で変更できます。
  これは探索範囲であり、累積移動量が 3% を超えたフレームを必ず拒否する制限ではありません。
- A/B/C を選ぶと OpenFocus 位置合わせが選ばれます。ただし、位置合わせを明示的に選択した場合やプロジェクトを復元した場合はその設定を維持します。
- 非剛体や極端な幾何には ECC かホモグラフィを選んでください。
- 前の位置合わせ済みフレームを使い、累積した変換を初期値として探索します。幾何基準は既定で最初のフレームです。
  位置合わせの推定で実際にエラーが発生した場合、既定の `continue` は未位置合わせのフレームで続行し、
  `fail` は描画またはバッチ項目を中止します。低テクスチャ、繰り返し模様やフォーカス変化などでは
  不正確に位置合わせされることがあるため、結果を確認してください。
- CLI では `--align openfocus --align-param 'failure_policy="fail"'` で同じ方針を選びます
  （シェルに応じて引用符を調整）。既定は `"continue"` です。バッチの各項目は独立して
  この方針を使います。
- **基準フレーム** には、含まれる処理対象スタックの 1 始まりの番号を指定して幾何を
  固定します。フレーム順は保たれ、明るさの均等化は独自の基準を使います。バッチの各
  スタックにその番号が必要で、なければ項目が失敗します。CLI 例：
  `--align openfocus --align-param reference_frame=3`。基準を選んでも視差や誤一致は
  直せません。結果を確認してください。

#### ホモグラフィ → ECC

ホモグラフィで粗く合わせてから ECC で精緻化します。最も遅い代わりに難しい幾何に最も
寛容な組み合わせで、これもドロップダウンの 1 項目です（2 手法の同時有効化ではありません）。

位置合わせレポートは基準フレームと各フレームの結果を示します。フォールバックは、手法が
位置合わせを確立できない、または以前の失敗した推定に依存している場合です。判明している
ときは弱い推定と制限外の動きを区別します。品質値は手法固有で、精度を保証しません。
変換はソース座標を位置合わせ段階の基準キャンバスへ写してから共通の裁ち落としを行い、
複合手法は段階ごとに報告します。ホモグラフィと ECC も `failure_policy="fail"` を受け付け、
既定は `"continue"` のままです。

描画を調べるには、**設定 → 詳細設定 → 位置合わせ** で **位置合わせ診断を収集** を有効に
して再描画します。キャッシュを再利用せずに位置合わせを再計算します。完了状態が
フォールバックを強調し、**設定 → 詳細設定 → 位置合わせ → 位置合わせ診断** でフレームごとのレポートを開けます。
失敗理由、手法固有のスコア、一致数、基準フレーム、変換が表示されます。基準の番号と名前は
除外フレームを含む元のソースリストに対応します。バッチとグループ描画ではこのレポートは
提供されません。

### 位置合わせを有効にする

1. 右パネルで **位置合わせ** グループを探します
2. ドロップダウンから手法を 1 つだけ選びます：**位置合わせなし**、**ホモグラフィ**、
   **ECC**、**OpenFocus（高速）**、または組み合わせの **ホモグラフィ → ECC**（既定は ECC）
3. OpenFocus（高速）では基準フレームを指定します。拒否フレームの扱いは **設定 → 詳細設定 → 位置合わせ** で選び、変更すると各手法に適用されます
4. **位置合わせ診断を収集** は詳細設定にあります（上記参照）。有効にしてから描画すると
   フレームごとのレポートが得られます

### 位置合わせを使うべき場合

- 画像に目に見えるずれがある
- 手持ちで撮影した画像である
- シーンに視差がある（近い被写体がフレーム間で移動する）
- 結果にゴーストや二重像のアーティファクトがある

### 位置合わせ設定

追加の設定は **設定 → 詳細設定 → 位置合わせ** から行います。
- **ダウンスケール幅**：前処理の解像度を制御します（既定：1024px）
- 小さい値 = 高速だが精度が下がる可能性があります
- 大きい値 = 低速だが精度が上がる可能性があります
- **位置合わせ診断を収集** と **位置合わせキャッシュ** も同じセクションにあります

## 8. 画像融合手法

OpenFocus には 10 種類の融合アルゴリズム（および位置合わせ専用モード）があります。
それぞれ特性が異なり、画像の種類に応じて使い分けられます。新規プロファイルでは
**StackMFF V3** と **ECC** 位置合わせが既定です。ドロップダウンの先頭は
**位置合わせのみ** で、既定では **AI（StackMFF V3）** が選ばれています。その後に
StackMFF V2/V1、OpenFocus A/B、ガイドフィルタ、GFG-FGF、OpenFocus C、DCT、DTCWT が
続きます。

### ガイドフィルタ

- **アルゴリズム**：ガイドフィルタによるエッジ保持融合
- **適した用途**：汎用。速度と品質のバランスが良い
- **利点**：エッジ保持に優れ、処理が高速
- **パラメータ**：カーネルサイズ（1〜51、奇数のみ）
  - 小さいカーネル：より局所的なディテール、ノイズが増える可能性
  - 大きいカーネル：より滑らかな結果、ノイズ抑制が向上

### DCT（離散コサイン変換）

- **アルゴリズム**：DCT 係数を用いた周波数領域の融合
- **適した用途**：テクスチャの多い画像、科学画像
- **利点**：細かいテクスチャを保持し、数学的に堅牢
- **パラメータ**：カーネルサイズが処理ウィンドウを決めます

### DTCWT（双樹複素ウェーブレット変換）

- **アルゴリズム**：マルチスケールのウェーブレット領域融合
- **適した用途**：複数のディテールレベルを持つ複雑なシーン
- **利点**：優れたマルチスケール解析と方向選択性
- **融合規則**：すべての方向とカラーチャンネルについて、画素とレベルごとに 1 つの
  判断を行います（N 方向、多数決の整合性チェック付き）。低域は全フレームの平均では
  なく、最も粗いレベルの判断に従います
- **パラメータ**：右パネルのウェーブレット階層数（1〜6、既定 4）。空間カーネルは
  使わないため、カーネルスライダーはこの手法では非表示になります。

### GFG-FGF（ガウス類似四近傍勾配＋高速ガイドフィルタ）

- **アルゴリズム**：Fu ら（*Laser & Optoelectronics Progress*、2024）の実装。
  ぼかし差分フォーカスマップ |I − mean(I)| をガウス類似四近傍勾配（GFG）演算子で
  強調し、高速ガイドフィルタで精緻化し、画素ごとに判断します（同値の場合は 3×3
  Sobel の小領域指標で決定）。二値判断マップは加重合成の前に再度高速ガイドフィルタで
  平滑化されます。
- **適した用途**：顕微鏡画像や、フォーカス領域が明確な画像
- **利点**：高速でフォーカス領域の境界がシャープ。メモリ使用量がフレーム数に依存
  しません
- **パラメータ**：カーネル = 粗いフォーカスマップの平均フィルタのサイズ

### StackMFF（V1、深層学習）

- **アルゴリズム**: 単一スケールの注意機構ネットワークがソフトマックスの重みで入力輝度を合成します。
  Cb/Cr は合成輝度に最も近い輝度を持つ入力フレームから取得します
- **適する場面**: フォーカススタック全体のニューラル融合
- **利点**: パラメータ不要、色はガモット内。合成輝度はフレーム順に依存しませんが、輝度との差が同じ場合は色差が変わることがあります
- **注意**: 約 156,172 パラメータ。大きなスタックは GPU が有効です

### StackMFF V2（深層学習）

- **アルゴリズム**: 単一スケールの注意機構ネットワークが期待フォーカス深度を正規化し、
  最も近い入力フレームをサンプリングします。深度インデックスはスタック順に依存します。
  **フレームは元のフォーカス順を保つ必要があり**、逆順は無効です
- **深度マップ**: 対応。選択したフォーカス層を返します
- **適する場面**: 連続フォーカススキャンで、非常に小さく高速なモデルが必要な場合
- **要件**: ONNX Runtime と付属の ONNX モデル。

### StackMFF V3（深層学習）

- **アルゴリズム**：画素単位のソース分類(ONNX Runtime)。ネットワークは各画素が
  どの入力フレームに由来するかを予測し、その確率でフレームを合成するか、1 つの
  フレームを選択します
- **AI 出力モード**（右パネル、この手法のみ）：
  - **ソフト合成（確率加重）** — 既定。各画素は確率で加重したフレームの混合です。
    遷移が滑らかで継ぎ目が出ず、論文の報告構成に一致します
  - **ハード選択（単一フレーム）** — 各画素は最も確率の高いフレームからコピーされます。
    フレーム間の補間がなく選択が鮮明ですが、2 つのフレームが拮抗する箇所では
    画素レベルの継ぎ目が現れることがあります
- **適した用途**：GPU が使える場合に最高品質
- **利点**：順序不変（フレームの順序が結果に影響しない）、利用可能なリソース内のスタック長に対応、
  手法ごとの調整が不要、自動最適化
- **要件**：ONNX Runtime と付属の ONNX モデル。

各ニューラルタイルは全フレームを使用します。元画像と位置合わせの一時データはディスクに保存できますが、空き容量と利用可能なメモリがスタックの大きさを制限します。V2 の空間タイル処理は画像全体の推論の近似です。

一時ディレクトリを指定しない場合、OpenFocus は既知の入力と一時データから必要容量を見積もり、システムの一時ディスクが不足すると書き込み可能な固定ローカルディスクを検討します。指定したディレクトリが使えない場合は通知してシステムの一時ディレクトリを使い、新しい処理ごとに保存された選択を再試行します。指定ディスクの空き容量不足では自動的に切り替えません。容量確認はその時点の推定であり予約ではありません。エラー時は詳細設定で書き込み可能なディレクトリを選んでください。


### OpenFocus A / B / C

- **OpenFocus A**：マルチスケールの焦点応答を使います。
- **OpenFocus B**：深度マップを使ってフレームをブレンドします。
- **OpenFocus C**：重み付きの多階層ピラミッドを使って融合します。

| 手法 | パラメーターの既定値 | 効果 |
|---|---|---|
| OpenFocus A | 半径 8、スムージング 4 | スムージングは現在無効で、結果に影響しません |
| OpenFocus B | 半径 8、スムージング 4、フェザー 3 | 深度マップとブレンドを調整します |
| OpenFocus C | スムージング 4 | ピラミッド融合を調整します。半径はありません |

保存済みの値は保持されます。リセットすると各手法の既定値に戻ります。CLI の例：
`--method openfocus_b --param radius=8 --param smoothing=4 --param feather=3`。

**明るさオプションは手法ごとに記憶されます。** GUI では融合前の露出合わせは A/B/C で
既定でオン、他の手法ではオフです。CLI では全手法で既定でオンです。有効な場合、A/B/C は処理順の最初のフレーム、
他の手法は最後のフレームに合わせます。保存済みのオン／オフの選択は保持されますが、
有効な A/B/C の基準は最初のフレームになります。明度ドリフト除去は既定でオフです。
リセットは各手法の明るさ設定とパラメーターをそれぞれの既定値に戻します。CLI では
`--exposure-match` または `--no-exposure-match` で明示的に切り替えられます。

### 位置合わせのみ（融合しない）

手法として **位置合わせのみ（融合しない）** を選ぶと、スタックを位置合わせし、出力
リストへ 1 つのスタック項目を追加します。フレームは書き出すまでメモリに残り、
位置合わせ専用のキャッシュを追加したり、ソースファイルの隣へ書き込んだりしません。
項目を保存すると、選んだ保存先に 1 つのフォルダが作られます。元のファイル名の幹を
保ち、拡張子は選択した形式になります。

### 融合手法の選択

1. 右パネルで **融合** グループを探します
2. **ドロップダウン** から手法を選びます（常にちょうど 1 つが選択され、既定は
   AI（StackMFF V3）。位置合わせ専用モードも同じ一覧にあります）
3. 該当する場合はカーネルサイズを調整します。ラベルには選択中の手法にとっての
   カーネルの意味が表示されます
4. **レンダリング開始** をクリックして処理します

### アルゴリズム比較ガイド

| アルゴリズム | 速度 | 品質 | 適した用途 |
|-----------|-------|---------|----------|
| ガイドフィルタ | 高速 | 良好 | 汎用 |
| DCT | 中速 | 良好 | テクスチャ |
| DTCWT | 中速 | 非常に良好 | 複雑なシーン |
| GFG-FGF | 高速 | 良好 | フォーカス領域 |
| StackMFF（V1） | 低速（GPU） | ここでは未計測 | 合成輝度は順序に依存せず、輝度差が同じ場合は色差が変わることがある |
| StackMFF V2 | 高速（GPU） | ここでは未計測 | 小型モデルを使う連続スイープ |
| AI 融合（StackMFF V3） | 低速（GPU） | 最高 | 最高品質 |
| OpenFocus A | スタックによる | スタックによる | マルチスケールの焦点応答と低詳細領域の混合 |
| OpenFocus B | スタックによる | スタックによる | 深度に基づく隣接フレームのブレンド |
| OpenFocus C | スタックによる | スタックによる | 重み付き多階層ピラミッドによる融合 |

**ツール → 手法を比較** では複数の手法を個別に調整できます。ウィンドウが狭くなっても、
各手法の名前、パラメーター名、入力欄はまとまって折り返されます。変更するとプレビューが
自動更新されます。**ROI プレビュー（高速）** は選択範囲と周辺を融合し、**全画像融合** は
画像全体の結果を確認してから、再描画せずに別の範囲を調べられます。露出統計や一部の
アルゴリズムは画像範囲に依存するため、ROI の結果と全画像の結果が異なることがあります。
初期設定は**全画像融合**です。

右側のプレビュー上にある **プレビューサイズ (px)** は、スライダーまたは数値入力で
160〜960 ピクセルの正方形から選べます。すべての手法が同じサイズを使い、利用可能な幅に
合わせて折り返します。次回開いたときもサイズを記憶します。サイズを変えても現在の倍率は
保たれ、検査用の枠が中心を基準に拡大・縮小され、画像の端で制限されます。

**F11** または **全画面（F11）** ボタンで画面全体を使えます。ボタンは **全画面を終了
（F11）** に変わり、タイトルバーの最大化でも同じです。**Esc** はまず全画面を終了し、
もう一度押すとダイアログを閉じます。全画面から戻ると元のウィンドウサイズに復元され、
結果グリッドはどちらの場合も利用可能な幅に再配置されます。

作業画面には選択方法のヒントが表示されます。結果をクリックするか、`Tab` でフォーカスして
`Enter` または `Space` を押すと、選択または選択解除できます。

ソース画像を左ドラッグして白い検査枠を移動し、ボタンを離すとその位置に固定されます。
右側の各手法は同じ位置合わせ済みスタックの正確にその領域を表示します。ホイールで領域の
倍率、右ドラッグでソースのパン、**Ctrl+ホイール** でソースのズーム、**F** でフィット
します。ソースフレームの切り替えやウィンドウのサイズ変更でも選択は保たれます。キャンセル
は以降の処理を停止し、閉じる操作は現在のネイティブ処理が安全に戻るまで待ちます。

### クイックプレビュー（下書きレンダリング）

大きなスタックでフル解像度のパラメータ調整を行うと時間がかかります。**レンダリング設定**を
開いて **クイックプレビュー** にチェックを入れると、OpenFocus はまず線形サイズの半分
（長辺は最低 320 px）で下書きをレンダリングします。位置合わせを含めて通常は数倍高速です。
完了メッセージ（および最新結果のツールチップ）には **品質：プレビュー** と表示され、
下書きは出力履歴に追加されません。チェックを外して再度レンダリングするとフル解像度の結果が
得られます。プレビューモードは ROI レンダリングには適用されず、フル解像度の
位置合わせキャッシュを汚すこともありません。

## 9. 画像の変換

### 回転

1. **編集 → 回転** に移動します
2. 回転の種類を選びます：
   - **90° 右回転**：すべての画像を右に 90 度回転します
   - **90° 左回転**：すべての画像を左に 90 度回転します
   - **180°**：画像を上下逆にします

### 反転

1. **編集 → 反転** に移動します
2. 反転の種類を選びます：
   - **左右反転**：左右を鏡像にします
   - **上下反転**：上下を鏡像にします

### サイズ変更

1. **編集 → サイズ変更** に移動します
2. サイズ変更オプションのダイアログが表示されます
3. 新しい寸法または拡大縮小率を入力します
4. スタック内のすべての画像が比例してサイズ変更されます

### 変換の適用順序

変換は画像スタック全体に適用され、フレーム間の位置合わせは維持されます。

## 10. レタッチ、ラベル、注釈

### 結果のレタッチ（編集 → 結果をレタッチ…、`Ctrl+T`）

融合後も局所的な欠陥が残ることがあります。高コントラストのエッジ周りのハロー、
誤ったフレームから取られた毛、平坦な領域のノイズなどです。作業領域は、選択した結果を
実際に生成したフレームから画素をコピーします。

1. 出力リストで 1 つの結果を選び（右クリック → *結果をレタッチ…* でも可）、`Ctrl+T` を
   押します。何も選んでいない場合は、全結果とソース記録の有無を示す選択画面が開きます。
2. 左がソースフレーム、右が結果です。両者はズームと位置を共有します。ホイールでズーム、
   右／中ドラッグ（または Space+ドラッグ）でパン、`F` でフィット、`1` で 100% です。
3. サムネイルを選ぶ、フレームスライダーを動かす、または `,` / `.` を押してフレームを
   選びます。1 ストロークはその時点のフレームとブラシ設定に固定され、ストロークが終わる
   までフレームを変更できません。
4. **ソースブラシ**（`B`）または**復元ブラシ**（`E`）を選びます。直径、硬さ、不透明度は
   スライダーと数値入力の両方で調整でき、`[` / `]` で直径を変更します。`Ctrl` を押しながら
   ホイールを上に回すと直径が大きくなり、下に回すと小さくなります。ホイールだけならズームです。
   復元ブラシは開いた時点の画像へ戻すもので、古い出力へ戻すものではありません。
5. `Tab` を押している間は今回のセッション前の結果、`Alt` ではソースフレームを確認できます。
   鮮明度の参照表示は任意で、ソースキャンバスだけを覆い、全フレームで同じ尺度を使います。
6. `Ctrl+Z` / `Ctrl+Y` はストローク単位の元に戻す／やり直しです。**すべて復元…** も
   1 回の undo 可能な操作です。**新しい出力として適用** は「<名前> · レタッチ N」という
   項目を追加して選択します。元の出力は変更されません。新しい項目は書き出すまで
   *未書き出し* と表示され、履歴からの自動削除や、未保存のまま終了する操作から保護されます。

新しい出力として適用して選択し、**名前を付けて保存**の形式一覧でレイヤー付き TIFF を選ぶと、ソースフレームと一緒に保存できます。ライブのラベルとスケールバーは
含まれず、未保存の注釈変更は保護されたままです。ソースの幾何と有効マスクは保持されます。
結果と各ソースは、サイズの一致する不透明な RGB またはグレースケール画像で、8bit または
16bit の深度が同じである必要があります。各ソース矩形は結果内に収まらなければなりません。
最大 128 個のソースに対応しますが、ソース名は 255 文字までで、NUL や基本多言語面外の
文字（多くの絵文字など）は使えません。安全でない状況や 512 MiB を超えると推定される処理は拒否し、不完全なファイル
を書かずにエラーを報告します。Windows の GIMP 3.2.6 は 8bit/16bit レイヤーをオフセットと
透明な位置合わせ余白を含めて読み込めます。結果が表示され、ソースレイヤーは非表示になり、
GIMP は表示される背景レイヤーも追加します。他のエディタは未検証です。

局所的な明るさ補正には**露出ブラシ**を使います。量は 1/100 段で指定し（100 で画素値が
2 倍、-100 で半分）、結果の上を塗ります。プレビューは塗りながら更新されます。1 ストローク
は重なった部分も含めて現在の結果を 1 回だけ調整し、次のストロークはその上に積み重なり
ます。ブラシの不透明度と硬さで混ざり方を制御します。明るくするときはハイライトが飽和
することがあります。**Before** を押している間は開いた時点の結果と比較でき、ストローク中に
Esc を押すと取り消せます。ストローク後は undo/redo も使えます。これらは画素編集であり、
調整可能なレイヤーではありません。新しい出力として適用し、その項目を書き出して初めて
画素が保存されます。プロジェクトはこれらの画素を保存しません。

**結果の調整…** は現在のレタッチ結果全体を変更します。露出とコントラストを変えると
サンプリングプレビューが更新され、**Before** で調整前の結果と比較できます。どちらも
1/100 段単位です。露出が画素値を掛け、次にコントラストが中間グレーからの距離を拡大・縮小
します。極端な値ではハイライトやシャドウが飽和することがあります。**OK** は 1 回の
undo 可能な編集として適用し、**キャンセル** は結果を変えません。処理中にキャンセルすると
ロールバックを要求します。画像全体の調整は、レタッチ履歴のメモリ上限に収まる必要が
あります。その後、上記の手順で公開・書き出しを行います。

出所は出力と共に移動します。位置合わせ済みフレーム、ROI の切り出し／貼り戻しオフセット、
DCT の端処理、ビット深度は描画時に記録されます。バッチファイル、旧結果、位置合わせのみの
フォルダ項目にはソース記録がないため、現在のスタックから推測せず「利用不可」と表示します。
未適用のストロークと undo 履歴はセッション内だけに存在し、プロジェクトを保存しても
保存されません。

**編集 → 画像ファイルをレタッチ…** では、既存の結果と 1 つ以上のソース画像を個別に選べ
ます。ソースは同じ画素グリッド上で結果に位置合わせ済みである必要があり、サイズが同じだけ
では位置合わせを証明できません。正立した寸法、チャンネル、8bit/16bit 深度が一致する
単一ページの PNG、TIFF、JPEG、BMP を受け付け、読み込み時に EXIF の向きを適用します。
アルファ付き画像とマルチページ画像は未対応です。選んだフレームはユーザー提供であり、
描画時の出所記録ではありません。適用すると別の未書き出し出力が作られ、出力リストから
保存します。選択したファイルはこのセッション中、深度マップや 3D メッシュの書き出しを
含めて上書きから保護されます。他の結果と同様、プロジェクトファイルはこれらの画素や
ブラシ履歴を保存しません。

レタッチ作業画面のチェックポイント保存・読み込み機能は、元のベース画像と処理済み
ソースを使います。自動背景のセッションは、画素を変更しない成功した解析も含め、
JSON メタデータと NumPy データを含む可逆 ZIP 形式の v2 `.ofretouch` スナップショットを
保存します。正確な作業画像、利用可能な undo/redo タイル、診断状態、ソースの由来を
保存し、v2 読み込み時は背景を再計算しません。ブラシ・色調のみのセッションは小さな
JSON v1 を使う場合があり、従来の背景 JSON v1 も引き続き再生できます。

ソース検証はキャンセル可能なバックグラウンド処理です。保存時は出力先を置き換える前に
準備したファイルを読み直し、現在の画像、利用可能な undo/redo タイル、診断状態の完全一致を
確認します。ソースの不一致、検証失敗、キャンセル、メモリ不足の場合は現在の編集と既存の
チェックポイントを変更しません。記録上限に達したら現在の編集を適用し、新しいセッションを
開始してください。どちらの形式も元のベース画像と実際に使った全処理済みソースを、
セッションと同じ順序で指定します：

```bash
openfocus retouch replay edits.ofretouch --base fused.png --sources frame1.png frame2.png --output retouched.tif
```

位置合わせや ROI 切り出しなどを行った後の、元の画素値とビット深度を持つフレームを使って
ください。再生は記録されたフレームオフセットと位置合わせ動作を再構築し、ベース、順序付き
フレーム、有効マスクを検証します。画素、幾何、マスクが互換でなければ拒否されます。各
パスには 1 枚の画像だけを指定でき、出力は PNG または TIFF でベースのビット深度を保ちます。
チェックポイントと入力画像を出力には指定できません。

### 背景の置き換え（自動背景）

スタックすると、被写体と一緒に背景もシャープになります。そのためスタック画像の背景は、ぼけ方の異なる部分の寄せ集めになり、被写体の周りにハローが出がちです。レタッチ作業領域の **自動背景…** は、背景を同じスタックの実際の1フレームに置き換えます。被写体はスタック結果のままです。背景は1枚のフレームとスタック結果から作られ、処理の過程で画素が再構成、調整、合成されることがあります。

1. 結果をレタッチ作業領域で開き、**自動背景…** をクリックします。
2. 背景を選びます。
   - **自動**（推奨）はソフト背景を使います。ただし、スタックが背景の多くをピントの合った状態で記録している場合はシャープ背景を使います。
   - **ソフト背景** は背景が最もぼけているフレームを使います。
   - **シャープ背景** は最も遠くにピントを合わせたフレームを使います。
3. **エッジのハローを除去** をオンのままにすると、被写体の輪郭に沿ったハローを取り除きます。各フレームが記録した範囲を超えることはありません。オフにするとスタック本来の輪郭を保ちます。
4. 突起の先の球のように、被写体の一部が被写界深度のすぐ外にある場合は、**被写体につながったぼけた部分を残す** をオンにします。被写体の隣の背景物もスタックのまま残ることがあるので、結果を確認してください。
5. **背景を置き換え** をクリックします。20メガピクセル15フレームのスタックで約1分かかり、約3.5 GBの空きメモリが必要です。**キャンセル** で中止できます。

この変更は1回で取り消せる1ステップで、先に被写体に描いたストロークは残ります。被写体の手前にあるぼけた草の葉など、スタックの画素を戻したい場所には **復元ブラシ** を使います。林床のシーンのように被写体が画面のほぼ全体を占める場合、画像はスタックのまま残り、その旨が表示されます。

すでにレタッチした結果でレタッチを開くと、自動背景はその元になったスタック結果を解析し、新しい背景をレタッチ済みの画像に重ねます。被写体へのブラシ作業は残り、以前に置き換えた背景を再び解析することはないので、2回実行してもハローが重なりません。

処理後、**欠損データを表示** をオンにすると、どのフレームにもきれいに写っていない場所が色付けされます。確認や手作業のレタッチが必要な場所です。

- マゼンタ：被写体に遮られずに記録したフレームがない背景
- シアン：カメラから隠れた被写体
- 黄：スタックのフォーカス範囲外の被写体
- スレート：滑らかすぎて判定できない部分

**欠損データマップを保存…** は、色付きのプレビューと、色ごとの白黒マスクを書き出します。自動背景には結果を作ったフレームが必要で、領域（ROI）結果では使用できません。新しい背景チェックポイントは、背景を再計算せずに画像、利用可能な履歴、診断状態を正確に復元します。

### ラベル

画像を読み込むか結果を生成した後、**ツール → ラベル → ラベルを管理…** を開きます。
各ラベルには対象（ソーススタック、位置合わせ済みスタック、出力結果）があります。出力
ラベルはすべての結果に適用することも、名前で選択中の結果に関連付けることもでき、その
結果の名前変更や並べ替えでは関連が変わりません。

**追加** で新しいラベルを作り、項目を選んで編集し、チェックボックスで有効／無効を
切り替えます。固定文字のほか、`{value}` でフレーム番号を挿入できます。番号は開始値に
0 始まりのフレーム番号×間隔を加えたもので、単一の出力では常に開始値を使います。

全フレーム、現在のフレーム、または `3-5,8` のようなカスタム範囲を選べます。無効または
利用できないフレーム番号があるとドラフトを適用できません。現在／カスタム範囲はスタック
の並べ替え後も選択したソースの同一性に従い、全フレームのラベルは後から追加したフレーム
にも適用されます。対象が見つからない場合、ラベルは明示的に新しい対象を選ぶまで元の
同一性との関連を保ちます。

プレビューは実際の対象を使います。前へ／次へ、またはフレーム番号の入力で移動し、
**フィット** か **100%** を選び、100% では画像をドラッグしてパンします。位置と文字
サイズは画像の画素単位です。代替フォントの使用や描画失敗は報告されます。PNG または
TIFF に書き出すときは元のビット深度を保ちます。

**適用して閉じる** はドラフト全体を 1 回の undo 可能な変更として確定します。キャンセル、
Esc、ダイアログを閉じる操作はドラフトを破棄します。別のラベルを選んでも未確定の編集は
残ります。**削除** は選択中の項目だけを、最後の 1 件でも削除します。メニューの削除操作は
ソース、位置合わせ済みスタック、出力、すべてのラベルを個別に消去でき、こちらも undo
できます。ラベルの適用はセッション表示を変えるだけなので、ファイルに書き込むには画像を
書き出してください。

## 11. 設定と構成

**設定 → 詳細設定** では、パフォーマンス、位置合わせ、センサー補正、出力命名、
StackMFF AI、起動の設定を編集できます。**OK** を押すまで変更は下書きで、キャンセル、
Esc、閉じる操作では破棄されます。タイルサイズを小さくすると、表示される重なり上限は
即座にタイルの半分へ更新されます。AI セクションの保存済みバッチ上限は保持されますが、
現在の推論は 1 回の呼び出しにつき 1 タイルです。位置合わせの幅は精度に影響し、診断の
収集は位置合わせセクションのチェックボックスです。

自動アップデートのダウンロードはアイドル中に実行され、自動ではインストールされません。
完了したダウンロードは **再起動して更新** を明示的に選ぶまで準備完了のまま残ります。
再起動は編集中の内容と未保存の作業を保護し、復元データを書き込んでから置換版を起動
します。ダウンロードや準備のキャンセルは現在の安全な境界まで待ちます。完全で新しい
ステージ済みビルドがあればオフラインでもインストールできます。

ステータスパネルは、OS が両方を提供できる場合に使用中／合計の物理メモリを表示し、
取得できない場合は `N/A` と表示します。

### タイル設定（メモリ最適化）

大きな画像では、メモリ問題を避けるために OpenFocus はタイルベースの処理を行います。

**設定 → 詳細設定 → パフォーマンス** から設定します。

- **タイル処理を有効化**：オフにすると強制的に画像全体を処理します（大きな画像ではメモリ不足になる可能性があります）
- **タイルサイズ**：各処理タイルのサイズ（既定：1024px）
- **タイル重なり**：継ぎ目のない合成のためのタイル間の重なり（既定：256px）
- **タイルしきい値**：このサイズを超える画像でタイル処理を使用（既定：2048px）

**推奨**：
- 小さいブロックサイズ：メモリ使用量が少なく、処理は遅い
- 大きいブロックサイズ：メモリ使用量が多く、処理は速い
- 結果に継ぎ目が見える場合は重なりを増やしてください

### 位置合わせ設定

**設定 → 詳細設定 → 位置合わせ** から設定します。

- **ダウンスケール幅**：位置合わせの前処理解像度
  - 既定：1024px
  - 速度を優先するなら小さく、精度を優先するなら大きく

### 性能の参考値

大規模な実スタックでの実測スループットとメモリ使用量、深いスタックや高解像度入力に
対する実践的な指針は [PERFORMANCE.md](./PERFORMANCE.md) を参照してください。

### スレッド設定

CPU の並列処理を制御します。

**設定 → 詳細設定 → パフォーマンス → スレッド数** から設定します。

- `0` は自動調整です。新しい設定の既定値は `0` です。
- 正の値はスレッド数の上限です。保存済みの上限は引き継がれます。
- CPU 容量、リソースモード、空きメモリに応じて並列数を下げます。

### リソースモード

**設定 → 詳細設定 → パフォーマンス → リソースモード** は、1 回の描画がマシンの
どこまで使えるかを決めます。融合結果自体は変わりません。

| モード | 動作 |
|---|---|
| バランス（既定） | 物理コアの約 20% とメモリ余裕をデスクトップ用に残します |
| 応答優先 | コアの約半分と小さめの実行中ウィンドウを使います。描画は遅くなりますが、マシンは最も快適です |
| 最大 | メモリ予算が許すすべての物理コアを使います |

プランナーは物理コア、CPU affinity、クォータを考慮し、同時に 1 層の並列処理だけを
実行します。重い処理は準備から公開まで同じ admission を共有し、キャンセルは実行中の
ネイティブ呼び出しが終わるまで待ちます。メモリが不明または不足している場合はリソース
エラーになります。選択したタイルグリッドは変わらず、自分で小さいタイルを選ぶと出力画素が
変わる可能性があります。

### GPU アクセラレーションの切り替え

StackMFF V1/V2/V3 は ONNX Runtime を使用します。Windows の DirectML と macOS の CoreML で推論を加速できる場合があり、それ以外は CPU を使用します。プロバイダーの存在だけでは GPU 実行の証拠になりません。他の GPU のサポートは検証が必要です。
従来のアルゴリズムは常に CPU で動作します。

- **設定 → GPU アクセラレーション** で切り替えます
- チェックを外すと AI 手法が CPU で実行されます。GPU ドライバが不調なときに便利です
- アクセラレータが使えない、または使われていない場合は `N/A`、アクセラレータはあるが
  選択中の手法が CPU 専用の場合は `CPU*` と表示されます
- 選択は次回のレンダリングから有効になり、記憶されます

### AI バッチサイズ

**設定 → 詳細設定 → AI** から設定します。

- 保存するバッチ上限の既定値は 2 ですが、現在はすべてのデバイスで 1 回に 1 タイルを推論します。
- 上限を増やしても GPU の並列バッチ処理は有効になりません。

### テーマ

**ライト（既定）** と **ダーク** の 2 つのインターフェーステーマがあります。
**設定 → テーマ** で切り替えると即座に適用され（Windows のタイトルバーも追従）、
記憶されます。初回起動時はウェルカムダイアログでテーマを選びます。

### ポータブルモード

`OpenFocus.exe` の隣に `OpenFocus.portable` という名前の空ファイルを作成すると
（ポータブル版の zip には最初から含まれています）、設定、ログ、最近使ったファイル
などすべてのユーザーデータが、ユーザープロファイルではなくアプリの隣の
`OpenFocusData` フォルダに保存されます。USB メモリに入れて持ち運べます。
このマーカーファイルを削除すると通常のプロファイルに戻ります。

### EXIF メタデータ

PNG/TIFF/JPEG/WebP への書き出しでは、サニタイズ済みのカメラ・レンズ・露出・日付・GPS
メタデータを保持し、Orientation を 1 に設定します。BMP には EXIF を埋め込みません。
JPEG の EXIF または ICC が形式の上限を超える場合は明確なエラーを表示するため、
PNG または TIFF を選んでください。元画像のサニタイズ済み EXIF が 16 MiB を超える場合、
OpenFocus は読み込みを拒否します。先にそのファイルの EXIF を削除するか縮小してください。

### HEIC/HEIF 入力

iPhone の写真をそのまま読み込めます。オプションの `pillow-heif` パッケージが必要です
（`pip install pillow-heif`。パッケージ版のビルドには含まれています）。

### センサー補正とフラットフィールド

フラットフィールド補正はセッションの作業画素を変えますが、ソースファイルは上書き
しません。白基準画像とプレビュー用フレームを選び、ソースや倍率を変えたらプレビューを
再生成します。基準画像と作業／ベース画像は同じ座標範囲とサイズである必要があります。
適用時は両方のスタックを準備してから確定し、任意の基準フレーム削除も同じ undo 手順に
含まれます。セッション外に画素を残すには、補正後のソース画像を書き出してください。

バッチ処理でも処理オプションで任意の白場画像を選べます。元のフレーム解像度のピント外れ
の基準を選ぶと、入力スタックに合わせて縮小され、既定のダストサイズで位置合わせ前に
適用されます。読み取れない基準やサイズ不一致は、そのスタックを明確に失敗させます。
基準はフォルダ入力（グループ処理を含む）から除外され、融合には少なくとも 2 つの
ソースフレームが必要です。空欄なら補正なしで処理します。CLI でも `--dust-map WHITE`
で指定できます。フラットフィールド補正は透明入力と併用できません。

センサー補正は任意で、位置合わせ前に元のセンサー座標のフレームへ実行されます。
デスクトップでは **設定 → 詳細設定 → センサー補正** にあり、バッチダイアログにも
同じコントロールがあります。既知のホット／デッド画素を直すには明示的な欠陥マスクを
選びます。OpenFocus が標本画像からマスクを推測することはありません。マスクはソースと
同じ寸法の単一チャンネル 8bit または 16bit 画像で、0 は正常、1 またはチャンネル最大値が欠陥です。処理前に範囲を確認して
ください。画面の 10% を超えるマスクや、未マスクの隣接画素がない欠陥は拒否されます。
マスクは元の解像度のままにし、ソース画像として選択しないでください。GUI で欠陥マスクを
使うときはソースフレームを原寸で読み込みます。マスクが縮小されることはありません。
GUI スタックで回転、反転、フラットフィールド補正などのソース変更を行った後は、センサー
補正（ノイズ除去を含む）を適用できません。元のフレームを読み直すか補正を無効にして
ください。そのようなソース履歴を持つ復元プロジェクトも同様です。事前位置合わせの ROI
処理とは併用できません。補正設定は現在のセッションと保存プロジェクトに属し、グローバル
設定ではありません。バッチと CLI は元の入力を別々に処理し、センサー補正、フラット
フィールド補正、位置合わせの順に実行します。欠陥マスクには中立な EXIF 方向を持つ
ソースが必要です。方向付きファイル、カメラ RAW、方向を確定できないソースは、デコード
後の画素がセンサー座標と一致しない可能性があるため拒否されます。

任意のセンサー ノイズ除去は欠陥マスクとは独立で、既定では無効です。原寸で結果を確認し、
平滑化が標本に適しているか判断してください。センサー補正はソースファイルと 8bit/16bit
深度を保持し、フラットフィールド補正とは別の処理です。CLI では
`--defect-mask-path MASK` と `--sensor-denoise` を使い、レシピと Python レシピ API も
これらのオプションを記録します。レシピはマスクの指紋を保存し、欠落または変更された
マスクを拒否します。CLI の補正は透明入力と併用できません。グループ処理では元のフレーム
だけを補正し、中間グループ結果には適用しません。

レシピは出力先がすべての入力フォルダの外にあることを要求し、明示的に選んだ入力を
出力にはできません。ソース画像を保護し、再実行時に以前の結果を入力へ含めないためです。
プロジェクトの処理設定は、元のソースが移動していてもテンプレートやレシピとして再利用
できます。**ファイル → 処理テンプレートを保存…** はソースパスなしで設定を保存し、
**ファイル → 処理テンプレートを適用…** は読み込み済みスタックへ適用します。
`openfocus recipe create --project` が書き出すヘッドレスレシピには、引き続き明示的な
`--input` が必要です。テンプレートはセンサーノイズ除去フラグを運びますが欠陥マスクの
パスは保存せず、レシピはマスクのパスと指紋を保存します。プロジェクト自体を開くには
ソースと記録されたフラットフィールド基準が必要です。

**ツール → ダストマップ（フラットフィールド）** でスタックのベース倍率のときに
ファイル基準を適用すると、保存プロジェクトはその絶対パス、内容ハッシュ、ダストサイズを
記録し、開くときに元のソースへ 1 回再適用します。基準ファイルは変更せず同じ場所に
置いてください。欠落または変更された基準があるとプロジェクトを開けません。スタックから
選んだ基準や、作業／ベース倍率が異なる補正では、プロジェクトを保存する前に補正後の
ソーススタックを書き出す必要があります。補正後に作業倍率を変えた場合は、保存前に
補正時の倍率へ戻すか、補正後のスタックを書き出してください。

**ヘルプ → フィードバックを送る** はローカルログを開きます。「コピー」は表示中の
セッションログだけをコピーし、フィードバック ZIP にはセッション／アプリ全体のログと
環境情報が入ります。提出前に内容を確認してください。GitHub を開く操作はトラッカーを
開くだけです。書き出しのキャンセルはファイルを変更せず、エラー時は以前の保存先ファイル
を残して失敗したパスを表示します。

各起動は独自のローテーションログを書き込むため、同時に動く GUI/CLI の記録は分かれます。
タスク ID はパラメータ、経過時間、完了／キャンセル／失敗を結び付け、予期しないエラーには
完全なトレースバックが付きます。フィードバック ZIP には現在のクラッシュレポートと依存
バージョンも含まれます。**ヘルプ → ログフォルダーを開く** またはフィードバック画面に
表示されるパスからファイルを探してください。ログはプロセスごとに 1 MB でローテーション
し、3 つのバックアップを保持します。14 日を超えた非アクティブなセッションログは削除
されます。詳しいサポートログが必要な場合は、起動前に
`OPENFOCUS_LOG_LEVEL=DEBUG` を設定してください。`OPENFOCUS_LOG_DIR` で別のログ
フォルダーを指定できます。

### アップデート

ヘルプ → アップデートを確認 で、お使いのバージョンを `openfocus.top` のリリース情報と比較します。
新しいリリースは同サイトからアプリのアイドル中にバックグラウンドでダウンロードされます。ビルドが
ステージされると、バナーとステータス領域に **再起動して更新** が表示され、オフラインで
適用できます。自己更新できないビルドでは公式サイトのダウンロードページが開きます。自動確認は
1 日に最大 1 回、静かに実行されます。

### 位置合わせキャッシュ

OpenFocus は位置合わせ結果をソーススタックの隣の `.openfocus_cache` フォルダに
保存できます。同じスタックを再度開くと（ファイルが変更されていなければ）
位置合わせを完全に省略できます。**設定 → 詳細設定 → 位置合わせ → 位置合わせキャッシュ**
で切り替えます。
古くなったエントリは自動的に置き換えられます。

### 出力命名

**設定 → 詳細設定 → 出力命名** では、新しく描画した結果を識別するための任意の
ファイル名プレフィックスを設定できます。入力すると例が更新されます。使えるのは
最大 40 文字の英字、数字、アンダースコア、ハイフンです。空欄なら元の命名のままです。
**OK** で記憶し、キャンセルすると変更を破棄します。プレフィックスは新しい出力
リスト名と推奨書き出し名の一部になり、既存の結果は元の名前を保ちます。保存
ダイアログでは名前を編集できます。この設定はソースファイルやバッチ出力名を
変更しません。

### 保存される設定

以下はすべてアプリケーションの再起動後も自動的に保持されます。スレッド数、
リソースモード、タイルパラメータ、位置合わせのダウンスケール幅、AI 融合（StackMFF V3）の
バッチサイズ、GPU アクセラレーションの切り替え、位置合わせキャッシュと位置合わせ診断の
切り替え、表示言語、ウィンドウサイズ／パネルレイアウト、ドラッグ出力形式、手法ごとの
明るさオプション、平滑化と半径の値、最近開いたスタック。
設定ダイアログは確認した時点で保存され、アプリケーション終了時にもすべて保存されます。
環境設定はユーザーごとに `OpenFocus/OpenFocus.ini`（QSettings の INI 形式）へ
保存されます。

### 表示言語

**設定 → 言語** から 12 言語（English、中文、日本語、Español、Deutsch、Français、
Русский、한국어、Português、Italiano、Nederlands、Polski）をいつでも切り替えられます。
変更は即座に反映され、以降のセッションでも記憶されます。新しい言語パックは
`locales/<code>.py` を追加するだけでメニューと自動検出に加わります。

### 自動アップデート確認

1 日 1 回、起動から数秒後に OpenFocus は新しいリリースがないか `openfocus.top` を静かに
確認します。リリースノートも同サイトから取得します。見つかると画像パネルの上にバナーが表示されます。内容はバージョン、
**今すぐ更新**（ステージ済みビルドを適用、またはダウンロードを開始します）、**新機能を見る**
（リリースノート）、閉じるボタンです。閉じるとそのバージョンについてのみ
バナーが隠れます。
次のリリースでは再び表示され、**ヘルプ → アップデートを確認** ですぐに再表示できます。

バックグラウンドでダウンロードが進んでいる間は、ステータスバーに進捗が表示されます。
**ヘルプ → アップデートを確認** からいつでも手動で確認することもできます。

## 12. バッチ処理

複数のフォルダを自動で処理します。

1. **ツール → バッチ処理** に移動します
2. バッチダイアログで操作します：
   - **フォルダ追加**：画像シーケンスを含むフォルダを選択します
   - **フォルダをドラッグ**：1 つ以上のスタックフォルダをダイアログ（またはフォルダ
     一覧）の任意の場所へドロップすると一度に追加されます。ドロップすると複数フォルダ
     モードに切り替わり、デコードに合わせてサムネイルが表示されます
   - **選択を削除**：選択したフォルダを一覧から削除します
3. 出力設定を構成します：
   - **元のフォルダにサブフォルダを作成**：各入力フォルダ内に結果を作成します
   - **元のフォルダと同じ**：既存ファイルを保ったまま入力の隣に保存します
   - **出力フォルダを指定**：出力先を指定します
4. 現在の融合／位置合わせ設定を確認します
5. **バッチ処理開始** をクリックして開始します

バッチダイアログにはリアルタイムの進捗が表示されます。処理はいつでもキャンセルできます。

### バッチ処理の注意点

- 開始時のメインウィンドウ設定のスナップショットを初期値にし、バッチ側の設定で上書きできます
- 各フォルダまたは分割グループは、同じパイプラインで独立して処理されます
- **グループ融合** は複数フォルダモードでのみ使え、**大きなスタックをグループに分けて処理**
  チェックボックスで有効にします。オフのときはグループサイズと重なりが非表示になります。
  オンにするとグループサイズは 2 以上、重なりは 0 からグループサイズ−2 までです。
  デスクトップの重なりは 1 から始まり、サイズ変更時に許容範囲へ制限されます。
  グループは一時ディスクを使ってラウンドごとに融合し、進捗表示に各ラウンドが出ます。
  融合、露出合わせ、ベース補正、位置合わせは各グループ自身のフレームと基準を使うため、
  結果はスタック全体を一度に処理した結果の近似になります。融合手法が必要で、元フレームの
  深度、出所、位置合わせ済みフレームの書き出しは利用できません。分割フォルダモードには
  対応しないため、そこではチェックボックスが拒否されます。位置合わせするグループは自身の最初のフレームを座標基準にします。各回の
  位置合わせは補間用に保守的な境界を削り、後のラウンドは残存矩形の交差を取るため、最終
  画像は裁ち落とされます。各グループは両辺 8 画素より大きい必要があり、難しい回転や射影
  変換では安全な矩形が得られずエラーになることがあります。その場合は位置合わせなしの
  事前に整列した入力を選ぶか、グループ化を無効にしてください。
- グループ入力は向きを揃えた同一寸法の単一フレームファイルで、Pillow が読めるヘッダーを
  持つ必要があります。カメラ RAW、マルチページファイル、アルファ付き画像や透明 PNG は
  非対応です。アルファを除去するかグループ化を無効にしてください。CLI の dry-run でも
  この制限を確認します。コマンド例：
  `python main.py --input stack --output fused.png --group-size 8 --group-overlap 1`。
  CLI のグループ入力はフォルダでなければならず、`--depth-map` と併用できません。
  スタック全体に別の OpenFocus 位置合わせ基準を指定する場合も併用できません。フラット
  フィールド基準は位置合わせ前の元フレームに適用され、出力のシャープ化は最終グループの
  後に 1 回だけ適用されます。
- **ファイル → 処理テンプレートを保存** はソースパスを含まない処理設定を保存します。
  **処理テンプレートを適用** はテンプレート、プロジェクト、またはプロジェクト由来の
  レシピを現在のスタックへ適用し、入力、変換、除外、ラベルは置き換えません。テンプレート
  自体は実行可能なレシピではありません。CLI では `openfocus recipe create` と
  `openfocus recipe run` で処理レシピを保存・再実行できます。プロジェクト内のソース変換は
  直接 CLI レシピへ取り込めないため、先に処理済みのソーススタックを書き出してください。
- **モードごとの出力先**：**位置合わせのみ** では、選択した出力先にスタックごとの
  `<stack>_aligned` フォルダが作られ、出力パネルにはそのフォルダが表示されます。
  **融合＋位置合わせ済みを保存** では、融合画像を `<stack>.<ext>` として出力先に書き、
  整列フレームを隣の `<stack>_aligned` に置きます。出力パネルには融合結果だけが表示
  されます。**融合のみ** では融合画像だけを書き出します。出力パネルのフォルダ名は
  ディスク上の名前と一致します。
- 整列フレームは元のファイル名の幹を保ちます。重複名と既存フォルダには連番が付き、
  ソースファイルが置き換えられることはありません。
- 同じフォルダに元ファイルがある場合、旧ビルドが残した `*_registered*` コピーはフレーム
  として読み込まれません。読み込みメッセージにスキップ数が表示されます。
- PNG/TIFF は 16bit を保持し、JPG/BMP を明示すると 8bit に変換されます。
- キャンセルはワーカーが停止するまで待ちます。確定済みファイルは残り、部分成功、失敗、
  キャンセル、未開始のタスクは別々に数えられます。

## 13. 結果の書き出し

### 単一の結果を保存する

1. 出力リストで保存したい結果を選択します
2. **ファイル → 保存** に移動するか、`Ctrl+S` を押します
3. 形式と保存先を選択します
4. **保存** をクリックします

### 結果を共有する

出力を右クリックして **共有** を開きます。**プレビュー画像をコピー（JPEG）** は、現在の結果をラベルとスケールバーを含むフル解像度の実際の JPEG と、デコード済みビットマップとしてクリップボードに置きます。**ファイルパスをコピー** は選択した結果のローカルパスをテキストとファイル URL でコピーします。保存後に変更のない結果は既存ファイルを使い、未保存・変更済み・ファイルがない結果はシステムの一時フォルダーに PNG を自動作成します。これによって保存済みにはなりません。一時ファイルはシステムに削除されることがあるため、長期保存には **名前を付けて保存** を使ってください。**フォルダーで表示** はフォルダー選択画面を出さずにエクスプローラー、Finder、またはファイルマネージャーでそのファイルを選択します。**プライベート共有リンクを作成** はホスト型共有が提供されるまで無効です。

### レイヤー付き TIFF の保存

レタッチした出力を選び、**名前を付けて保存**の形式一覧でレイヤー付き TIFF を選ぶと、結果と
記録されたソースフレームを 1 つのレイヤー付き TIFF として保存できます。ライブのラベルと
スケールバーは含まれず、未保存の注釈変更は保護されたままです。ソースの幾何と有効マスクは
保持されます。結果と各ソースはサイズの一致する不透明な RGB またはグレースケール画像で、
8bit/16bit 深度が同じである必要があり、各ソース矩形は結果内に収まらなければなりません。
最大 128 ソース、ソース名は 255 文字までで、NUL や基本多言語面外の文字（多くの絵文字など）
は使えません。安全でない状況や 512 MiB を超えると推定される処理は拒否され、不完全なファイルは書かれません。
Windows の GIMP 3.2.6 はオフセットと透明な位置合わせ余白を含めて読み込めます。結果が
表示され、ソースレイヤーは非表示になり、GIMP は表示される背景レイヤーも追加します。
他のエディタは未検証です。

### ドラッグ出力形式

出力リストから結果をドラッグすると、出力リストのコンテキストメニューで選んだ形式
（**ドラッグ出力形式**：JPG、PNG、WebP、TIFF）で画像ファイルが書き出されます。選択は
記憶されます。

### 位置合わせ済みスタックの保存

1. **ファイル → スタックを保存 → 位置合わせ済みスタック** に移動します
2. 保存形式を選びます：
   - **フォルダとして保存**：整列済みの各フレームを個別の画像ファイルとして保存します
   - **マルチページ TIFF として保存**：スタック全体を 16bit 深度を保ったまま 1 つの `.tif` に書き出します
   - **GIF として保存**：整列済みシーケンスのアニメーション GIF を作成します

### 入力スタックの保存

1. **ファイル → スタックを保存 → 入力スタック** に移動します
2. 保存形式を選びます：
   - **フォルダとして保存**：元のフレームを個別の画像として保存します
   - **マルチページ TIFF として保存**：入力スタックを 16bit 深度を保ったまま 1 つの `.tif` に書き出します
   - **GIF として保存**：入力シーケンスのアニメーション GIF を作成します

### 書き出し形式

- **JPG**：非可逆圧縮。8bit。品質とサイズのバランスが良い
- **PNG**：可逆圧縮。8bit/16bit の画像データを保持
- **BMP**：非圧縮。16bit データは 8bit に変換
- **TIFF**：8bit/16bit を保持。マルチページ書き出しではスタック全体を 1 ファイルに保存
- **GIF**：8bit パレットのアニメーション。キャンセルしても既存の出力先は壊れません

## 14. コマンドラインインターフェース

`pip install openfocus` には AI モデルと重み、HEIC とカメラ RAW のデコードが含まれます。Python 3.13 以降で DTCWT を使うには、続けて `python -m pip install --no-deps dtcwt==0.14.0` を実行します。OpenFocus は NumPy 2 の互換アダプターを提供しますが、`pip check` は元パッケージの NumPy 制約を報告します。

OpenFocus は GUI なしでも動作します。スクリプト化したパイプラインや CI に便利です。
pip パッケージを入れると `openfocus` コマンドを直接使えます。ソースから実行する場合は
`openfocus` を `python main.py` に読み替えてください。主なサブコマンドは次のとおりで、
融合オプションはどちらの入口でも同じです。

```bash
openfocus version                       # バージョンを表示
openfocus describe                      # JSON：手法、パラメータ、機能、制御コマンド
openfocus gui [--control] [--socket NAME] [パス…]   # デスクトップアプリを起動
openfocus ctl <command> [flags]          # 実行中のウィンドウを操作（AGENT_CONTROL_SPEC.md）
openfocus recipe create FILE --input … --output … [処理オプション]
openfocus recipe run FILE [--dry-run]    # 保存済みヘッドレスレシピを再生
openfocus retouch replay CHECKPOINT --base BASE --sources … --output RESULT
```

`openfocus gui` は切り離して起動します。`--control` は制御チャネルの確立を待ち、
接続情報の JSON を表示します。`openfocus describe` と `version` は入力不要です。
Agent 向けの手順は [AGENT_CONTROL_SPEC.md](./AGENT_CONTROL_SPEC.md) と
`skills/openfocus-control/SKILL.md` にあります。デスクトップ版は起動時にトークン保護
されたローカル Agent チャネルも自動で開始します。

```bash
pip install openfocus
openfocus -i ./stack_folder -o ./result/fused.png
```

```bash
# 既定の AI（StackMFF V3）でフォルダを融合
python main.py --input ./stack_folder --output ./result/fused.png

# DTCWT と ECC 位置合わせ、8 スレッド
python main.py -i ./stack_folder -o ./result/fused.png -m dtcwt -a ecc -t 8

# StackMFF V3 を CPU に強制し、タイルサイズを指定
python main.py -i ./stack_folder -o ./result/fused.png -m stackmffv3 --cpu --tile-size 512

# ファイルを明示的に列挙。動画ファイルも入力として受け付けます
python main.py -i img1.jpg img2.jpg img3.jpg -o fused.png -m gfgfgf

# メタデータから較正したスケールバー付きのマルチページ TIFF Z スタック
python main.py -i ./zstack.tif -o fused.png -m dtcwt --scale-bar

# 融合せず、入力も変えずに隣接する類似フレームだけを調べる
python main.py -i ./stack_folder --suggest-duplicates
```

`--suggest-duplicates` はフォルダまたは順序付きの単一フレーム画像リストを受け取り、
`files` と `suggestions` 配列を持つ JSON オブジェクトを出力します。`index` と
`reference_index` は `files` 内の 0 始まりの位置、`difference` は正規化したサンプル差の
平均です。`--json report.json` を加えると同じオブジェクトを保存できます。この確認モードは
`--output`、`--output-dir`、`--json-progress`、`--dry-run` と併用できません。レポートは
指定した入力順で隣接ファイルを比較するだけで、後から除外するフレームは考慮しません。
基準フレームを除外する場合は、その後続フレームを再検討するか、意図した順序で再度確認して
ください。

1 回の描画に `--align openfocus --alignment-report alignment.json` を加えると、フレーム
ごとの位置合わせ結果を保存できます。JSON には `method`、`input`、`frame_count`、`entries`
が入り、`frame_index` は融合前のデコード入力順で 0 始まりです。マルチページ画像はページ順、
動画はデコード順に展開されます。複合手法は段階ごとに別の項目を持ちます。レポートは成功後
にアトミックに書き込まれ、入力や他の出力を置き換えることはできません。バッチ、グループ、
dry-run では使えません。

### 処理レシピ

処理レシピはヘッドレス設定を保存して再利用・移行できます。

```bash
openfocus recipe create workflow.json -i ./stack_folder -o ./result/fused.png -m dct --cpu
openfocus recipe run workflow.json --dry-run
openfocus recipe run workflow.json
```

レシピ JSON のバージョン 1 は `version`、`input` 配列、`output` または `output_dir`、
`options` オブジェクトを含みます。パスはレシピファイルからの相対パスで、移動するときは
入力も一緒に移動してください。作成時は CLI 設定と解決済みのアルゴリズムパラメータを記録し、
未知のフィールド、不正な値、未対応バージョンは拒否します。`--dry-run`、`--resume`、
`--json`、`--config` などの一時的な制御項目はレシピに書き込まれません。dry-run は入力を
確認するだけで結果ファイルを書きません。既存の `.ofproj` から設定を取り出すこともできます。

```bash
openfocus recipe create workflow.json --project session.ofproj -i ./new_stack -o ./result/fused.png
```

融合、位置合わせ、明るさ、順序、シャープ化、タイル設定が転送され、GUI 用の処理設定も
埋め込まれます。フレーム除外、読み込み倍率、ラベル、編集は転送されません。ソース変換
（適用済みフラットフィールド補正を含む）があるプロジェクトは、先に補正済みソーススタックを
書き出してください。レシピの出力は入力フォルダの外に置く必要があり、入力ファイルを出力には
指定できません。グループ化オプションは CLI 引数から取り込めます。GUI の
**ファイル → 処理テンプレートを保存** はソースパスなしで設定を保存し、
**処理テンプレートを適用** はテンプレート、プロジェクト、プロジェクト由来のレシピを
現在のスタックへ適用します（入力、変換、除外、ラベルは置き換えません）。テンプレート自体は
実行可能なレシピではありません。レシピに埋め込まれた GUI 設定と CLI オプションは独立して
いるため、JSON を編集する場合は両方を一致させてください。

PyQt をインポートせずに、同じヘッドレス API を Python から利用できます。`dry_run=False` で処理を実行します。

```python
from core.recipes import capture_project_recipe, capture_recipe, load_recipe, save_recipe, run_recipe

capture_recipe("workflow.json", ["-i", "stack_folder", "-o", "result/fused.png", "-m", "dct"])
capture_project_recipe("from-project.json", "session.ofproj",
                       ["-i", "new_stack", "-o", "result/fused.png"])
recipe = load_recipe("workflow.json")
save_recipe("workflow.json", recipe)
exit_code = run_recipe("workflow.json", dry_run=True)
```

`capture_recipe` の引数のパスは現在のディレクトリからの相対パスとして、`save_recipe` に保存するパスはレシピからの相対パスとして扱われます。レシピは設定と参照、明示的に選択したセンサー欠陥マスクの内容のフィンガープリントを記録しますが、入力画素、ソフトウェアのバージョン、ハードウェア、元スタックのチェックサムは記録しません。来歴が重要な場合は別途保存してください。同じ設定でもソフトウェア、ドライバー、デバイスが異なれば画素が同一になる保証はなく、GPU のニューラル処理は非決定的な場合があります。CPU での実行が必要な場合は `--cpu` を使い、インストールしたソフトウェアと入力を保存してください。

### レタッチチェックポイントの再生

GUI と同じ v2 `.ofretouch` と従来の JSON v1 をヘッドレスでも読み込めます。v2 は正確な
画像、利用可能な undo/redo タイル、診断状態を復元し、自動背景を再計算しません。

```bash
openfocus retouch replay edits.ofretouch --base fused.png --sources frame1.png frame2.png --output retouched.tif
```

どちらの形式も元のベース画像と、実際にレタッチに使った全処理済みソースフレームを
セッション順に指定してください。位置合わせ、ROI 切り出しやその他の処理後の元の画素値と
ビット深度を保ちます。ベース、順序付きフレーム、記録された位置と有効マスクを検証し、
不一致を拒否します。
各パスには 1 枚の画像だけを指定でき、出力は PNG または TIFF でベースのビット深度を保ちます。
チェックポイントと入力画像を出力には指定できません。

| オプション | 説明 |
|--------|-------------|
| `--input, -i` | 画像フォルダ、動画ファイル、1 つ以上の画像ファイル、またはマルチページ TIFF |
| `--output, -o` | 単一スタックの出力画像パス（拡張子が形式を決定）。`--output-dir` がない場合は必須 |
| `--output-dir, -d` | バッチモード：各入力フォルダを処理し、スタックごとに `<folder>.png` を書き出す |
| `--method, -m` | `stackmffv3`（既定）、`stackmffv2`、`stackmff`、`openfocus_a/b/c`、`guided_filter`、`dct`、`dtcwt`、`gfgfgf` |
| `--param KEY=JSON_VALUE` | 融合パラメータ。複数回指定でき、旧式の専用フラグより優先 |
| `--align, -a` | `none`（既定）、`homography`、`ecc`、`openfocus`、`both` |
| `--align-param KEY=JSON_VALUE` | 位置合わせパラメータ。例：`failure_policy="fail"`、`reference_frame=3` |
| `--align-shift-limit` | `openfocus` 位置合わせの移動探索範囲（フレームサイズに対する割合、既定 0.03）。累積移動の拒否しきい値ではありません |
| `--alignment-report PATH` | 位置合わせを有効にした単一・非グループ描画のフレーム別結果を JSON で保存。バッチ／グループ不可 |
| `--suggest-duplicates` | 隣接する類似フレームを JSON で提案。融合も除外も行わない。出力・進捗・dry-run・センサー補正オプションとは併用不可 |
| `--exposure-match` | 融合前の露出合わせを有効化（CLI では全手法で既定オン）。A/B/C は処理順の最初のフレーム、他の手法は最後のフレームを基準にします。`--no-exposure-match` で無効化 |
| `--base-frame` | 融合後の任意ステップ：出力の低周波成分を `last`/`first` フレームに合わせます（既定 `none`） |
| `--sharpen-output` | 融合後、量子化前に軽いアンシャープマスクを適用。既定はオフ |
| `--sort` | `openfocus_a/b/c` のフレーム順：`asc`（既定、ファイル順）、`desc`（遠→近のスイープを反転）、`off` |
| `--frame-order` | フォルダ入力：`auto`（既定）は全フレームに EXIF のフォーカスステップがあれば近→遠の順に並べます（OM SYSTEM のフォーカスブラケットは中間の深さから始まります）。なければ名前順。`name` は常にファイル名順。明示的に指定したファイルは指定順のまま |
| `--dust-map WHITE` | ピントを外した白場画像によるフラットフィールド（ダストマップ）補正 |
| `--defect-mask-path MASK` | センサー座標の欠陥マスク。非ゼロ画素を位置合わせ前に修復 |
| `--sensor-denoise` | 位置合わせ前に保守的なセンサーノイズ除去を適用 |
| `--kernel, -k` | `kernel_size` を持つ手法のカーネルサイズ。A/B/C のパラメーターは `--param` で指定 |
| `--threads, -t` | スレッド数の上限。`0` は自動（既定値）、正の値は並列数を制限 |
| `--resource-preference` | リソースモード：`balanced`（既定）、`responsive`、`maximum` |
| `--batch-size` | AI タイルのバッチ上限（既定 2）。現在は 1 回に 1 タイルを推論 |
| `--ai-mode` | StackMFF V3 の出力：`soft`（既定、確率で混合）または `hard`（画素ごとに最も確率の高いフレーム） |
| `--cpu` | GPU が利用可能でも CPU を強制します |
| `--downscale` | 位置合わせの特徴検出のダウンスケール幅 |
| `--tile-size` | 大きな画像向けのタイルブロックサイズ |
| `--tile-enabled` / `--no-tile-enabled` | 必要時のタイル処理を有効／無効化（既定は有効） |
| `--tile-overlap` | タイルの重なり（画素） |
| `--tile-threshold` | タイル処理を始める最小画像サイズ |
| `--group-size` | グループ融合の各グループのフレーム数。`0` で無効（既定）、有効時は 2 以上。フォルダ入力のみで、`--depth-map`、RAW/アルファ/マルチページ入力、既定以外の OpenFocus 基準フレームとは併用不可 |
| `--group-overlap` | 連続グループが共有するフレーム数。既定 `0`、最大でグループサイズ−2 |
| `--scale-bar` | スケールバーを描画します（較正は TIFF メタデータから自動検出） |
| `--depth-map [path]` | カラー化したフォーカス位置（深度）マップも保存します（既定：`<output>_depth.png`）。対応手法のみ、グループ／透明入力では拒否。バッチでは既定パスのみ |
| `--depth-colormap` | `--depth-map` のカラーマップ：turbo、viridis、jet、gray など（既定 turbo） |
| `--auto-background [preset]` | レタッチの自動背景と同様に、スタックした背景を位置合わせ済みフレームの背景に置き換えます：`auto`（既定）、`soft`（最もぼけた背景）、`sharp`（最も遠くにピントが合ったフレーム）。位置合わせ済みフレームが必要なため、グループ合成では使えません |
| `--background-mode` | 自動背景：`clean`（既定）はフレームが記録した範囲内でスタックの輪郭のハロも取り除きます。`faithful` は残します |
| `--keep-soft-parts` | 自動背景：いずれかのフレームでピントが合った、被写体につながる柔らかい部分を残します |
| `--save-stacked [path]` | `--auto-background` と併用し、置き換え前の結果も保存します（既定：`<output>_stacked<ext>`）。バッチでは既定パスのみ |
| `--missing-data-map [path]` | `--auto-background` と併用し、欠損データマップとクラスごとの 8 ビットマスクも保存します（既定：`<output>_missing.png`）。バッチでは既定パスのみ |
| `--scale-um` | µm/px 単位のピクセルサイズ。メタデータより優先されます（`--scale-bar` を暗黙に有効化） |
| `--dry-run` | パラメータと入力を確認するだけで、結果を書きません |
| `--resume` | バッチの未完了タスクを再開 |
| `--json FILE` | 結果概要を JSON で保存 |
| `--json-progress` | 進捗を JSON 行（NDJSON）で出力。通常の文章は stderr へ |
| `--config FILE` | バッチモード：フォルダ別上書きを JSON で指定（例 `{"stackA": {"method": "dct"}}`） |

`--method none` はありません。CLI は常に融合を実行します。位置合わせ専用の出力には
デスクトップアプリを使ってください。

終了コード：`0` 成功、`1` 処理エラー、`2` 使用法エラー。`python main.py --help`
ですべてのオプションが表示されます。パスだけを指定して起動した場合
（`python main.py C:\stack`）も、そのフォルダを読み込んだ状態で GUI が開きます。

## 15. キーボードショートカット

### ファイル操作

## 16. トラブルシューティング

### よくある問題

#### 「画像が読み込まれていません」

- 先に画像フォルダまたは動画を読み込んだか確認してください
- フォルダに対応形式の画像が含まれているか確認してください

#### 融合結果がぼやける・ゴーストが出る

- 画像の位置合わせを有効にします（ドロップダウンからホモグラフィ / ECC / OpenFocus（高速）のいずれかを選択）
- 融合前に画像が正しく整列しているか確認します
- 別の融合アルゴリズムを試します
- より滑らかな結果を得るにはカーネルサイズを大きくします

#### AI が利用できません

- ONNX Runtime と付属モデルを確認してください。
- **ヘルプ → 環境情報** で確認します

#### メモリ不足エラー

- **設定 → 詳細設定 → パフォーマンス** でタイル処理を有効にします
- タイルブロックサイズを小さくします
- より小さいカーネルサイズを使用します
- 画像を小さい寸法にリサイズします

#### 位置合わせに失敗する

- 有界の剛体運動には **OpenFocus（高速）** を使うか、**拒否フレームで停止** を有効にして
  未位置合わせのフレームを受け入れず、早めに失敗させます
- **設定 → 詳細設定 → 位置合わせ** でダウンスケール幅を小さくします
- 画像に十分なコントラストと特徴があるか確認します
- **位置合わせ診断を収集** を有効にして再描画し、**設定 → 詳細設定 → 位置合わせ → 位置合わせ診断** で失敗した
  フレームを確認します

#### 処理が遅い

- スレッド数は自動（`0`）のままにします。CPU 容量、リソースモード、空きメモリがすでに
  並列数を制限しています
- 無人バッチでは **最大** リソースモードを使うか、AI 手法の代わりにガイドフィルタ /
  GFG-FGF を使います
- 画像の解像度を下げるか、調整中は **クイックプレビュー** を使います

#### 初回起動時の Windows SmartScreen 警告

Windows ビルドの署名状態はリリースごとに異なります（リリースノートを参照）。
署名は保証されません。**https://openfocus.top** から
ダウンロードし（第三者ミラーは避けてください）、SmartScreen の警告が出た場合は
**詳細情報 → 実行** をクリックしてください。zip 展開後の初回起動には 30〜60 秒
かかることがあります。

#### macOS で「開けません」「壊れています」と表示される

macOS ビルドは公証されていません。**https://openfocus.top** から Apple Silicon
向けビルドをダウンロードしてください。DMG で `OpenFocus.app` を Applications に

```bash

```

ターミナルで `install.sh` を使ってインストールした場合、アプリは `~/Applications`
にあります。その場合は `xattr -cr ~/Applications/OpenFocus.app` を実行してください。

またはアプリを右クリックして **開く** を選びます。配布されている macOS ビルドは
Apple Silicon（M1/M2/M3/M4）向けです。Intel Mac ではソースから実行できます。

## 付録：融合アルゴリズムの詳細

### ガイドフィルタ

ガイドフィルタは、ガイド画像を用いてエッジを保持した平滑化を行います。ガイド画像と
入力画像の間の局所的な線形変換を計算し、それを出力に適用します。エッジを保ちながら
ノイズを低減するのに優れた手法です。

### DCT（離散コサイン変換）

DCT は画像を周波数領域へ変換し、係数の大きさに基づいて融合を判断します。高周波成分
（ディテール）は保持され、低周波成分（滑らかな領域）は局所エネルギーに基づいて統合
されます。

### DTCWT（双樹複素ウェーブレット変換）

DTCWT は画像をマルチスケールかつ多方向に分解します。異なるスケールと方向の特徴を
捉えるため、テクスチャと構造の両方の情報を保持する高度な融合規則が可能になります。

### GFG-FGF

Fu ら（2024）の実装です。粗いフォーカスマップ |I − mean(I)| をガウス類似四近傍
勾配で強調します。3×3 テンプレート T = [1 2 1; 2 4 2; 1 2 1]/16 から P = I⊗T を
求め、G = (|I(x±1,y) − P|)/2 + (|I(x,y±1) − P|)/2 を計算し、T0 = 0.005 未満の値は
切り捨てます。その後、高速ガイドフィルタで精緻化します。画素はフォーカス値が最大の
フレームを選び（同値の場合は 3×3 Sobel の小領域指標）、二値判断マップを加重合成の前に
高速ガイドフィルタで平滑化します。

### AI 融合（StackMFF V3）

多焦点画像ペアの大規模データセットで学習したニューラルネットワークを用いる深層学習
アプローチです。ネットワークが最適な融合戦略を自動的に学習するため、適切に設定すれば
最先端の結果が得られます。
