## 2. 导出图像（EX-01，P0）

### 2.1 同一条导出规则

菜单保存、Ctrl+S、输出右键另存为、导出所选/全部、修饰退出保护中的导出复用同一份对象选择和格式解析规则；底层仍使用 `imwrite_auto`。拖拽导出也使用相同标注与位深策略，不能静默采用另一套全局配置。

1. 开始时固定目标 `output_id` 或明确的栈/帧列表。对话框期间列表重排不改变导出对象。
2. 展示对象名称、尺寸、源位深、目标格式和目标位深。16-bit 默认 PNG/TIFF；用户主动选择 JPG 等时显示“将转换为 8 位”的就地提示。一次明确选择即可，不要每张重复弹框。
3. 文件扩展名与选定格式保持一致：没有扩展名时从选定 filter 补全；显式扩展名不同则明确同步格式或要求选择，不能暗中把 TIFF 变成 PNG。无支持的扩展名就地解释。
4. 显示“包含标签”“包含比例尺”，默认继承目标对象的有效配置；预览与最终写入都使用这份快照。原始无标注导出可显式选择，不能以屏幕截图替代原位深数据。
5. 成功后记录实际输出路径、格式、时间；只有完整写入成功才改变导出状态。图像内容或烙入配置变更后应显示“导出后有更改”，原文件仍存在但不代表当前内容已保存。
6. 成功用状态条“已导出到 …”和打开文件夹；失败明确路径/原因，不关闭用户的工作对象。

### 2.2 多项与覆盖（EX-02，P0）

导出列表显示每项短名、最终文件名、格式和状态。默认保留对象名称，不用当前算法下拉给历史结果命名。已有文件冲突默认自动增加序号；覆盖须用户明确选择，可对本批统一应用。判断冲突要检查磁盘，不能只检查本次循环内重名。

每个文件原子完成后才算成功。批次结束汇总成功/失败/取消数量，失败列表带路径和重试入口。取消保留已完成文件，清理本次未完成文件；不得宣称全批成功。多页 TIFF 的“保存完成”以整个容器成功为准。

GIF 和多页 TIFF 明示源/配准栈、帧数和顺序；GIF 提供时长、总时长与 8-bit/调色板限制说明，沿用现有 DurationDialog，不另造视频编辑器。

## 3. 工程的真实含义（EX-03，P0）

采用保守定义：**工程保存输入引用和可重建的处理配置；图像结果需要单独导出。** 本轮不引入把所有大图塞入 `.ofproj` 的新容器。

- 保存成功文案为“工程配置已保存”；若有未导出的受保护结果，同一区域继续显示“还有 N 张结果未导出”。保存工程不能解除修饰或正式采用比较输出的保护。
- 标题保留工程名和未保存标记。UI分别表示“工程有更改”和“结果未导出”，不用一个星号表达两种状态。
- 补齐工程 round-trip：源顺序、排除帧、工作倍率、每方法实际生效参数、标注目标/范围、完整比例尺配置（目标/位置/字体/颜色等）。添加字段时旧工程使用明确默认值；保持已有读取能力，不要求用户手改 JSON。
- 对不能从引用与配置恢复的变换像素，必须明示限制。旋转/翻转可记录变换；白场校正如果需要参考文件才能重建，记录其来源和参数；来源无法重建时引导导出处理栈。禁止只保存“已校正=True”然后恢复原图冒充校正后栈。
- 保存快照应对应实际当前状态；无法完整重建某项时，在保存摘要中列出该项，不声称“完整会话”。不把修饰撤销历史和未应用笔画加入本轮承诺。

### 丢弃与恢复

有工程修改时提供“保存工程并继续 / 放弃工程更改 / 取消”，默认取消。保存失败或用户取消文件选择，原操作不继续。随后若还涉及未导出的修饰或正式采用比较输出，走其导出/放弃保护；尽可能合并成一份清晰待处理列表，避免连续弹出内容近似的框。

缺源文件时显示缺失数量和样例，支持指定一个新目录重新匹配；匹配前展示对应关系，不能静默选同名但身份不同的文件。无法确认时保持工程未加载。现有项目原子写与路径校验必须保留。

崩溃/更新恢复提示必须列出实际能恢复的项目：源、配置、标注等；明确“上次未导出的像素结果不会从工程自动重建”。这项文字不代替退出前的像素保护。

## 4. 输出状态契约（EX-04，P1）

不要将历史 `exported=True` 自动解释为可靠保存记录。新输出的状态根据真实写出事实建立：

- 会话中生成、没有成功导出记录：未导出。
- 成功导出：已导出，附路径/版本。
- 结果或导出标注配置之后改变：导出后有更改。
- 从批处理文件加载：已有磁盘文件，显示该路径；是否可修饰由来源能力决定。

沿用对修饰输出的防删除/防退出保护，并按[方法对比](03-method-compare.md)扩展到用户正式采用的比较输出。普通可重新计算的预览不因增加状态显示而一律弹退出确认。显示状态与保护策略分开；只设置 `exported=False` 不足以扩展当前仅认 retouch 的保护规则。
