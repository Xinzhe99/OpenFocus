# OpenFocus UI / UX 审查与实施规格

基准：**v1.67.0 当前工作区**，含已有“高级设置”菜单翻译键修复。本目录是待实现设计，不表示问题已修复或新增能力已经发布。目标是在现有 PyQt6、八种融合方法、十二语言和明暗主题基础上，让数据来源、参数、预览、应用及保存形成可验证的闭环。

每份规格包含已有能力、剩余问题与代码证据、具体交互、状态/取消/失败规则、实现落点和验收。优先级：P0涉及错数据、假成功或工作损失；P1是主要工作流和必要可用性；P2是明确标出的可选增强。

## 2. 审查依据与边界

代码证据来自本工作区的实际入口和调用链；文件行号仅是此基准的位置，实施时以所列symbol为准。标为 **[INFERENCE]** 的影响由静态代码推导，尚未逐项执行复现。设计和验收是目标，不是测试通过记录。已有CHANGELOG和现有测试用于识别已经完成的修复；阅读测试源码不等于运行测试。

本轮原生Windows Qt检查使用隔离QSettings及合成数据：3帧、720×480、uint8，中文浅色为主，补充中文深色标签和德语深色小窗口。图像直接注入审查会话，不能据此宣称验证了文件导入/容器解码。

实际执行与观察：DCT CPU融合；OpenFocus B/DCT方法对比得到两个结果、无错误且worker结束；DCT深度图生成并显示二维及3D页。其他截图验证窗口呈现。修饰没有落笔/发布，批处理没有启动任务，白场没有应用，ROI没有实际渲染；没有导出OBJ、真实更新、全语言/高DPI全覆盖或性能计时。

详细元数据见 [审查记录](evidence/audit-summary.json)。未把布局截图当成算法正确性、真实安装成功或完整回归的证据。

## 3. 首批应处理的问题

以下均有对应代码路径，除已注明窗口观察外，实施前先按规格复现当前后果，再修正并验证。

| 风险类别 | 对应规格ID | 修复必须证明 |
|---|---|---|
| 用错输入/参数 | CP-01、DP-01/02/03、BT-01/02/03/04/05 | 排除、顺序、配准、加载比例与所有有效参数贯穿实际执行 |
| 标注物理/对象含义错误 | LB-02/03/07、SC-01/02/03/04/07/09 | 取消不改值；范围不扩大；缩放标定和各出口一致 |
| 写入/发布失败被当成功 | RT-08/09、BT-06/07、DP-11/12、EX-01/02 | 不丢旧历史/文件；必要产物齐全才成功；原始深度不隐式降位 |
| 重启丢工作或恢复旧状态 | UP-01/02/03/08 | 退出保护先于脚本；最新快照成功落盘并加载；安装模式不变 |
| 控件显示与真实行为分离 | RT-04/06、OT-01/02 | 快捷键和按钮同条件；设置实际提交；白场源变更使旧增益失效 |

布局改进不替代这些数据和状态修复。P0可先按具名闭环交付；只有一份规格的必选条款及验收全部覆盖，才能称该规格完成。

## 4. 共用契约与单一责任

| 共用事项 | 权威定义 | 消费方及约束 |
|---|---|---|
| 帧/输出身份与来源快照 | 00；扩展现有RenderContext/OutputRecord/effective_stack | 03/04/06/07/08；不用行号、同尺寸或活动window补猜旧来源 |
| 标签目标与帧范围 | 01 | 02复用合法范围；09统一出口；旧格式仅加载边界迁移 |
| 原始/有效像素标定 | 02 | 04物理模型、07每任务、09持久化；resize换算、ROI不再次缩放 |
| 导出对象、格式、路径及状态 | 09 | 01/02/03/06/07；DP文件组扩展同一失败原则，保持Unicode/位深 |
| 输出发布事务与未导出保护 | 06与09 | 03正式采用复用；先成功提交再淘汰，保护按明确类型/事实判定 |
| 工程与恢复范围 | 09 | 01/02/05/08/10；输入引用/可重建配置不等于保存输出像素 |
| 更新退出与恢复完成 | 05 | 主窗口和活动工具只走同一保护入口，不绕过既有关闭协议 |
| 参数适用性和贯穿 | 03/07及主渲染 | 08/10一致呈现，复用现有方法定义；不形成三套默认值 |

数据模型新增只为现有跨功能行为服务。优先扩展现有记录、worker和utility，避免万能对话框基类或通用任务平台。运行时使用一套新契约，旧工程只在读取时转换，不保留双轨导出解释。

两个容易混淆的决策已统一：方法对比“采用参数并返回”不启动渲染；“采用为新输出”必须有当前完整原始像素，并进入未导出保护。普通可重算预览仍不因状态徽标而全部强制弹保存确认。

| 4 | 03比较采用完整闭环、06辅助显示/焦点、08主流程 | 从预览到正式输出到导出可完成，状态/来源持续可见 |

真正独立的修复可并行，共用文件/数据契约指定一个整合负责人。不要等整个UI改造完成才修P0；也不要把一段代码编译成功当作其工作流完成。

## 6. 跨功能验收场景

以下是实施后必须运行的组合场景，本轮未执行。

| 编号 | 场景 | 可观察结果 |
|---|---|---|
| INT-A01 | 含TIFF页的16位栈排除部分帧，比较/正式渲染/深度分析 | 三处参与身份/顺序一致；选择旧输出来源时明确使用其旧快照 |
| INT-A02 | 标定0.5µm/原始像素，50%加载，ROI、标签和custom比例尺，经各出口保存 | 有效标定1µm/当前像素；同目标几何/样式一致；PNG/TIFF保位深 |
| INT-A03 | A栈输出后加载同尺寸B，选旧A修饰、深度和导出 | 均绑定A来源/纹理/标定，不从B补猜 |
| INT-A04 | 比较全图正式采用、修饰生成子输出，历史满时一次发布失败 | 原列表/选择/像素完整；成功输出未导出保护不被淘汰绕过 |
| INT-A05 | 新增标签/比例尺/排除帧，保存工程重开；另有未导出图像 | 可重建配置往返；工程保存不解除像素保护或承诺恢复像素 |
| INT-A06 | 批次同名目录、部分写失败、取消，再对成功产物另存 | 路径无冲突、终态准确，任务EXIF/标定正确，不叠当前主窗标注 |
| INT-A07 | 下载中继续工作，有dirty工程和未导出修饰，随后请求更新 | 就绪先停；每步保护可取消；最新快照真实恢复，模式不变 |
| INT-A08 | 模型附属文件重名、Unicode路径，提交失败或取消 | 旧文件组保留，无半套成功；父输出导出状态不变 |
| INT-A09 | 白场预览后换源，提交时base失败，再取消窗口 | 无旧增益应用、半状态或误删帧；可继续原工作 |
| INT-A10 | 中/英/德/日实际操作，全部十二语言键/占位符，960×640和高DPI | 数值/状态/主要动作可达，焦点和快捷键正确；无中文界面OK/All/Frame残留 |

每个功能验收编号在对应文档；不以这张组合表替代单功能验收。普通输入/拖动约100ms是目标，需附实际硬件/图像/计时证据；本轮没有测得性能达标结论。

## 8. 交给实施者的执行约定

可将本段与一个功能spec一并交给DeepSeek或其他实施者：

> 先读00-shared及本spec列出的依赖，确认当前代码仍与证据一致。按全部必选要求实现具名闭环，保留已修能力。先复现尚未验证的缺陷；使用现有对象/worker/utility，迁移所有受影响调用方，不保留旧接口旁路。新增用户文字覆盖十二语言。为来源、位深、状态转换、取消、文件保护等消费者可感知边界补必要回归，不写源码镜像/固定措辞测试。完成后运行真实工作流，保存界面与产物证据，同步手册和CHANGELOG。报告完成的验收ID、实际命令/场景和未能验证的平台；没有执行的验收不得写通过。只完成部分时明确列出剩余条款，不能宣称整份spec完成。

本目录本次交付是审查和设计。未来实现过程中若新证据推翻静态推导，更新对应问题依据及验收，保留正确行为目标，不按过时行号机械修改代码。
