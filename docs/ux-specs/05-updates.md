## 2. 用户可见状态与动作（UP-10，P1）

更新容器统一驱动顶部条、状态栏及帮助菜单。顶部显示状态标题和“当前 → 目标版本”；一个主要动作，次级查看说明、隐藏。窄窗可折到两行，640逻辑px仍能访问主动作；只隐藏更新容器，不隐藏整个状态栏。

| 状态 | 主反馈/动作 | 退出或取消 |
|---|---|---|
| 手动检查中 | 不定进度“正在检查” | 不重复发请求；完成可重试 |
| 已最新 / 检查失败 | 当前版本或失败原因、重试 | 静默检查不弹错误 |
| 可下载 | 下载更新；版本/包大小可知时显示 | 稍后、隐藏此版本提醒 |
| 下载中 | 已下载/总量，未知总量为不定进度 | 取消下载 |
| 校验中 / 准备中 | 真实阶段及可用计数 | 文件安全边界合作取消 |
| 正在取消 | 立即确认请求，禁用重复取消 | 真正停止后才显示已取消 |
| 已取消 | 可重新下载 | 不称暂停/续传 |
| 就绪 | 重启并安装；可离线 | 稍后保留暂存；隐藏只隐藏提醒 |
| 保存现场 / 停止任务 | 明确正在处理什么 | 取消本次重启，保留就绪包 |
| 安装未完成 | 实际失败阶段、详情和对应下一步 | 重试适用阶段或下载页 |
| 独立安装包已下载 | 打开安装包 / 打开位置 | 不混称原地更新就绪 |

下载完成停在就绪，不自动重启。切换语言更新所有文案、版本说明、tooltip及accessible name。发布说明显示实际获取的版本范围；超过上限说明更多版本在发布页，不声称已列全。

## 3. 统一重启保护（UP-11，P0）

顶部条、状态栏、帮助菜单和旧下载完成回调均进入同一入口。实际交接顺序固定：

1. 请求活动编辑窗口按原协议结束：修饰的应用/放弃/继续，比较的合作关闭；用户取消则终止重启。
2. 枚举全部在途任务，包括比较队列间隔、子窗口和准备任务；显示任务名，默认“继续工作”。只有明确选“取消任务并更新”才发合作取消，finished前不交接。
3. 处理未导出结果：复用导出/放弃/取消；取消目录、保存失败、Esc或关闭确认均停止重启。包括本组规格新增的正式采用比较输出。
4. 处理工程保存选择，成功写入本次最新会话快照与恢复标记，保留project关联及dirty状态。空工作区写明确空会话，不复用旧快照。
5. 以上均成功后才创建/启动替换交接，标记本次已完成保护，再正常close收尾。不能提前用布尔标记跳过保护。

后台下载不会取消用户工作。重启被取消时完整暂存仍可用。主线程不靠长时间wait冻结界面，不terminate原生计算。

## 4. 恢复契约（UP-12，P0）

本次快照优先，原工程路径只是关联，不能用旧工程替换最新未保存设置。工程能恢复的是源引用与可重建配置，不能恢复的输出像素必须在退出前导出或由用户明确放弃；提示不得承诺“完整工作现场全部恢复”。

快照或恢复标记写入失败：显示具体路径/原因，允许重试或继续工作；不启动脚本。启动后依次显示读取现场、加载源图、恢复参数；只有真实异步成功回调才能清标记并报完成。源不存在/解码失败保留恢复数据，可重试或继续进入应用。

更新恢复与“恢复上次文件夹”互斥，不重复加载；恢复源顺序、页号和排除项遵从工程规格。分别报告程序替换、应用启动、现场恢复的结果，前一阶段成功不证明后一阶段成功。

## 5. 安装模式与平台能力（UP-13，P0）

- 更新前固定安装版/便携版模式及数据位置。安装版复制ZIP时不接受便携标记；便携版保留标记和OpenFocusData。程序载荷替换不覆盖、删除或迁移用户数据。
- 恢复交接使用更新前确认的数据位置，不能在恢复完成前被包内标记改变。保持发布ZIP本身可作便携包使用。
- 源码运行显示“前往发布页获取发行版”；Linux、无匹配架构包、无有效.app等环境按真实能力给下载入口，不显示必然失败的原地安装动作。
- 目录不可写时说明原因并提供下载页，不让重试无限重复同一权限失败。
- macOS暂存保留执行权限与链接，验证真实可执行入口及架构；ZIP和DMG统一匹配。失败保留可重试载荷，成功才清理；沿用现有.old回退。
- Windows复制中断可能留下不完整安装；失败提示依据真实状态给出重新下载安装包/恢复路径，不能未经实现承诺整目录自动回滚。

## 6. 检查、下载和就绪一致性（UP-14，P0/P1）

checker仅产生结果，经queued signal进入GUI槽；槽先完整更新数据，再通知界面、写设置和安排定时器。同一时刻一个检查；手动点击可接管静默结果的展示意图，不另发重复请求。关闭开始后忽略迟到检查，不再安排下载。

检查状态和下载任务分开。运行任务固定tag、URL、摘要和目标目录；再次检查发现新版本不能改绑当前任务。静默检查保留现有24小时节流；手动检查始终可执行。文案准确称启动时/节流检查，不宣称当前实现已有持续每日循环。

自动下载设置通过现有setter提交并读回；取消设置不变。文案“空闲时自动下载更新：不会自动安装，仍会检查新版本”。关闭后取消未来自动安排；当前下载需显式取消，不把关闭设置等同强制中断。

“稍后”关闭当前提示并保留就绪；“隐藏此版本提醒”持久隐藏同tag顶部条，但帮助/状态入口仍可找到。该版本下载完成或重启不翻转隐藏决定；手动检查可重新显示，新版本重新提醒。× 的名称明确此行为。

未知下载总量用不定进度；取消立即显示请求状态，网络读取应有可解释的有界等待。准备支持文件边界取消；取消不写完整标记、不自动应用。失败记录阶段与原因：完整ZIP可校验则重试准备，摘要不符重新下载，不一律“检查失败/下载失败”。

启动恢复和实际应用前都验证候选版本高于当前、平台/架构匹配、完整标记及入口有效。旧候选不提供安装，临时包被清理则回到需下载。完整新包断网可安装；离线缺更新说明应单独说明，不阻断有效包。

### 本轮代码修复记录（尚未执行安装验收）

检查结果通过 queued Qt signal 回到 GUI，重复检查合并，活动下载的版本和摘要保持固定。新下载停止在 READY；实际安装统一先保护工作、写入恢复快照/标记，成功后才启动替换脚本。准备过程移到工作线程，校验和解包均支持合作取消；未知下载长度报告不定进度。准备失败保留 ZIP 供再次准备，旧版本不得交接。

Windows 复制排除便携标记和用户数据目录；macOS 校验 Info.plist 声明的可执行入口、执行权限和 Mach-O 架构，解压保留权限及安全链接，失败不清理载荷。新增离线行为回归位于 `tests/test_update_contract.py`；既有端到端模拟用例改为明确第二次重启动作。真实 Windows/macOS 安装、权限失败、启动恢复及界面验收仍需主集成验证，不以脚本生成或 mock 代替。
