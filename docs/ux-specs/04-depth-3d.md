# 深度图与 3D 模型：来源、数值、网格与导出

历史审查与初始设计基准：v1.67.0；其中未完成条目不代表当前版本仍有相同缺口。当前深度交互修复基于 `1.70.0` 的 `perf/params-dtcwt-decode-20261026` 优化分支、HEAD `f98da1e`，具体事实和实施范围见下方修复规格。依赖 [共用规范](00-shared.md)、[比例尺标定](02-scalebar.md)及[导出规则](09-export-project-recovery.md)。历史审查用合成栈实际完成 DCT 深度计算，并查看[二维](evidence/depth_map_zh.png)、[3D](evidence/depth_3d_zh.png)和[960×640 窗口](evidence/depth_3d_small_zh.png)；当时未导出 OBJ、验证物理量或运行所有错误场景。

交互修复以[手动计算、度量参数与真实色纹理修复规格](04-depth-3d-fix.md)为准：全部方法只在显式点击后计算，取消后不自动续算；参数紧随度量选择，3D 默认使用匹配的真实图像。本次已实现，运行证据见修复规格第 9 节；下文历史观察与修订记录不替代当前验证。

## 2. 布局与来源（DP-20，P0/P1）

保留“深度图 / 3D 曲面”页签。顶部固定来源摘要；右侧可滚动四组：“来源与方法 / 深度轴与标定 / 显示与纹理 / 网格与导出”。底部固定阶段、计算/取消和导出。长错误可展开，不挤走动作。

来源是显式选择：

- **所选输出的来源**：仅一个合法输出选中时默认用它，通过 output_id/context 固定像素、帧身份、实际顺序、配准、ROI、参数和标定。多选时要求选一个。没有上下文的 batch/旧输出说明“没有可验证的来源”，不得拿当前栈补猜。
- **当前勾选帧**：打开或明确刷新时捕获 effective_stack，显示 M/N、文件名/页号、当前域及配准方式。不足两帧禁用计算，空集合不退回全栈。

配准结果只有来源版本、参与帧/顺序、尺寸和参数全部匹配才可复用；否则执行所选配准，或让用户明确采用未配准数据。切换来源使旧请求失效。后续计算、纹理与导出都消费同一快照，不反复读取活动主窗口。

ROI 裁剪按输出坐标域计算；贴回输出只在真实可用的 ROI 内有深度，外部是无数据，不用 0 冒充第一焦平面。网格不连接无效域或跨无数据洞生成面。分析不修改来源数组或父输出导出状态。

## 3. 数值与算法含义（DP-21，P0）

用户通用名称采用“焦点位置估计”。硬选择方法只有在复用相同决策、曝光、顺序和后处理时才能称“融合决策”；C/DTCWT 明示频带/活动估计，AI 明示概率期望，软融合没有唯一源帧。

复用逐帧归一化。DCT 补边/B 后处理等共享现有融合决策函数，保持融合算法本身数学含义不变。旧结果缺完整参数时只能独立估计，不能宣称复现该输出。

原始 map 及平滑/高度场保持 float32；只在配色查表、显示纹理或明确编码出口量化。保留原始归一化 map，不被平滑、反转、Gamma、网格采样覆盖。原始保存名称为“16 位归一化索引（0–65535）”，说明它是编码后的索引，不是 µm，也不是任意 float32 的无损保存。

## 4. 相对与物理模式（DP-22，P1 新增）

| 模式 | 所需参数 | 显示与输出承诺 |
|---|---|---|
| 相对焦点位置，默认 | 参与帧顺序；相对起伏 | 无物理单位的可视化高度场 |
| 已标定焦平面位置 | Z 起点、正步长、单位、采集方向；真实比例模型另需 XY 标定 | 基于焦点估计的高度，明确物理单位，仍不等同实测表面 |

- 内部单位统一 µm，可输入/换算 nm、mm。拒绝空值、零/负步长和非有限值；方向单独表达，不用负数兼任。
- Z 位置绑定原始采集身份：`z_i = z0 + capture_index_i × Δz`。排除帧保留间隔，不按剩余帧压缩；倒序时坐标随身份移动。没有可信采集序号时要求提供/确认映射，不能从文件名猜距离。
- 对连续焦点索引按参与帧的 Z 表映射，不直接乘“剩余帧数×步长”。反转显示深度轴不改采集标定，UI需明示当前显示方向。
- XY 使用结果坐标域的实际像素尺寸，按真实加载/缩放比换算；ROI 不再次缩放。只有 Z 时可显示高度读数，缺 XY 则不允许标为真实比例 OBJ。
- 物理模式默认 Z 比例 1:1；“显示 Z 放大”单列并持续标识。物理导出默认不带视觉放大；选择带放大时在导出摘要和元数据记录。
- 新增 float32 物理深度 TIFF，单位和无数据规则明确；无数据用 NaN 并记录掩码/域语义，不能与合法零高度混淆。扩展现有 Unicode 写入通道并实际读回验证编码，不因文件后缀正确就宣称精度正确。
- OBJ 元数据注明“1 单位 = 1 µm”、原点/方向、XY、Z 表及放大；数值格式须保存小物理间隔，不能固定三位小数把不同顶点压平。

## 5. 同一网格、纹理与最终预览（DP-23，P1）

生成一份版本化网格数据：处理后高度、有效域、坐标、UV、纹理身份、采样和平滑参数。最终预览与 OBJ 使用它，禁止两边各自再做隐藏中值滤波。

“网格长边顶点数”默认 600，但不超过可用数据分辨率；最少 2，域不足 2×2 时解释不能生成面。显示实际宽×高、顶点和三角形数量。“交互预览质量”是独立参数，拖动可简化，停止后恢复；“最终网格预览”使用实际导出数据。不能把相对 220 工作图的倍率包装成输出分辨率。

纹理明确选择“关联输出 / 指定参与帧 / 深度伪彩”。只有身份和坐标域匹配的输出可选；否则说明原因，不能无提示退回首帧。预览与 PNG 共享 `to_display_uint8()` 生成的纹理，允许预览光照造成合理差异，不允许 uint16 截断。

3D 更新失败时取消旧图的当前标记，显示失败和重试；二维可继续用。若网格成功但显示失败，可准确说明“预览失败，模型数据可导出”。保留 CPU 软件渲染，不新增必须 GPU/OpenGL 的前提；空态和错误全部本地化。

## 6. 展示参数与图例（DP-24，P1）

| 参数 | 二维伪彩/伪彩导出 | 原始索引 | 3D几何 | 关联输出纹理 |
|---|---|---|---|---|
| 深度平滑 | 生效 | 不变 | 同一处理结果 | 不变 |
| 反转深度轴 | 映射与图例同步 | 不变 | 改方向，注明基准 | 不变 |
| Gamma/配色 | 生效 | 不变 | 不改高度 | 不变；伪彩纹理除外 |
| 叠加/透明度 | 仅二维叠加 | 不变 | 不变 | 不变 |
| 起伏/显示Z放大 | 不改原索引 | 不变 | 按模式显式生效 | 不变 |
| 交互预览质量 | 不改数据 | 不变 | 只改变显示简化 | 不改导出纹理 |

图例必须由图像同一映射函数产生，两端和中间刻度显示数值/单位；帧标签和读数只来自当前结果帧表。叠加检查身份、尺寸和 ROI，不能保持勾选却没有实际叠加。旧图可以供参考，但图例仍显示它自己的来源，不读取新栈数量。

## 7. 请求状态、取消与关闭（DP-25，P0）

状态：来源不可用、待计算、计算中、取消中、当前结果、已过时、已取消、失败、关闭中。每次请求记录来源 ID/版本、帧表、顺序、算法参数及几何域；成功、失败和进度都检查 revision 与 worker 身份。

运行中改计算参数立即标过时并合作取消。所有方法均在旧 worker 真正结束后回到待计算，只有再次点击“计算”才启动当前参数；不按方法快慢自动运行。用户主动取消清除执行意图，不能被旧回调或定时器重新启动。色图、Gamma、相机等显示变化不重跑焦点估计。具体参数、按钮状态与纹理规则见[交互修复规格](04-depth-3d-fix.md)。

计算中、取消中及过时结果禁止导出，说明现有图属于何参数；取消/失败保留上一份成功 map 和准确状态。AI 不伪装逐帧进度，无法中断的原生步骤显示“正在完成当前步骤后停止”。Esc、X、关闭复用现有 orphan 生命周期，关闭后迟到回调无效，不强杀线程。

会话缓存可复用完整来源/参数键对应的结果，不能仅以尺寸判断；不为摘要复制整栈。参考 CompareDialog 已有 revision/finished 模式，不另造调度框架。

## 8. 文件导出（DP-26，P0/P1）

导出摘要显示结果版本、来源、相对/物理模式、有效域、网格、纹理和全部将生成文件。现有 OBJ 三件套继续支持；新增元数据也列入文件组，说明移动模型需要一起保留。

- 对整组 OBJ、MTL、纹理及元数据检查冲突；OBJ 不存在也不能覆盖同名纹理。列出冲突后选择替换/改名/取消。
- 后台准备网格并写出，阶段为准备、纹理、模型、提交。文件边界合作取消；不在 GUI 线程同步写大量文本。
- 全组先暂存；准备失败或取消不碰旧文件。提交提供可回滚的整组替换，失败恢复旧组，不能把几个独立 rename 称为天然原子事务。
- 只有全部必要文件提交成功才完成；显示完整清单、顶点/面数。失败给出阶段、路径及可复制详情，保留分析结果。
- 原始16位和 float32 出口严格限制支持的编码与后缀，不接受 JPG/BMP 隐式降位；普通图像导出的合法8位转换保持不变。
- 元数据记录来源/参与帧顺序、算法参数、归一化关系、有效域、标定、网格/平滑、纹理身份和方向。Unicode 路径及 OBJ→MTL→纹理相对引用保持正确。
- 保存深度/模型不改变父输出的 exported/protected；它不是保存父融合/修饰图像。

## 10. 实施落点与边界

复用 OutputRecord/RenderContext 扩展来源快照；分别保存“深度结果”和“展示/网格结果”，下游不读活动 window 补猜。核心接口改动同步 `core/cli.py` 调用；复用图像归一化、Unicode写入和配准逻辑。

先做来源与请求一致性，再统一数值/图例/网格，随后交付物理标定和后台文件组导出。物理模式是新增能力，不能作为已有模型正确性的未经验证宣传。不新增 PLY/STL/glTF 支持或把高度场宣称成体重建。

承接 `test_depth_map`、`test_mesh_export`、`test_16bit_and_cache`、现有UI和取消回归；新增用例关注来源、精度、坐标、请求转换和失败文件保护。实际运行含3D交互和完整OBJ重新读取；本轮未执行这些验收。同步十二语言和深度/3D手册。

本轮代码修订（未运行验证）：当前勾选帧与所选输出来源独立快照，当前来源可明确选择不配准或重新配准；不猜复用旧配准缓存或活动 fusion_result。方法切换使请求失效并等 finished 后重算最后请求；取消清除续算。逐帧归一化、float32 平滑、DCT 补边、AI 连续期望、共享网格和纹理转换已修订。DP-22 是必选新增能力，已接入原始采集序号确认、Z 起点/步长/方向/单位、物理 TIFF 与需 XY 标定的物理 OBJ。OBJ 四文件组先暂存并可回滚提交，在工作线程写出。主集成须检查：历史 A/B 同尺寸、ROI 非零原点、0/1有效帧、混合位深、排除帧间隔、微小 Z、模型附属文件冲突和提交失败、关闭长任务。未取得 GUI/读回证据前不宣称整份规范验收通过。
