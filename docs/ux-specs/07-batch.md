## 2. 输入与任务布局（BT-20，P1）

一个普通目录产生一个栈任务；一个拆分目录产生多个任务，保留共同输入组。两个入口进入同一任务表，保留“添加目录 / 添加并拆分”和路径框/拖放。

表列为顺序、名称、帧数、处理方案、输出位置、状态。选中行下方显示完整来源、首末帧、尺寸/位深、参数和最终产物预览。提供上移、下移、移除、清空；执行顺序不改变任务内帧序。

添加后立即显示扫描中；缩略图只读必要首帧，完整检查在后台可取消。移除/关闭后旧扫描不能把行重新插入。内容可滚动、底部开始/取消固定；取消固定800高度。配置取消/Esc/×不写文件、不改主窗口参数。

## 3. 排序和分组（BT-21，P0）

- 排序依据、分组方式、组内融合方向分开。固定张数默认自然文件名顺序，张数在边界转成合法int；不改变通用小数控件来掩盖类型问题。
- 时间阈值按拍摄时间，等时间按自然文件名/页号稳定排序。相邻差**大于**阈值才断组，等于仍同组；秒数保留float。
- 缺时间显示数量，用户可改固定张数或明确排除；不静默拼进任意组。预览每组帧数、首末成员、时间跨度，支持查看完整成员。
- 保留尾组，明确不足N张。融合至少两帧，单帧尾组需排除或改分组；不融合逐帧导出可一帧。
- 所有入口统一多页TIFF展开和`容器路径+页号`身份；不能以路径相同把页去重。预览和执行使用同一冻结成员清单，不在worker重新分组。
- OpenFocus反转作用于已分好组的融合顺序，不能跨组重划。基底首/末引用最终融合顺序；源顺序与融合顺序都可查看。

## 4. 参数继承与单一执行路径（BT-22，P0/P1）

三层：打开窗口时主窗口快照 → 输入组/批次默认 → 任务覆盖。界面显示继承/已覆盖及恢复继承；False、0、none均是显式值，不能用真假判断是否继承。改组默认只改变未覆盖任务。

每算法记忆自身参数，复用比较窗口的适用参数元数据：C不假装消费kernel，DTCWT有N，AI模式/批量明确。高级折叠摘要显示实际CPU/GPU、线程、瓦片、加载比例和AI模式；任务运行后不再读取活动主窗口补配置。

“加载尺寸”和“配准计算尺寸”分别显示。旧100%实际继承全局配准宽度，应改为明确“继承全局：1024px / 输入宽度比例”，展示最终计算宽度，避免误称原分辨率。

两入口规范化为同一种任务，共用读取→配准→融合可选→写出。每任务生成局部算法参数，不pop计划共享字典。唯一OpenFocus配准结果必须继续传给融合及对齐帧导出；仅对齐不再位于融合条件内。加载比例、曝光、基底、倒序、瓦片、AI等有效值贯穿摘要和执行。

## 5. 输出计划与源文件保护（BT-23，P0）

开始前为所有任务的全部产物分配路径并显示。三种目标位置统一：融合图放目标根目录；对齐栈放`<task_name>_aligned/`。subfolder的两种产物都在选定子目录内，不能对齐帧仍散落源目录。

默认保留已有文件并自动编号；另可显式选择跳过任务或替换已有结果。替换数量和完整路径可查看，但**源文件永远不能作为替换目标**。保护整批真实来源集合，覆盖Windows大小写/路径别名及TIFF容器，不只比较当前任务合成页名。

同批先保留所有名称，再执行；同名来源目录也获得独立任务/产物路径。编号耗尽继续找新名或报错，禁止退回已占用路径。子目录必须保持在来源目录内，绝对路径/越界只通过自定义目录模式表达。

写入用同目录临时文件，成功提交后才登记。运行时目标被外部占用按既定策略重新安全分配并更新实际路径；不覆盖源。取消保留已提交文件、清理未提交文件。任务允许部分成功，但不能以临时文件存在或一个文件成功冒充完成。

## 6. 启动前检查（BT-24，P0/P1）

状态为空、扫描中、需处理问题/就绪、检查中、可启动。扫描/检查未完开始禁用并解释。摘要显示任务/帧数量、排除项、尺寸/位深、加载比例、算法依赖、实际路径、冲突数和可写性。

阻断项：来源缺失或变化、未处理解码失败、融合不足两帧、不支持尺寸组合、必要模型/库缺失、无效目标/源冲突。检查实际子目录，而非只探测父目录；保留真实临时写入可写探测。

部分坏帧需显式排除并重新确认成员，不能静默少帧继续；不通过悄悄缩图解决不支持组合。CPU可回退时说明实际计划，经典方法不因缺torch被禁用。16位默认未选格式可用PNG，显式JPG/BMP在开始前说明保存8位并尊重决定。

可以明确只运行勾选的就绪任务，但摘要列出排除项。检查取消回编辑态，保留配置。启动后读取冻结清单，源变化定位该任务，不重新扫描采用新成员。

## 7. 进度、取消、关闭和终态（BT-25，P1；成功判定P0）

运行视图保留任务表，参数只读。显示已完成/总任务，当前读取、配准、融合、写入阶段；有帧/瓦片/文件计数就用真实计数，无法细化则不定进度。最后一次提交后更新到total/total。

取消立即进入正在取消，禁用重复取消和重启；实际worker结束后才恢复闲置。检查点覆盖读文件间、配准/融合原检查点、产物提交间。原生步骤不可立即停止时明确等待当前单元，不强杀。

运行视图X/Esc只隐藏，主窗口有当前批处理入口可重开；再次打开返回同一运行。退出应用默认继续处理，明确选取消并退出才合作收尾，不在GUI线程连续长wait。

每任务终态：成功、部分成功、失败、已取消、未开始、按策略跳过。成功要求所有必要产物全部提交；取消单列，不算失败。无配准且无融合时称逐帧导出，不假称配准成功。

单任务失败继续独立任务；全批不可恢复错误才停止其余任务。错误行含完整来源、阶段、可读原因、技术详情和成功/失败产物。可由用户主动重运行失败/未完成任务，生成新执行记录并遵从冲突策略；不自动重试或用文件存在猜计算完成。

## 8. 结果入口与元数据（BT-26，P0/P1）

批次结果表保留全部任务，每任务主行展开融合图及对齐栈，提供查看融合图、打开目录、复制路径、错误详情。它不受主窗口20条像素历史限制；主窗口按用户选择加载，对齐栈作为一个目录产物，不自动回读所有帧。

写出成功和预览加载成功分别计数。文件后来丢失/不可读保留记录并说明路径，不把原计算改为失败。已有未导出修饰/比较输出不被批次插入挤掉。

每任务显式传自己的EXIF、自动/手动标定、实际像素尺寸、完整标尺配置；无EXIF也明确为空，不能落回主窗口全局SOURCE_EXIF。手动优先规则保留，缩放后标定换算。

产物记录已烧入哪些标注。再导出默认保留文件本身像素/元数据，不叠当前工作区标签或第二条标尺；跨格式仍走imwrite_auto。缺真实RenderContext的batch产物继续不可修饰并说明原因，不借当前帧猜来源。

## 9. 最小数据契约

以下是语义字段，使用简单记录即可，不要求复杂队列框架。

| 对象 | 必须保存 |
|---|---|
| BatchPlan | run_id、输入组、顺序任务、默认快照、冲突策略、完整源保护集合；启动后不可变 |
| InputGroup | group_id、入口/目录、排序、分组方式、count:int或threshold_seconds:float、任务ID |
| FrameRef | 真实source_path、page_index、文件名、时间及缺失状态、尺寸/位深、来源身份 |
| BatchTask | task_id、group_id、显示名、冻结帧表、覆盖值、完整effective_settings、必要产物 |
| effective_settings | 方法及适用参数、配准实际宽度、源/融合顺序、曝光/基底、加载比例、GPU/线程/瓦片/AI、格式质量、任务元数据/标注 |
| PlannedArtifact | artifact_id、task_id、种类、目标路径、来源帧映射、预期位深及冲突决定 |
| Progress | run/task身份、阶段代码、真实计数或不定进度、取消请求；由UI翻译，不解析英文句子 |
| TaskResult | 终态、实际已提交产物、逐产物失败、阶段/原因；不是一个success布尔 |
| BatchResult | 所有任务结果；总数=成功+部分成功+失败+取消+未开始+跳过 |

## 11. 实施与边界

先修分组/参数/成功判定/路径的P0，再统一任务表和结果视图。规范化后删除两分支重复提取及保存判断，不保留新旧双轨。复用ImageStackLoader、natural_sort_key、ImageRegistration、MultiFocusFusion及imwrite_auto。

本地顺序处理保留；不新增云调度、并行队列或自动重试。任务模板/跨会话批次历史为P2。CLI已有dry-run/resume/config，不能写成全产品缺少这些能力。

承接批处理位深/仅对齐、GUI参数/目标预检、加载器分组回归，实际运行两种入口及故障写出/取消场景。同步十二语言、进度硬编码和手册中“清空/只沿用主窗”等旧描述。本轮未运行这些验收。
