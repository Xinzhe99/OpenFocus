# 跨功能 UI / UX 规范

状态：待实现设计。基准：v1.67.0 当前工作区（含本地“高级设置”翻译键修复）。本文中的响应时间、布局和验收均为目标，不代表当前实现已达到。阅读顺序见 [实施总览](README.md)。

## 1. 目标与边界

让用户在任意工具里能回答：**现在操作的是哪份数据，看到的是否是当前结果，下一步会改动或保存什么。** 保留 PyQt6、现有八种融合算法、十二种语言和浅/深色主题。改进现有工作流，不改算法数学含义、不引入插件平台或统一“大工作台”重写。

优先级统一：P0 是可能处理错数据、误判保存状态或丢失工作的缺口；P1 是主要操作路径的易用性；P2 是不阻碍主流程的效率增强。各 spec 独立给出验收编号，不能用“窗口已能打开”代替交付。

## 2. 数据对象、选中和作用范围（SH-01，P0）

| 用户可见名称 | 精确定义 | 默认选择规则 |
|---|---|---|
| 当前源图像栈 | 本次导入并完成当前变换后的源帧 | 展示总帧数、参与处理数、工作分辨率 |
| 参与处理的帧 | 源列表中勾选的帧，保持明确的顺序 | 渲染、方法对比、深度图一致；空集合不退回全栈 |
| 已配准图像栈 | 对某一次输入/参数快照配准的结果 | 仅匹配当前来源时可复用，否则重新配准或说明不适用 |
| 当前输出 | 输出列表明确选中的 `output_id` 对应结果 | 历史排序、重命名不改变对象身份；多个选中时明确数量 |
| 草稿预览 | 降采样或 ROI 的参数试验结果 | 标明分辨率/区域；不能冒充完整输出 |
| 已应用结果 | 存在于本次会话输出列表的像素 | 不等于已写文件，也不等于工程可恢复它 |
| 已导出文件 | 完整且成功写入指定位置的文件 | 展示实际路径和格式；失败/取消不改变已导出状态 |

每个图像工具顶部增加紧凑的上下文摘要，按需显示：对象名称、参与帧数、尺寸/位深、配准方式、加载倍率或 ROI。高级来源详情按需展开，普通界面不出现 UUID、内部键名、Python 类名。

实现时扩展现有 `OutputRecord` / `RenderContext` 和 `effective_stack()`，不要另建一套并行历史库。源列表改变、勾选改变、变换改变时递增轻量版本号；请求记录所用的帧标识、顺序和参数。不要为每次拖动画布计算整栈内容哈希，也不要复制整栈只为生成摘要。多页 TIFF 的帧身份需包含容器和页号。

## 3. 预览、应用、导出（SH-02，P0）

统一状态含义：

| 状态 | 展示 | 可执行操作 |
|---|---|---|
| 无数据 / 不满足前提 | 原因与可执行下一步 | 导入、选择对象、修改范围；禁用无效计算/保存 |
| 可计算 | 当前参数摘要 | 开始计算 |
| 排队 / 等待 | 等待原因和当前任务 | 取消等待；不能显示假进度 |
| 计算中 | 阶段、可确定的完成量 | 取消；仍允许平移/缩放已有结果 |
| 正在取消 | 明确“正在取消…” | 不启动竞争任务、不显示“已取消” |
| 当前结果 | 标识与当前参数一致 | 应用、采用、导出 |
| 旧结果 | 清楚标记“参数已改变，尚未更新” | 重新生成；可看旧图，但不能静默将其当新图导出 |
| 失败 | 哪一步失败、可读原因、详情入口 | 重试该操作/返回编辑；保留成功结果 |
| 已取消 | 停止在哪一步，哪些结果已完成 | 继续编辑/重新开始；不弹成功提示 |

图像与状态提示不能互相覆盖后导致“旧图+完成”的组合。计算请求的身份必须匹配发布时的对象与参数；过时回调不得覆盖新结果。展示变化（画布大小、色图、观察视角）和数据变化（方法、帧集合、核参数）分开，不因窗口 resize 重跑融合。

只有执行者确认结束才能关闭进度或释放任务对象。沿用合作取消；禁止 `QThread.terminate()`。若某后端不能即时退出，界面说明当前阶段正在结束。长任务窗口关闭必须有明确策略，不能在用户以为已结束时继续隐形占满资源。

## 4. 动作文字与反馈（SH-03，P1）

| 动作 | 推荐文案 | 行为约束 |
|---|---|---|
| 仅检查参数效果 | 生成预览 / 更新预览 | 不产生正式输出 |
| 标注或设置的提交 | 应用并关闭 / 保存设置 | 取消和 Esc 不提交草稿 |
| 修饰完成 | 应用为新输出 | 保留原输出；明确仍需导出文件 |
| 对比方案采用 | 采用参数并返回 | 将选定方案回填主面板，不暗中开始渲染 |
| 对比全图采用 | 采用为新输出 | 仅发布当前完整原始数组，保留来源与位深，标记未导出 |
| 写入磁盘 | 导出图像… / 导出全部… | 打开保存流程，显示位深与标注策略 |
| 关闭只读工具 | 关闭 | 无修改不弹确认 |
| 更新软件 | 下载更新 / 重启并安装 | 下载和重启是两个不同动作 |

同一状态一个主要动作。普通“已保存”“已删除标注”“已复制”用窗口内状态条；完成后提供“打开文件夹”等实际下一步。错误用就地信息；仅需要用户做决定的损失风险、覆盖或重启才用模态确认。文案描述对象和后果，不只说“确定/是/否”。

窗口底部固定放状态和主要动作。表单滚动不能把保存/取消按钮滚出窗口。禁用动作旁解释前提，不能只靠鼠标悬停才能知道原因。

## 5. 布局、主题与可访问性（SH-04，P1）

- 沿用 `utils/design_tokens.py`、`ui/styles.py`、`FlowPanel`、`StepperSpinBox`。共享的是行为与有限样式工具，不是把所有对话框塞入万能基类。
- 复杂图像工具采用“来源摘要 → 操作区 → 可伸缩画布+可滚动参数 → 状态/动作”的顺序。简单设置对话框保留表单。
- 参考验收尺寸为可用工作区 1280×800、960×640；不能把物理屏幕像素当 Qt 逻辑像素。更新提示条另验收 640 px 窄宽。屏幕比建议工作区小则参数滚动、面板折叠，关键动作仍可达。
- 数字框按最大允许值、单位、正负号和 stepper 宽度定下限；不要任意固定 78/90 px。所有数字可键入并提交，滑块和数字同步。鼠标滚轮在滚动表单中不意外改参数。
- 标题、参数标签与危险操作不得以省略号作为正常布局方案。文件名可省略，中间或末尾截断后提供完整 tooltip 和复制路径。
- 浅/深色都使用已有语义颜色；去掉标签编辑器固定白底/黑字等局部覆盖。色块选择器本身可显示真实颜色，但需有名称或数值，不能只靠颜色区分状态。
- 键盘 Tab 顺序遵循视觉顺序；输入框内快捷键保留文字编辑语义。所有图标按钮具备本地化 accessible name、tooltip、焦点框。
- 图像工作区沿用滚轮缩放、约定的平移操作、适应窗口、100% 和 F11；同时提供按钮，让操作不依赖记住快捷键。Esc 先退出全屏，再执行普通关闭语义。

## 6. 国际化（SH-05，P1）

中文模式下已实测高级设置仍有 `OK/Cancel`、ROI 底图有 `Frame 1`、标签范围有 `All`。这是本轮范围，不能只修此前 `action_advanced_settings` 一个键。

1. 新用户文案进入全部十二种表，保留占位符；程序标识如 DCT、OBJ、CPU 和文件名不用伪翻译。
2. Qt 标准按钮必须安装与当前语言匹配的 Qt 翻译或显式使用 `trans.t()`；选一个项目统一方式，不让不同窗口各自漏掉。
3. 菜单动作注册时使用真实翻译键；复用现有 `trans_key` 约定。窗口标题、tooltip、状态、无障碍名称都属于重翻译范围。
4. 主窗口语言切换立即更新；模态工具不会并发接收设置操作时，可在重新打开时应用，但不得丢草稿来强制重建窗口。
5. 帧号统一面向用户从 1 开始，底层索引仍可从 0 开始；原始深度编码另见深度 spec，不能因文案统一改变文件编码。

## 7. 设置与撤销（SH-06，P1）

界面几何、主题和显示偏好可即时记忆；影响处理的设置先编辑草稿，明确提交后才生效。关闭/取消不改变主窗口参数或工程状态。参数有效范围需联动限制，禁止点击保存后静默截断为另一个值。

撤销范围分别明确：主窗口源栈变换、标注配置、修饰笔画；不要让用户在修饰窗口按 Ctrl+Z 却修改主栈。某操作尚不支持撤销时，不显示假入口；对于可逆配置操作优先提供真正的一步撤销。

## 8. 共用验收与交付要求

- SH-A01：勾掉一帧，主渲染/对比/深度使用相同有效集合；全不选均提示选择帧，不退回全栈。
- SH-A02：计算中改参数或对象，旧请求结束后不能显示成新参数结果；取消状态可观察，未完成任务不发布。
- SH-A03：960×640 和高 DPI 下每个主要动作可达；中/英/德/日人工检查，十二语言跑既有键/占位符检查。检查真实界面，不用源码字符串断言代替。
- SH-A04：源/结果均含 16-bit 和 Unicode 路径的场景；预览显示正确，PNG/TIFF 导出保持位深，不重复烙入标注。
- SH-A05：Tab 到每个参数可编辑；输入文字时常规编辑快捷键有效；Esc/关闭不误提交。
- SH-A06：打开、取消工具后，处理参数与工程脏状态不变；实际应用才产生变化。

每次交付一个具名功能闭环：代码、受影响调用方、十二语言、对应手册、必要行为回归与实际窗口截图。只有覆盖一份 spec 全部必选条款及验收，才称该 spec 完成。只为数据来源、状态转换、取消、位深等消费者可感知边界补永久测试；不为控件摆放代码或固定措辞写源码镜像测试。性能目标：普通输入/拖动可感知响应不超过约 100 ms；耗时计算离开 GUI 线程；实际测量条件与结果随交付记录，不能未经测量声称达标。
