# 其他已支持功能：设置、白场校正、导航与帮助

状态：待实现。覆盖七个专项之外的现有功能；导入/ROI/处理/输出列表详见 [主工作流](08-main-workflow.md)，文件/GIF/TIFF/工程/恢复详见 [导出规格](09-export-project-recovery.md)。本轮实际查看高级设置、白场、ROI和主窗口；视频、反馈、CLI等仅作源码审查。

## 1. 高级设置、主题与语言（OT-01，P1）

证据：`dialogs/advanced_settings.py` 已有可滚动表单、固定按钮；[中文窗口](evidence/advanced_zh.png)仍显示OK/Cancel。介绍称设置只影响速度/内存，但页面包含会影响结果的AI软/硬模式和配准宽度。`_apply`将overlap静默截到block_size/2，自动下载赋给只读属性并吞异常。

要求：

- 保留性能、配准、AI、启动与更新分组；简介准确说明部分设置影响输出，不把全部都称性能参数。每组用短说明交代适用方法和生效时点。
- 处理设置编辑草稿，取消/Esc/×不提交。确认前校验全部字段，失败定位字段，不发生部分保存；成功统一刷新主面板、菜单和持久化状态。
- 修改分块大小时立即更新重叠合法范围并展示最终数值；采用当前安全上限半个块尺寸，不能点确定后才悄悄变值。整数参数在提交边界转换，thread_count至少1。
- AI模式/批量只说明对StackMFF的影响，经典CPU方法不被全局GPU勾选误导；实际设备和回退原因在相关处理摘要中显示。
- 自动下载使用现有setter，按[更新规格](05-updates.md)解释下载与安装；确认后读回，失败显示原因。
- 确定/取消及标准按钮统一本地化。原有高级菜单`trans_key`修复保留；不把它再次列为缺失。
- 主题/语言是显示偏好，可即时应用并记忆；与需要明确提交的处理参数分开。切换不清图、不清来源、不重算融合。

P2可加入“恢复本组默认”，与主窗口“重置处理参数”范围区分。不能将重置布局、清图和重置算法合成一个含糊动作。

## 2. 白场/尘点校正（OT-02，P0/P1）

已有文件或栈帧白场、尺度参数、增益场、前后预览、应用全栈、可选移除白场帧与撤销。见[当前窗口](evidence/dust_zh.png)、`dialogs/dustmap.py`、`main.py::apply_flat_field_to_stack`。

静态缺口：

| 证据 | 影响边界 |
|---|---|
| `_source_changed`只切控件enabled；栈选择没有失效增益连接 | [INFERENCE] 换来源后仍可应用旧增益场 |
| `_sigma_changed`只依赖缓存`_white`；栈预览不更新它 | [INFERENCE] 改尺度可能不更新当前栈白场，或重新算以前选过的文件 |
| 预览固定使用第0帧；解码/增益/应用同步执行 | [INFERENCE] 难检查其他帧；大图计算期间GUI缺响应 |
| 主窗口先赋raw，再计算/赋base，失败只return；对话框无成功返回判断便删所选帧并accept | [INFERENCE] raw成功/base失败可留下半应用状态，失败后仍移除白场帧并关闭 |
| `_fail`清增益但未清旧预览；错误混称“不是白场” | [INFERENCE] 旧图与失败状态易混淆，尺寸不符和解码失败无法区分 |

要求：

1. 顶部显示校正目标栈、帧数、工作尺寸/位深；白场来源显示文件或稳定帧身份、尺寸。移除选项只在使用栈帧时可用，显示具体被移除帧，不以当前高亮行猜测。
2. 来源/帧/尺度变化立即失效旧增益，禁用应用；按来源和参数revision更新预览。原始白场引用与生成增益分开，禁止用旧文件缓存替代当前选择。
3. 前后对比可选目标帧，标明帧号/文件名，共享视图与倍率；增益热图提供范围/含义。未生成、计算中、已过时、可应用、失败分别呈现，旧图保留时明确旧版本。
4. 解码/增益和全栈应用在后台处理，合作取消；预览失败分清文件不可读、不是有效白场、尺寸/坐标域不符、应用失败，不把所有异常都翻成同一句。
5. 同一次事务准备raw/base及相关元数据，全部成功后才提交；后续resize必须仍基于正确校正后的base。没有可验证域映射时明确拒绝，不能悄悄拉伸白场掩盖问题。
6. 只有校正成功才移除明确选择的白场帧；校正与移除合成一次撤销。失败/取消保持原raw/base、帧列表、来源版本和工程状态，窗口保留可重试。成功递增来源版本，使派生配准缓存失效，旧输出继续持有自己的来源。
7. “应用到整个栈”明确改变会话工作像素，不覆盖磁盘源文件；若使用多次，摘要显示已应用状态，避免把旧预览误当重新计算。工程可重建范围按导出规格说明。

不改白场校正的数学算法，不增加自动识别尘点或修补工具。保留现有16位与Unicode输入能力。

## 3. 导入视频、多页图与源栈变换（OT-03，P1）

`SourceManager.load_video_stack`已使用加载worker；`ImageStackLoader.load_from_video`逐帧解码，只有结尾报告数量，循环无逐帧取消回调。多页TIFF普通路径已展开；拖放和菜单支持情况不能写成待新增格式。

- 导入提示明确“替换当前栈 / 追加到当前栈 / 作为批处理输入”的后果；沿用既有入口和保护，不能菜单/拖放相同文案却隐藏追加语义。
- 视频显示实际解码帧数和可知总量，未知总量用不定进度；支持帧边界取消。异常提前结束与正常结束区分，数量不足时说明而非无条件全成功。取消或失败保留此前栈。
- 视频帧与TIFF页的身份包含容器和帧/页号；不能把多个相同容器路径折叠成一帧。显示从1编号，底层索引不变。
- 加载比例始终显示，说明导入缩小后当前会话可恢复的最高分辨率；不把插值放大称恢复原细节。不增加视频剪辑、转码或新抽帧算法。
- 旋转/翻转/resize作用于全栈还是所选对象写清；当前全栈行为保留，确认前显示目标帧数和尺寸变化。resize已有从base重建而非重复缩小的修复保留。
- 变换与来源、标定、标签坐标和有效配准缓存一起更新/撤销；保留历史输出独立上下文。普通成功用状态提示，避免每次resize弹模态成功框。

数据保护及加载状态具体沿用主工作流，不再维护第二套导入状态机。

## 4. 画布、放大镜、清晰度曲线和A/B（OT-04，P1）

`MagnifierLabel.wheelEvent`已有鼠标点锚定缩放及放大镜优先；主窗口resize复用缓存，清晰度曲线可点选帧；这些能力保持。

- 在画布提供可见“适应 / 100%”及当前倍率，短帮助说明滚轮、平移、放大镜操作；快捷键入口能看到完整说明，不只靠隐藏手势。
- 倍率、平移、放大镜只改变观察，不改工作尺寸；已修好的缩放锚点、窗口缩放缓存和切帧响应不退化。
- 清晰度曲线说明是相对指标，不自动排除低谷帧；点击切到该帧，勾选参与仍是另一动作。无分数/计算中明确状态，不能显示为全部0分。
- A/B两侧名称、源帧/输出身份、跟随/固定行为遵从主工作流；坐标域不匹配明示。切换标注及时失效缓存，不通过重融合刷新显示。
- ROI编辑保留现有拖动/缩放/删除；显示尺寸和底图，中文Frame N问题按主工作流修复。键盘快捷键只在相应画布作用，文本框保留输入语义。
