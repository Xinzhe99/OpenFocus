## 2. 目标流程

导入后显示“已载入 13 帧 · 参与处理 11 帧 · 4032×3024 · 16 位 · 加载 100%”。随后用户选择配准与融合，必要时先做草稿/方法对比，再生成正式输出。输出自动被选中，旁边给出“导出、修饰、查看信息”，不要求先猜右键菜单。

保留传统菜单、已有快捷键和输出右键入口。此轮不将整个应用改造成向导，也不强制用户按线性步骤操作。

## 3. 具体要求

### WF-01 输入与选择（P1）

- 空画布提供“打开文件夹”“打开图像文件”“加载示例”，支持原有拖放、视频、多页 TIFF。增加显式文件选择入口，复用现有 filepaths 加载路径。
- 导入期间保持持久状态行：扫描、解码、已加载数量；总量未知使用不定进度。显示取消操作，实际合作停止后再解除忙碌。新导入失败保留先前可用栈，不能先清空再报错。
- 加载比例对话框显示所选倍率和可确定的工作尺寸；不知道尺寸时如实说明。记忆“不再询问”的倍率后，主窗口仍显示实际倍率和恢复提示路径。
- 列表勾选表示“参与计算”；行高亮表示“当前查看/批量列表操作”。列表头显示“参与 11 / 共 13 帧”，排除帧仍可浏览。
- 有效帧不足两张时，融合/深度/对比的主要动作就地解释；不要点击后才弹重复警告。仅配准是否允许单张按现有后端能力处理，不虚构变换。
- 导入/追加、旋转、翻转、缩放、白场校正、勾选变化后更新来源版本。历史输出保留自己的上下文，不能误标为当前栈结果。

### WF-02 配准和融合参数（P1）

- 保持“配准 → 融合 → 本方法参数 → 生成”的顺序。将低频选项放在“更多参数”折叠组；已改变的隐藏设置在摘要中可见，避免“折叠=无效”的误解。
- 核大小增加与滑块同步的数字框，沿用奇数归一化。参数名随方法改变，不能把 DTCWT 分解层数当作通用核大小。
- GPU 行说明当前方法实际使用 CPU / CUDA / MPS；选择 CPU-only 方法时，不把全局 GPU 开关显示成对此算法的性能承诺。
- “重置默认”改成“重置处理参数”，只重置处理参数，不清源帧、输出、标签、比例尺或界面布局；可一次撤销参数重置。
- 快速预览呈现为“草稿预览”，结果显著标注工作尺寸和倍率。关闭草稿选项不会让旧预览突然变成正式输出；“生成完整结果”明确重新计算。

### WF-03 区分两种比较（P1）

- 主面板常用入口采用“方法对比…”打开交互对比窗口。
- 现有一次生成所有方法结果的能力保留，名称改成“生成全部方法结果…”，放在工具菜单或比较入口的次级动作。启动前显示方法数、分辨率和输出会加入历史列表，不再使用与检查预览混淆的“对比全部”。
- `Ctrl+Shift+R` 保留完整逐方法生成语义并更新说明；普通“方法对比…”不暗中变成八次全图渲染。

### WF-04 ROI（P1）

- 选区旁显示宽×高及“裁剪输出 / 贴回底图”的区别。把“融合并覆盖在底图上”改为“生成一张贴回底图的新输出”，避免被理解为覆盖源文件。
- 贴回模式选择“第 N 帧 · 文件名”，展示实际缩略图，底层帧索引来自同一输入快照。排除帧、配准后序号不允许错位。
- 显示输出规格：裁剪是 ROI 尺寸；贴回是完整底图尺寸。来源区域边界、DCT 裁边等由管线决定，界面展示实际结果，不承诺未实现的无缝修补。
- 取消 ROI 选项返回选区，保留坐标；清除选区提供可见动作。保持创建 ROI 不发 `roiDeleted` 的现有约束。

### WF-05 输出与 A/B 查看（P1）

- 输出条目采用两行：可读短名；方法/尺寸/位深/草稿或修饰状态。长文件名省略并保留完整 tooltip，避免以水平滚动条作为常态。
- 输出区域提供可见的“导出…”和“修饰…”；多选时显示选中数，修饰解释只支持一项。右键菜单继续可用。
- A/B 标题始终指出两侧实际对象：源帧号/文件名、输出名/配准帧；“跟随当前选择”和“固定此对象”用清楚文案区分。
- 对不在同一坐标域的图像（裁剪、不同分辨率）说明对比局限；禁止为了看似重合而静默改变源像素。保留原有画布缓存和比例尺/标签重绘逻辑。
- 默认分割比例保证至少 3 行源帧与 2 行输出在 1280×800 可见；参数区可滚动，主要渲染动作固定可达。用户调整后记忆比例，不强制每次重置。

## 4. 状态与失败

导入/渲染期间的关闭、取消按共用任务规则。完整渲染失败保留此前输出和当前参数；错误定位“加载/配准/融合/发布”，提供查看日志。完整逐方法生成允许部分成功，汇总成功/失败方法；不能用一个“完成”掩盖失败。

新增可见动作按当前选择派生，不维护与输出记录不一致的第二套 enabled 标志。
