# GPU support

StackMFF V1, V2 and V3 use the bundled dynamic ONNX models through ONNX Runtime. The standard Windows package includes DirectML; macOS uses CoreML when available. The runtime also recognizes CUDA and ROCm execution providers when a compatible ONNX Runtime build and its driver libraries are installed. The standard Linux dependency is CPU-only; an accelerator-specific ONNX Runtime distribution must be installed separately. Classical fusion and application registration use the CPU; explicitly requested low-level CuPy registration is a separate backend. PyTorch is not bundled for production inference.

An available provider does not by itself prove that the GPU executed a model. OpenFocus probes an accelerator by running a small model and inspecting its ONNX Runtime profile before selecting it. ONNX Runtime may place some operations on the CPU, and CoreML may use different compute units. If an accelerator fails or its memory budget is insufficient, inference can fall back to CPU. The provider probe is not a substitute for validating a complete job on the target machine.

Windows DirectML probes hardware adapters and prefers a usable adapter with dedicated memory; the selected adapter's DXGI budget is used for admission. CUDA and ROCm require a readable free-VRAM budget from the driver. An OpenVINO GPU provider without a reliable free-VRAM reading is not admitted and falls back to CPU. Provider availability, driver compatibility and target hardware behavior still require real-device validation, including RTX 3090, ROCm and Intel GPU configurations. GPU memory does not replace the system memory and temporary disk space used for images, alignment and output.
