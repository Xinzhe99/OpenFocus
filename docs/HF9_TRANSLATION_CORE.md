# HF9 reusable alignment core

`core.hf9_alignment` contains the proven translation core and the wide similarity detector ported from `F:/REA_heliconfocus9/tools/scripts/helicon_align4d.py::align_pair_wide`. Production has no runtime dependency on the research checkout. `openfocus` registration now uses `core.registration._align_helicon_impl`; the previous native ECC proposal, NCC decision, Lanczos warp and thumbnail cache engine have been removed.

## Production plan and apply APIs

`estimate_alignment_plan(sources, *, max_shift_ratio=.05, reference_frame=1, rotation=0., magnification=3., should_cancel=None, progress_callback=None, failure_policy='fail')` accepts a sized sequence of arrays or `resolve_frame` descriptors. Rotation is a search radius in degrees; magnification is a search radius in percent. Brightness stays fixed at 1. The registry exposes the active rotation and magnification parameters through the existing GUI and CLI parameter editor. Explicit saved shift values remain intact; fresh configurations default to 5%.

The returned frozen `AlignmentPlan` has:

- `transforms`, indexed by original source index, with immutable `f8` and `pair_f8` tuples, source identity, estimation rounds, pair reference index and any estimation failure reason;
- `reference_index`, `processing_order`, `max_shift_ratio`, `rotation`, `magnification`, `failure_policy` and `estimation_bytes`;
- `validate_sources(sources, *, should_cancel=None)`, which checks metadata and file identity without decoding file descriptors, and hashes ndarray sources;
- `to_dict()` and `AlignmentPlan.from_dict(data)` for a versioned JSON-serializable plain-data representation.

`apply_alignment(image, transform, *, should_cancel=None)` validates source shape, dtype, SHA-256 and recorded file size/time. It returns the same shape and dtype. Exact identity returns the original borrowed array unchanged. Other transforms allocate one output and never mutate input pixels. Sources and borrowed results must be treated as immutable. Every repeated fusion or retouch application validates the decoded pixels again.

The stored detector tuple is `(tx, ty, cx, cy, rotation, magx, magy, brightness)`. It describes an inverse sampling map, not an OpenCV forward affine matrix. With `angle = float32(-rotation) * pi_f32 / 180_f32`, the map preserves the prototype's separate float32 operation order:

```
u = (x-cx) * cos(angle)/magx + (y-cy) * sin(angle)/magy + tx
v = (y-cy) * cos(angle)/magy - (x-cx) * sin(angle)/magx + ty
```

In particular, a source enlarged by 1.06 requires the inverse correction magnification near 0.94344. A large combined affine translation caused by centered rotation is not separately rejected as a shift-limit violation. The shift setting controls the prototype's actual candidate domain, rather than post-clamping affine coefficients. Zero shift explicitly disables estimation and emits identity transforms.

When rotation and magnification are both disabled, the initial translation grid uses at most one pixel between candidates before the existing quarter-pixel refinement. A fixed seventeen-position grid can skip the true phase for wide ranges, even with a unique source. The same detector and bounded candidate chunks are used; no alternate estimator or retry is added. Joint rotation/magnification searches retain the research grid settings.

Input may be uint8 or uint16, grayscale or one/three/four channels. Spatial dimensions must match; channel counts and uint8/uint16 types may differ between sources. Gray is the truncated equal mean of up to the first three channels. Uint8 gray is shifted left eight bits; native uint16 low bits are preserved. The public registration wrapper retains the prior rejection of transparent images. Standalone application preserves every channel.

Public in-memory registration also preserves the existing normalized internal float32/float64 domain `[0,255]`, including mapped arrays retained by generic caches and deferred processors rooted in these arrays. This follows `utils.image_utils.normalize_fuse_input`; it does not enable float TIFF decoding. Native file descriptors still require uint8/uint16. Float identity returns borrowed pixels exactly. Estimation recovers uint16 channel codes by `rint(value*257)` before the truncated equal-channel mean. Nonidentity float application uses the same float32 coordinates, Q8.8 weights, geometric masks and edge clamp, but divides the weighted float values by 65536 without integer truncation, preserving fractional pixel values and the original float dtype. Non-finite or out-of-domain internal pixels are rejected.

## Reference and failure behavior

Reference 1 estimates the current raw gray against the previous aligned gray. That detector result already maps the current source into the anchor's coordinates: it must not add the previous translation, rotation or magnification again. The current gray is warped once with this absolute result for the next comparison. Both the wide API and the retained translation API use this rule. Real three-frame regressions cover accumulated motion; historical mock tests that required double accumulation were removed. Plan version 2 and aligned-cache format 6 reject results produced by the former chain.

An explicitly selected later reference retains the public fixed-anchor behavior. Estimation visits that reference first, then frames to its left in descending order and to its right in ascending order. Each is estimated against the chosen anchor. Output and transform tuples always remain in original source order. This reference selection is a product ordering rule, not a reconstruction of native autosort.

`failure_policy='fail'` raises an `AlignmentEstimationError` identifying the source frame when the detector cannot estimate a pair. `continue` records the reason and uses an identity transform for that frame. Decode, source identity, unsupported format, memory and cancellation errors propagate. Registration reports include the forward matrix, exact detector and pair parameters, pair reference, round count and actual fallback reason. No ECC/NCC retry or unproven confidence threshold is used.

## Eager and deferred registration

`ImageRegistration(..., defer_warps=False)` retains an eager array return by default. The option is keyword-only and belongs to the registration instance; extension runners do not receive a new generic keyword. OpenFocus estimation exposes the immutable HF9 plan as `registration.alignment_plan`. Homography, ECC and their ordered combinations expose a separate immutable `PerspectiveAlignmentPlan`.

`core.registration.apply_alignment_plan(sources, plan, *, defer_warps=False, should_cancel=None)` handles cold and cached plans. For HF9 plans, deferred mode wraps every original source, including the reference and identity transforms, in `source_frames.process_frame`, whose processor calls `apply_alignment`. It supplies explicit shape/dtype, cancellation and warp-only `scratch_bytes`. A nontrivial common crop is represented with `crop_frame`; HF9 identity plans preserve the complete source dimensions. Eager mode returns actual stored arrays.

Geometric validity is independent of pixel darkness. `alignment_valid_mask(transform, *, should_cancel=None)` exposes an exact per-pixel in-bounds mask. `transform.valid_bounds` computes a conservative centered rectangle wholly inside the valid affine domain without allocating a full mask. Registration intersects these rectangles, records grouped crop offsets and rejects an empty common crop. The crop is conservative, not a claim of maximal area.

Homography/ECC estimation resolves only the active bounded set of sources and reduces them with the existing estimator interpolation and width rules. ECC retains adjacent reduced gray planes rather than a full gray staging generation. CPU output descriptors retain each stage's forward `H_final = T_crop @ H`, original matrix precision, cropped output size, `INTER_LANCZOS4` and `BORDER_CONSTANT`. Invalid common crops retain the existing uncropped output behavior. Chaining retains every intermediate crop and resampling inside the descriptor chain; multiplying stage matrices into a single warp would change pixels and is deliberately avoided. Source order, native uint8/uint16 and internal floating pixels, fingerprints, source operations, ROI provenance and cancellation survive repeated resolution. Changed source pixels or processor output are rejected against the estimator fingerprint. Explicit legacy CuPy ECC remains eager with its existing linear interpolation. Extension stages receive materialized arrays at their boundary.

GUI, CLI, comparison and batch routes select descriptor-preserving fusion input through the registered `FusionAlgorithm.streaming_sources` capability. This storage capability does not change a method's numerical domain: native integer fusion codes remain the A/B/C family. Deferred perspective registration itself does not establish streaming support for a classical fusion backend.

ROI alignment retains processing descriptors for fusion and provenance. The ROI canvas and base-frame dialog obtain display pixels through finite `ROIFramePreviewWorker` jobs using the existing bounded source-region renderer. Source resolution and linear development stay off the GUI thread for descriptors; the canvas preserves the full aligned coordinate domain for ROI selection, viewport tiles and loupe requests. Changing frames coalesces region requests, discards stale delivery and cancels previous producers. Preview jobs release their resolved source on completion and participate in dialog/application shutdown.

ROI preview scheduling bounds worker retirement as well as pixel execution. The base-frame dialog retains one active or retiring QThread and only the latest selected descriptor pending. The main canvas has three fixed slots (initial preview, viewport and loupe), each retaining one active or retiring worker and one latest request across frame generations; replacing a frame clears its pending requests and waits for slot retirement before starting replacements. Closing clears pending work before cancellation. Preview delivery preserves the label's live ROI state, including deletion or redrawing while pixels load, without restoring an earlier captured rectangle.

Perspective output shape follows OpenCV: an `(H, W, 1)` input produces a two-dimensional warp, including in later plan stages and cached application. Deferred directory imports preserve the eager decoder's BGR contract for opaque alpha-bearing files, validating transparency before retaining a BGR processor; nonopaque inputs remain rejected.

## Memory, lifetime and cancellation

`alignment_resolution_bytes(frame)` estimates only a new warp output plus bounded row/hash scratch. Producers add their source decoder's `frame_resolution_bytes`; decode is not double-counted. `estimate_alignment_bytes(sources)` and `plan.estimation_bytes` expose the separate estimator admission bound. The estimator calls `resource_policy.plan_execution` with one sequential owner before decoding. It retains an anchor/previous gray, two native gray pyramids and bounded candidate scratch, never N decoded color frames. Different channel counts are accounted for by the descriptor decoder estimate.

The source's candidate enumeration is generated in chunks of at most 65,536 sample points, retaining original index order and strict first-minimum tie behavior. Reduction is performed in rows with replicated odd edges and `(sum+2)>>2`, preserving the wide source's pyramid. Warping also uses rows. Coordinates and GPU parameter construction remain float32 in the source's operation order. Sampling uses Q8.8 integer weights, truncates by `>>16`, fills out-of-bounds with black and preserves the verified `W/H-1.001f` last-column/row clamp. Identity bypasses all interpolation.

Cancellation is checked before/after resolution, per hash/gray/downsample/warp row, per candidate chunk and search round, and before publication. It raises the existing `RegistrationCancelled`. Parent job leases and producer concurrency remain owned by the pipeline; the core does not acquire another competing lease inside each producer.

## Transform-plan cache

`utils.align_cache.load_alignment_plan(folder, filenames, sources, *, identity=None, should_cancel=None)` returns a fully validated immutable HF9 or perspective plan, or `None`. `save_alignment_plan(folder, filenames, plan, sources, *, identity=None, should_cancel=None)` publishes only metadata through atomic manifest replacement. No aligned full frames are written for the deferred path. Extensions that require materialized arrays retain the separate array cache.

Plan manifests use `.openfocus_cache/plans/<signature>/meta.json`, independent cache version 2, with distinct backend identities `hf9-wide4d-v1` and `opencv-perspective-v1`. Identity includes ordered file names/stat fingerprints, original descriptor path/page, shape/dtype and calibration/orientation/scale/source operations/native geometry. The caller supplies its effective parameters and source revision in `identity`; HF9 rotation/magnification/reference/shift/failure policy are also checked against its immutable plan when provided. Perspective plans validate the complete ordered homography/ECC stages, registration parameters, requested downscale width, matrix precision, per-stage source fingerprints, output sizes and crop bounds. Perspective matrices are never encoded as HF9 f8 fields. The payload has a SHA-256 checksum. Every read validates source identities and rechecks file signatures before returning. Every apply still checks decoded pixels. Corruption, unsupported schema, changed files, calibration, parameters, order or geometry produce a cache miss. Cancellation propagates and leaves the previous manifest intact.

Arbitrary `ProcessedFrame` callables have no stable disk identity, so plan cache helpers refuse them. Such sources still support bounded cold estimation, in-memory plans and deferred repeatable application; their decoded digest protects each reuse. Pipeline sensor cleanup therefore disables disk plan caching rather than treating arbitrary processors as unchanged sources.

## Evidence and limits

The current detector is compared with `helicon_align4d.align_pair_wide` using the same gray16 input and explicit search parameters. The historical `aligrange_f8_*.npy` files have no recorded generator, command or parameter provenance; they do not establish native HF9 transforms. See the research checkout's `docs/ALIGNMENT_F8_PROVENANCE.md`. The rollback disassembly establishes that slots 0–3 divide by pyramid scale without crossing and slots 4–7 carry unchanged. An enlarged source requires inverse correction magnification.

`tests/test_hf9_wide_alignment.py` compares transforms, search rounds, public plan calls and full-resolution warps against the real research module. Independent geometry assertions use the injected shift, rotation and scale in `stacks/aligrange/cases.json`, not the historical transform cache. It also covers scalar warp/mask checks, immutable serialization, references, dtype/calibration/pixel reuse, estimation failures, cancellation, metadata cache integrity and deferred registration. Set `HF9_RESEARCH_ROOT` if the research checkout is not `F:/REA_heliconfocus9`; the real-source differential explicitly skips when that external evidence is unavailable.

`tests/test_deferred_registration.py` covers real eager-versus-resolved-deferred pixels for uint8 gray, uint16 RGB and internal floats, cropped/uncropped and ordered composite modes, repeated consumption, processor/file changes, cancellation, strict extension signatures, GUI/CLI/comparison native fusion consumers and cold/warm perspective plan caching.

`tests/test_roi_deferred_consumers.py` exercises actual ROI alignment, options-dialog construction/base selection and the main ROI canvas with uint8, uint16 and camera-linear pixels. It checks bounded previews, aligned coordinate preservation, native development, off-GUI source resolution and cancelled producer delivery. Perspective tests also cover singleton-channel eager/deferred/cached chains and opaque/nonopaque alpha directory behavior.

The 2026-11-08 alignment sweep covered 316 cases across the two HF9 APIs, bit depth, array/plan caches, resource control, eager/deferred consumers and public registration. It passed 315; the remaining cancellation test intercepted the former OpenCV affine path. After migrating that injection to the actual final-frame processor, all three cancellation cases passed. A real headless CLI smoke retained all uint16 TIFF pixels, and a deferred three-frame stack recovered 0/6/12-pixel shifts with exact anchor pixels in the common interior. Injected rotation/scale geometry uses explicit 8-degree/8-percent search ranges. The earlier 6/6 boundary configuration still has the documented research accuracy limitation; these runs do not establish full native HF9 geometric parity.

The source's effective `cnt>=2` sample eligibility is an explicit upstream inference; a single-sample zero-variance candidate otherwise wins spuriously. The production implementation also raises on an excessive candidate domain or no eligible candidates instead of silently returning an accumulated base. Ordinary executable differential fixtures exercise the eligible finite-domain path. Rotation3 has a documented native behavior difference (-3.003° versus native -3.652°); full S0–S16 parity is not claimed. The constant 0.2 seed is established, but its driver-table argument ownership and autosort trigger details remain open. No seed/autosort controls or photometric optimizer are exposed.

## Retained translation API

`estimate_translation_plan`, `apply_translation`, `TranslationPlan`, `TranslationTransform`, `estimate_translation_bytes` and `translation_resolution_bytes` remain distinct standalone APIs exercised by `tests/test_hf9_alignment.py`. They retain the `(12,64,37,2)/115` separable pyramid, centered cropped difference-variance search and quarter-pixel fine grid. Estimation uses the previous aligned gray; its result is already an absolute anchor displacement and is checked against the per-axis admission bound. Signed `dx/dy` sample `x-dx,y-dy`, unlike detector f8 coordinates. These helpers do not alias the wide backend and have no public OpenFocus registry caller.
