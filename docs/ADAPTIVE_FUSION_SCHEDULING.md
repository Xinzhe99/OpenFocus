# OpenFocus 自适应融合调度设计

设计草案。源码基线为 `332fc2bf463743f90e5a31ed548d23182c9d802b`（合并 PR #130 后的 `main`）。本文中的候选策略与验收门槛供后续实现使用。现有测量见 [性能参考](PERFORMANCE.md)。

## 1. 调度目标

用户选择融合方法、算法参数以及工作分辨率或预览模式。OpenFocus 从已通过画质验收且能安全运行的计划中，选择预计总耗时最小的计划。候选集合、估算式、预算快照和同分规则均有版本，同一输入得到同一计划。可用资源变化时可以产生新的计划。预计耗时来自实测校准，硬件规格和内存公式本身无法推出最快线程数或设备。

传统方法优先整图计算。OpenFocus A、B、C 的自动与手动路径都保持整图上下文，允许内部按行、条带或磁盘映射执行。Guided Filter、GFG-FGF、DCT 和 DTCWT 在整图候选不满足准入时才允许外部空间分块。StackMFF V1、V2、V3 在经验验证的推理尺度下使用空间瓦片，并保留每块全部焦点帧。小工作图可使用一个瓦片。任何降级都保留选定的工作分辨率、位深、帧数、顺序、对齐结果、颜色与算法参数。

## 2. 十种算法的基线和目标

默认设置为启用外部分块、长边阈值 2048、块长 1024、重叠 256。下面的「分块」指独立处理空间瓦片后拼合。DCT 的 8×8 变换块、OpenFocus 的行级执行属于算法内部实现。融合选择与方法规格见 [调度入口](../core/multi_focus_fusion.py)、[融合注册表](../core/algorithms.py) 和 [估算适配器](../core/algorithm_adapters.py)。

| 方法 | 基线的整图与分块条件 | 基线设备与主要内存项 | 自动调度目标 |
|---|---|---|---|
| Guided Filter | 长边超过阈值时外部分块 | 整图 CPU／OpenCL。全图累积图加每个活跃帧的导向滤波与解码工作集 | 整图 CPU／GPU 优先。两者均无法准入时使用验证过的 CPU 瓦片 |
| GFG-FGF | 长边超过阈值时外部分块 | 整图 CPU／OpenCL。累积图、每帧滤波中间量、解码与设备传输 | 整图优先。瓦片覆盖串联滤波与缩放的完整依赖区 |
| DCT | 长边超过阈值时外部分块。整图也使用内部 8×8 块 | CPU/SciPy。分块方差、最佳帧索引、低分辨率一致性中值滤波与颜色回填 | 整图优先。外部分块锚定同一个 8 像素格点，支持中值滤波所需的相邻块 |
| DTCWT | 估计的单轮工作集超过当前预算时外部分块 | CPU/`dtcwt`。指定层数的变换、选择、逆变换及有序帧处理 | 整图优先。逐级验证瓦片的相位、边界扩展、重叠及最小核心尺寸 |
| OpenFocus A | 默认整图。显式非默认阈值可触发分块 | CPU／整图 OpenCL。整图选择和合成出图，有限行缓冲与可映射累积量 | 禁止外部分块。根据预算选完整 GPU、CPU 内存或 CPU 映射 |
| OpenFocus B | 默认整图。显式非默认阈值可触发分块 | CPU／OpenCL 混合。完整 GPU 深度路径或受限 GPU 活动计算和合并，全局深度图与行缓冲 | 禁止外部分块。完整 GPU 深度、有限 GPU 阶段和 CPU 都沿用全局深度坐标 |
| OpenFocus C | 只支持整图上下文 | CPU／整图 OpenCL。全局深度递推、权重和平面重建 | 保留全局递推和映射路径。显存不足时切整图 CPU |
| StackMFF V1 | 长边或整栈字节数触发分块。分块重新做几何和设备准入 | 验证过的推理设备或 CPU。全部帧、全尺度与 0.75 尺度、中间概率及亮度重建 | 先限定经过验证的空间尺度，再联合选择瓦片大小和推理设备 |
| StackMFF V2 | 长边、整栈字节数或整图推理准入触发专用分块 | 验证过的推理设备或 CPU。注意力工作集随帧数增长，在瓦片中预测位置，混合后统一采样 | 使用 V2 专用网格与位置混合。保留焦点帧顺序和统一采样 |
| StackMFF V3 | 长边或整栈字节数触发分块。分块重新做几何和设备准入 | 验证过的推理设备或 CPU。全尺度与 0.75 尺度、概率平面和 soft/hard 重建 | 根据模式、模型和设备核定瓦片尺度与重叠。保留两次推理和重建规则 |

OpenCL 设备需要真实设备、可用的编译路径和有效预算。离散卡需读取对应设备的空闲显存，集成卡结合主机预算。神经后端按平台支持 TensorRT、PyTorch CUDA、ONNX Runtime 的 DirectML、CUDA、ROCm 或 CoreML，以及 CPU。CoreML 的 provider 证据不能区分它选择的具体计算单元。DCT 的 OpenCL 提案在基线尚未合并，DTCWT 的 GPU 候选也需独立验证。调度器只接纳相应版本已验证的实现。设备条件见 [GPU 支持](GPU_SUPPORT.md)。

## 3. 估算与准入

### 输入和生命周期

- 导入或更换方法时凭元数据给出预估。对齐与公共裁剪完成后，根据本次实际融合矩形和 source descriptors 生成最终计划。全图使用所选工作尺寸，ROI 使用同一坐标域内实际需计算的扩展区域。OpenFocus A/B/C 的 ROI 策略必须保留各自的全局依赖。
- 分开记录原始尺寸、解码工作集和融合工作尺寸。即便选择一半尺寸，RAW 整传感器解码、整页 TIFF 解码或延迟 warp 仍可能需要原始尺寸工作区。使用各输入的位深、通道、stride、源类型、是否映射和解码峰值上界。避免在准入前物化整个栈。
- 每个候选列出固定活跃字节、每在途单元字节、最大任务数、临时磁盘及设备内存。取各阶段同时存活对象的最大和。包含准备与曝光、滤波或推理、结果及权重、待顺序归约的 worker 结果、色彩转换和输出。模型估算按实际 padding 核算 V1/V3 两个尺度及各自缓存，包含加载、首次编译和 staging 峰值。V2 估算包含栈深所致的注意力项，不能只按像素计。
- 使用快照时已驻留内存所对应的剩余量，仅为新增量再次准入。分开计算映射触及的行和未驻留部分，区别共享缓冲与并行复制，共享物理内存仅计一次。临时磁盘根据实际选定卷和中间文件寿命计算，预估需容纳至少最大待写输出、映射峰值和卷预留空间。

### 初始预算

沿用 [`resource_policy`](../core/resource_policy.py) 的常量和新分配语义。10 进制与二进制单位在日志中分开，以下内存量以字节计算。

- 物理内存余量为 `available − max(1 GiB, min(15% × total, 4 GiB))`，再钳制到非负值、可读的 Windows 系统及进程 commit 余量、隔离渲染进程和显式限制。舒适预算取该余量与 `45% × min(available, 已知 commit 余量)` 的较小值。只允许一个最小工作集在舒适预算上方、硬上限以内运行，并禁用额外并发。
- 离散设备从已验证的实际 adapter 读取可用量，初值取 `max(0, min(70% × free, free − max(512 MiB, 15% × total)))`。设备的最大单次分配、驱动预算和已保留会话还可减小上限。共享内存设备的主机和设备新增量合并检查，由 GPU 内存 API 报告的独立限制也须满足。未知 RAM 时无法准入新重任务。未知离散显存时跳过需要该预算的 GPU 候选。
- 从可用 CPU 拓扑、亲和性和配额得到容量。自动策略初值沿用 Balanced 的上限，最多约 80% 物理核且在多核时至少留一个核。外层并行时限制滤波、FFT 等内层线程。单个 native 后端占用预算时外层并发为 1。GPU 单队列，主机准备仅重叠一个已准入单元。按 `min(可用任务, CPU 上限, 用户上限, floor((舒适预算 − fixed)/per_task))` 计算并发范围，评估其中有校准结果的离散候选。单线程仍是一种候选。
- 复用桌面的重任务队列与隔离进程预算。在应用内把 GUI、比较、批量和深度阶段的同时持有量纳入同一预算所有者。进程内 `heavy_job` 只串行化该进程内的任务。前端保持可交互，调度器避免无界排队或依靠页面交换完成计算。

### 候选顺序与退路

1. 按版本化规则生成候选。传统方法先生成所有已验证的整图设备和有界工作集。先评估舒适预算内的并发，整图优先策略允许预估安全的单工作集整图。OpenFocus A/B/C 在同一域内依次评估可用 GPU 阶段、CPU 并发、条带宽度和映射后备。允许外部分块的方法在整图选项全部未通过准入后生成 CPU 瓦片候选。
2. 在画质等级和整图优先级相同的候选间，比较总耗时估计。代价包含对齐或缓存命中、解码、颜色和曝光准备、每像素/每帧计算、边缘冗余、设备传输、引擎加载或首次构建、拼合与最终输出。按机器类别、provider 版本、模型与实际 padding 几何选离线校准条目。使用已存在的编译计划信息区分冷、热成本。没有可信校准时使用经过验证的保守固定顺序，并记录原因。同分按预估峰值、固定后端顺序、瓦片几何和线程数排序。
3. 在大缓冲、模型会话和输出提交前复核实时余量。可恢复的资源拒绝时先释放当前尝试拥有的库缓冲与可重建缓存，刷新快照，排除失败的候选，再从可行集合取下一完整计划。每个阶段最多两次补救尝试。已证明可安全续跑且同签名可复用的输出才保留。更换会改变结果的设备或几何时，从阶段起点重跑，避免一个结果混用不同策略的瓦片。
4. 无法准入时报告阶段、估算需求、安全可用量和已经排除的策略。归因使用结构化资源错误。损坏的输入、磁盘 I/O 错误、失效变换、模型不匹配与取消沿各自错误通道处理。取消后停止投递新工作，等待在途调用结束；隔离 worker 异常退出时清理其临时产物。失败任务不发布半成品或覆盖原有结果。

## 4. 瓦片几何和画质

传统回退从每个方法的依赖区和格点推导最小真实上下文。同一封闭计算的输入包括边缘外推、缩放采样相位以及串联滤波。候选以 64 或 128 像素总覆盖重叠起步，按算法和参数补齐或扩大。分别记载每边只读上下文 `h` 与核心羽化宽度 `b`。若输入瓦片边长为 `T`，正的核心步长至多为 `T − 2h − b`，并对齐方法的原点格点。用实际区间计数与计算像素评估尾块，保证全覆盖且权重和非零。DCT 将中值滤波半径换算为像素并保留全图 8×8 相位。DTCWT 按 `2^N` 网格扩展，边缘配对、层数、逆变换和拼合需用整图对照校验。相位或上下文未达到门槛时，排除该候选。

StackMFF 的首批候选以仓库已有 `1024 → 512 → 256` 行为为基准，按模型、帧数、实际 `64` padding 和已验证 provider 细化。每个瓦片包含完整序列，保留 V1/V3 的双尺度及 V2 的位置图拼合。已有 V1/V3 证据支持 512／256 瓦片上的 128 像素重叠。256 瓦片上的 64 像素重叠曾出现可见差异。保持 128 的初始下限，只有独立对照达标后才启用更窄区域或更小瓦片。用户给出的块长和重叠在允许的覆盖与质量区间内参与候选生成。各瓦片的真实尺寸、数量、边缘多算像素比例和实际重叠归入计划报告。

## 5. 用户设置、旧工程与诊断

- 新安装和普通渲染进入自动模式。高级设置使用「允许必要时分块」，仅作用于支持传统回退的算法。手动块长和重叠在高级区域可选，默认自动。StackMFF 保留模型尺度的独立选择与说明。去掉日常操作中必须选择的资源模式，保留 CPU 强制和高级线程上限。GPU 选项继续表示可用时允许实际验证并准入设备。
- 加入 `fusion_policy` 的版本字段。新版保存算法参数和显式覆盖。旧设置中的默认资源模式和 `2048/1024/256` 尺寸组迁移为自动；已有非默认显式块长、重叠、CPU 开关、线程上限作为安全边界内的高级覆盖。旧工程和 recipes 若有显式几何与旧模式，保留其解析值和版本。旧工程中曾要求 A/B 空间分块时保留历史像素与快照，重新运行应用整图约束，并显示一次迁移说明。`tile_threshold` 只在旧策略解析时继续生效。CLI 明确覆盖、recipes 与 GUI 使用同一解析器并导出有效值。
- 渲染结果保存与像素有关的有效签名，如算法与模型、工作域、执行序列、瓦片几何及量化路径。比较或深度功能按已有像素复用合同检查签名。计划供日志与控制接口查询，包含版本、尺寸、各预算和峰值估计、并发、估计与实际设备、候选拒绝/降级理由、冷暖耗时。前端常态只显示必要阶段、进度和实际设备，详细资源解释放日志及报告。

## 6. 实现顺序与验收

| 阶段 | 实现范围 | 合入门槛 |
|---|---|---|
| 1 | 用基线记录确定性计划输入、输出几何和分阶段峰值。建立算法资源模型、候选排序、日志和离线回放。选择结果先用于内部对照 | 对同一快照与版本逐字段得到同一候选、拒绝和选中结果。回放覆盖 RAM/commit 缺失、设备不可读、共享内存、CPU 配额及磁盘量不足 |
| 2 | 接入传统方法整图优先和安全瓦片回退。迁移 A/B 旧阈值，验证全局深度、曝光、ROI 和拼合 | A/B/C 同一 CPU 实现逐像素匹配整图基准。四种传统方法在可准入时报告整图，且资源受限时报告明确回退。瓦片全覆盖、位深与通道一致，固定样本通过接缝验收 |
| 3 | StackMFF 联合选择几何和设备，纳入真实计划缓存、冷启动、显存与注意力。接入实际设备和失败复核 | 三个模型覆盖 CPU 和每个准备启用的真实加速设备。保持完整焦点序列与双尺度语义，记录预测与实际 backend。校验 52 帧高像素、V2 深栈与首次构建峰值 |
| 4 | GUI、CLI、批处理与比较切换新的默认，迁移旧工程和高级选项 | 同尺寸和参数在各入口得到等价策略。旧工程与 recipes 有回读对照。实际 Windows/macOS/Linux 验证可取消、保留旧结果、清理临时文件与缩放后的设置可用性 |

### 共用对照协议

- **样本与可复现性。** 固定栈、照片哈希、焦点顺序、色彩配置和各方法参数。包含 8/16 位、窄长图、边缘高频、空白、透明导出、ROI 和真实裁剪。硬件覆盖低内存 CPU、GPU 共享内存、Windows DirectML／可选 CUDA 后端、macOS CoreML 与 Linux CPU。记录应用、驱动、库、模型、工作尺寸和缓存状态。将输入清单与可再生的合成桩一并提交。
- **画质。** 先校验尺寸、位深、alpha、参数及裁剪完全匹配。签名不变的确定性 CPU 计算逐像素相等。不同设备和近似瓦片采用同算法参考图，并分别计算全图与接缝带的 MAE、99 百分位和最大误差。初始近似门槛为全图 MAE ≤ 0.01% 满幅及接缝带 99 百分位误差 ≤ 1% 满幅。每个真实场景同时检查细节放大图、深度断层、重复边缘与色偏。若方法已有更严格的像素对照，沿用它。阈值需用先前样本与独立留出集验证，候选不过线则不进入自动集合。
- **速度。** 每个候选采集至少三次独立冷启动和五次热启动，分开报告中位总耗时、阶段时间与最高观测值。总耗时从相同入口到可用输出，包含准备、传输、输出和首次构建。对同输入与可行质量等级的候选做对照，初始目标为自动选择在至少 90% 的校准外常见栈上处于当时最快候选的 110% 总耗时以内。对更高质量的整图策略单独记录相对旧分块的耗时。
- **资源和响应。** 记录 CPU 进程组的峰值 RSS 与新增 commit、设备峰值与高水位、临时磁盘和 GUI 事件延迟。实测峰值须落在当时准入上限内，无 OOM、无异常退出及可归因的换页风暴。目标为负载期间 GUI 事件 p95 ≤ 100 ms，取消在 200 ms 内停止投递新单元；另记录等待已在途 native 调用退出的时间。通过资源注入跨越软、硬上限，验证能降并发、映射、切换通过验证的候选或给出明确拒绝。比较 baseline 和候选时同时提交日志和对照图。
