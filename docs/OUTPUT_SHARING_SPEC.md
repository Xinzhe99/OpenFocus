# 输出结果本地分享 SPEC

## 目标和范围

在输出列表的右键菜单中增加“分享”子菜单，支持把当前融合结果作为 JPEG 图片或本地文件交给其他应用，并在文件管理器中找到文件。暂不实现托管、上传、账号或私密链接服务；只显示不可点击的“创建私密分享链接（开发中）”。

本 SPEC 基于 `feat/output-share` 分支的现有实现。结果可能尚未导出：`OutputRecord.image` 可能只存在于会话中，`export_path` 不一定存在或反映当前修改。现有拖拽所创建的临时文件会在下一次拖拽或退出时清理，不能用于需要延迟粘贴的文件路径。输出列表也包含对齐堆栈目录，它不是本功能所要求的单张融合图。

## 菜单与选择

- 在输出列表现有右键菜单中增加“分享”子菜单，依次显示：
  1. 复制预览图片（JPEG）
  2. 复制文件路径
  3. 在文件夹中显示
  4. 创建私密分享链接（开发中）：始终禁用，不执行网络操作。
- 右键已有选中项时保留整个多选；右键未选中项时只选择右键目标。现有删除操作继续处理选中项，“另存为”和修图继续以右键目标为准。右键空白处不能悄悄分享之前的当前行。
- JPEG 预览和“在文件夹中显示”操作右键目标；复制文件路径操作所有选中的有效融合图，单选时仅操作目标。目标不是带图像的输出、选区包含不支持的对齐堆栈/无图像项、或没有目标时，对应功能禁用；不要静默丢弃部分选区。
- 中文、英文和现有全部语言包提供菜单及必要反馈文案。菜单应遵循现有语言切换机制，不硬编码用户可见文案。

## 复制预览图片（JPEG）

- 使用被右键点击的那一条结果的当前图像，而不是列表缩略图或另一个当前结果；包含该结果当前适用的文字、比例尺等现有导出标注，已烘焙标注不得重复绘制。遵循项目现有输出导出的 RAW 显影和像素解析逻辑。
- 生成完整尺寸的 8 位显示预览，并实际编码为 JPEG（可用合理的固定高质量，如 95）；原结果及其位深不变。灰度和 BGR 色序正确；透明像素按已有显示棋盘格合成后再编码（JPEG 不支持透明度）。
- 剪贴板放入真实 `image/jpeg` 字节，另提供可供普通桌面程序粘贴的 Qt 图像数据（例如从 JPEG 解码后的 `QImage` 与 JPEG 字节共同放在 `QMimeData`）；不得只复制文本、文件路径、缩略图或未编码的图像并称为 JPEG。正确管理像素和 MIME 数据生命周期。
- 不创建需要清理的临时 JPEG，不把复制预览记为保存结果。失败时沿用现有错误提示，不改变原图，不报告成功；成功给出简短状态提示。

## 复制文件路径

- 向系统剪贴板放入所有目标对应的本地文件 URL（`QMimeData.setUrls`，`QUrl.fromLocalFile`），以支持资源管理器、聊天软件等将它们当文件粘贴；路径中空格、非 ASCII 字符和 Windows 路径须正确处理。URL 必须指向实际存在的持久文件，不能是拖拽临时文件，也不能仅以普通文本冒充文件。
- 已有导出文件仅在文件存在且能确定对应当前图像与当前标注时复用：检查记录的导出状态、导出图像身份与当前图像、标注是否变化等现有状态。不得因路径存在就复用已过期的结果。按原样分享已保存文件（因此已保存的 JPEG 仍是 JPEG，不应宣传其无损）。
- 对未保存、文件缺失或已修改的目标，请用户选择一个真实保存目录；取消则不改剪贴板。只为需要保存的目标按现有安全命名与不覆盖策略写出 PNG，使用现有输出导出路径以保留 8/16 位、透明度和当前适用标注；对 RAW 结果使用现有显影语义。多个目标都需要保存时只选择一次目录，已有且仍有效的文件不必重写。写入后的文件应持续存在，不因下次拖拽或程序退出而删除。
- 写入成功后按现有机制更新相应记录的导出状态；不能把已经取消或失败的记录标为已保存。如果任何目标保存失败，不要将不完整的集合写到剪贴板；保留已成功写入的用户文件并准确报告失败。不要覆盖已有文件或原始输入。
- 成功后反馈复制的文件数量。PNG 对导出的像素是无损的；RAW 显影结果和已存在的 JPEG 不应被描述为原始 RAW 数据或无损 JPEG。

## 在文件夹中显示

- 针对右键图像，先按同一文件有效性规则取得持久文件；未保存或过期时走相同的选择目录与 PNG 保存流程，取消/失败不打开文件管理器。
- Windows 使用资源管理器打开包含文件的目录并选中文件；实测可用 `ILCreateFromPathW` 和 `SHOpenFolderAndSelectItems` 定位含空格及中文的路径，并释放 PIDL。macOS 使用 Finder 显示并选中；Linux 尽可能使用现有系统文件管理器能力选中文件，无法选择时至少打开其父目录。路径作为系统 API 或进程参数处理，不使用 shell 字符串拼接；打开失败有可见错误提示。

## 边界、验证与交付

- 现有输出列表含单张 fusion、retouch、compare、batch 等图像结果及 aligned 目录；不要因增加菜单破坏原有拖拽、另存为、删除、多选和导出保护。菜单状态由实际目标决定，不依赖名称推断类型。
- 对需要渲染及保存的大图，沿用现有的像素解析、导出和后台处理机制，避免把整批结果同时复制进内存；真实反馈必须反映成功或失败。
- 增加有意义的行为回归覆盖：选区和右键目标；JPEG 字节解码及图像剪贴板；多选文件 URL 和 Unicode；未保存/已过期时选择目录生成 16 位 PNG、当前标注、命名冲突、取消和失败；有效已保存文件复用；对齐目录不可误分享；平台打开文件管理器的参数。覆盖语言包键/占位符一致性。不要写仅复述源码或 mock 原样转发的测试。
- 运行针对性测试，并实际启动 GUI 验证菜单、JPEG 可粘贴图片、多文件 URL 及 Windows 文件夹定位；无法在当前机器实测的其他平台能力应如实标注。更新用户手册中相关说明及 CHANGELOG，不做私密托管链接。
- 完成后提交实现、相关用户文档与变更记录，由独立验收确认通过后创建 PR。
