## 1. 简介

OpenFocus 是一款面向科研人员、工程师和图像处理从业者的专业多焦点图像融合桌面应用。软件通过先进的配准与融合算法处理多焦点图像序列，生成全景深的全清晰图像。

### 核心功能

- **多焦点图像融合**：将多张不同焦点的图像合成为一张全清晰图像
- **十种融合算法**：StackMFF V1/V2/V3（深度学习）、OpenFocus A/B/C、引导滤波、DCT、DTCWT、GFG-FGF，并带"仅对齐"模式
- **图像配准**：OpenFocus 快速配准、ECC、单应性或其组合，校正偏移、旋转、缩放与透视变化
- **自动背景**：用一张真实的帧替换堆栈后杂乱的背景，并显示没有任何帧清晰拍到的位置
- **Wipe 对比视图**：通过 A/B 分割线视图直观检查配准质量、对比不同结果
- **源帧修饰**：从生成结果的源帧取材，提供源帧/还原/曝光画笔、整笔撤销与分层 TIFF 导出
- **工程文件**：保存输入引用与可重建的处理配置（结果图像需单独导出）
- **处理模板**：保存融合、配准与资源设置，并套用到任意已加载的图像栈
- **多页 TIFF**：单文件 Z-Stack 逐页载入，也可整体写回单文件
- **深度图**：逐像素焦点位置图、物理 Z 标定、3D 曲面与 OBJ 导出
- **比例尺**：论文级比例尺，支持元数据自动标定或手动输入
- **批处理**：多文件夹作业、分组融合、仅对齐/融合/保存对齐三种落盘模式
- **崩溃自动恢复**：崩溃后下次启动可一键恢复上次工作现场
- **多语言**：共十二种界面语言——English、中文、日本語、Español、Deutsch、Français、Русский、한국어、Português、Italiano、Nederlands、Polski，自动检测系统语言
- **无头命令行**：支持脚本化调用、配方复用、修饰重放与 CI 集成
- **Agent 可驱动**：受令牌保护的本地通道可操作实时 GUI（命令、控件路径或真实鼠标键盘事件）
- **灵活导出**：结果可保存为单张图像、文件夹、多页 TIFF 或 GIF 动画
- **图像变换**：旋转、翻转、调整大小整个图像栈
- **标签标注**：为源栈、配准栈或指定输出添加可管理、可生成帧号的文字标签
- **设置持久化**：偏好设置、界面语言、最近打开的图像栈在重启后自动恢复

### 支持的输入格式

- 图像文件：JPG/JPEG、PNG、BMP、TIFF、WebP 及其他常见格式
- 视频文件：MP4、AVI、MOV、MKV、WMV、FLV、WEBM（自动解码为图像序列）
- 包含按序号命名的图像序列的文件夹
- 相机 RAW 文件（DNG、CR2/CR3、NEF、ARW、RAF、ORF、RW2、RWL、FFF、MEF、DCR 等）：
  解码使用 `rawpy`（LibRaw）：`pip install openfocus` 会一并安装，Windows
  与 macOS 安装包也已内置。
  支持的相机型号和压缩方式取决于所用 LibRaw 版本。RAW 会先以原尺寸解码为 16 位
  图像，再按所选加载比例缩小；缩小比例可减少后续处理的内存，但不能消除解码时的
  原尺寸内存峰值。分组融合暂不支持 RAW。

透明 PNG 图像栈可在桌面、批处理和命令行中融合，但不支持分组融合。各帧必须是
尺寸、位深和透明蒙版相同的 8 位或 16 位 PNG：一个非空矩形内为相同的非零透明度，
矩形外透明；矩形内允许统一的半透明。程序只融合可见矩形，输出 PNG 保持原画布和
透明度，隐藏区域的颜色为零。桌面视图以棋盘格显示透明区域。

请以原尺寸载入，关闭配准、快速预览和 ROI，选择融合算法后保存为 PNG。批处理同样
要求 PNG 输出，不能保存配准栈。改变矩形尺寸的融合方法会被拒绝。透明图不支持缩放、
白场校正、深度图、比较、修饰、标签或比例尺；渐变透明、不同蒙版、透明 TIFF、GIF 和
多页 TIFF 导出均不支持。CLI 也会拒绝透明输入的传感器清理与深度图。

命令行示例：`python main.py --input ./png-stack --output ./result.png --method guided_filter --align none`。

### 支持的输出格式

在**另存为**中，普通 TIFF 将结果保存为单张图像；分层 TIFF 将源帧作为图层一并保存。Linear DNG 始终显示，但保存时需要通过**打开原生 RAW**得到、具有相机校准信息且未烘焙调整的相机线性结果。

- 单张图像：JPG、PNG、BMP、TIFF、WebP
- 图像序列：以文件夹形式保存
- 动画：GIF 格式

## 2. 快速开始

### 启动应用

安装完成后，通过以下方式启动 OpenFocus：

1. **Windows（可执行包）**：双击 OpenFocus 快捷方式或可执行文件
2. **macOS**：把 DMG 中的 `OpenFocus.app` 拖入"应用程序"后双击；未公证版本若被拦截，请先在 **系统设置 → 隐私与安全性** 中点 **仍要打开**，或执行 `xattr -cr /Applications/OpenFocus.app`；用 `install.sh` 安装到 `~/Applications` 的，执行 `xattr -cr ~/Applications/OpenFocus.app`（macOS 15 起右键"打开"不再绕过 Gatekeeper）
3. **Linux**：不提供桌面构建，请安装 pip 包并使用 `openfocus` 命令行
4. **Python 源码**：在激活的 conda 环境中执行 `python main.py`

建议从 [OpenFocus 官网](https://openfocus.top/#download) 下载最新版本；同样的文件和旧版本也在
[GitHub Releases](https://github.com/Xinzhe99/OpenFocus/releases) 提供。也可以从终端安装：

```bash
# macOS（Apple Silicon，安装到 ~/Applications）或 Linux（无界面 CLI）
curl -fsSL https://openfocus.top/install.sh | sh -s -- --dry-run
curl -fsSL https://openfocus.top/install.sh | sh
```

```powershell
# Windows PowerShell
irm https://openfocus.top/install.ps1 | iex
```

首次启动会显示浅色主题的主界面（可在欢迎对话框中选择主题）。首次启动可能需要 30–60 秒加载，请耐心等待。

### 快速上手流程

1. 导入图像序列（文件 → 打开文件夹，或直接拖拽）
2. 在右侧面板配置融合参数
3. 在"配准"下拉框中选择**一种**方式（默认为 ECC）
4. 需要时调整核大小
5. （可选）打开 **渲染设置**，勾选 **快速预览**，先用缩小的草稿试参数
6. 点击"开始渲染"开始处理
7. 导出结果

## 3. 主界面概览

OpenFocus 界面分为三个主要区域：

### 左侧面板：图像显示区

窗口左侧以分屏方式显示图像：

- **源图像面板**：显示输入图像序列
- **结果图像面板**：显示融合或配准结果
- **导航滑块**：拖动每个面板下方的滑块浏览帧
- **图像信息标签**：显示当前帧位置和图像尺寸

拖动面板之间的分割条可以调整面板大小。

### 右侧面板：控制面板

右侧面板自上而下排列所有配置项：

1. **融合设置**：选择融合算法和核大小
2. **配准设置**：从下拉框选择一种对齐方式（或不对齐）
3. **操作按钮**：开始渲染，以及恢复默认、**渲染设置**和渲染所有方法；渲染设置对话框包含快速预览、帧顺序、曝光匹配、亮度漂移消除和输出锐化
4. **源图像列表**：显示已加载的所有帧
5. **输出列表**：显示已生成的结果

### 菜单栏

顶部菜单栏提供全部功能入口：

- **文件**：导入/导出、工程文件、处理模板、保存堆栈、最近打开列表
- **编辑**：图像变换、修饰结果、修饰图像文件、撤销/重做、初始化当前堆栈
- **工具**：图像拼接、批处理、批量图像转换、方法对比、深度图、尘点图（平场校正）、比例尺、标签
- **设置**：高级设置（性能、配准及配准诊断、传感器清理、输出命名、AI、启动）、GPU 加速、主题、语言
- **帮助**：用户手册、环境信息、反馈、检查更新、打开日志文件夹

图像拼接是实验性功能，开发尚未完成。导出前请检查位置与接缝。

**工具 → 图像拼接…** 打开独立工作区，用于拼接已经融合好的显微区域图。添加图像
文件或选择已有输出结果，点击**自动对齐**后检查各重叠区；也可以拖动图像或输入
X/Y 像素坐标手动调整。透明度滑块只改变预览。缺少可靠共同特征的图像会标记为
未匹配，可根据载物台位置换算出的像素坐标手动摆放；无重叠且无特征的图像无法仅靠
图像内容推断相对位置。自动匹配估计平面旋转、缩放和平移，重复纹理或样本移动时
应特别检查接缝。

也可将图像文件或文件夹拖入列表、画面。文件夹只导入直接包含的受支持文件，不扫描
子文件夹；按自然文件名排序并去重。选中列表或画面中的图像，按 Delete / Backspace
可移除该项，不删除磁盘文件。

已知载物台网格时，可设置行列数、按行/按列拍摄、单向/蛇形、起始角和预计重叠率，
再点击**应用网格位置**。网格数必须等于图像数；仅修改参数不会改动手动位置，点击
应用后才会替换。应用后仍需检查重叠区，并可继续调整 X/Y。预览透明度在追加、移除和
布局变化后保留，不影响实际导出。该工作区继续保持实验性。

输出支持 TIFF 和 PNG。TIFF 使用磁盘后备画布、分块合成及逐条写入，较大结果自动
使用 BigTIFF；请预留足够的临时和输出磁盘空间。PNG 编码需要额外内存。8 位输入
保持 8 位；含 16 位输入或混合位深时输出 16 位。预览透明度不会写入结果。拼接图
不会自动推断物理比例，也不会继承单张输入图的 EXIF/ICC 元数据。

**编辑 → 初始化当前堆栈…** 将图像、顺序和缩放恢复到导入时的状态，包括后来
删除或排除的帧。所有输出（包括未保存的内容）、各目标的标签和比例尺、ROI 与配准
状态以及撤销/重做历史都会被清除。确认对话框默认选择取消；磁盘上的文件不会被删除。
请等待正在进行的操作结束后再初始化；空堆栈无法初始化。
重新打开工程后，初始化以工程保存的帧和加载比例为准。保存工程前已删除的帧不在
工程中，无法通过初始化找回。

## 4. 导入图像与视频

### 打开图像文件夹

1. 点击 **文件 → 打开文件夹** 或按 `Ctrl+O`
2. 选择包含图像序列的文件夹；也可以在地址栏输入或粘贴路径，按回车进入后再选择
3. 弹出加载比例对话框——选择缩放比例（100% = 原始分辨率）
4. 点击确定加载图像

加载时状态栏显示已处理文件数；单张 RAW 解码期间数字可能暂时不变。取消请求会在
当前文件的解码完成后生效。

在该对话框勾选 **不再询问** 后，以后每次导入都直接按所选比例加载；
**设置 → 高级设置 → 启动与更新 → 导入时询问加载缩放比例** 可重新打开提示。已加载的栈之后仍可
通过 **编辑 → 调整大小** 缩小。

软件会自动：
- 按文件名检测并排序图像文件
- 在源图像面板显示第一帧
- 将所有帧填入源图像列表

### 打开视频文件

1. 点击 **文件 → 打开视频** 或按 `Ctrl+Shift+O`
2. 选择视频文件（支持 MP4、AVI、MOV、MKV、WMV、FLV、WEBM）
3. 视频会自动解码为逐帧图像
4. 每一帧成为图像栈的一部分

### 工程文件

文件 → 保存工程 将输入引用与可重建的配置存为 `.ofproj`：精确帧顺序
（含 TIFF 页与重复帧）、排除帧、旋转/翻转、加载倍率、各算法参数、标签、
比例尺完整样式及当前帧。工程**不保存**融合或修饰结果的像素，须单独导出；
无法由源文件重建的处理须先保存为新的输入栈。

打开工程会先确认所有记录帧均可解码，再替换当前工作栈。源文件移动后，
可选择新的源目录，并核对完整的新旧路径映射；重新保存工程才能保留新引用。
标题中的 `*` 表示配置尚未保存，保存工程不会解除结果图像的未导出保护。

### 处理模板

处理模板只携带设置，从不包含源路径。**文件 → 保存处理模板…** 写出 `.oftemplate`，
内容包括当前融合方法与参数、配准方法与参数、按算法记忆的亮度选项、线程数、瓦片设置、
配准下采样宽度、StackMFF AI 批量大小、锐化、反序和传感器降噪开关。坏点蒙版路径
有意不保存。

**文件 → 应用处理模板…** 把这类设置应用到已经加载的图像栈，不会替换当前源图。
选择器也接受 `.ofproj` 工程（只提取设置，不要求其源文件）和包含工程设置的配方
`.json`。应用模板会把工程标记为已修改，并可能改变算法参数和资源设置，渲染前请
检查右侧面板。配方仍是无头格式，会保存坏点蒙版路径和指纹。

### 示例图像栈

欢迎对话框提供 **加载示例图像栈**：内置六张真实焦点堆叠拍摄的示例照片，
无需自己的素材即可立即体验完整工作流，也可用于验证安装是否正常。

### 清晰度曲线

源图像导航滑块上方有一条每帧清晰度（归一化）曲线。离焦帧显示为带红点的
低谷。点击曲线任意位置跳转到对应帧；悬停显示帧号。

### 多页 TIFF 图像栈

显微软件（ZEN、NIS-Elements、ImageJ/Fiji）常把整个 Z-Stack 导出为
**单个多页 TIFF**。OpenFocus 会把这类文件的每一页展开为图像栈的一帧——
打开或拖入即可得到完整堆栈（帧命名为 `<文件名>_page_001` 依此类推）。
单页 TIFF 行为不变。反向同样支持：**文件 → 保存堆栈 →（已配准/输入）→
保存为多页 TIFF** 可把整个栈写回单个 `.tif`，保留 16-bit 位深。

### 比例尺（论文配图）

工具 → 比例尺… 配置导出图像上烙入的比例尺。标定方式在对话框中显式选择：
**使用图像元数据**（ImageJ 的 `unit=micron` 约定、OME-TIFF 的
`PhysicalSizeX`、或显式以厘米为单位的标签；原生 Linear DNG 与 TIFF 使用同一套
规则，显微图像栈含多页 TIFF 自动完成）或**手动标定**。DNG 导出会把结果像素的
标定写回文件，重新导入该 Linear DNG 时保持相同的物理比例。手动值以**原始像素**
为单位，优先于元数据（配图里一个看着
合理的错误比例尺比没有更糟），并按当前加载/缩放比例换算成工作像素：
0.5 µm/原始像素在 50% 加载下即 1 µm/工作像素。打印分辨率（72/300 dpi 之类）
不会被当成标定。对话框显示原始值、加载比例与实际绘制值，可选择角落或自定义
百分比位置、颜色（自动与背景反色）、字体、字号、粗体与文字对齐，并带实时预览。
取消对话框不会改变已提交的标定。启用后所有导出（单张、文件夹栈、多页 TIFF、GIF、
批处理）都会烙上论文级比例尺：1-2-5 圆整长度（约占图宽
12%）、带描边的清晰文字。图形长度与文字标注始终描述同一距离；图像过小时
明确提示无法放置，而不是画一条与文字不符的短条。CLI 通过 `--scale-bar`
（自动标定）和 `--scale-um <µm/px>` 支持。

所选目标没有可用元数据时，窗口默认选择手动标定，并等待输入有效像素尺寸。

再次移除请用 **工具 → 比例尺 → 删除比例尺**：*从源图像栈* / *从结果*
会把对话框中的"应用到"收窄到仍保留的一侧，*全部删除* 则直接关闭比例尺。
两个画布与 A/B 滑动对比立即重绘；对本来就没有比例尺的一侧执行删除不会
改变现有设置。

预览先在目标图像的原生像素上绘制，再适应窗口；适应、100%、平移与切帧只
改变查看方式。应用作为一步可撤销操作提交，取消保留原标定。历史输出保存
各自的标定与样式，载入其他源栈后不会套用新栈的比例尺。

### 深度图（焦点位置）

工具 → 深度图… 使用所选方法的活动度估计焦点位置；它不是实测表面，也不等同于
融合图每个像素的精确来源。可选择当前勾选帧或所选输出的记录来源；旧输出没有
来源记录时，不会猜用当前图像栈。计算、纹理与导出始终绑定同一份来源快照。

支持深度图的七种方法（DCT、DTCWT、GFG-FGF、OpenFocus B/C、StackMFF V2/V3）都必须点击**计算**。
StackMFF V1 没有深度图；透明 PNG 图像栈在 GUI 和 CLI 中也不能生成深度图。
打开窗口、切换度量/来源/配准或修改参数均不会启动计算。参数编辑区紧接度量选择器：
DCT 中值核和 GFG 初始核为 1–51 的奇数（默认 7）；B 使用焦点响应半径和深度平滑，
C 使用**混合平滑**来平滑深度图，没有半径参数。DTCWT 分解层数可在此作为局部草稿编辑，初始值来自来源参数。
StackMFF V3 显示自己的 AI 输出方式（默认软融合，可选硬融合）及
焦点位置说明，不提供数值核；软融合按概率加权估计连续帧位置，硬融合逐像素采用最
可能的源帧，两者都不是物理距离。
草稿初始值来自匹配输出的参数或主窗口已记忆的方法参数；本次打开期间按来源和方法
分别保留，不回写主窗口、工程或输出记录，关闭后不应用。

修改计算设置后，旧二维图持续标记为**非当前结果**，3D 曲面清空；伪彩、索引、物理深度
和 OBJ 等全部导出均被禁用，直到重新计算成功。运行中的任务会合作取消，结束后须再次
点击**计算**，不会排队或自动续算。计算按钮始终可见，计算、取消及导出期间禁用。

- **伪彩色**：灰度（论文标准）及 15 种科研配色（Turbo、Viridis、Magma 等），也可
  新建自定义配色，从任意数量的色标构建渐变（双击色标编辑位置和颜色）；自定义方案会
  保存并出现在下拉框中。
- **反转 / 伽马 / 平滑**：调整深度轴方向、显示明暗与保边平滑。
- **叠加**：仅在关联输出具有相同坐标范围时可用。
- **索引 TIFF 与替代图像 TIFF**：索引导出把当前深度估计写成无符号 16 位帧号；
  1–N 指深度计算实际使用的帧顺序（已配准、已重排），0 表示无效像素，最多支持
  65535 帧，分数位置按最近帧取整（正好一半向上）。替代图像在每个有效位置从对应
  深度输入帧取像素，无效区域置零；任一输入为 16 位时，8 位值乘以 257 提升到 16 位。
  两者都使用深度图的 ROI。索引是估计的焦点位置，不等同于融合结果的真实像素来源。
- **原始导出**：16 位 TIFF 把归一化指数编码到 0–65535，不是无损浮点数据，也不是
  物理距离；JPEG/BMP 会被拒绝。
- **物理深度**：填写 Z 起点、正步长、单位与采集方向，确认原始采集序号。
  排除帧仍保留其位置间距。浮点 TIFF 保存微米值、缺失区域的 NaN 与来源元数据；
  物理 OBJ 还需要 XY 标定，使用 1:1 的物理 Z 比例。在当前图像栈与所选输出之间切换，
  即使帧名称和索引相同，也会清除已确认的采集序号；必须重新确认后才能导出。
- **3D 模型 / 3D 纹理**：网格长边默认 600 顶点。每次打开默认**自动（真实色）**：
  仅使用身份及坐标域/ROI 与已完成深度图匹配的关联输出，否则使用本次成功计算中
  已配准、按实际顺序排列的第一张参与帧；界面显示实际采用的输出或帧名称。
  也可明确选择匹配输出、指定参与帧或**深度伪彩**。没有匹配图像时明确提示，
  不使用其它历史输出替代。3D 预览和 OBJ 的 PNG 共用同一纹理来源。
  二维图保留自己的色图与叠加设置；改变色图或 Gamma 不会重染真实色照片，
  显式伪彩纹理才响应色图、Gamma 和反转。静止预览和导出共用同一采样高度场，
  没有额外隐藏平滑。
- **模型导出**：OBJ、MTL、PNG 纹理和 JSON 元数据作为四文件组保存，请一起保留。
  后台准备、取消与失败回滚共同保护已有文件；导出模型不会解除父图像的未导出保护。

计算在后台进行，带进度与取消；AI 方法复用与 AI 融合相同的内存安全
分块，深栈可用。CLI 对应 `--depth-map [路径]` 与 `--depth-colormap`；它只写
伪彩图（默认 `<输出名>_depth.png`），仅适用于上述支持深度图的方法，并拒绝透明或
分组输入。GUI 还可导出原始深度、帧索引、替代图像、物理深度和 3D 模型。

### 崩溃自动恢复

OpenFocus 会持续保存工作会话快照（图像栈、设置、标签、当前帧）。若应用
异常退出——崩溃、断电或被强制结束——下次启动会检测到并提示**恢复会话**，
一键回到上次的工作现场。正常退出不会出现提示。恢复数据与设置存放在同一
位置（便携版保存在程序旁，随 U 盘携带）。

### 最近打开

每次打开的图像栈都会记录在 **文件 → 最近打开** 中（最多 8 条，在子菜单中依次编号；没有全局快捷键）。点击条目即可重新打开；重复打开同一栈会自动置顶；文件已不存在的条目会提示移除；**清空最近列表**可清空菜单。

### 拖拽导入

将文件夹直接拖到应用窗口即可导入。将更多文件拖到已加载的栈上可以追加图像（会先做尺寸校验）。

### EXIF 方向

带 EXIF Orientation 标签的相机 JPEG/TIFF 文件在导入时会自动旋转/翻转纠正，竖拍素材正常直立显示。

### 16-bit 素材

16-bit PNG/TIFF 输入会被自动识别并全流程保留位深：融合以完整深度运行，结果可以保存回 16-bit PNG/TIFF（JPG/BMP 导出会转为 8-bit，这两种格式无法存储 16 位）。

相机 RAW 文件会以 16 位解码（采用相机白平衡、sRGB 色域与传递曲线），并关闭自动提亮，使栈中每一帧使用相同的曝光映射；逐帧自动曝光会导致帧间亮度闪烁。保存为 TIFF 或 PNG 即可保留 16 位数据。

如需相机线性工作流，请选择 **文件 → 打开原生 RAW 图像栈…** 并选择原始相机 RAW 帧。
也可选择 DNG 文件，包括扩展名为 `.tif` 或 `.tiff` 的 DNG；普通 TIFF 图像不属于相机 RAW。
具体相机能否解码取决于安装的 LibRaw。所有帧必须具有相同的相机校准和白平衡；
不支持或不兼容的文件会被拒绝。导入前无需将厂商 RAW 转换为 DNG。

照常配准并融合图像栈，选择结果后通过 **另存为 → 线性 DNG** 保存，即可在兼容的 RAW
编辑器中继续调整色彩和白平衡。融合后的线性 DNG 包含经过解马赛克的相机线性 RGB 像素，
并非原始传感器马赛克数据。OpenFocus 在配准、融合和修饰过程中保留 16 位相机线性像素，
同时显示冲洗后的预览。若要以 16 位保存冲洗后的外观，请在另存为中选择普通 **TIFF**；
PNG 等普通导出也使用冲洗后的外观。相机配置文件允许时，DNG 的标注会写入导出像素。
如果标注颜色超出相机色域，DNG 导出会失败；请更换颜色，或导出冲洗后的 TIFF、PNG。
普通 RAW 导入仍生成冲洗后的 sRGB。即使降低加载比例，RAW 解码仍需要原始分辨率的工作内存。
对于具有复杂相机配置文件的 DNG 输入，保存的线性 DNG 会保留受支持的色彩配置文件元数据，供支持 DNG
的编辑器使用。OpenFocus 的预览和冲洗后的 TIFF/PNG 使用简化的 D65 矩阵，不应用 DNG
配置文件变换或基准曝光，因此其外观可能与该编辑器不同。
对于复杂配置文件，标注和比例尺无法烘焙到线性 DNG 中，因为它们在 RAW 编辑器中的颜色可能不正确。
请移除它们后保存 DNG，或导出带标注的 TIFF/PNG。

如果无法识别相机型号，只能单独打开一张 RAW；其 DNG 使用通用相机标识，
不会保留厂商型号或专有配置文件。

### 色彩配置文件

当所有源帧嵌入相同的 RGB ICC 配置时，单张 PNG、TIFF、JPEG 和 WebP 导出会保留
该配置；配置不同或有未标记帧时，输出不附加 ICC 配置。OpenFocus 只保留配置，
不会将源像素转换到统一色彩空间，也不对预览进行色彩管理。请在载入前将混合
配置的图像转换到相同色彩空间。RAW 输入会解码为 sRGB，使用生成的 sRGB 配置而非相机 ICC 配置。

多页 TIFF 的所有页必须具有相同的有效 RGB 配置，否则整组帧按未标记处理；视频帧
同样视为未标记。追加的帧和某次渲染实际选中的帧都会参与该结果的配置判断，配置
随结果保留，供后续导出使用。

### 清空图像栈

点击 **文件 → 清空图像栈** 或按 `Ctrl+W` 移除所有已加载的图像。

## 6. Wipe 对比视图

Wipe 视图将两张图像叠加在同一画面中，中间有一条可拖动的垂直分割线，让配准偏差和质量差异跨越分割线时一目了然。

### 进入 Wipe 视图

1. 先渲染出至少一个结果（融合或配准）
2. 点击结果面板标题栏右上角的 **对比** 开关
3. 结果区域切换为对比视图；再次点击 **对比** 返回普通视图

### 界面说明

- **A 侧（分割线左侧）**：源帧——默认跟随源面板滑块
- **B 侧（分割线右侧）**：最近一次渲染结果
- **白色分割线 + 圆形手柄**：水平拖动即可移动分割位置
- 让穿过分隔线的边缘在两侧错位，可以直观暴露并排面板难以察觉的配准偏差

### 选择对比内容

对比视图底部的工具条每侧一组控件：

- **A 侧** — 勾选 **跟随源图**（默认）实时跟随源面板滑块；取消勾选后滑块解锁，可锁定任意帧
- **B 侧** — 勾选 **最新结果**（默认）始终显示最新渲染；取消勾选后拖动滑块浏览输出历史

两侧实时更新：新渲染、源滑块移动、帧删除都会立即反映到对比视图中。

历史输出使用各自的来源帧；当前源图与输出不匹配时，不能跟随当前源图。

如果所选输出没有可用的来源图像，Wipe 会提示来源不可用。配准裁剪的位置未知时，
源图与配准图分别保持宽高比适配显示，并提示裁剪位置未知。

### 缩放与平移

对比视图的两张图共享同一变换：

- **缩放**：鼠标滚轮（围绕光标位置缩放）
- **平移**：在分割线以外区域按住拖动
- **复位**：双击

Wipe 模式与 ROI 模式共用结果面板，进入其一自动退出另一个；清空图像栈也会退出 Wipe 模式。

## 7. 图像配准

图像配准用于校正图像栈中帧与帧之间的空间偏移。当图像存在轻微位移或透视变化时，配准是必不可少的步骤。

### 配准方法

#### ECC（增强相关系数）

- 基于优化寻找相关性最大的对齐方式
- 适合细微偏移
- 提供亚像素级精度
- 比单应性慢但更精确

#### 单应性（Homography）

- 基于特征点匹配（SIFT/ORB 特征）
- 处理更大的几何变换
- 初始对齐比 ECC 快
- 适合透视变化明显的图像

#### OpenFocus（快速）

- 有界相似变换对齐（平移 + 旋转 + 缩放），附带逐帧亮度均衡与自动裁边
- 使用采样图像差异搜索有界相似变换，并以 Lanczos 插值进行图像变换
- 位移超过**帧尺寸 8%** 的帧会放弃对齐，而不是被强行半校正。可用 CLI
  `--align-shift-limit` 覆盖
- 非刚性或极端几何请改选 ECC 或单应性
- 可选择**遇到被拒绝帧时停止**：当检测质量低于 0.06，或估计运动超过位移限制（默认
  帧尺寸的 8%）、旋转 8°、缩放 5% 时，在产生结果前让本次渲染或批处理任务失败；
  默认仍继续使用未对齐帧。帧号按处理栈顺序从 1 开始。几何参考帧默认为第 1 帧；
  直接匹配较弱时会尝试与更靠近参考帧的相邻帧重试。该策略只能发现被拒绝的估计，
  不能保证所有匹配都正确——低纹理、重复图案、遮挡、大位移或对焦变化仍可能让配准
  失败，请检查结果。
- CLI 用 `--align openfocus --align-param 'failure_policy="fail"'` 选择同一策略
  （按 shell 规则加引号），默认是 `"continue"`。批处理中的每个条目独立使用该策略。
- **参考帧**：按实际参与处理、从 1 开始的顺序填写，用来锚定几何；帧顺序保持不变，
  亮度均衡使用自己的参考。批处理中的每个栈都必须包含该帧号，否则该项失败。CLI 示例：
  `--align openfocus --align-param reference_frame=3`。参考帧不能修正视差或错误匹配。

#### Homography → ECC

先用单应性做粗对齐，再用 ECC 精修。它是最慢、但对困难几何最宽容的组合方式，仍然是
下拉框中的一个选项，不是同时启用两种模式。

配准报告会标明参考帧和每帧的结果。回退表示该方法无法建立对齐，或依赖了先前失败的
估计；已知时会区分弱估计与超出限制的运动。质量值只在该方法内有意义，不代表绝对精度。
变换把源坐标映射到配准阶段的参考画布，再进行统一裁边；组合方法会分别报告各阶段。
Homography 与 ECC 也接受 `failure_policy="fail"` 参数，默认仍为 `"continue"`。

要检查某次渲染，请先在 **设置 → 高级设置 → 配准** 中启用 **收集配准诊断**，然后重新
渲染；这会重新计算对齐，而不复用缓存。完成状态会标出回退帧，之后从 **设置 → 高级设置 → 配准 → 配准诊断**
打开逐帧报告，其中包含失败原因、方法相关分数、匹配数、参考帧与变换。参考编号和名称
按原始源列表计算，包括被排除的帧。批处理和分组渲染不提供该报告。

### 启用配准

1. 在右侧面板找到 **配准** 组
2. 从下拉框选择一种方法：**不对齐**、**Homography**、**ECC**、**OpenFocus（快速）** 或组合的 **Homography → ECC**（默认 ECC）
3. 按需要调整位移限制和参考帧；在 **设置 → 高级设置 → 配准** 中选择被拒绝帧的处理方式，修改后应用于各方法
4. **收集配准诊断** 位于高级设置中（见上），渲染前启用才能得到逐帧报告

### 何时需要配准

- 图像存在可见偏移
- 手持拍摄
- 场景存在视差（近景物体在帧间移动）
- 结果出现重影或拖尾

### 配准设置

通过 **设置 → 高级设置 → 配准** 访问：

- **下采样宽度**：控制特征提取的预处理分辨率（默认 1024px）
- 数值越低处理越快，精度可能下降
- 数值越高处理越慢，精度可能提升
- **收集配准诊断** 与 **配准缓存** 也位于同一区域

## 8. 图像融合方法

OpenFocus 提供十种融合算法（外加"仅对齐"的配准模式），各自适用于不同类型的图像。
全新配置默认使用 **StackMFF V3** 与 **ECC** 配准；下面逐一说明所有选项。

下拉框以**仅对齐**开头，默认选中 **AI（StackMFF V3）**，其后依次是 StackMFF V2、StackMFF V1、OpenFocus A、OpenFocus B、引导滤波、GFG-FGF、OpenFocus C、DCT、DTCWT。

### 引导滤波

- **算法**：使用引导滤波进行边缘保持融合
- **适用**：通用场景，速度与质量均衡
- **优点**：边缘保持好，处理快
- **参数**：核大小（1–51，仅奇数）
  - 小核：局部细节多，可能有噪声
  - 大核：结果更平滑，抑噪更好

### DCT（离散余弦变换）

- **算法**：基于 DCT 系数的频域融合
- **适用**：纹理丰富的图像、科学成像
- **优点**：保留精细纹理，数学原理可靠
- **参数**：核大小控制处理窗口

### DTCWT（双树复小波变换）

- **算法**：多尺度小波域融合
- **适用**：具有多层次细节的复杂场景
- **优点**：出色的多尺度分析能力，方向性好
- **融合规则**：每个像素、每一层只做一次 N 路决策（6 个方向 + 3 个颜色通道共用，3×3 多数一致性校验）；低频带跟随最粗层决策，而非对所有帧取平均
- **参数**：右侧面板的小波分解层数（1–6，默认 4）。本方法没有空间核，核大小滑块会隐藏。

### GFG-FGF（类高斯四邻域梯度 + 快速引导滤波）

- **算法**：实现付宏语等（《激光与光电子学进展》2024）的方法：均值差分粗略聚焦图 |I − mean(I)| 叠加类高斯四邻域梯度（GFG）算子提取的高频信息，经快速引导滤波优化后逐像素决策（并列时用 3×3 Sobel 小区域聚焦度量），二值决策图再经快速引导滤波平滑后加权融合
- **适用**：显微图像及焦点区域清晰的图像
- **优点**：速度快，焦点边界清晰；内存不随帧数增长
- **参数**：核大小 = 粗略聚焦图的均值滤波窗口

### StackMFF（V1，深度学习）

- **算法**：单尺度注意力网络使用 softmax 权重混合源帧亮度；Cb/Cr 取自亮度最接近融合亮度的源帧
- **适用**：需要对完整焦点栈进行神经网络融合的场景
- **优势**：无需参数、颜色保持在色域内；融合亮度不随帧序变化，但亮度距离并列时色度可能不同
- **注意**：约 156,172 个参数；较大图像栈建议使用 GPU

### StackMFF V2（深度学习）

- **算法**：单尺度注意力网络归一化期望对焦深度，并采样最近的源帧。深度索引取决于图像栈顺序。
  **必须保持原始对焦顺序**——该方法已禁用反序
- **深度图**：支持；给出取样的对焦层
- **适用**：连续对焦扫描，且需要极小、快速模型的场景
- **要求**：ONNX Runtime 和随附的 ONNX 模型。

### StackMFF V3（深度学习）

- **算法**：逐像素来源分类(ONNX Runtime)。网络为每个像素预测它最可能
  来自输入栈中的哪一帧，再按概率混合，或直接取该帧
- **AI 输出方式**（右侧面板，仅选中本方法时出现）：
  - **软融合（概率加权）**——默认；每个像素由各帧按概率加权混合，过渡
    平滑、无硬接缝，对应论文报告的配置
  - **硬融合（单帧选取）**——每个像素选取一个来源，避免不同帧的颜色混合；
    分块重叠处选择距瓦片内部更近的结果。它可能减少细毛边缘的混色，也可能出现
    锯齿或瓦片接缝，并不保证前后遮挡正确；可在 ROI 对比并用修饰工具局部修复
- **适用**：需要逐像素选择或混合焦点帧的场景
- **优点**：与帧序无关（打乱顺序结果不变）、支持资源允许范围内的栈长、无需逐方法调参
- **要求**：ONNX Runtime 和随附的 ONNX 模型。

处理大栈时，临时目录需要容纳源帧以及可能同时存在的对齐或校正帧。可在
**设置 → 高级设置 → 性能 → 临时目录**选择空间充足的现有文件夹；留空使用系统默认。
更改立即作用于新建的临时数据，已载入的帧仍留在原目录，直到释放。OpenFocus 会在
创建映射前检查可用空间，并在可读取图像头时估计整栈需求；这不是空间预留，其他
程序仍可能随后占用磁盘。

每个神经网络图块都使用全部帧。源帧和配准临时数据可以存放在磁盘上，但空闲磁盘空间和可用内存仍会限制栈大小。V2 空间分块是整图推理的近似。


### OpenFocus A / B / C

- **OpenFocus A**：先平滑多尺度焦点响应图，再选择清晰像素。
- **OpenFocus B**：由平滑深度图引导混合相邻帧。
- **OpenFocus C**：由平滑深度图引导重建多尺度频带。
- **参数**：A、B 的 kernel 滑块控制焦点响应尺度，C 没有半径参数；三者的平滑参数控制过渡强度。

**平滑**：kernel 滑块下方的一个数值框（范围 0–8，步长 0.2），含义随所选算法变化：

| 算法 | 标签 | 默认 | 作用 |
|---|---|---|---|
| OpenFocus A | 混合平滑 | 2.0 | 控制选择像素前对焦点响应图的平滑强度 |
| OpenFocus B | 深度过渡平滑 | 1.2 | 控制引导混合的深度图平滑强度 |
| OpenFocus C | 混合平滑 | 3.0 | 控制引导多尺度重建的深度图平滑强度 |

值越大，过渡平滑越强。每个算法各自记住自己的值，批处理使用同一规则。

C 没有半径参数，因此选中 C 时会隐藏 kernel 滑块。

命令行参数：`--depth-smoothing VALUE`（B）、`--blend-smoothing VALUE`（A、C）。

**亮度选项按算法独立记忆。**「融合前匹配曝光」与「消除亮度漂移」对每个融合
算法分别记住，因为它们回答的是"这一栈怎么处理"，而不是全局偏好。OpenFocus
A/B/C 两者都默认开启（它们没有内置曝光标定）；其余算法沿用历史默认（曝光
匹配开、漂移校正关）。切换算法时复选框会显示该算法自己的值，这些值在重启后
仍然保留。按**重置**会清除所有算法记住的亮度、平滑与半径值。

**锐化融合结果**默认关闭，可在主界面或批处理选项启用；融合后进行轻度锐化，
不会锐化已配准源帧。它可能放大噪点和光晕，请检查结果。CLI 使用
`--sharpen-output`，工程会保存该设置。

### 仅对齐（不融合）

融合下拉选择**仅对齐（不融合）**时，只运行配准，并在结果列表中添加一个图像栈条目。
导出前帧保留在内存中，不额外生成配准缓存，也不在源文件旁写入副本。
保存时选择目标目录和编码格式，每个栈在目标目录下生成一个文件夹；保留原文件名主体，
扩展名使用明确选择的格式。

### 选择融合方法

1. 在右侧面板找到 **融合** 组
2. 在**下拉框**中选择融合算法（始终恰好选中一项；首项为仅对齐，默认选中 AI）
3. 按需调整核大小——标签会显示该参数在当前算法下的含义
4. 点击 **渲染** 开始处理

### 算法对比指南

| 算法 | 速度 | 质量 | 适用场景 |
|------|------|------|----------|
| 引导滤波 | 快 | 好 | 通用 |
| DCT | 中 | 好 | 纹理 |
| DTCWT | 中 | 很好 | 复杂场景 |
| GFG-FGF | 快 | 好 | 焦点区域 |
| StackMFF（V1） | 慢（GPU） | 此处未做基准测试 | 融合亮度不随帧序变化；亮度距离并列时色度可能不同 |
| StackMFF V2 | 快（GPU） | 此处未做基准测试 | 使用极小模型的连续扫描 |
| AI 融合（StackMFF V3） | 慢（GPU） | 极好 | 最高质量 |
| OpenFocus A | 取决于图像栈 | 取决于图像栈 | 多尺度清晰像素选择 |
| OpenFocus B | 取决于图像栈 | 取决于图像栈 | 深度引导的相邻帧混合 |
| OpenFocus C | 取决于图像栈 | 取决于图像栈 | 深度引导的多尺度重建 |

打开 **工具 → 方法对比**，可分别调整多个方法的参数。窗口变窄时，每个方法的
名称、参数标签和输入框作为整体换行。修改后自动更新预览。
**ROI 局部预览（快速）**融合选区及周边区域；**整图融合对照**计算整幅图像，
随后移动检查区域可直接查看已有结果，无须重新融合。由于曝光统计和部分算法
依赖图像范围，ROI 预览可能与整图结果不同。
默认选择**整图融合对照**。

右侧预览上方的 **预览窗口大小 (px)** 可通过滑块或数字输入调整，范围为
160–960 像素。所有方法使用相同尺寸，并按可用宽度自动换行；下次打开会
记住尺寸。调整大小时保留当前放大倍率，左侧白框围绕中心扩大或缩小，
到达图像边缘时自动限制范围。

按 **F11** 或 **全屏（F11）** 按钮可使用整个屏幕，按钮文字会变为
**退出全屏（F11）**；也可直接最大化标题栏。**Esc** 会先退出全屏，
再次按下才关闭窗口。退出全屏后恢复原有窗口大小，结果网格按可用宽度重排。

工作区显示选择提示：单击结果，或用 `Tab` 聚焦后按 `Enter` 或空格，可选择或取消选择。

在源图上按住左键拖动白色检查框，松开后固定位置；右侧各方法显示同一对齐图像栈
中与白框完全一致的区域。滚轮调整选区放大倍率，右键拖动平移源图，
**Ctrl+滚轮**缩放源图，**F**适应窗口。切换源帧或缩放窗口会保留选区。
取消会停止后续工作；关闭窗口时会等待当前原生计算安全返回。


### 快速预览（草稿渲染）

大图上反复调参很耗时。打开 **渲染设置** 并勾选 **快速预览** 后，OpenFocus 先按线性尺寸的一半渲染草稿（最长边不低于 320px）——通常快数倍，配准同样受益。完成消息（以及最新结果的工具提示）会标注 **质量：预览**，草稿**不会**加入输出历史。取消勾选再次渲染即得到全分辨率结果。预览模式不作用于 ROI 渲染，也不会污染全分辨率的对齐缓存。

## 10. 修饰、标签与标注

### 修饰结果（编辑 → 修饰结果…，`Ctrl+T`）

融合结果仍可能有局部瑕疵——高反差边缘的光晕、选错帧的细毛、平坦区的噪点。
修饰工作区只从生成该结果的帧取材：

1. 在输出列表中选中一项（右键 → *修饰结果…* 亦可），按 `Ctrl+T`。没有选中项时，
   会列出所有结果并标明哪些具有来源记录。
2. 左侧是源帧，右侧是结果。两侧共享倍率和观察位置：滚轮缩放，右键/中键拖动
   （或空格+拖动）平移，`F` 适应窗口，`1` 显示 100%。
3. 在底部缩略图条选帧、拖动帧滑动条，或按 `,` / `.`。每一笔锁定当时的源帧和画笔参数；
   本笔结束前不能换帧。
4. 选择 **源帧画笔**（`B`）或 **还原画笔**（`E`）。直径、硬度和不透明度均有
   滑块和数字输入；`[` / `]` 调整直径。按住 `Ctrl` 向上滚动增大直径，向下滚动减小直径；
   单独滚动滚轮仍用于缩放。还原画笔恢复到本次打开时的底图，不会从更早的祖先输出取材。
5. 按住 `Tab` 查看本次修饰前的图像，按住 `Alt` 暂看源帧。清晰度参考图默认关闭，
   只覆盖左侧源帧，并对所有帧使用同一尺度。
6. `Ctrl+Z` / `Ctrl+Y` 按整笔撤销/重做。**还原全部…** 本身也是一步可撤销操作。
   **作为新输出应用** 会新增“<名称> · 修饰 N”并选中它，原输出不变。新条目在
   导出前标记为 *未导出*；应用退出和输出历史淘汰都不会静默丢弃它。

来源信息在渲染时随输出记录：已对齐帧、ROI 裁剪/粘回的偏移、DCT 边缘裁剪和位深
都属于该结果。批处理文件、旧结果和仅对齐的文件夹条目没有来源记录，会明确标为
不可修饰，而不是用当前图像栈猜测。未应用的笔画和撤销历史仅存在于当前会话，
保存工程不会保存这些像素。

**作为新输出应用**后，选中该输出，在**另存为**的格式列表中选择分层 TIFF，即可将结果与源帧
一起保存。实时标签和比例尺不会写入；未保存的标注更改仍受保护。源几何与有效区域
蒙版会保留。结果和各源必须是尺寸匹配的不透明 RGB 或灰度图，位深同为 8 位或 16 位，
且每个源矩形都要落在结果内。最多支持 128 个源；源文件名最长 255 个字符，不能包含
NUL 或基本多文种平面之外的字符（例如许多 emoji）。不安全上下文或预计需要超过 512 MiB 内存的任务会被
拒绝并报告，而不是写出不完整文件。Windows 上的 GIMP 3.2.6 能导入 8 位和 16 位图层，
包括偏移和透明配准填充；结果层可见、源层隐藏，GIMP 还会添加一个可见的背景层。
其他编辑器尚未测试。

工作区中的**曝光画笔**以百分之一档为单位调整局部亮度（100 使像素值加倍，-100 减半），
预览会随涂抹更新。每一笔只调整当前结果一次，重叠的笔迹不会重复叠加；下一笔在上一笔
的基础上继续。用画笔的不透明度和硬度控制混合，提亮时高光可能被裁切。按住 **Before**
可与打开时的结果比较，涂抹中按 Esc 取消该笔，之后也可撤销/重做。这些是像素编辑，
不是可调图层；应用为新输出并导出才会保存。

**结果调整…** 改变整个当前修饰结果。调整曝光和对比度时，采样预览会实时更新；勾选
**Before** 可与打开调整前的结果比较。两个控件都以百分之一档为单位：曝光先乘像素值，
对比度再按它们与中灰的距离缩放。极端值可能裁切高光或阴影。**确定** 作为一步可撤销
编辑应用，**取消** 保持结果不变；处理中取消会请求回滚。全图操作必须能放进修饰历史
的内存上限内。之后按上面的方式发布并导出结果。

在修饰工作区用检查点保存/加载功能，并保留原始底图和处理后的源帧。自动背景会话
（包括成功但未改变像素的分析）保存为无损 v2 `.ofretouch` ZIP 快照，内含 JSON 元数据和
NumPy 数据：精确的工作图像、仍可撤销/重做的图块、诊断状态及源数据出处。加载 v2 不会
重新计算背景。仅画笔/色调编辑的会话可使用紧凑的 JSON v1；旧版背景 JSON v1 仍可重放。

源数据校验在可取消的后台操作中进行。保存会在替换目标文件前重新加载待保存文件，
检查当前图像、仍可撤销/重做的图块及诊断状态是否完全一致。源不匹配、校验失败、取消
或内存不足时，当前编辑和已有检查点都保持不变。若记录上限阻止继续编辑，请先应用
当前编辑，再开始新的修饰会话。两种格式均须提供原始底图，以及本次会话实际使用的
全部处理后源帧（已配准、已 ROI 裁剪或经过其他处理，保持原像素值和位深），按会话顺序加载：

```bash
openfocus retouch replay edits.ofretouch --base fused.png --sources frame1.png frame2.png --output retouched.tif
```

重放会重建记录的帧偏移与对齐行为，并校验底图、顺序帧和有效区域蒙版；像素、几何或
蒙版不兼容会被拒绝。每个路径只能包含一张图，输出必须是 PNG 或 TIFF 并保留底图位深，
检查点和输入图像不能作为输出。

**编辑 → 修饰图像文件…** 可单独选择已有结果和已对齐源图。只接受单页 PNG、TIFF、
JPEG 和 BMP，正立尺寸、通道及 8 位/16 位深度必须一致，加载时会应用 EXIF 方向；
不支持 alpha 和多页图像。所选帧由用户提供，不是渲染记录的来源。尺寸相同并不能证明
图像已经对齐。应用会创建独立、未导出的输出，仍需从输出列表保存。所选文件在本次
会话内受保护，不会被覆盖，包括深度图和 3D 网格导出。与其他结果一样，工程文件不保存
这些像素或画笔历史。

### 替换背景（自动背景）

堆栈时，背景会和主体一起被锐化。因此堆栈图像的背景常常像由不同模糊程度拼凑而成，主体周围还会出现光晕。修饰工作区中的 **自动背景…** 会用同一组堆栈中的一张真实帧替换背景。主体保持堆栈结果不变。背景由一张帧和堆栈结果得出，处理过程中可能会对其像素进行重建、调整和混合。

1. 在修饰工作区中打开结果，然后点击 **自动背景…**。
2. 选择背景：
   - **自动**（推荐）使用柔和背景；如果堆栈清晰记录了背景的大部分，则使用清晰背景。
   - **柔和背景** 使用背景最模糊的那一帧。
   - **清晰背景** 使用对焦最远的那一帧。
3. 保持 **清除边缘光晕** 开启，可去除主体边缘的光晕。它绝不会超出各帧实际记录的范围。关闭则保留堆栈原有的边缘效果。
4. 当主体的某些部分刚好在景深之外（例如突起末端的小球）时，勾选 **保留与主体相连的柔和部分**。主体旁边的背景物体也可能保留为堆栈结果，请检查效果。
5. 点击 **替换背景**。一组 15 帧、2000 万像素的堆栈大约需要一分钟，并需要约 3.5 GB 可用内存。**取消** 可以中止。

这项更改是一步可撤销的操作，之前在主体上画的笔触会保留。对于希望恢复为堆栈像素的地方（例如主体前方失焦的草叶），请使用 **还原画笔**。当主体几乎占满整个画面时（例如林地地面场景），图像会保持堆栈结果并显示提示。

运行后，开启 **显示缺失数据** 会给没有任何帧清晰拍到的位置着色。这些是需要检查或手动修饰的地方：

- 品红：没有任何帧在主体不遮挡的情况下拍到的背景
- 青色：被遮挡、相机看不到的主体
- 黄色：超出堆栈对焦范围的主体
- 灰蓝：过于平滑、无法判断的区域

**保存缺失数据图…** 会保存着色预览，以及每种颜色各一张黑白蒙版。自动背景需要生成该结果的原始帧，因此不适用于区域（ROI）结果。新版背景检查点会精确还原图像、仍可访问的历史和诊断状态，不会重新计算背景。

### 管理标签

加载图像或生成结果后，打开 **工具 → 标签 → 管理标签…**。每个标签有自己的目标：
源图像栈、已配准栈或输出结果。输出标签可应用到全部结果，也可按名称关联当前选中的
输出；重命名或重新排序该结果不会改变关联。

用 **添加** 新建标签，选中条目进行编辑，用复选框启用或停用。可以输入固定文字，或插入
`{value}` 表示帧号。帧号 = 起始值 + 从 0 开始的帧序号 × 间隔；单个输出始终使用起始值。

范围可选全部帧、当前帧或自定义区间（如 `3-5,8`）。无效或不可用的帧号会阻止应用草稿。
当前帧和自定义范围在图像栈重排后会跟随所选源帧的身份；全部帧标签也会应用到后来追加
的帧。目标缺失时，标签会保持与原身份的关联，直到你明确选择新目标。

预览使用真实目标。可用上一帧/下一帧或直接输入帧号导航，选择 **适应** 或 **100%**，
在 100% 下拖动图像平移。位置和字号以图像像素为单位。缺少字体或绘制失败会明确报告。
导出为 PNG 或 TIFF 时保留原始位深。

**应用并关闭** 把完整草稿作为一步可撤销更改提交；取消、Esc 和关闭对话框都会丢弃草稿。
切换标签会保留未提交的编辑。**删除** 只移除当前条目，包括最后一条。菜单中的移除操作
可分别清除源标签、配准栈标签、输出标签或全部标签，同样可以撤销。应用标签只改变会话
显示；要写入文件必须导出图像。

## 11. 设置与配置

通过 **设置 → 高级设置** 编辑性能、配准、传感器清理、输出命名、StackMFF AI 和启动选项。点击“确定”前均为草稿，取消、Esc 或关闭不会提交。缩小分块时，重叠上限立即调整为块尺寸的一半并显示最终数值。AI 输出方式只影响 StackMFF；配准宽度可能影响对齐精度；配准诊断收集是配准区域中的复选框。

**设置 → 高级设置 → 分享使用统计** 在未保存偏好时默认开启，此前明确关闭的偏好会保留。OpenFocus 最多每天成功发送一次随机安装标识、应用版本和操作系统到 openfocus.top，不发送图像、路径、硬件信息或日志。该标识是假名标识，同一标识的记录可以关联。关闭开关并点击“确定”会停止后续报告并删除本地标识及发送时间；再次启用会生成新标识。取消、Esc 或关闭设置窗口会放弃草稿，不改变统计状态；没有新人引导选择或额外同意弹窗。退出应用会取消后续报告，已经发出的请求仍可能完成。

约 30 天活跃安装量指该期间报告过的不同标识数量，可按版本分组。这只是估计值，不代表人数或全部用户：离线安装和已关闭报告的用户不会计入。发送失败会在应用运行期间或以后启动时重试。更新会随设置保留标识；复制便携版设置也会复制标识，多个副本可能算作一个安装；重新安装只有保留原设置时才保留标识。

自动下载在空闲时进行，不会自动安装。下载完成保留在就绪状态，只有明确选择“立即重启更新”才安装。重启先保护活动编辑和未保存工作，成功写入恢复数据后才启动替换。取消下载或准备会等待当前安全边界；已有完整且较新的暂存包可以离线安装。

白场校正改变会话工作像素，不覆盖磁盘源文件。选择白场参考和预览帧；改变源或倍率后
要重新生成预览。参考图与工作/底图必须具有相同的坐标域和尺寸。应用会先准备好两个栈
再提交，可选的参考帧删除属于同一步撤销。需要在会话外保留校正像素时，请导出校正后的
源图像。

文件白场在基础尺度下应用时，工程会记录其绝对路径、内容哈希、尘点尺寸和参数，并在
打开时对原始源帧重放一次；文件缺失、内容改变或尺度不符时会报错。若校正后改变工作
比例，请在保存前恢复到校正比例，或先导出校正后的源栈。使用栈内帧作为白场或尺度
不一致时，同样请先导出校正后的源栈。

批处理也可选择原始分辨率的白场文件（失焦参考）；它会随输入栈缩放，并在配准前用默认
尘点尺寸应用。无法读取或尺寸不符会让受影响的栈明显失败。白场文件会从文件夹输入
（包括分组处理）中排除，融合至少还需保留两帧源图。留空即不做校正。CLI 也可用
`--dust-map WHITE` 指定。校正不能与透明图像同时使用。

传感器清理是可选的，在配准前对原始传感器坐标帧运行。选择明确的坏点蒙版可校正已知的
热像素或坏点；OpenFocus 不会从样本图像猜测蒙版。蒙版必须是与源图同尺寸的单通道
8 位或 16 位图像：0 表示不受影响，1 或通道最大值标记缺陷。处理前请检查其范围；覆盖
超过 10% 画面，或缺陷周围没有未屏蔽邻居的蒙版会被拒绝。蒙版保持原始分辨率，且不能
被选作源图像。在 GUI 中使用坏点蒙版时，源帧必须按原始比例载入，蒙版从不缩放。对
GUI 图像栈做过旋转、翻转、平场校正或其他源修改后，不能再应用传感器清理（包括降噪）；
请重新载入原始帧或关闭清理，恢复的、带此类源历史的工程也一样。预对齐 ROI 处理不能
与传感器清理同时使用。清理设置属于当前会话和保存的工程，不是全局偏好；批处理和 CLI
分别处理原始输入，顺序为传感器清理、平场校正、配准。坏点蒙版要求源文件具有中性 EXIF
方向；带方向、RAW 或无法确定方向的源会被拒绝，因为解码像素可能不再对应传感器坐标。
可选的传感器降噪独立于坏点蒙版，默认关闭；请以原尺寸检查结果，判断平滑是否适合样本。
清理保留源文件和 8/16 位深度。CLI 使用 `--defect-mask-path MASK` 与
`--sensor-denoise`，配方和 Python 配方 API 也会记录这些选项；配方保存蒙版指纹，并
拒绝缺失或已改变的蒙版。CLI 清理不能与透明输入同时使用；分组处理只清理原始帧，
不清理中间组结果。

处理配方要求输出位于所有输入文件夹之外，并拒绝把显式输入当作输出。这样可以保护源
图像，避免重跑时把旧结果算进输入。即使工程原始源已移动，也可以把处理设置提取为模板
或配方：**文件 → 保存处理模板…** 只保存设置、不含源路径；**文件 → 应用处理模板…**
把模板、工程或含工程设置的配方应用到已加载图像栈；`openfocus recipe create --project`
写出的无头配方仍需显式 `--input`。打开工程本身仍需要源文件和记录的白场参考。

**帮助 → 发送反馈** 打开本地日志。“复制日志”只复制当前可见会话日志；反馈 ZIP 包含会话/完整应用日志及环境信息。请检查包内容后自行提交；打开 GitHub 只打开页面。取消导出不写文件，写入失败保留原目标文件并显示失败路径。

每次启动独立写入滚动日志，并行运行的 GUI/CLI 不再共用同一文件。任务 ID
关联参数、耗时和完成/取消/失败状态；未预期的错误记录完整调用栈。反馈 ZIP
还包含本次崩溃报告和依赖版本。通过 **帮助 → 打开日志文件夹** 或反馈页显示的
实际路径查找文件。单进程日志在 1 MB 时滚动，保留三份备份；超过 14 天且进程
已退出的会话日志会清理。需详细诊断时，启动前设置 `OPENFOCUS_LOG_LEVEL=DEBUG`；
可用 `OPENFOCUS_LOG_DIR` 指定日志目录。

状态面板在系统能提供读数时显示已使用和总物理内存；无法获取时显示 `N/A`。

### 瓦片设置（内存优化）

大图默认使用分块（瓦片）处理以避免内存问题。

通过 **设置 → 高级设置 → 性能** 访问：

- **启用瓦片处理**：关闭后强制整图处理（大图可能内存不足）
- **分块大小**：每块的处理尺寸（默认 1024px）
- **重叠**：块间重叠量，用于无缝拼接（默认 256px）
- **阈值**：图像超过该尺寸时启用瓦片处理（默认 2048px）

**建议**：
- 分块越小：内存占用越低，处理越慢
- 分块越大：内存占用越高，处理越快
- 结果出现接缝时增大重叠量

### 配准设置

通过 **设置 → 高级设置 → 配准** 访问：

- **下采样宽度**：配准特征提取的预处理分辨率
  - 默认 1024px
  - 调低提速，调高提精度

### 性能参考

实测吞吐与内存数据见 [PERFORMANCE.md](./PERFORMANCE.md)（大真实栈的测量值，
以及深栈/高分辨率输入的实用建议）。

### 线程数设置

控制 CPU 并行处理：

通过 **设置 → 高级设置 → 性能** 访问：

- `0` 表示自动调度，新设置默认使用自动。
- 正数是线程上限；升级时保留已保存的上限。
- 可用 CPU 容量、资源模式和内存余量可能降低实际并发，线程更多不一定更快。

### 资源模式

**设置 → 高级设置 → 性能 → 资源模式** 决定一次渲染最多占用多少机器资源，不会改变融合结果。

| 模式 | 行为 |
|---|---|
| 均衡（默认） | 为桌面保留约 20% 物理核心和内存余量 |
| 优先流畅 | 约一半核心与更小的在途窗口；渲染更慢，机器最流畅 |
| 全速 | 在内存预算内使用全部物理核心 |

规划器同时考虑物理核心、CPU affinity 和配额，每次只运行一层并行。重计算任务从准备到发布共用准入；取消会等待当前 native 调用实际结束。可用内存未知或不足时会报告资源错误，保持所选分块网格不变；手动缩小分块可能改变输出像素。

### GPU 加速开关

StackMFF V1/V2/V3 使用 ONNX Runtime。Windows 的 DirectML 和 macOS 的 CoreML 可能加速推理，否则使用 CPU。仅凭提供程序可用不能证明实际使用了 GPU。其他 GPU 的支持仍需验证。


- 通过 **设置 → GPU 加速** 开关切换
- 取消勾选后 AI 方法强制使用 CPU——GPU 驱动异常时非常有用
- 没有可用加速器，或未使用加速器时，状态面板显示 `N/A`；存在加速器但当前算法仅用
  CPU 时显示 `CPU*`
- 设置对下一次渲染生效，并会被记住

### AI 批量大小

通过 **设置 → 高级设置 → AI** 访问：

- 保存的批量上限默认 2；当前执行策略在所有设备上均限制为每次推理一个分块。
- 增大该上限不会启用未经验证的 GPU 批处理，也不会缩小空间分块。

### 主题

界面提供**浅色（默认）**和**深色**两套主题。通过 **设置 → 主题** 切换，
立即生效（Windows 标题栏同步变色）并被记住。首次启动时会在欢迎对话框中
选择主题。

### 配准缓存

OpenFocus 可以把配准结果保存在源图像栈旁的 `.openfocus_cache` 文件夹中。再次打开同一个图像栈（文件未变化）时会直接跳过配准。通过 **设置 → 高级设置 → 配准 → 配准缓存** 开关；过期条目会被自动替换。

### 输出命名前缀

在 **设置 → 高级设置 → 输出命名** 中，可为新渲染结果添加可选的文件名前缀，帮助识别。
输入时示例会同步更新；最多 40 个字母、数字、下划线或连字符。留空保持原命名。点击
**确定** 记住设置，取消则丢弃更改。前缀会成为新输出列表名称和建议导出名的一部分，
已有结果保持原名；保存对话框中仍可修改名称。该偏好不会重命名源文件，也不会改变
批处理输出名。

### 便携模式

在 `OpenFocus.exe` 旁创建名为 `OpenFocus.portable` 的空文件（便携版 zip
自带），所有用户数据——设置、日志、最近文件——会改存到应用旁的
`OpenFocusData` 文件夹，安装可随 U 盘移动。删除标记即恢复普通模式。

### HEIC/HEIF 输入

直接加载 iPhone 照片。需要可选的 `pillow-heif` 包

### 更新

帮助 → 检查更新 会与 `openfocus.top` 的发布信息比对版本。新版本会在应用空闲时从该网站后台下载；
暂存完成后，横幅和状态区提供 **立即重启更新**，可离线应用。无法自更新的构建会
打开官网下载页面。自动检查静默进行，每天最多一次。

### 设置持久化

以下设置在应用重启后自动恢复：线程数、资源模式、瓦片参数、配准下采样宽度、AI 批量大小、GPU 加速开关、配准缓存与配准诊断开关、界面语言、窗口大小与面板布局、拖出导出格式、按算法记忆的亮度选项、平滑与半径值，以及最近打开的图像栈。设置对话框确认即保存；应用关闭时再次整体保存。偏好按用户存储在 `OpenFocus/OpenFocus.ini`（QSettings INI 格式）。

### 自动检查更新

每天一次，启动数秒后 OpenFocus 会静默检查 `openfocus.top` 上是否有新版本，更新说明也从该网站获取。发现新版本时，

**查看新功能**（更新说明）与关闭按钮。关闭只对当前版本生效——下个版本会重新提醒，
**帮助 → 检查更新** 也可立即恢复提醒。

后台下载期间状态栏显示进度。也可以随时通过 **帮助 → 检查更新** 手动检查。

## 12. 批处理

自动处理多个文件夹：

1. 点击 **工具 → 批处理** 菜单
2. 在批处理对话框中：
   - **添加文件夹**：选择包含图像序列的文件夹
   - **直接拖入文件夹**：把一个或多个图像栈文件夹拖到对话框（或文件夹列表）任意位置即可整批加入；拖入后自动切换到多文件夹模式，缩略图随后逐个生成
   - **移除文件夹**：从列表移除选中项
3. 配置输出设置：
   - **保存到子文件夹**：在各输入文件夹内生成结果
   - **保存到同目录**：与输入保存在一起
   - **自定义目录**：指定输出位置
4. 检查当前融合/配准设置
5. 点击 **开始批处理** 运行

批处理对话框实时显示进度，随时可以取消。

### 批处理说明

- 以打开窗口时的主窗口参数快照为默认值，可在批处理窗口中修改
- 每个文件夹或拆分组通过相同的处理流程独立执行
- **分组融合**仅用于多文件夹模式，由 **将大型堆栈分组处理** 复选框开启；关闭时组大小与
  重叠控件隐藏。开启后组大小至少为 2，重叠数为 0 到组大小减 2；桌面重叠数从 1 开始，
  调整组大小时会限制在允许范围内。拆分文件夹模式不支持分组，复选框在那里会被拒绝。
  各组分轮融合并使用临时磁盘，组内有自己的参考帧，结果是整栈融合的近似值。必须选择
  融合算法；不支持原始帧深度、来源信息或对齐帧导出。仅支持文件头可读的同尺寸单帧
  图像，不支持相机 RAW、多页文件及带 alpha 通道的图像（包括透明 PNG）。OpenFocus
  配准不能指定非首帧的全栈参考帧。配准组以自身第一帧作为坐标参考；每轮配准会裁去
  保守边缘，后续轮次取有效区域交集（包括单帧尾组），因此结果可能裁边。每个参与配准
  的组在两个方向都必须大于 8 像素；困难的旋转或投影变换可能没有安全矩形并报错，
  此时请改用预对齐输入或关闭分组。白场只作用于原始帧，结果锐化只在最终融合后应用
  一次。命令行示例：
  `python main.py --input stack --output fused.png --group-size 8 --group-overlap 1`；
  命令行分组要求文件夹输入，不能与 `--depth-map` 同时使用，dry-run 也会检查这些限制。
- **文件 → 保存处理模板**保存不含源路径的处理参数；**应用处理模板**将模板、
  工程或带工程设置的配方应用到当前图像栈，不替换源图、排除帧或标注。CLI 的
  `openfocus recipe create` 和 `openfocus recipe run` 可保存并重跑处理配方。
  工程中的源图变换不能直接捕获为 CLI 配方，请先导出处理后的源栈。
- **三种模式的落盘位置**：**仅对齐**时，所选目标下每个栈生成一个
  `<栈名>_aligned` 文件夹，输出列表显示该文件夹；**融合并保存对齐**时，
  融合图写成目标下的 `<栈名>.<扩展名>`，对齐帧放进旁边的 `<栈名>_aligned`，
  输出列表只显示融合结果；**融合且不导出对齐**时只写融合图。输出列表中的
  文件夹名与磁盘上的名称一致。
- 对齐帧保留原文件名主体；重名文件和已有文件夹自动编号，不覆盖源文件
- 同目录下若残留旧版本写入的 `*_registered*` 副本，且原图存在，则不再把它们当作帧加载；载入信息会报告跳过的数量
- PNG/TIFF 保留 16 位数据；明确选择 JPG/BMP 时转换为 8 位，JPG 质量可调整（默认 100）
- 取消会等待线程实际停止；保留已成功提交的文件，分别统计成功、部分成功、失败、取消和未开始的任务

### 批量图像转换

选择 **工具 → 批量图像转换…**，可独立于当前堆栈处理文件。添加图像文件或文件夹，
选择已有的输出文件夹和格式，然后点击**转换**。列表显示各源文件的输出路径或错误；
取消会在当前操作结束后停止，已经完成的文件会保留。已有文件和源文件不会被覆盖，
重名输出会自动编号。

可直接将本地图像或文件夹拖入队列或窗口，文件夹只导入直接子文件；按自然文件名排序
并去重，反馈新增、跳过和总数。队列非空且输出路径指向已有文件夹时才允许转换；
输出路径支持引号和环境变量。

每行左侧显示固定 96×72 缩略图；可多选后按 **Delete / Backspace** 或点击**移除**。
删除键只在列表内移除队列项，在输出路径框中仍正常编辑文字。转换或取消真正结束前，
不能增删输入。缩略图使用独立有界后台队列、JPEG 缩小解码或小型图像页；
大型 RAW 只读取 TIFF 类 RAW 或 RAF 容器中的有界内嵌 JPEG。
没有安全预览的格式（包括部分 CR3）显示占位图，不为缩略图展开整个传感器。
缺少缩略图不影响转换。
缩略图准入同时预算 JPEG 原始尺寸：渐进式 JPEG 即使缩小解码输出，仍需
原图大小的 DCT 系数缓存。预览超过资源预算时，会在解码像素前显示占位图。

选择 **DNG** 可直接进行 RAW 转 DNG，无需安装 Adobe DNG Converter。
支持的三色 Bayer、X-Trans 保留有效 CFA 样本及黑电平、白电平、拍摄白平衡、
D65 相机矩阵、裁切与方向；仅移除遮光边缘，不缩放或显影有效像素。
输出用 16 位 TIFF 容器承载原有 12/14/16 位白电平。已有 DNG 逐字节复制，
保留原配置、处理指令及专有元数据。非 CFA 三色传感器使用 **LinearRaw**，
其内容是相机线性 RGB，不承诺原始马赛克。普通 JPEG/PNG/TIFF 不能通过选择
DNG 变成相机 RAW，会逐项报错。

相机校准由 LibRaw 提供；其 Python API 未公开所有专有修正、空间黑电平表及
厂商配置，不保证与原厂显影完全一致。未知 CFA、四色传感器、非方形或斜排
布局、缺失校准、各色不同饱和值及超过标准 TIFF 4 GiB 的 CFA 会明确报错。
运行时无需 Adobe SDK。持久测试包含由独立 LibRaw 解码的合成 Bayer、X-Trans
及 LinearRaw 小样；具体相机支持仍取决于 LibRaw。

七个合成小样（三种 12/14/16 位传感器范围的 Bayer 与 X-Trans，以及一张
16 位 LinearRaw）已通过 **Adobe DNG SDK 1.6 dng_validate**，退出码均为 0。
校验器构建关闭了 XMP 和外部有损 JPEG 支持；生成文件不含这两类数据。
六张 CFA 小样四边均有 SDK 的“Too little padding (possible interpolation
artifacts)”提示：遮光边缘裁掉后，ActiveArea 覆盖整个存储图像，因此不同
读取器的边缘插值可能不同。不会伪造 padding 或修改 CFA 值来隐藏提示。
该结果仅证明这些合成文件通过校验，不代表所有相机或 Adobe 产品认证。

并行转换复用应用资源预算，按每个任务最大 TIFF 页预留内存，待处理任务数
不超过 worker 数，任务内原生解码器使用单线程。取消后停止新任务准入，
在页、解码/写入阶段及 DNG strip 之间检查取消；原生调用返回后合作停止。
已完成文件保留，未完成临时文件清理，多线程输出通过原子占名避免碰撞。
TIFF 预检只打开一次文件、顺序遍历页面头，并在读取和估算每页前检查取消；
取消或关闭窗口也会打断这段预检，不会继续遍历所有剩余页面。

输出普通图像格式时，相机 RAW 使用相机白平衡和 sRGB 传递曲线显影，不自动提亮；具体相机支持取决于
LibRaw 版本。多页 TIFF 分别输出为编号文件，并分别保留各页有效的 RGB 配置；RAW
在支持的格式中写入生成的 sRGB 配置。PNG 和 TIFF 保留 16 位，JPEG、BMP 和 WebP
将 16 位图像转换为 8 位，JPEG 是有损格式；透明图像请使用 PNG。带透明通道的 LZW
TIFF 页、不支持的 TIFF 色彩布局及样本类型会报错。每项任务仍需足够的内存和
磁盘空间容纳单张图像及编码器。

## 13. 导出结果

### 保存单张结果

1. 在输出列表中选择要保存的结果
2. 点击 **文件 → 保存** 或按 `Ctrl+S`（也可以右键输出条目选择"另存为"，或直接把输出条目拖出软件到文件夹）
3. 选择格式和位置
4. 保存

### 保存分层 TIFF

选中修饰过的输出，在**另存为**的格式列表中选择分层 TIFF，可把结果与记录的源帧保存为一个分层
TIFF。实时标签和比例尺不会写入；未保存的标注更改仍受保护。源几何与有效区域蒙版会
保留。结果和各源必须是尺寸匹配的不透明 RGB 或灰度图，位深同为 8 位或 16 位，且每个
源矩形都要落在结果内。最多 128 个源；源文件名最长 255 个字符，不能包含 NUL 或基本
多文种平面之外的字符（例如许多 emoji）。不安全上下文或预计需要超过 512 MiB 内存的任务会被拒绝并报告，
而不是写出不完整文件。Windows 上的 GIMP 3.2.6 能导入这些图层，包括偏移和透明配准
填充；结果层可见、源层隐藏，GIMP 还会添加一个可见的背景层。其他编辑器尚未测试。

### 拖出导出格式

从输出列表拖出结果时使用的图像格式，在输出列表右键菜单的 **拖出格式**（JPG、PNG、WebP 或 TIFF）中选择，选择会被记住。

### 保存配准栈

1. 点击 **文件 → 保存堆栈 → 已配准堆栈**
2. 选择保存格式：
   - **保存为文件夹**：选择目标目录和编码，每个栈生成一个新子文件夹，内含原名称的逐帧图像
   - **保存为多页 TIFF**：把整个栈写回单个 `.tif`，保留 16 位深度
   - **保存为 GIF**：生成对齐序列的动画

### 保存输入栈

1. 点击 **文件 → 保存堆栈 → 输入堆栈**
2. 选择保存格式：
   - **保存为文件夹**：原始帧保存为单独图像
   - **保存为多页 TIFF**：把输入栈写回单个 `.tif`，保留 16 位深度
   - **保存为 GIF**：生成输入序列动画

### 导出格式

- **JPG**：有损压缩，质量-体积比好
- **PNG**：无损，保留 8 位和 16 位数据
- **BMP**：无压缩，将 16 位数据转换为 8 位
- **TIFF**：保留 8 位和 16 位数据；多页导出把整个栈保存为一个文件
- **GIF**：8 位调色板动画；取消不会损坏已有目标文件

## 14. 命令行界面

`pip install openfocus` 包含 AI 模型、权重、HEIC 与相机 RAW 解码。Python 3.13+ 会跳过 `dtcwt`，此时 DTCWT 项保持禁用并给出提示。

OpenFocus 支持无界面运行——适合脚本流水线和 CI 集成。安装 pip 包后可直接使用
`openfocus` 命令；从源码运行时把 `openfocus` 换成 `python main.py` 即可。常用
子命令如下，融合参数对两种入口相同：

```bash
openfocus version                       # 打印版本
openfocus describe                      # JSON：方法、参数、能力与控制命令
openfocus gui [--control] [--socket NAME] [路径…]   # 启动桌面应用
openfocus ctl <command> [flags]          # 操作运行中的窗口（见 AGENT_CONTROL_SPEC.md）
openfocus recipe create FILE --input … --output … [处理参数]
openfocus recipe run FILE [--dry-run]    # 重放保存的无头配方
openfocus retouch replay CHECKPOINT --base BASE --sources … --output RESULT
```

`openfocus gui` 会分离启动；`--control` 会等待控制通道建立并打印连接 JSON。
`openfocus describe` 与 `version` 不需要输入。面向 Agent 的流程见
[AGENT_CONTROL_SPEC.md](./AGENT_CONTROL_SPEC.md) 和
`skills/openfocus-control/SKILL.md`；桌面版启动时会自动开启受令牌保护的本地 Agent 通道。

```bash
pip install openfocus
openfocus -i ./stack_folder -o ./result/fused.png
```

```bash
# 使用默认的 AI 融合处理一个文件夹
python main.py --input ./stack_folder --output ./result/fused.png

# DTCWT + ECC 配准，8 线程
python main.py -i ./stack_folder -o ./result/fused.png -m dtcwt -a ecc -t 8

# StackMFF V3 强制 CPU + 自定义瓦片尺寸
python main.py -i ./stack_folder -o ./result/fused.png -m stackmffv3 --cpu --tile-size 512

# 显式文件列表；也接受视频文件作为输入
python main.py -i img1.jpg img2.jpg img3.jpg -o fused.png -m gfgfgf

# 单个多页 TIFF Z-Stack + 元数据自动标定的比例尺
python main.py -i ./zstack.tif -o fused.png -m dtcwt --scale-bar

# 只检查相邻相似帧，不融合也不改变输入
python main.py -i ./stack_folder --suggest-duplicates
```

`--suggest-duplicates` 接受文件夹或有序的单帧图像列表，输出一个包含 `files` 和
`suggestions` 数组的 JSON 对象；`index` 与 `reference_index` 是 `files` 中从 0 开始
的位置，`difference` 是归一化采样的平均差异。加 `--json report.json` 可保存同一对象。
该模式不能与 `--output`、`--output-dir`、`--json-progress` 或 `--dry-run` 同时使用。
报告只按给定输入顺序比较相邻文件，不知道你之后会排除哪些帧；若排除参考帧，请重新考虑
其后继帧，或按预期顺序再次检查。

给单次渲染加 `--align openfocus --alignment-report alignment.json` 可保存逐帧配准结果。
JSON 包含 `method`、`input`、`frame_count` 和 `entries`；`frame_index` 按解码输入顺序
从 0 开始，位于融合排序之前，多页图像按页展开、视频按解码顺序展开。组合方法会为每个
阶段分别列出条目。报告在成功处理后才原子写入，不能覆盖输入或其他输出；批处理、分组
和 dry-run 不接受该选项。

### 处理配方

处理配方可保存并复用参数，也便于整体迁移：

```bash
openfocus recipe create workflow.json -i ./stack_folder -o ./result/fused.png -m dct --cpu
openfocus recipe run workflow.json --dry-run
openfocus recipe run workflow.json
```

配方 JSON 第 1 版包含 `version`、`input` 数组、`output` 或 `output_dir`，以及 `options`
对象。路径相对于配方文件；移动配方时请连同输入一起移动。创建会记录 CLI 设置和解析后的
算法参数；未知字段、非法值和不支持的版本会被拒绝。`--dry-run`、`--resume`、`--json`
和 `--config` 等临时控制项不会被写入配方。dry-run 只检查输入，不写结果文件。
也可以从现有 `.ofproj` 捕获设置，并显式选择新的输入与输出：

```bash
openfocus recipe create workflow.json --project session.ofproj -i ./new_stack -o ./result/fused.png
```

这会转移融合、配准、亮度、帧序、锐化和瓦片设置，并嵌入供 GUI 使用的处理设置；帧排除、
加载倍率、标签和编辑不会转移。含源图变换（包括已应用平场校正）的工程必须先导出校正后的
源栈。配方要求输出位于输入文件夹之外，且不能把输入文件当作输出。分组选项可从 CLI 参数
捕获。GUI 中 **文件 → 保存处理模板** 保存不含源路径的设置，**应用处理模板** 把模板、
工程或带工程设置的配方应用到当前图像栈，不替换其输入、变换、排除帧或标签；模板本身
不是可执行配方。配方内嵌的 GUI 设置与 CLI 选项相互独立，手工编辑 JSON 时请保持一致。

无需导入 PyQt，即可从 Python 使用相同的无界面 API。将 `dry_run=False` 用于实际处理：

```python
from core.recipes import capture_project_recipe, capture_recipe, load_recipe, save_recipe, run_recipe

capture_recipe("workflow.json", ["-i", "stack_folder", "-o", "result/fused.png", "-m", "dct"])
capture_project_recipe("from-project.json", "session.ofproj",
                       ["-i", "new_stack", "-o", "result/fused.png"])
recipe = load_recipe("workflow.json")
save_recipe("workflow.json", recipe)
exit_code = run_recipe("workflow.json", dry_run=True)
```

`capture_recipe` 将参数路径视为相对于当前目录的普通 CLI 路径；`save_recipe` 将保存的路径视为相对于配方文件。配方记录设置和引用，包括明确选定的传感器缺陷掩码的内容指纹，但不记录输入像素、软件版本、硬件或源图像栈的校验和；需要追溯来源时请另行保存。同样的设置不能保证在不同软件版本、驱动或设备上得到完全相同的像素；GPU 神经网络运算可能具有不确定性。需要在 CPU 上运行时使用 `--cpu`，并保留已安装的软件和输入。

### 重放修饰检查点

命令行可加载与 GUI 相同的 v2 `.ofretouch` 和旧版 JSON v1。v2 精确还原图像、仍可
撤销/重做的图块及诊断状态，不会重新计算自动背景：

```bash
openfocus retouch replay edits.ofretouch --base fused.png --sources frame1.png frame2.png --output retouched.tif
```

两种格式均须提供原始底图和修饰时实际使用的全部处理后源帧，按会话顺序排列，保持
配准、ROI 裁剪或其他处理后的原像素值和位深。加载会校验底图、有序源帧、记录的位置
和有效区域蒙版，不匹配则拒绝加载。每个路径只能包含一张图，输出必须是 PNG 或 TIFF，
保留底图位深，且不能覆盖检查点或输入图像。

| 参数 | 说明 |
|------|------|
| `--input, -i` | 图像文件夹、视频文件、一个/多个图像文件，或单个多页 TIFF |
| `--output, -o` | 单栈输出图像路径（扩展名决定格式）；没有 `--output-dir` 时必需 |
| `--output-dir, -d` | 批处理模式：逐个处理输入文件夹，每个栈写入 `<文件夹名>.png` |
| `--method, -m` | `stackmffv3`（默认）、`stackmffv2`、`stackmff`、`openfocus_a/b/c`、`guided_filter`、`dct`、`dtcwt`、`gfgfgf` |
| `--param KEY=JSON_VALUE` | 算法参数，可重复；优先于旧式专用参数 |
| `--align, -a` | `none`（默认）、`homography`、`ecc`、`openfocus`、`both` |
| `--align-param KEY=JSON_VALUE` | 配准参数，可重复，例如 `failure_policy="fail"`、`reference_frame=3` |
| `--align-shift-limit` | 仅 `openfocus` 对齐：可接受的最大位移（帧尺寸比例，默认 0.08；超限帧放弃对齐而非半校正） |
| `--alignment-report PATH` | 为启用了配准的单次非分组渲染保存逐帧配准结果 JSON；批处理/分组不支持 |
| `--suggest-duplicates` | 输出相邻相似帧的 JSON 建议，供人工复查；不融合、不排除；不能与输出、进度、dry-run 或传感器清理选项同用 |
| `--exposure-match` | 融合前把每帧均值标定到末帧（默认开启；`--no-exposure-match` 关闭）。增益按整栈计算，分块输出无接缝；对所有算法生效，并决定 OpenFocus 对齐的亮度参考端 |
| `--base-frame` | 可选的后融合步骤：把输出低频对齐到 `last`/`first` 帧（默认 `none`） |
| `--sharpen-output` | 融合后、量化前做轻度锐化；默认关闭 |
| `--sort` | `openfocus_a/b/c` 的帧序：`asc`（默认，文件序）、`desc`（反转远→近扫描）、`off` |
| `--frame-order` | 文件夹输入：`auto`（默认）在所有帧都有 EXIF 对焦步数时按由近到远排序（OM SYSTEM 焦点包围从中间深度开始），否则按文件名；`name` 始终按文件名。显式列出的文件保持原顺序 |
| `--dust-map WHITE` | 用失焦白场照片做平场（尘点图）校正 |
| `--defect-mask-path MASK` | 传感器坐标坏点蒙版；非零像素在配准前修复 |
| `--sensor-denoise` | 配准前做保守的传感器降噪 |
| `--kernel, -k` | 核大小（自动取奇）；控制 `openfocus_a` 和 `openfocus_b` 的焦点响应尺度，C 没有半径参数 |
| `--depth-smoothing VALUE` | 仅 `openfocus_b`：深度过渡平滑强度（默认 1.2） |
| `--blend-smoothing VALUE` | 仅 `openfocus_a` / `openfocus_c`：过渡平滑强度（默认 A 2.0、C 3.0） |
| `--threads, -t` | 工作线程上限；`0` 表示自动（默认），正数限制并发 |
| `--resource-preference` | 资源调度偏好：`balanced`（默认）、`responsive`、`maximum` |
| `--batch-size` | AI 分块批量上限（默认 2）；当前实际每次推理一个分块 |
| `--ai-mode` | StackMFF V3 输出：`soft`（默认，按概率混合）或 `hard`（逐像素取最可能帧） |
| `--cpu` | 即使有 GPU 也强制 CPU |
| `--downscale` | 配准特征提取的下采样宽度 |
| `--tile-size` | 大图的瓦片分块尺寸 |
| `--tile-enabled` / `--no-tile-enabled` | 启用或禁用按需瓦片处理（默认启用） |
| `--tile-overlap` | 瓦片重叠像素数 |
| `--tile-threshold` | 启用瓦片处理的最小图像尺寸 |
| `--group-size` | 分组融合的每组帧数；`0` 关闭（默认），开启时至少 2。仅限文件夹；不能与 `--depth-map`、RAW/alpha/多页输入或非默认的 OpenFocus 参考帧同用 |
| `--group-overlap` | 相邻组的重叠帧数；默认 `0`，最多为组大小减 2 |
| `--scale-bar` | 绘制比例尺（标定从 TIFF/DNG 显微元数据自动检测） |
| `--depth-map [路径]` | 同时保存伪彩焦点位置（深度）图（默认 `<输出名>_depth.png`）；仅支持支持深度图的方法，分组或透明输入会被拒绝；批处理只允许默认路径 |
| `--depth-colormap` | 深度图配色：turbo、viridis、jet、gray 等（默认 turbo） |
| `--scale-um` | 手动指定像素大小 µm/px，覆盖元数据（隐含 `--scale-bar`） |
| `--dry-run` | 只检查参数和输入，不写结果 |
| `--resume` | 续跑批处理中尚未完成的任务 |
| `--json FILE` | 把结果摘要写成 JSON |
| `--json-progress` | 以 JSON 行（NDJSON）输出进度；普通文字写入 stderr |
| `--config FILE` | 批处理模式：读取按文件夹覆盖的 JSON，例如 `{"stackA": {"method": "dct"}}` |

没有 `--method none`：CLI 总会执行融合。仅对齐输出请使用桌面应用。

退出码：`0` 成功，`1` 处理错误，`2` 用法错误。`python main.py --help` 打印全部参数；以普通路径启动（`python main.py C:\stack`）仍会打开 GUI 并自动加载该文件夹。

## 16. 故障排除

### 常见问题

#### 提示"No Images Loaded"

- 先导入图像文件夹或视频
- 检查文件夹内是否包含受支持的图像格式

#### 融合结果模糊或有重影

- 启用图像配准（下拉单选：单应性 / ECC / OpenFocus 快速，任选其一）
- 确认融合前图像已正确对齐
- 尝试其他融合算法
- 增大核大小获得更平滑的结果

#### StackMFF V3 不可用

- 检查 ONNX Runtime 和随附模型。
- 通过 **帮助 → 环境信息** 检查安装状态

#### 内存不足（OOM）

- 在 **设置 → 高级设置 → 性能** 中确认已启用瓦片处理
- 减小分块尺寸
- 大图栈的原图和配准结果会同时占用系统内存；GPU 显存不能替代这部分内存
- 使用更小的核
- 将图像缩放到更小的尺寸

#### 配准失败

- 对有界刚性运动改用 **OpenFocus（快速）**，或启用 **遇到被拒绝帧时停止**，在失败时
  立即报错，而不是接受未对齐的帧
- 在 **设置 → 高级设置 → 配准** 中减小下采样宽度
- 确保图像有足够的对比度和特征
- 启用 **收集配准诊断** 后重新渲染，再从 **设置 → 高级设置 → 配准 → 配准诊断** 查看失败帧

#### 处理速度慢

- 线程数保持自动（`0`）；可用 CPU 容量、资源模式和内存余量已经限制并发
- 无人值守批处理可使用 **全速** 资源模式，或改用引导滤波 / GFG-FGF 代替 AI 方法
- 降低图像分辨率，或在调参时使用 **快速预览**

#### Windows 首次启动弹出 SmartScreen 警告

Windows 构建的签名状态因具体 release 而异，见发布说明；不保证签名。请从 **https://openfocus.top** 下载，而不要使用第三方镜像；若出现 SmartScreen 警告，点击 **更多信息 → 仍要运行**。解压后的首次启动可能需要 30–60 秒。

#### macOS 提示"无法打开"或"已损坏"

macOS 构建未公证。请从 **https://openfocus.top** 下载 Apple Silicon 构建。若通过 DMG 将 `OpenFocus.app` 移入"应用程序"，在终端执行：

```bash
xattr -cr /Applications/OpenFocus.app
```

若通过终端 `install.sh` 安装到 `~/Applications`，执行 `xattr -cr ~/Applications/OpenFocus.app`。

macOS 15 Sequoia 起，右键点击应用选择 **打开** 不再绕过 Gatekeeper。若想走图形界面，请先尝试打开一次，再到 **系统设置 → 隐私与安全性** 中点 **仍要打开**。发布的 macOS 包面向 Apple Silicon（M1/M2/M3/M4）；Intel Mac 请从源码运行。

### 获取帮助

1. **环境信息**：点击 **帮助 → 环境信息** 检查安装状态
2. **联系方式**：点击 **帮助 → 联系我们** 获取支持信息

## 附录：融合算法细节

### 引导滤波

引导滤波使用引导图像进行边缘保持平滑。它计算引导图像与输入图像之间的局部线性变换，再将其应用于输出。该方法在降噪的同时能出色地保留边缘。

### DCT（离散余弦变换）

DCT 将图像变换到频域，基于系数幅值做出融合决策。高频分量（细节）被保留，低频分量（平滑区域）按局部能量合并。

### DTCWT（双树复小波变换）

DTCWT 提供图像的多尺度、多方向分解。它捕获不同尺度和方向上的特征，使融合规则能够同时保留纹理与结构信息。

### GFG-FGF

实现付宏语等（2024）：粗略聚焦图 |I − mean(I)| 叠加类高斯四邻域梯度——3×3 模板 T = [1 2 1; 2 4 2; 1 2 1]/16 得 P = I⊗T，G = (|I(x±1,y) − P|)/2 + (|I(x,y±1) − P|)/2，低于 T0 = 0.005 的置零——再经快速引导滤波优化。每个像素取聚焦值最大的帧（并列时用 3×3 Sobel 小区域度量），二值决策图经快速引导滤波平滑后加权融合。

### AI 融合（StackMFF V3）

基于深度学习的方法，使用在大规模多焦点图像对上训练的神经网络。网络自动学习最优融合策略，配置得当时可提供当前最先进的结果。
