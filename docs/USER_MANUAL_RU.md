## 1. Введение

OpenFocus — профессиональное настольное приложение для объединения многофокусных изображений, предназначенное для исследователей, инженеров и специалистов по обработке изображений. Программа обрабатывает многофокусные последовательности снимков современными алгоритмами совмещения и объединения и создаёт изображения со всем в фокусе и полной глубиной резкости.

### Ключевые возможности

- **Объединение многофокусных изображений**: несколько снимков с разными точками фокуса объединяются в одно полностью резкое изображение
- **Несколько алгоритмов объединения**: направляющий фильтр, DCT, DTCWT, GFG-FGF и ИИ-объединение (глубокое обучение)
- **Совмещение изображений**: выравнивание смещённых последовательностей методами ECC или гомографии
- **Сравнение «Шторка»**: проверка выравнивания и сравнение результатов с разделителем A/B
- **Файлы проектов**: сохранение и восстановление полного рабочего сеанса
- **Многостраничный TIFF**: Z-стеки в одном файле загружаются постранично и экспортируются обратно в один файл
- **Карта глубины**: попиксельные карты положения фокуса с пользовательскими псевдоцветовыми схемами
- **Масштабная линейка**: линейки публикационного качества с автоматической калибровкой мкм/пикс
- **Автовосстановление после сбоя**: после аварийного завершения предлагается восстановить последний рабочий сеанс
- **Многоязычный интерфейс**: английский, 中文, 日本語, Español с автоопределением языка системы
- **CLI без графического интерфейса**: управление OpenFocus из командной строки для автоматизации и CI
- **Гибкий экспорт**: сохранение результатов отдельными изображениями, папками или GIF-анимациями
- **Преобразования изображений**: поворот, отражение и изменение размера стеков
- **Добавление подписей**: текстовые подписи на выровненном и исходном стеках
- **Сохранение настроек**: параметры, язык и недавно открытые стеки сохраняются между запусками

### Поддерживаемые входные форматы

- Файлы изображений: JPG/JPEG, PNG, BMP, TIFF, WebP и другие распространённые форматы
- Видеофайлы: формат MP4 (автоматически раскладывается на последовательность кадров)
- Папки с нумерованными последовательностями изображений
- RAW-файлы камер (DNG, CR2/CR3, NEF, ARW, RAF, ORF, RW2 и другие
  распространённые форматы RAW). Декодирование выполняет `rawpy` (LibRaw):
  его ставит `pip install openfocus`, а сборки для Windows/macOS содержат его внутри

### Поддерживаемые выходные форматы

- Отдельные изображения: JPG, PNG, BMP, TIFF, WebP
- Последовательности изображений: сохраняются как папки
- Анимации: формат GIF

## 2. Начало работы

### Запуск приложения

После установки запустите OpenFocus одним из способов:

1. **Windows (исполняемый файл)**: дважды щёлкните ярлык или исполняемый файл OpenFocus
2. **Исходный код на Python**: выполните `python main.py` в активированной среде conda

После запуска откроется главное окно приложения с тёмной темой оформления.

### Быстрый старт

1. Импортируйте последовательность изображений (Файл → Открыть папку или перетаскивание)
2. Настройте параметры объединения на правой панели
3. При необходимости включите совмещение для выравнивания
4. При необходимости измените размер ядра
5. *(необязательно)* Установите флажок **Быстрый предпросмотр**, чтобы сначала подобрать параметры на уменьшенном черновике
6. Нажмите «Начать рендеринг», чтобы запустить обработку
7. Экспортируйте результаты

## 3. Обзор основного интерфейса

Интерфейс OpenFocus состоит из трёх основных областей:

### Левая панель: область отображения изображений

В левой части окна изображения показываются в разделённом виде:

- **Панель исходного изображения (сверху)**: показывает входную последовательность изображений
- **Панель результата (снизу)**: показывает результаты объединения или совмещения
- **Ползунок навигации**: ползунок под каждой панелью служит для перелистывания кадров
- **Информационные подписи**: показывают номер текущего кадра и размеры изображения

Размер панелей можно менять, перетаскивая разделитель между ними.

### Правая панель: панель управления

Правая панель содержит все параметры конфигурации, расположенные сверху вниз:

1. **Параметры объединения**: выбор алгоритма объединения и размера ядра
2. **Параметры совмещения**: включение и отключение методов выравнивания
3. **Кнопки действий**: сброс к значениям по умолчанию и запуск рендеринга
4. **Список исходных изображений**: все загруженные изображения с именами файлов
5. **Список результатов**: созданные результаты

### Строка меню

Верхняя строка меню открывает доступ ко всем функциям:

- **Файл**: операции импорта и экспорта, список недавних файлов
- **Правка**: преобразования изображений и подписи
- **Инструменты**: пакетная обработка
- **Настройки**: ускорение на GPU, язык, тайлы, совмещение и настройки потоков
- **Справка**: сведения о среде, контактная информация, проверка обновлений и папка журналов

## 4. Импорт изображений и видео

### Открытие папки с изображениями

1. Выберите **Файл → Открыть папку** или нажмите `Ctrl+O`
2. Укажите папку с последовательностью изображений
3. Появится диалог масштаба загрузки — выберите масштаб (100 % = полное разрешение)
4. Нажмите OK, чтобы загрузить изображения

Установите в этом диалоге флажок **Больше не спрашивать**, чтобы в дальнейшем
загружать стек в выбранном масштабе без запроса; **Настройки → Спрашивать масштаб
при импорте** возвращает запрос. Уже загруженный стек можно уменьшить и позже —
командой **Правка → Изменить размер**.

Программа автоматически:
- Найдёт и отсортирует файлы изображений по именам
- Покажет первое изображение на панели источника
- Заполнит список исходных изображений всеми кадрами

### Открытие видеофайлов

1. Выберите **Файл → Открыть видео** или нажмите `Ctrl+Shift+O`
2. Укажите видеофайл (MP4, AVI, MOV, MKV, WMV, FLV, WEBM)
3. Видео автоматически раскладывается на отдельные кадры
4. Каждый кадр становится частью стека изображений

### Файлы проектов

Файл → Сохранить проект сохраняет весь рабочий сеанс в файле `.ofproj`:
точный список исходных файлов (в порядке загрузки), масштаб загрузки, метод
объединения, параметры совмещения, размер ядра, настройки тайлов, потоков и
совмещения, конфигурации подписей и текущий кадр. Файл → Открыть проект
восстанавливает этот сеанс в точности (исходные изображения указываются по
ссылке, а не копируются, — поэтому не перемещайте их). Имя открытого проекта
показывается в заголовке окна.

### Демонстрационный стек

В приветственном диалоге есть кнопка **Загрузить демо-стек**: шесть встроенных
примеров снимков из настоящего фокус-стека, чтобы сразу опробовать весь процесс
без собственных изображений. Пригодится и для проверки установки.

### Кривая резкости

Небольшая кривая над ползунком исходного стека показывает резкость каждого кадра
(нормированную). Расфокусированные кадры видны как провалы, отмеченные красной
точкой. Щёлкните в любом месте кривой, чтобы перейти к этому кадру; при наведении
показывается номер кадра.

### Многостраничные стеки TIFF

Программы для микроскопии (ZEN, NIS-Elements, ImageJ/Fiji) часто экспортируют
целый Z-стек как ОДИН многостраничный файл TIFF. OpenFocus читает каждую страницу
такого файла как отдельный кадр стека — перетащите или откройте файл, и стек
появится целиком (кадры называются `<file>_page_001` и так далее).
Одностраничные TIFF работают как раньше. Обратное тоже возможно:
**Файл → Сохранить стек → (Выровненный / Исходный) → Сохранить как многостраничный TIFF**
записывает весь стек обратно в один `.tif` с сохранением 16-битной глубины.

### Масштабная линейка (для публикаций)

Настройки → Масштабная линейка… задаёт линейку, впечатываемую в экспортируемые
изображения. Размер пикселя (мкм/пикс) определяется автоматически по метаданным
TIFF — соглашение ImageJ `unit=micron`, `PhysicalSizeX` в OME-TIFF или явно
заданная единица разрешения в сантиметрах, — поэтому стеки из микроскопии (в том
числе многостраничные TIFF) калибруются сами. Разрешение принтера (72/300 dpi и
подобное) намеренно *не* считается калибровкой, а введённое вручную значение
всегда важнее найденных метаданных: правдоподобная, но неверная линейка на
иллюстрации хуже, чем её отсутствие. Выберите угол
и цвет (режим «Авто» инвертирует цвет относительно фона); в диалоге есть живой
предпросмотр. Если линейка включена, каждый экспорт (отдельное изображение, стеки
в папку, многостраничный TIFF, GIF, экспорт всех результатов, пакетная обработка)
получает линейку публикационного вида: скруглённая длина из ряда 1-2-5 (около
12 % ширины изображения) и обводка текста для читаемости. В CLI это доступно через
`--scale-bar` (автоматическая калибровка) и `--scale-um <um/px>`.

### Карта глубины (положение фокуса)

**Инструменты → Карта глубины…** оценивает положения фокуса по мере активности выбранного
метода (DCT, DTCWT, GFG-FGF, StackMFF V3, OpenFocus B/C). Это не измеренная поверхность
и не точная карта происхождения пикселей результата объединения. Выберите текущие
отмеченные кадры или записанный источник выбранного результата. Отсутствующие сведения
о происхождении не заменяются текущим стеком. Вычисление, текстура и экспорт привязаны
к одному снимку состояния источника.

Все шесть методов требуют явного нажатия **Вычислить**. Открытие окна и смена меры,
источника, совмещения или параметров не запускают вычисление. Редактор находится сразу
под выбором меры: медианное ядро DCT и начальное ядро GFG принимают нечётные значения
1–51 (по умолчанию 7); B использует окно дисперсии, а C — окно полосовой энергии,
нечётные 1–21 пикс. (по умолчанию 11). Уровни разложения DTCWT редактируются здесь
как локальный черновик, инициализированный параметрами источника. StackMFF V3 показывает свой
режим вывода ИИ (по умолчанию мягкое смешивание или жёсткий выбор) и пояснение вместо
числового ядра: мягкое смешивание оценивает взвешенное по вероятностям непрерывное
положение кадра, жёсткий выбор берёт самый вероятный кадр для каждого пикселя. Ни то,
ни другое не является физическим расстоянием. Начальные значения берутся из параметров
соответствующего результата или сохранённых настроек метода в главном окне. Черновые
значения сохраняются отдельно для источника и метода, пока открыт диалог, и не меняют
главное окно, проект или записанный результат.

Изменение настроек вычисления постоянно помечает прежнюю 2D-карту как **неактуальную**,
очищает 3D-поверхность и блокирует любой экспорт, включая исходные данные, физическую
глубину и OBJ, до успешного нового вычисления. Активная задача отменяется кооперативно.
После её завершения снова нажмите **Вычислить**: следующая задача не ставится в очередь
и не запускается автоматически. Кнопка остаётся видимой и отключается на время вычисления,
отмены и экспорта модели.

- **Цветовая карта**: оттенки серого (стандарт для публикаций) плюс 15 научных
  палитр (Turbo, Viridis, Magma, …) и
  ваша собственная — *Новая пользовательская схема…* строит градиент из любого
  числа цветовых точек (двойной щелчок по точке меняет позицию и цвет); свои схемы
  сохраняются и предлагаются в раскрывающемся списке.
- **Инвертировать / Гамма / Сглаживание**: переворачивает ось глубины,
  перебалансирует тон (гамма < 1 высветляет малые индексы) и убирает крапчатость
  проходом с учётом границ.
- **Наложение**: 2D-карта смешивается со связанным результатом с регулируемой
  непрозрачностью только при совпадении областей координат.
- **Экспорт**: цветная версия поддерживает PNG/JPEG/TIFF/BMP. Исходный 16-битный TIFF
  кодирует нормированные индексы фокуса значениями 0–65535; это не данные с плавающей
  точкой без потерь и не физические расстояния. JPEG/BMP для исходных данных запрещены.
- **3D-модель / 3D-текстура**: по умолчанию длинная сторона сетки содержит 600 вершин.
  При каждом новом открытии выбран режим **Автоматически (истинные цвета)**: связанный
  результат используется, только если его идентичность и область координат/ROI совпадают
  с завершённой картой. Иначе используется первый участвующий кадр завершённого вычисления,
  после совмещения и в фактическом порядке. Имя выбранного результата или кадра отображается.
  Можно явно выбрать подходящий результат, участвующий кадр или **Псевдоцвета глубины**;
  отсутствие доступной текстуры указывается явно. 3D-предпросмотр и PNG-текстура OBJ
  используют одно изображение. 2D-карта сохраняет собственную палитру и наложение;
  изменения палитры и гаммы не перекрашивают фотографии. Только явно выбранная
  псевдоцветная текстура следует палитре, гамме и инверсии. Неподвижный предпросмотр
  и экспорт используют одно дискретизированное поле высот без дополнительного скрытого
  сглаживания. Относительный рельеф — визуализация в единицах изображения.

Вычисление идёт в фоне с индикатором прогресса и возможностью отмены; метод ИИ
использует то же экономное по памяти разбиение на тайлы, что и ИИ-объединение,
поэтому глубокие стеки обрабатываются. Аналог в CLI — `--depth-map [path]`
вместе с `--depth-colormap`.

### Автовосстановление после сбоя

OpenFocus постоянно хранит снимок рабочего сеанса (стек, настройки, подписи,
текущий кадр). Если приложение закрылось неожиданно — из-за сбоя, отключения
питания или принудительного завершения, — при следующем запуске это
обнаруживается и предлагается **Восстановить сеанс**, чтобы вернуться ровно туда,
где вы остановились. При корректном выходе запрос не появляется. Данные
восстановления хранятся рядом с настройками (в портативной установке — рядом с
исполняемым файлом, так что переезжают вместе с ней).

### Недавние файлы

Каждый открытый стек запоминается в **Файл → Открыть недавнее** (до 8 записей).
Нажмите `Alt+1`–`Alt+8`, чтобы сразу открыть нужную запись. Повторное открытие
того же стека поднимает его наверх; записи, файлы которых больше не существуют,
удаляются с подтверждением, а **Очистить список недавних** опустошает меню.

### Перетаскивание

Папку можно перетащить прямо в окно приложения, чтобы импортировать изображения.
Если перетащить файлы в уже загруженный стек, они добавятся к нему (после проверки
размеров).

### Ориентация EXIF

JPEG/TIFF-файлы камер с тегом EXIF Orientation автоматически поворачиваются и
отражаются при импорте, поэтому портретные снимки загружаются правильно
ориентированными.

### 16-битные источники

16-битные PNG/TIFF определяются автоматически и сохраняются на всём пути:
объединение идёт на полной глубине, а результаты можно сохранять обратно как
16-битные PNG/TIFF (экспорт в JPG/BMP преобразуется в 8 бит, поскольку эти
форматы не умеют хранить 16 бит).

RAW-файлы камер проявляются в 16 бит (баланс белого камеры, гамма sRGB) с
отключённым автоповышением яркости, чтобы все кадры стека получали одинаковое
отображение экспозиции; автоматическая экспозиция для каждого кадра заставила бы
яркость мигать от кадра к кадру. Сохраняйте в TIFF или PNG, чтобы не потерять
16-битные данные.

### Очистка стека

Чтобы удалить все загруженные изображения, выберите **Файл → Очистить стек** или
нажмите `Ctrl+W`.

## 5. Просмотр и навигация по изображениям

### Навигация по стеку изображений

- **Ползунок**: перетаскивайте ползунок под панелью источника, чтобы перелистывать кадры
- **Список файлов**: щёлкните имя файла в списке исходных изображений на правой панели
- **Клавиатура**: используйте стрелки влево/вправо

### Масштабирование и панорамирование

- **Увеличение/уменьшение**: колесо мыши над изображением
- **Точное масштабирование**: удерживайте `Ctrl` и крутите колесо для меньшего шага
- **По размеру окна**: двойной щелчок по изображению переключает между вписыванием и видом 100 %
- **Панорамирование**: нажмите и перетаскивайте, чтобы перемещать изображение внутри панели

### Синхронная навигация

При переходе по кадрам на панели источника панель результата показывает
соответствующий кадр результата, если он есть.

## 6. Сравнение «Шторка»

Режим «Шторка» накладывает два изображения в одном кадре с перетаскиваемым
вертикальным разделителем, поэтому несовпадения и разница в качестве сразу видны
по разные стороны от него.

### Открытие режима «Шторка»

1. Получите хотя бы один результат (объединение или совмещение)
2. Нажмите переключатель **Шторка** в правом верхнем углу заголовка панели результата
3. Область результата переключится в режим сравнения; нажмите **Шторка** снова, чтобы вернуться

### Как читать вид сравнения

- **Сторона A (слева от разделителя)**: кадр источника — по умолчанию он следует за ползунком исходного стека
- **Сторона B (справа от разделителя)**: последний результат рендеринга
- **Белый разделитель с круглым ползунком**: перетаскивайте по горизонтали, чтобы двигать границу
- Перетаскивание через разделитель краёв, которые «прыгают», выявляет ошибки совмещения, плохо заметные при сравнении панелей рядом

### Что сравнивать

Панель внизу вида сравнения содержит по одной группе для каждой стороны:

- **Сторона A** — установите **Следовать за источником** (по умолчанию), чтобы сторона следовала за ползунком исходного стека, или снимите флажок, чтобы закрепить на любом кадре собственным ползунком
- **Сторона B** — установите **Последний результат** (по умолчанию), чтобы всегда показывать самый свежий рендеринг, или снимите флажок, чтобы листать историю результатов своим ползунком

Обе стороны обновляются сразу: новые результаты, перемещения ползунка источника и
удаление кадров отражаются немедленно.

### Масштабирование и панорамирование

Вид сравнения применяет одно преобразование к обоим изображениям:

- **Масштаб**: колесо мыши (масштабирует вокруг курсора)
- **Панорама**: нажмите и перетаскивайте в любом месте, кроме разделителя
- **Сброс**: двойной щелчок

Режим «Шторка» и режим ROI используют одну и ту же панель результата, поэтому
вход в один выходит из другого. Очистка стека также выключает режим «Шторка».

## 7. Совмещение изображений

Совмещение устраняет пространственное несовпадение кадров в стеке. Оно
необходимо, когда снимки слегка смещены или сняты с другой перспективой.

### Методы совмещения

#### ECC (улучшенный коэффициент корреляции)

- Ищет наилучшее выравнивание оптимизацией по корреляции
- Подходит для небольших смещений
- Даёт субпиксельную точность
- Медленнее гомографии, но точнее

#### Гомография

- Основана на сопоставлении особых точек (признаки SIFT/ORB)
- Справляется с более крупными геометрическими преобразованиями
- Для начального выравнивания быстрее ECC
- Хороша для снимков со значительным изменением перспективы

#### OpenFocus (быстро)

- Ограниченное выравнивание подобия (сдвиг + поворот + масштаб),
  с выравниванием яркости по кадрам и автокадрированием
- Менее секунды на кадр — намного быстрее ECC или гомографии
- Кадры, смещённые **более чем на 8 % размера кадра, остаются невыровненными**,
  а не исправляются частично. Порог меняется в CLI параметром
  `--align-shift-limit`
- Для нежёсткой или экстремальной геометрии выбирайте ECC или гомографию

### Включение совмещения

1. На правой панели найдите группу **Совмещение**
2. Выберите один метод в раскрывающемся списке: **Без выравнивания**, **OpenFocus (быстро)**,
   **ECC** или **Гомография**
3. Быстрое выравнивание OpenFocus можно также поставить перед ECC или
   гомографией (сначала грубый глобальный проход, затем точный локальный)

### Когда нужно совмещение

- На изображениях заметно несовпадение
- Снимки сделаны с рук
- В сцене есть параллакс (близкие объекты смещаются между кадрами)
- В результатах видны ореолы или двоение

### Настройки совмещения

Дополнительные параметры открываются через **Настройки → Настройки совмещения**:
- **Ширина уменьшения**: разрешение предварительной обработки (по умолчанию 1024 px)
- Меньшие значения — быстрее обработка, но точность может снизиться
- Большие значения — медленнее обработка, но точность может вырасти

## 8. Методы объединения изображений

OpenFocus предлагает десять алгоритмов объединения (плюс режим только
выравнивания). У каждого свои особенности, подходящие для разных типов
изображений.

### Направляющий фильтр (по умолчанию)

- **Алгоритм**: направляющая фильтрация с сохранением границ
- **Лучше всего для**: универсальных задач, разумный баланс скорости и качества
- **Преимущества**: хорошо сохраняет границы, быстро работает
- **Параметр**: размер ядра (от 1 до 51, только нечётные значения)
  - Меньшее ядро: больше локальных деталей, возможен рост шума
  - Большее ядро: более гладкий результат, лучше подавление шума

### DCT (дискретное косинусное преобразование)

- **Алгоритм**: объединение в частотной области по коэффициентам DCT
- **Лучше всего для**: изображений, богатых текстурами, научной съёмки
- **Преимущества**: сохраняет тонкие текстуры, математически обоснован
- **Параметр**: размер ядра задаёт окно обработки

### DTCWT (комплексное вейвлет-преобразование с двойным деревом)

- **Алгоритм**: объединение в многомасштабной вейвлет-области
- **Лучше всего для**: сложных сцен с деталями разных масштабов
- **Преимущества**: отличный многомасштабный анализ, хорошая направленность
- **Правило объединения**: одно решение на пиксель и уровень для всех ориентаций и
  цветовых каналов (N-вариантный выбор с проверкой согласованности большинством);
  низкочастотная полоса следует самому грубому решению, а не усреднению всех кадров
- **Параметр**: уровни вейвлетов (1–6, по умолчанию 4) на правой панели. У метода
  нет пространственного ядра, поэтому ползунок ядра для него скрыт.

### GFG-FGF (гауссоподобный градиент по четырём соседям + быстрый направляющий фильтр)

- **Алгоритм**: реализация метода Fu et al. (*Laser & Optoelectronics
  Progress*, 2024): карта фокуса по разности размытий |I − mean(I)| обогащается
  оператором гауссоподобного градиента по четырём соседям (GFG), уточняется
  быстрым направляющим фильтром, решение принимается по каждому пикселю (ничьи
  разрешаются мерой малой области по Собелю 3×3), а бинарные карты решений
  повторно сглаживаются быстрым направляющим фильтром перед взвешенным
  смешиванием.
- **Лучше всего для**: микроскопии и снимков с чёткими областями фокуса
- **Преимущества**: быстро, резкие границы областей фокуса; память не растёт
  с числом кадров
- **Параметр**: ядро = размер фильтра среднего для грубой карты фокуса

### StackMFF (V1, глубокое обучение)

- **Алгоритм**: 3D U-Net предсказывает яркость объединённого изображения
  для всего стека за один проход; Cb/Cr берутся из ближайшего исходного кадра
- **Лучше всего для**: стеков без фиксированного порядка фокусировки или
  снятых не непрерывной серией
- **Преимущества**: не зависит от порядка, без параметров, цвет в пределах gamut
- **Примечание**: 6 млн параметров; большим стекам помогает GPU

### StackMFF V2 (глубокое обучение)

- **Алгоритм**: оценка фокуса по слоям, уточнённая двунаправленным
  рекуррентным слоем; сеть регрессирует индекс фокальной плоскости и
  выбирает кадры из стека. **Кадры должны сохранять исходный порядок
  фокусировки** — обратный порядок отключён
- **Карты глубины**: поддерживаются; сообщают выбранный фокальный слой
- **Лучше всего для**: непрерывных серий фокусировки с очень маленькой быстрой моделью
- **Требования**: PyTorch; около 0,05 млн параметров; без параметров
### StackMFF V3 (глубокое обучение)

- **Алгоритм**: попиксельная классификация источника (требуется PyTorch).
  Сеть предсказывает для каждого пикселя, из какого входного кадра он взят, а затем
  либо смешивает кадры по этим вероятностям, либо выбирает один кадр
- **Режим вывода ИИ** (правая панель, только для этого метода):
  - **Мягкое смешивание (взвешенное)** — по умолчанию; каждый пиксель — это
    взвешенная по вероятностям смесь кадров. Плавные переходы, без резких швов;
    соответствует конфигурации из статьи
  - **Жёсткий выбор (один кадр)** — каждый пиксель копируется из наиболее
    вероятного кадра. Более чёткий выбор без межкадровой интерполяции; на границе
    двух равновероятных кадров может появиться шов
- **Лучше всего для**: максимального качества при наличии GPU
- **Преимущества**: не зависит от порядка кадров (их порядок никогда не меняет
  результат), работает со стеком любой длины, не требует подбора параметров,
  оптимизируется автоматически
- **Требования**: установленный PyTorch, GPU с CUDA по желанию (torchvision не нужен)
- **Примечание**: может быть недоступен, если PyTorch не установлен

### OpenFocus A / B / C

- **Алгоритм**: взвешенное по дисперсии среднее, выбор по карте дисперсии и
  объединение на пирамиде Лапласа
- **OpenFocus A**: взвешенное по дисперсии среднее с приоритетом последнего кадра —
  быстро, стабильные цвета на коротких стеках
- **OpenFocus B**: выбор по карте дисперсии — для каждого пикселя берётся самый
  резкий кадр; лучше всего на гладких поверхностях и в микроскопии
- **OpenFocus C**: смешивание по полосам пирамиды Лапласа — естественный вид на
  текстурированных объектах, усиливает локальный контраст
- **Параметры**: A и B используют окно дисперсии (ползунок ядра); у C радиуса нет.
  Все три используют сигму сглаживания.

**Сглаживание**: один счётчик под ползунком ядра, смысл зависит от выбранного
метода (диапазон 0–8, шаг 0,2):

| Метод | Подпись | По умолчанию | Эффект |
|---|---|---|---|
| OpenFocus A | Сглаживание смешивания (σ) | 2,0 | Гауссово сглаживание карты весов кадров — насколько широко смешиваются резкие области соседних кадров |
| OpenFocus B | Сглаживание глубины (σ) | 1,2 | Гауссово сглаживание карты глубины — ширина перехода между кадрами |
| OpenFocus C | Сглаживание смешивания (σ) | 3,0 | Гауссово сглаживание карты весов каждой полосы пирамиды |

Значение 0 сохраняет самый чёткий попиксельный выбор (мельчайшие детали, но
крапчатость на шумных стеках); большие значения смягчают переходы и ореолы.
Каждый метод запоминает своё значение между сеансами, и пакетная обработка
использует то же правило.

У C нет радиуса: метод C в Helicon предоставляет только сглаживание, поэтому
ползунок ядра для C скрыт, а не молча ничего не делает.

CLI: `--depth-smoothing SIGMA` (B) и `--blend-smoothing SIGMA` (A, C).

**Параметры яркости задаются отдельно для каждого метода.** *Выравнивать экспозицию
перед объединением* и *Убирать дрейф яркости* запоминаются отдельно для каждого
метода объединения, потому что отвечают на вопрос конкретного стека, а не на общий
вопрос предпочтений. Оба по умолчанию включены для OpenFocus A/B/C (у которых нет
встроенной калибровки экспозиции); остальные методы сохраняют прежние значения по
умолчанию (выравнивание экспозиции включено, удаление дрейфа выключено).
При переключении метода показываются его собственные значения.

### Только выравнивание (без объединения)

Выберите **Только выравнивание (без объединения)** в качестве метода, чтобы
совместить стек и отправить выровненные кадры в список результатов без
объединения — удобно для оценки качества совмещения или экспорта выровненных
кадров.

### Выбор метода объединения

1. На правой панели найдите группу **Объединение**
2. Выберите метод в **раскрывающемся списке** (всегда выбран ровно один;
   первый пункт выполняет совмещение без объединения)
3. При необходимости настройте размер ядра — подпись показывает, что означает
   ядро для выбранного метода
4. Нажмите **Начать рендеринг**, чтобы запустить обработку

### Сравнительная таблица алгоритмов

| Алгоритм | Скорость | Качество | Лучше всего для |
|-----------|-------|---------|----------|
| Направляющий фильтр | Быстро | Хорошо | Общего применения |
| DCT | Средне | Хорошо | Текстур |
| DTCWT | Средне | Очень хорошо | Сложных сцен |
| GFG-FGF | Быстро | Хорошо | Областей фокуса |
| ИИ-объединение (StackMFF V3) | Медленно (GPU) | Отлично | Наилучшего качества |
| OpenFocus A | Очень быстро | Очень хорошо | Коротких стеков, стабильности цвета |
| OpenFocus B | Очень быстро | Очень хорошо | Гладких поверхностей, микроскопии |
| OpenFocus C | Быстро | Очень хорошо | Текстурированных объектов, естественного вида |

### Быстрый предпросмотр (черновой рендеринг)

Подбор параметров на больших стеках в полном разрешении идёт медленно. Установите
флажок **Быстрый предпросмотр** над кнопкой рендеринга, и OpenFocus сначала
отрисует уменьшенный черновик (длинная сторона 1200 px) — обычно в несколько раз
быстрее, включая совмещение. После рендеринга предпросмотр отображается с пометкой
«Предпросмотр» в сводке строки состояния и **не добавляется** в историю результатов.
Снимите флажок и запустите рендеринг снова, чтобы получить результат в полном
разрешении. Режим предпросмотра не применяется к рендерингу ROI и никогда не
попадает в кэш совмещения полного разрешения.

## 9. Преобразования изображений

### Поворот

1. Выберите **Правка → Поворот**
2. Выберите тип поворота:
   - **90° по часовой стрелке**: поворот всех изображений на 90 градусов вправо
   - **90° против часовой стрелки**: поворот всех изображений на 90 градусов влево
   - **180°**: переворот изображений вверх ногами

### Отражение

1. Выберите **Правка → Отражение**
2. Выберите тип отражения:
   - **Отразить по горизонтали**: зеркальное отражение слева направо
   - **Отразить по вертикали**: зеркальное отражение сверху вниз

### Изменение размера

1. Выберите **Правка → Изменить размер**
2. Откроется диалог параметров изменения размера
3. Введите новые размеры или процент масштабирования
4. Все изображения в стеке масштабируются пропорционально

### Порядок преобразований

Преобразования применяются ко всему стеку изображений и сохраняют выравнивание
между кадрами.

## 10. Ретушь, подписи и аннотации

### Ретушь результата (Правка → Ретушь результата…, `Ctrl+T`)

Объединение всё же может оставить локальный дефект — ореол на контрастной границе,
деталь, взятую из неверного кадра, шум на ровном участке. Кисть ретуши копирует
пиксели исходного кадра на результат:

1. Отрисуйте результат (или выберите его в списке результатов; правый щелчок →
   *Ретушь результата…* тоже работает) и нажмите `Ctrl+T`.
2. Зарисуйте дефект левой кнопкой мыши. Если включён **Автовыбор самого резкого
   кадра для каждого штриха** (по умолчанию), каждый штрих сначала выбирает кадр
   с наибольшей детализацией под кистью — исправление ореола обычно требует одного
   движения. Выключите его, чтобы выбирать кадр самостоятельно ползунком
   или клавишами `,` / `.`.
3. Настройте **радиус** (`[` / `]`), **жёсткость** (мягкие края скрывают шов) и
   **непрозрачность**. Перекрывающиеся мазки внутри одного штриха не накапливаются.
4. **Показать исходный кадр** (`Tab`) показывает кадр, с которого вы копируете.
   Колесо масштабирует, перетаскивание правой/средней кнопкой панорамирует,
   `F` вписывает изображение.
5. `Ctrl+Z` / `Ctrl+Y` отменяют и повторяют целые штрихи. **Применить как новый результат**
   добавляет отретушированное изображение в список результатов (суффикс `_Retouched`);
   исходный результат остаётся нетронутым.

Кисть использует выровненные кадры, из которых получился результат, поэтому
совпадает с ним; 16-битные результаты остаются 16-битными. Результаты по ROI и
изменённые по размеру стеки ретушировать нельзя (их кадры больше не совпадают по
геометрии с результатом).

### Добавление подписей

1. Убедитесь, что есть результаты рендеринга или загруженные изображения
2. Выберите **Правка → Добавить подпись**
3. Введите текст подписи в диалоге
4. Подписи добавляются и на выровненный стек, и на исходный

### Удаление подписей

- **Удалить подписи выровненного стека**: убирает подписи с выровненных изображений
- **Удалить подписи исходного стека**: убирает подписи с исходных изображений

Эти пункты доступны в подменю **Правка → Удалить подпись**.

## 11. Настройки и конфигурация

### Настройки тайлов (оптимизация памяти)

Для больших изображений OpenFocus обрабатывает тайлы, чтобы избежать проблем с
памятью.

Открываются через **Настройки → Настройки тайлов**:

- **Размер блока тайла**: размер каждого обрабатываемого тайла (по умолчанию 1024 px)
- **Перекрытие тайлов**: перекрытие между тайлами для бесшовного смешивания (по умолчанию 256 px)
- **Порог тайлинга**: размер изображения, выше которого включаются тайлы (по умолчанию 2048 px)

**Рекомендации**:
- Меньший блок: меньше памяти, медленнее обработка
- Больший блок: больше памяти, быстрее обработка
- Увеличьте перекрытие, если в результатах видны швы

### Настройки совмещения

Открываются через **Настройки → Настройки совмещения**:

- **Ширина уменьшения**: разрешение предварительной обработки для совмещения
  - По умолчанию: 1024 px
  - Меньше — быстрее, больше — точнее

### Справочник по производительности

См. [PERFORMANCE.md](./PERFORMANCE.md): там измеренная пропускная способность и
расход памяти на больших реальных стеках, а также практические рекомендации для
глубоких стеков и входных данных высокого разрешения.

### Настройки потоков

Управление параллельной обработкой на CPU:

Открываются через **Настройки → Настройки потоков**:

- `0` означает автоматический выбор и используется по умолчанию для новых настроек.
- Положительное значение ограничивает число потоков; сохранённые пределы сохраняются.
- Доступная мощность CPU, режим ресурсов и свободная память могут уменьшить параллелизм.

### Ускорение на GPU

OpenFocus использует GPU (CUDA/MPS) только для нейросетевой модели ИИ
(StackMFF V3); классические алгоритмы всегда работают на CPU.

- Переключатель находится в **Настройки → Ускорение на GPU**
- Если снять флажок, всё будет выполняться на CPU — полезно, когда драйверы GPU работают некорректно
- Пока GPU отключён, на панели состояния показывается `CPU*`
- Выбор применяется при следующем рендеринге и запоминается

### Размер пакета ИИ

Открывается через **Настройки → Размер пакета ИИ**:

- Сохранённый предел пакета по умолчанию равен 2; сейчас на каждом устройстве обрабатывается один тайл за вызов.
- Увеличение предела не включает параллельную пакетную обработку на GPU.

### Темы

Доступны две темы интерфейса: **Тёмная (по умолчанию)** и **Светлая**. Переключение —
**Настройки → Тема**; выбор применяется сразу (заголовок окна Windows тоже
изменяется) и запоминается. При первом запуске тема выбирается в приветственном
диалоге.

### Портативный режим

Создайте пустой файл с именем `OpenFocus.portable` рядом с `OpenFocus.exe`
(в портативном zip-архиве он уже есть) — и все пользовательские данные (настройки,
журналы, недавние файлы) будут храниться в папке `OpenFocusData` рядом с
приложением, а не в вашем профиле пользователя, так что установка помещается на
флешку. Удалите этот файл-маркер, чтобы вернуться к обычному профилю.

### Метаданные EXIF

Метаданные источника (модель камеры, экспозиция, ориентация и т. д.) сохраняются:
ориентация применяется при загрузке, а экспорт в PNG/TIFF/WebP автоматически
встраивает исходный EXIF. Экспорт в JPG/BMP не может хранить полный EXIF и
записывается без него.

### Ввод HEIC/HEIF

Фотографии iPhone загружаются напрямую. Нужен необязательный пакет `pillow-heif`
(`pip install pillow-heif`; в готовых сборках он уже включён).

### Обновления

Файлы проектов (`.ofproj`) ведут себя как документ: в заголовке окна показывается
имя проекта с символом `*`, пока есть несохранённые изменения, а при закрытии
приложения или открытии другого проекта сначала спрашивается подтверждение.
Проект хранит список кадров, масштаб загрузки, все параметры рендеринга, подписи и
текущий кадр — сами изображения указываются по ссылке, а не копируются.

Справка → Проверить обновления сравнивает вашу версию с релизами на GitHub.
**Скачать и установить** загружает новый установщик прямо в приложении (с
индикатором прогресса) и запускает его; «Открыть страницу загрузки» ведёт к списку
релизов. Проверка выполняется без уведомления не чаще раза в день.

### Кэш совмещения

OpenFocus может хранить результаты совмещения в папке `.openfocus_cache` рядом с
исходным стеком. При повторном открытии того же стека (если файлы не изменились)
выравнивание полностью пропускается. Переключатель — **Настройки → Кэш
совмещения**; устаревшие записи заменяются автоматически.

### Сохраняемые настройки

Всё перечисленное ниже автоматически переживает перезапуск приложения:
число потоков, параметры тайлов, ширина уменьшения при совмещении, размер пакета
ИИ-объединения (StackMFF V3), переключатель ускорения на GPU, переключатель кэша
совмещения, язык интерфейса, размер окна и расположение панелей, формат экспорта
перетаскиванием и недавно открытые стеки. Диалоги настроек сохраняются в момент
подтверждения; всё также сохраняется при закрытии приложения. Параметры
хранятся отдельно для каждого пользователя в `OpenFocus/OpenFocus.ini` (формат
INI QSettings).

### Язык интерфейса

Переключить можно в любой момент: **Настройки → Язык → English / 中文**. Изменение
применяется сразу и запоминается для следующих сеансов.

### Автоматическая проверка обновлений

Раз в день, через несколько секунд после запуска, OpenFocus незаметно проверяет
GitHub на наличие новой версии. Если она есть, над панелями изображений появляется
баннер: версия, **Обновить** (загружает и перезапускает за один шаг),
**Что нового** (заметки о выпуске) и кнопка закрытия. Закрытие скрывает баннер
только для этой версии — следующий выпуск вернёт его, а
**Справка → Проверить обновления** включает его сразу.

Пока загрузка идёт в фоне, строка состояния показывает прогресс.
Проверить обновления вручную можно в любой момент через **Справка → Проверить обновления**.

## 12. Пакетная обработка

Автоматическая обработка нескольких папок:

1. Выберите **Инструменты → Пакетная обработка** или нажмите соответствующий пункт
2. В диалоге пакетной обработки:
   - **Добавить папки**: выберите папки с последовательностями изображений
   - **Удалить выбранные**: удалите выбранные папки из списка
   - **Очистить всё**: удалите все папки
3. Настройте параметры вывода:
   - **Создать подпапку в исходной папке**: результаты создаются в каждой входной папке
   - **Как в исходной папке**: перезаписать или сохранить рядом с исходными файлами
   - **Указать папку вывода**: задайте место сохранения
4. Проверьте текущие параметры объединения и совмещения
5. Нажмите **Начать пакетную обработку**, чтобы запустить

Диалог пакетной обработки показывает прогресс в реальном времени. Обработку можно
отменить в любой момент.

### Примечания к пакетной обработке

- Используются те же параметры объединения и совмещения, что и при ручной обработке
- Каждая папка обрабатывается независимо
- Имена файлов содержат отметку времени и параметры для идентификации

## 13. Экспорт результатов

### Сохранение отдельного результата

1. Выберите нужный результат в списке результатов
2. Выберите **Файл → Сохранить** или нажмите `Ctrl+S`
3. Укажите формат и место сохранения
4. Нажмите «Сохранить»

### Формат при перетаскивании

При перетаскивании результатов из списка результатов записываются файлы
изображений в формате, выбранном в контекстном меню списка результатов
(**Формат при перетаскивании**: JPG, PNG или TIFF). Выбор запоминается.

### Сохранение выровненного стека

1. Выберите **Файл → Сохранить стек → Выровненный стек**
2. Выберите формат сохранения:
   - **Сохранить как папку**: каждый выровненный кадр сохраняется отдельным файлом
   - **Сохранить как GIF**: создаётся анимированный GIF выровненной последовательности

### Сохранение исходного стека

1. Выберите **Файл → Сохранить стек → Исходный стек**
2. Выберите формат сохранения:
   - **Сохранить как папку**: исходные кадры сохраняются отдельными изображениями
   - **Сохранить как GIF**: создаётся анимированный GIF исходной последовательности

### Форматы экспорта

- **JPG**: сжатый, хорошее соотношение качества и размера
- **PNG**: без потерь, поддерживает прозрачность
- **BMP**: без сжатия, максимальное качество
- **TIFF**: высокое качество, поддерживает слои
- **GIF**: формат анимации

## 14. Интерфейс командной строки

OpenFocus может работать без графического интерфейса — удобно для
скриптовых конвейеров и CI. Из среды Python (или рядом с готовым исполняемым
файлом):

```bash
# Fuse a folder with the default Guided Filter
python main.py --input ./stack_folder --output ./result/fused.png

# DTCWT with ECC registration, 8 threads
python main.py -i ./stack_folder -o ./result/fused.png -m dtcwt -a ecc -t 8

# StackMFF V3 forced to CPU with a custom tile size
python main.py -i ./stack_folder -o ./result/fused.png -m stackmffv3 --cpu --tile-size 512

# Explicit file list; video files are also accepted as input
python main.py -i img1.jpg img2.jpg img3.jpg -o fused.png -m gfgfgf

# Single multi-page TIFF Z-stack with a metadata-calibrated scale bar
python main.py -i ./zstack.tif -o fused.png -m dtcwt --scale-bar
```

| Параметр | Описание |
|--------|-------------|
| `--input, -i` | Папка с изображениями, видеофайл или один либо несколько файлов изображений |
| `--output, -o` | Путь к выходному изображению (расширение задаёт формат) |
| `--method, -m` | `stackmffv3` (по умолчанию), `none`, `openfocus_a`, `openfocus_b`, `openfocus_c`, `guided_filter`, `dct`, `dtcwt`, `gfgfgf` |
| `--align, -a` | `none` (по умолчанию), `homography`, `ecc`, `both`, `openfocus` |
| `--align-shift-limit` | Только для `openfocus`: максимально допустимый сдвиг как доля размера кадра (по умолчанию 0.08; кадры с большим сдвигом остаются невыровненными) |
| `--exposure-match` | Приводит среднее каждого кадра к последнему кадру перед объединением (по умолчанию включено; `--no-exposure-match` отключает). Коэффициенты общие для всего стека, поэтому тайловый результат остаётся бесшовным; применяется ко всем методам и к опорной яркости выравнивателя OpenFocus |
| `--base-frame` | Необязательный шаг после объединения: подгоняет низкие частоты результата к `last`/`first` кадру (по умолчанию `none`) |
| `--sort` | Порядок кадров для `openfocus_a/b/c`: `asc` (по умолчанию, порядок файлов), `desc` (обратный порядок съёмки от дальних к ближним), `off` |
| `--dust-map WHITE` | Коррекция по плоскому полю (карта пыли) по расфокусированному снимку белого поля |
| `--kernel, -k` | Размер ядра (принудительно нечётный; для семейства openfocus задаёт радиус окна дисперсии) |
| `--depth-smoothing SIGMA` | Только `openfocus_b`: гауссова сигма перехода глубины между кадрами (по умолчанию 1.2; 0 сохраняет мельчайшие детали) |
| `--blend-smoothing SIGMA` | Только `openfocus_a` / `openfocus_c`: гауссова сигма карты весов кадров (по умолчанию 2.0 для A, 3.0 для C; 0 сохраняет самый чёткий попиксельный выбор) |
| `--threads, -t` | Предел потоков; `0` = автоматически (по умолчанию), положительные значения ограничивают параллелизм |
| `--resource-preference` | Режим ресурсов: `balanced` (по умолчанию), `responsive` или `maximum` |
| `--batch-size` | Предел пакета тайлов ИИ (по умолчанию 2); сейчас один тайл за вызов |
| `--cpu` | Принудительно использовать CPU, даже если доступен GPU |
| `--downscale` | Ширина уменьшения при поиске признаков для совмещения |
| `--tile-size` | Размер блока тайла для больших изображений |
| `--output-dir, -d` | Пакетный режим: объединить все входные папки, записав `<folder>.png` для каждого стека |
| `--scale-bar` | Нарисовать масштабную линейку (калибровка автоматически определяется по метаданным TIFF) |
| `--depth-map [path]` | Дополнительно сохранить раскрашенную карту положения фокуса (глубины) (по умолчанию `<output>_depth.png`) |
| `--depth-colormap` | Цветовая карта для `--depth-map`: turbo, viridis, jet, gray, … (по умолчанию turbo) |
| `--scale-um` | Размер пикселя в мкм/пикс, важнее метаданных (подразумевает `--scale-bar`) |

Коды возврата: `0` — успех, `1` — ошибка обработки, `2` — ошибка использования.
Запуск `python main.py --help` печатает все параметры; запуск с простым путём
(`python main.py C:\stack`) по-прежнему открывает графический интерфейс с
загруженной папкой.

## 16. Устранение неполадок

### Частые проблемы

#### «Изображения не загружены»

- Убедитесь, что вы сначала импортировали папку с изображениями или видео
- Проверьте, что в папке есть поддерживаемые форматы изображений

#### Результат объединения размыт или двоится

- Включите совмещение изображений (выберите в списке: гомография / ECC / OpenFocus быстро)
- Убедитесь, что изображения правильно выровнены до объединения
- Попробуйте другой алгоритм объединения
- Увеличьте размер ядра для более гладкого результата

#### ИИ недоступен

- Установите PyTorch: `pip install torch torchvision`
- Для работы на GPU установите сборку PyTorch с CUDA
- Проверьте через **Справка → Сведения о среде**

#### Ошибки нехватки памяти

- Включите обработку тайлами в **Настройки → Настройки тайлов**
- Уменьшите размер блока тайла
- Используйте меньшие ядра
- Уменьшите разрешение изображений

#### Совмещение не удаётся

- Пробуйте только один метод совмещения за раз
- Уменьшите ширину уменьшения в **Настройки → Настройки совмещения**
- Убедитесь, что на изображениях достаточно контраста и деталей

#### Обработка идёт медленно

- Увеличьте число потоков в **Настройки → Настройки потоков**
- Используйте более мощный CPU
- Уменьшите разрешение изображений
- Используйте более простые алгоритмы объединения (направляющий фильтр вместо ИИ-объединения)

#### Предупреждение Windows SmartScreen при первом запуске

Опубликованные сборки не подписаны. Нажмите **Подробнее → Выполнить в любом случае**.
Первый запуск после распаковки может занять 30–60 секунд.

#### macOS сообщает, что приложение «не может быть открыто» или «повреждено»

Приложение не подписано и не нотаризовано. Переместив `OpenFocus.app` в папку
Applications, выполните:

```bash
xattr -cr /Applications/OpenFocus.app
```

или щёлкните приложение правой кнопкой и выберите **Открыть**. Опубликованные
сборки macOS предназначены для Apple Silicon (M1/M2/M3/M4); на Mac с Intel можно
запускать из исходного кода.

2. **Связаться с нами**: откройте **Справка → Связаться с нами** для получения информации о поддержке

## Приложение: подробности алгоритмов объединения

### Направляющий фильтр

Направляющий фильтр выполняет сглаживание с сохранением границ, используя
направляющее изображение. Он вычисляет локальные линейные преобразования между
направляющим и входным изображениями, а затем применяет их к результату. Этот
метод отлично сохраняет границы и одновременно подавляет шум.

### DCT (дискретное косинусное преобразование)

DCT переводит изображения в частотную область, где решения об объединении
принимаются по величинам коэффициентов. Высокочастотные составляющие (детали)
сохраняются, а низкочастотные (гладкие области) объединяются по локальной энергии.

### DTCWT (комплексное вейвлет-преобразование с двойным деревом)

DTCWT даёт многомасштабное и многонаправленное разложение изображений. Он
фиксирует особенности на разных масштабах и в разных ориентациях, что позволяет
применять изощрённые правила объединения, сохраняющие и текстуру, и структуру.

### GFG-FGF

Реализует метод Fu et al. (2024): грубая карта фокуса |I − mean(I)| обогащается
гауссоподобным градиентом по четырём соседям — шаблон 3×3 T = [1 2 1; 2 4 2; 1 2 1]/16
даёт P = I⊗T, а G = (|I(x±1,y) − P|)/2 + (|I(x,y±1) − P|)/2 со значениями ниже
T0 = 0.005, которые отбрасываются, — затем уточняется быстрым направляющим
фильтром. Пиксели выбирают кадр с наибольшим значением фокуса (ничьи разрешает
мера малой области по Собелю 3×3), а бинарные карты решений сглаживаются быстрым
направляющим фильтром перед взвешенным смешиванием.

### ИИ-объединение (StackMFF V3)

Подход глубокого обучения с нейронной сетью, обученной на больших наборах пар
многофокусных изображений. Сеть сама изучает оптимальные стратегии объединения и
при правильной настройке даёт результаты на уровне лучших современных методов.
