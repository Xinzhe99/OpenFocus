## 1. 소개

OpenFocus는 연구자, 엔지니어, 이미지 처리 전문가를 위해 만든 전문가용 다초점 이미지 합성 데스크톱 애플리케이션입니다. 고급 정합 및 합성 알고리즘으로 다초점 이미지 시퀀스를 처리해 피사계 심도가 완전한 올인포커스 이미지를 만들어 냅니다.

### 주요 기능

- **다초점 이미지 합성**: 초점이 각기 다른 여러 이미지를 하나의 완전히 초점이 맞은 이미지로 결합합니다
- **열 가지 합성 알고리즘**: StackMFF V1/V2/V3(딥러닝), OpenFocus A/B/C, 가이드 필터, DCT, DTCWT, GFG-FGF, 그리고 정합 전용 모드
- **이미지 정합**: OpenFocus(고속), ECC, 호모그래피 중 하나를 선택해 이동·회전·크기·원근 변화를 보정합니다
- **와이프 비교 보기**: A/B 구분선 보기로 정합 상태를 확인하고 결과를 비교합니다
- **소스 고정 리터치**: 결과를 만든 프레임에서 픽셀을 가져오며 소스/복원/노출 브러시, 획 단위 실행 취소, 레이어 TIFF 내보내기를 제공합니다
- **프로젝트 파일**: 입력 참조와 재현 가능한 처리 설정을 저장합니다(결과 픽셀은 별도로 내보내야 함)
- **처리 템플릿**: 합성·정합·리소스 설정을 저장해 불러온 모든 스택에 다시 적용합니다
- **다중 페이지 TIFF**: 단일 파일 Z-스택을 페이지별로 불러오고 다시 하나의 파일로 내보냅니다
- **깊이 맵**: 픽셀별 초점 위치, 물리 Z 보정, 3D 표면, OBJ 내보내기
- **스케일 바**: 메타데이터 자동 보정 또는 직접 입력을 지원하는 논문용 스케일 바
- **배치 처리**: 여러 폴더, 그룹 합성, 정합만/합성/정합된 스택 저장의 세 가지 출력 모드
- **충돌 자동 복구**: 충돌이 발생하면 마지막 작업 세션을 복원하도록 제안합니다
- **다국어 지원**: English, 中文, 日本語, Español, Deutsch, Français, Русский, 한국어, Português, Italiano, Nederlands, Polski의 12개 언어. 시스템 언어를 자동 감지합니다
- **헤드리스 CLI**: 스크립트 처리, 레시피 재사용, 리터치 재생, CI 연동을 지원합니다
- **Agent로 제어 가능**: 토큰으로 보호된 로컬 채널로 실제 GUI를 조작합니다(명령, 위젯 경로, 실제 마우스·키보드 이벤트)
- **유연한 내보내기**: 결과를 개별 이미지, 폴더, 다중 페이지 TIFF, GIF 애니메이션으로 저장합니다
- **이미지 변환**: 이미지 스택을 회전, 뒤집기, 크기 조정합니다
- **레이블**: 소스 스택, 정합된 스택, 특정 출력에 프레임 번호를 생성할 수 있는 관리형 텍스트 레이블을 추가합니다
- **설정 유지**: 기본 설정, 언어, 최근에 연 스택이 재시작 후에도 그대로 남습니다

### 지원하는 입력 형식

- 이미지 파일: JPG/JPEG, PNG, BMP, TIFF, WebP 및 기타 일반적인 형식
- 동영상 파일: MP4, AVI, MOV, MKV, WMV, FLV, WEBM(자동으로 이미지 시퀀스로 디코딩)
- 번호가 붙은 이미지 시퀀스가 들어 있는 폴더
- 카메라 RAW 파일(DNG, CR2/CR3, NEF, ARW, RAF, ORF, RW2 및 기타 일반적인
  RAW 형식). 디코딩에는 `rawpy`(LibRaw)를 사용하며, `pip install openfocus`
  로 설치하거나 Windows/macOS 빌드에 함께 포함되어 있습니다

투명 PNG 스택은 데스크톱, 데스크톱 배치 처리, CLI에서 그룹 합성 없이 합성할 수 있습니다.
각 프레임은 크기, 비트 깊이, 알파 마스크가 같은 8비트 또는 16비트 PNG여야 하며 마스크는
하나의 비어 있지 않은 사각형 밖에서 0이고 안쪽은 일정한 0이 아닌 불투명도여야 합니다.
일정한 반투명은 허용됩니다. 보이는 사각형만 따로 합성하므로 숨은 색이 초점 측정이나 타일
경계에 영향을 주지 않습니다. PNG 출력은 원래 캔버스와 불투명도를 유지하고 숨은 출력 색은
0입니다. 데스크톱 소스/결과 보기는 투명 영역을 체커보드로 표시합니다.

원래 크기로 불러오고 정합 없음, 빠른 미리보기와 ROI를 끈 뒤 PNG로 렌더링해 저장하세요.
배치는 합성 방식과 PNG 출력이 필요하고 정합된 스택 저장은 지원하지 않습니다. 투명
데이터에서는 정합, 크기 조정/축소, 더스트 보정, 깊이 맵, 비교, 리터치, 레이블, 스케일
바를 쓸 수 없습니다. 사각형 크기를 바꾸는 합성 방식은 거부됩니다. 그라디언트나 페더
마스크, 프레임마다 다른 마스크, 투명 TIFF 입력, GIF와 다중 페이지 TIFF를 포함한 PNG 이외
출력은 지원하지 않습니다. CLI도 투명 입력의 센서 보정과 깊이 맵을 거부합니다. CLI 예:
`python main.py --input ./png-stack --output ./result.png --method guided_filter --align none`.

### 지원하는 출력 형식

- 개별 이미지: JPG, PNG, BMP, TIFF, WebP
- 이미지 시퀀스: 폴더로 저장
- 애니메이션: GIF 형식

## 2. 시작하기

### 애플리케이션 실행

설치 후 다음과 같이 OpenFocus를 실행합니다.

1. **Windows(실행 파일)**: OpenFocus 바로 가기나 실행 파일을 더블클릭합니다
2. **macOS**: DMG의 `OpenFocus.app`을 Applications로 옮긴 뒤 더블클릭합니다. 공증되지 않은 버전은 오른쪽 클릭 → "열기"를 선택합니다
3. **Linux**: 데스크톱 빌드는 없습니다. pip 패키지를 설치하고 `openfocus` 명령을 사용하세요
4. **Python 소스**: 활성화된 conda 환경에서 `python main.py`를 실행합니다

최신 버전은 [OpenFocus 공식 사이트](https://openfocus.top/#download)에서 받으세요.
같은 파일과 이전 버전은 [GitHub Releases](https://github.com/Xinzhe99/OpenFocus/releases)에도
있습니다. 터미널에서도 설치할 수 있습니다.

```bash
# macOS(Apple Silicon, ~/Applications) 또는 Linux(헤드리스 CLI)
curl -fsSL https://openfocus.top/install.sh | sh -s -- --dry-run
curl -fsSL https://openfocus.top/install.sh | sh
```

```powershell
# Windows PowerShell
irm https://openfocus.top/install.ps1 | iex
```

실행하면 밝은 테마의 기본 창이 나타납니다(첫 실행 시 시작 대화상자에서 테마를 고를 수 있음).

### 빠른 시작 워크플로

1. 이미지 시퀀스를 가져옵니다(파일 → 폴더 열기 또는 끌어다 놓기)
2. 오른쪽 패널에서 합성 설정을 구성합니다
3. **정합** 드롭다운에서 **하나만** 선택합니다(기본값은 ECC)
4. 필요에 따라 커널 크기를 조정합니다
5. *(선택 사항)* **렌더 설정**을 열고 **빠른 미리보기**를 선택해 축소된 초안으로 매개변수를 먼저 시험합니다
6. **렌더 시작**을 클릭해 처리를 시작합니다
7. 결과를 내보냅니다

## 3. 기본 인터페이스 개요

OpenFocus 인터페이스는 크게 세 영역으로 구성됩니다.

### 왼쪽 패널: 이미지 표시 영역

창의 왼쪽 부분은 분할 보기로 이미지를 표시합니다.

- **원본 이미지 패널(위)**: 입력 이미지 시퀀스를 표시합니다
- **결과 이미지 패널(아래)**: 합성 또는 정합 결과를 표시합니다
- **탐색 슬라이더**: 각 패널 아래의 슬라이더로 이미지 프레임을 넘겨 봅니다
- **이미지 정보 레이블**: 현재 프레임 위치와 이미지 크기를 표시합니다

두 패널 사이의 분할선 핸들을 끌어 패널 크기를 조절할 수 있습니다.

### 오른쪽 패널: 제어 패널

오른쪽 패널에는 모든 구성 옵션이 세로로 정리되어 있습니다.

1. **합성 설정**: 합성 알고리즘과 커널 크기를 선택합니다
2. **정합 설정**: 드롭다운에서 정합 방식을 하나 고릅니다(정렬 안 함 포함)
3. **작업 버튼**: 렌더 시작과 초기화, **렌더 설정**, 모든 방식 렌더링이 있습니다. 렌더 설정 대화상자에서 빠른 미리보기, 프레임 순서, 노출 맞춤, 밝기 드리프트 제거, 출력 선명화를 설정합니다
4. **원본 이미지 목록**: 불러온 모든 이미지의 파일 이름을 보여 줍니다
5. **출력 목록**: 생성된 결과를 보여 줍니다

### 메뉴 막대

상단 메뉴 막대에서 모든 기능에 접근할 수 있습니다.

- **파일**: 가져오기/내보내기, 프로젝트, 처리 템플릿, 스택 저장, 최근 파일 목록
- **편집**: 이미지 변환, 결과 리터치, 이미지 파일 리터치, 실행 취소/다시 실행
- **도구**: 배치 처리, 방법 비교, 깊이 맵, 더스트 맵(플랫 필드), 스케일 바, 레이블
- **설정**: 고급 설정(성능, 정합과 정합 진단, 센서 보정, 출력 이름, AI, 시작), GPU 가속, 테마, 언어
- **도움말**: 사용자 설명서, 환경 정보, 피드백, 업데이트 확인, 로그 폴더

## 4. 이미지와 동영상 가져오기

### 이미지 폴더 열기

1. **파일 → 폴더 열기**로 이동하거나 `Ctrl+O`를 누릅니다
2. 이미지 시퀀스가 들어 있는 폴더를 선택합니다
3. 로딩 배율 대화상자가 나타나면 배율을 선택합니다(100% = 전체 해상도)
4. 확인을 클릭해 이미지를 불러옵니다

대화상자에서 **다시 묻지 않고 항상 이 배율로 불러오기**를 선택하면 이후에는
묻지 않고 항상 선택한 배율로 불러옵니다. **설정 → 고급 설정 → 시작 및 업데이트 → 가져올 때 로딩 배율 묻기**를
켜면 다시 묻습니다. 이미 불러온 스택도 나중에 **편집 → 크기 조정**으로 축소할
수 있습니다.

애플리케이션이 자동으로 다음을 수행합니다.
- 이미지 파일을 검출해 파일 이름 순으로 정렬
- 첫 이미지를 원본 패널에 표시
- 원본 이미지 목록을 모든 프레임으로 채움

### 동영상 파일 열기

1. **파일 → 동영상 열기**로 이동하거나 `Ctrl+Shift+O`를 누릅니다
2. 동영상 파일을 선택합니다(MP4, AVI, MOV, MKV, WMV, FLV, WEBM)
3. 동영상이 자동으로 개별 프레임으로 디코딩됩니다
4. 각 프레임이 이미지 스택의 일부가 됩니다

### 프로젝트 파일

파일 → 프로젝트 저장은 입력 참조와 재현 가능한 설정을 `.ofproj`에 저장합니다. 정확한
프레임 순서(TIFF 페이지와 중복 프레임 포함), 제외 프레임, 회전/뒤집기, 로딩 배율,
방식별 렌더링 매개변수, 레이블, 스케일 바 스타일, 현재 프레임이 포함됩니다. 결과와
리터치 픽셀은 저장되지 않으므로 따로 내보내야 합니다. 소스 파일에서 재구성할 수 없는
작업은 먼저 새 입력 스택으로 저장해야 합니다.

파일 → 프로젝트 열기는 기록된 프레임을 먼저 재구성한 뒤 현재 스택을 교체합니다. 소스가
이동했다면 새 소스 루트를 고르고 이전/새 경로 대응을 모두 확인하세요. 이동한 참조를
유지하려면 프로젝트를 다시 저장해야 합니다. 저장하지 않은 변경이 있는 동안 제목 표시줄에
프로젝트 이름과 `*`가 표시되며, 종료하거나 다른 프로젝트를 열기 전에 확인합니다. 저장해도
결과 이미지의 미내보내기 보호는 해제되지 않습니다.

### 처리 템플릿

처리 템플릿은 설정만 담고 소스 경로는 담지 않습니다. **파일 → 처리 템플릿 저장…** 은
`.oftemplate`을 쓰며, 현재 합성 방식과 매개변수, 정합 방식과 매개변수, 방식별 밝기
옵션, 스레드 수, 타일 설정, 정합 축소 폭, StackMFF AI 배치 크기, 선명화, 역순,
센서 노이즈 제거 플래그를 기록합니다. 결함 마스크 경로는 의도적으로 저장하지 않습니다.

**파일 → 처리 템플릿 적용…** 은 이런 설정을 이미 불러온 스택에 적용하며 현재 소스를
교체하지 않습니다. 선택 창은 `.ofproj` 프로젝트(소스 없이 설정만 추출)와 프로젝트
설정을 담은 레시피 `.json`도 받습니다. 템플릿을 적용하면 프로젝트가 변경된 상태가 되고
알고리즘 매개변수와 리소스 설정이 바뀔 수 있으므로 렌더링 전에 오른쪽 패널을 확인하세요.
레시피는 계속 헤드리스 형식이며 결함 마스크 경로와 지문을 포함합니다.

### 데모 스택

시작 대화상자에서 **데모 스택 불러오기**를 선택할 수 있습니다. 실제 초점
스택에서 가져온 샘플 사진 여섯 장이 함께 제공되므로, 직접 찍은 이미지가 없어도
전체 워크플로를 바로 시험해 볼 수 있습니다. 설치 확인에도 유용합니다.

### 선명도 곡선

원본 탐색 슬라이더 위의 작은 곡선이 프레임별 선명도(정규화됨)를 보여 줍니다.
초점이 나간 프레임은 빨간 점으로 표시된 골짜기로 나타납니다. 곡선의 아무
곳이나 클릭하면 해당 프레임으로 이동하고, 마우스를 올리면 프레임 번호가
표시됩니다.

### 다중 페이지 TIFF 스택

현미경 소프트웨어(ZEN, NIS-Elements, ImageJ/Fiji)는 Z-스택 전체를 하나의 다중
페이지 TIFF 파일로 내보내는 경우가 많습니다. OpenFocus는 그런 파일의 모든
페이지를 이미지 스택의 개별 프레임으로 읽습니다. 파일을 떨어뜨리거나 열면
스택이 완전한 상태로 나타납니다(프레임 이름은 `<file>_page_001` 형식입니다).
단일 페이지 TIFF는 예전과 똑같이 동작합니다. 반대 방향도 가능합니다.
**파일 → 스택 저장 → (정합된 스택 / 입력 스택) → 다중 페이지 TIFF로 저장**을
실행하면 스택 전체를 16비트 심도를 유지한 채 하나의 `.tif`로 다시 씁니다.

### 스케일 바 (논문용 그림)

선택한 대상에 사용할 메타데이터가 없으면 수동 보정이 기본으로 선택되며 유효한 픽셀 크기를 입력해야 합니다.

**도구 → 스케일 바…**에서 내보낸 이미지에 새겨 넣을 스케일 바를 구성합니다. 보정 방식은
대화상자에서 명시적으로 선택합니다. **이미지 메타데이터 사용**은 ImageJ의
`unit=micron` 규칙, OME-TIFF의 `PhysicalSizeX`, 명시적인 센티미터 해상도 단위를 읽으므로
다중 페이지 TIFF를 포함한 현미경 스택이 스스로 보정됩니다. **수동 보정** 값은 **원본
픽셀** 단위로 입력하며 현재 로딩/축소 배율에 맞춰 작업 픽셀로 환산됩니다. 0.5µm/원본
픽셀은 50% 로딩에서 1µm/작업 픽셀입니다. 프린터 해상도(72/300dpi 등)는 의도적으로
보정 정보로 쓰지 않습니다. 대화상자는 원본 값, 로딩 배율, 실제 그려질 값을 보여 주고
모서리 또는 사용자 지정 비율 위치, 색상(자동은 배경에 따라 반전), 글꼴, 크기, 굵게,
문자 정렬을 선택할 수 있으며 미리보기가 실시간으로 갱신됩니다. 적용은 한 번의 실행
취소 가능한 편집으로 확정되고, 취소하면 이전 보정이 유지됩니다.

스케일 바를 켜면 모든 내보내기(단일 이미지, 폴더 스택, 다중 페이지 TIFF, GIF, 배치)에
논문용 스타일의 바가 들어갑니다. 길이는 1-2-5 눈금(이미지 폭의 약
12%)으로 반올림되고 읽기 쉽도록 외곽선을 넣은 텍스트가 표시됩니다. 바와 텍스트는 항상
같은 거리를 나타내며, 이미지가 너무 작아 읽기 좋게 들어가지 않으면 표시와 다른 짧은
바를 그리는 대신 명확히 알립니다. CLI에서는 `--scale-bar`(자동 보정)와
`--scale-um <µm/px>`를 씁니다.

**도구 → 스케일 바 → 스케일 바 제거**로 다시 제거할 수 있습니다. *소스 스택에서* /
*결과에서*는 대화상자의 "적용 대상"을 남은 쪽으로 좁히고, *모두에서*는 바를 완전히
끕니다. 두 캔버스와 A/B 와이프는 즉시 다시 그려지며, 원래 바가 없던 쪽을 제거해도
설정은 바뀌지 않습니다. 기록된 출력은 각자의 보정과 스타일을 유지하므로 다른 소스
스택을 불러와도 새 스택의 설정이 적용되지 않습니다.

### 깊이 맵 (초점 위치)

**도구 → 깊이 맵…**은 선택한 방식(DCT, DTCWT, GFG-FGF, OpenFocus B/C, StackMFF V2/V3)의
활동 척도로 초점 위치를 추정합니다. 측정된 표면이나 합성 이미지 픽셀의 정확한 출처가
아닙니다. 현재 체크한 프레임 또는 선택한 출력에 기록된 소스를 선택할 수 있습니다.
출처 기록이 없다고 현재 스택으로 대신하지 않습니다. 계산, 텍스처, 내보내기는 같은
소스 스냅샷에 연결됩니다. StackMFF V1에는 깊이 맵이 없습니다. 투명 PNG 스택은 GUI와
CLI 모두에서 깊이 맵을 만들 수 없습니다.

지원되는 7가지 방식 모두 **계산**을 직접 눌러야 합니다. 창 열기, 측정 방식·소스·정합 변경,
매개변수 편집만으로는 계산이 시작되지 않습니다. 편집기는 측정 방식 선택기 바로 아래에
있습니다. DCT 중앙값 커널과 GFG 초기 커널은 1–51의 홀수(기본 7)입니다. B는 반경과
깊이 스무딩(기본 1.2), C는 혼합 스무딩(기본 3.0)을 사용합니다. DTCWT 분해 단계는
소스 매개변수로 초기화되는 이 창의 편집값으로 변경할 수 있습니다. StackMFF V3는 숫자 커널 대신
자체 AI 출력 모드(기본 소프트 혼합 또는 하드 선택)와 설명을 표시합니다. 소프트 혼합은
확률로 가중한 연속 프레임 위치를, 하드 선택은 픽셀별로 가장 확률이 높은 프레임을
사용합니다. 둘 다 물리적 거리가 아닙니다. 초깃값은 일치하는 출력의 매개변수 또는 기본 창에 저장된
방식별 값에서 가져옵니다. 편집값은 이 창이 열려 있는 동안 소스와 방식별로 기억하며,
기본 창, 프로젝트 또는 기록된 출력의 설정을 변경하지 않습니다.

계산 설정을 바꾸면 이전 2D 맵에 **현재 결과가 아님**을 계속 표시하고 3D 표면을 지웁니다.
컬러, 원본 데이터, 물리 깊이, OBJ를 포함한 모든 내보내기는 새 계산이 성공할 때까지
차단됩니다. 실행 중인 작업은 협력적으로 취소됩니다. 종료 후 **계산**을 다시 눌러야 하며,
후속 계산은 예약하거나 자동 재개하지 않습니다. 계산 버튼은 항상 표시되며 계산, 취소,
모델 내보내기 중에는 비활성화됩니다.

- **색상 맵**: 회색조(논문 표준)에 15가지 과학용 팔레트(Turbo, Viridis, Magma
  등)와 직접 만든 색상표를 더했습니다. *새 사용자 색상표…*는 원하는 수의 색상
  지점으로 그라디언트를 만듭니다(지점을 더블클릭해 위치와 색상 편집). 사용자
  색상표는 저장되어 드롭다운에 나타납니다.
- **반전 / 감마 / 스무딩**: 깊이 축을 뒤집고, 톤을 다시 맞추고
  (감마 < 1은 낮은 인덱스를 밝게 함), 에지 보존 처리를 적용해 얼룩을 없앱니다.
- **오버레이**: 좌표 영역이 일치하는 연결 출력에만 2D 맵을 원하는 불투명도로
  겹쳐 표시할 수 있습니다.
- **내보내기**: 컬러 버전은 PNG/JPEG/TIFF/BMP를 지원합니다. 원본 16비트 TIFF는
  정규화된 초점 인덱스를 0–65535로 인코딩하며, 무손실 부동소수점 데이터나 물리적 거리가
  아닙니다. 원본 데이터에는 JPEG/BMP를 사용할 수 없습니다.
- **인덱스 TIFF와 대체 이미지 TIFF**: 인덱스는 현재 깊이 추정을 부호 없는 16비트 프레임
  번호로 저장합니다. 1–N은 깊이 계산에 실제 사용한 프레임 순서(정합·재정렬 후)이며
  0은 잘못된 픽셀입니다. 최대 65,535 프레임을 지원하고 소수 위치는 가장 가까운 프레임으로
  반올림하며(정확히 절반은 올림) 대체 이미지는 각 유효 위치에서 해당 깊이 입력 프레임의
  픽셀을 고르고 무효 영역은 0으로 둡니다. 입력에 16비트가 있으면 8비트 값을 257배 해
  16비트로 올립니다. 둘 다 깊이 맵의 ROI를 사용합니다. 인덱스는 추정한 초점 위치이며
  합성 결과의 실제 픽셀 출처가 아닙니다.
- **물리 깊이**: Z 시작, 양의 스텝, 단위, 획득 방향을 입력하고 원래 캡처 순서를
  확인합니다. 제외한 프레임의 간격은 유지됩니다. Float32 TIFF는 마이크로미터, 누락
  영역의 NaN, 소스 메타데이터를 저장합니다. 물리 OBJ에는 XY 보정도 필요하며 물리 Z는
  1:1 비율을 씁니다. 현재 스택과 선택한 출력 사이를 전환하면 프레임 이름과 인덱스가
  같아도 확인된 캡처 순서가 지워지므로 내보내기 전에 다시 확인해야 합니다.
- **3D 모델 / 3D 텍스처**: 메시 긴 변의 정점 수는 기본 600입니다. 새로 열 때마다
  **자동(실제 색상)**을 선택합니다. 연결된 출력의 식별 정보와 좌표 영역/ROI가 완료된
  맵과 일치할 때만 해당 출력을 사용하며, 그렇지 않으면 완료된 계산에 참여한 첫 프레임을
  정합 후 실제 순서에 따라 사용합니다. 사용한 출력 또는 프레임 이름을 표시합니다.
  일치하는 출력, 지정한 참여 프레임 또는 **깊이 의사 색상**을 직접 선택할 수도 있습니다.
  사용할 이미지가 없으면 안내합니다. 3D 미리보기와 OBJ 텍스처 PNG는 같은 이미지를 씁니다.
  2D 맵은 자체 색상 맵과 오버레이 설정을 유지하므로 팔레트나 감마를 바꿔도 실제 사진의
  색상은 변하지 않습니다. 의사 색상 텍스처를 선택했을 때만 팔레트, 감마, 반전을 반영합니다.
  정지 미리보기와 내보내기는 같은 샘플링된 높이 필드를 쓰며 숨겨진 추가 스무딩을 하지
  않습니다. 상대 요철은 이미지 단위의 시각화입니다.
- **모델 내보내기**: OBJ, MTL, 텍스처 PNG, JSON 메타데이터는 하나의 파일 그룹입니다.
  함께 보관하세요. 내보내기는 백그라운드에서 실행됩니다. 충돌은 모든 구성원에 대해
  확인하고, 준비는 스테이징되며, 취소하면 기존 파일이 남고, 커밋 실패 시 교체가
  롤백됩니다. 모델을 저장해도 부모 합성 이미지는 내보내지지 않고 해당 이미지의
  미내보내기 보호도 해제되지 않습니다.

계산은 진행률과 취소를 지원하며 백그라운드에서 실행됩니다. AI 방식은 AI 합성과
동일한 메모리 안전 타일링을 재사용하므로 깊은 스택도 처리됩니다. CLI에서는
`--depth-map [path]`와 `--depth-colormap`이 같은 기능이지만 컬러 맵만 씁니다(기본
`<output>_depth.png`). 위의 지원 방식에만 쓸 수 있고 투명 또는 그룹 입력에서는
거부됩니다. GUI는 원본 깊이, 프레임 인덱스, 대체 이미지, 물리 깊이, 3D 모델도
내보냅니다.

### 충돌 자동 복구

OpenFocus는 작업 세션(스택, 설정, 레이블, 현재 프레임)의 스냅샷을 계속
보관합니다. 충돌, 전원 차단, 강제 종료처럼 애플리케이션이 예기치 않게 닫히면
다음 실행 시 이를 감지하고 **세션 복원**을 제안해 작업하던 위치로 정확히
돌아가게 합니다. 정상 종료에서는 이 안내가 나타나지 않습니다. 복구 데이터는
설정과 같은 위치에 저장됩니다(포터블 설치에서는 실행 파일 옆에 보관되므로
함께 이동합니다).

### 최근 항목

연 스택은 모두 **파일 → 최근 항목 열기**에 기억됩니다(최대 8개). 항목은 하위 메뉴에서
번호가 붙지만 전역 단축키는 없습니다. 항목을 클릭하면 다시 열리고, 같은 스택을 다시 열면
목록 맨 위로 올라갑니다. 파일이 더 이상 없는 항목은 안내를 거쳐 제거할 수 있으며,
**최근 목록 지우기**는 메뉴를 비웁니다.

### 끌어다 놓기

폴더를 애플리케이션 창으로 직접 끌어다 놓아 이미지를 가져올 수도 있습니다.
이미 있는 스택에 파일을 더 떨어뜨리면 크기를 확인한 뒤 뒤에 덧붙입니다.

### EXIF 방향

EXIF Orientation 태그가 있는 카메라 JPEG/TIFF 파일은 가져오기 과정에서 자동으로
회전/뒤집기 보정되므로 세로 사진도 올바른 방향으로 불러옵니다.

### 16비트 원본

16비트 PNG/TIFF 입력은 자동으로 감지되고 끝까지 그대로 유지됩니다. 합성은 전체
심도로 실행되며 결과도 16비트 PNG/TIFF로 다시 저장할 수 있습니다. JPG/BMP
내보내기는 이 형식들이 16비트를 저장할 수 없으므로 8비트로 변환됩니다.

카메라 RAW 파일은 16비트로 현상되며(카메라 화이트 밸런스, sRGB 감마), 자동
밝기 보정은 꺼져 있습니다. 그래서 스택의 모든 프레임이 같은 노출 매핑을
받습니다. 프레임마다 자동 노출을 적용하면 프레임 사이에서 밝기가 깜빡이게
됩니다. 16비트 데이터를 유지하려면 TIFF나 PNG로 저장하세요.

### 색상 프로파일

모든 소스 프레임에 같은 RGB ICC 프로파일이 있으면 단일 PNG, TIFF, JPEG, WebP
내보내기에 그 프로파일이 유지됩니다. 프로파일이 섞여 있거나 태그가 없는 스택은 ICC
프로파일 없이 내보냅니다. OpenFocus는 프로파일을 보존할 뿐 소스 픽셀을 공통 색 공간으로
변환하거나 미리보기를 색 관리하지 않습니다. 프로파일이 다른 이미지는 불러오기 전에
공통 색 공간으로 변환하세요. RAW 입력은 sRGB로 현상되며 카메라 프로파일을 상속하지
않습니다.

다중 페이지 TIFF는 파일의 모든 페이지가 같은 유효 RGB 프로파일을 가져야 하며, 그렇지
않으면 해당 프레임들은 태그 없음으로 처리됩니다. 동영상 프레임도 태그 없음입니다.
추가한 프레임과 특정 렌더링에서 선택된 프레임이 그 결과의 프로파일 판단에 함께
참여하며, 프로파일은 이후 내보내기를 위해 결과에 남습니다.

### 스택 비우기

불러온 이미지를 모두 제거하려면 **파일 → 스택 비우기**로 이동하거나 `Ctrl+W`를
누릅니다.

## 5. 이미지 보기 및 탐색

### 이미지 스택 탐색

- **슬라이더**: 원본 패널 아래의 슬라이더를 끌어 프레임을 넘깁니다
- **파일 목록**: 오른쪽 패널의 원본 이미지 목록에서 파일 이름을 클릭합니다
- **키보드**: 전역 이전/다음 프레임 단축키는 없습니다. 원본 이미지 목록에 포커스를 두고
  위/아래 화살표로 선택을 이동하세요

### 유사 프레임 검토

소스 목록 제목 아래의 **프레임 검토**를 클릭하면 픽셀이 거의 같은 인접 프레임을 찾습니다.
분석 중에는 버튼이 **검토 취소**로 바뀝니다. 각 제안은 기준 프레임과 차이를 보여 주므로
두 프레임을 확인한 뒤 소스 체크박스로 한 프레임을 합성에서 제외하세요. 제안이 체크박스를
바꾸거나 파일을 삭제하지는 않습니다. 이 보수적인 비교는 유사 프레임을 놓칠 수 있고, 작은
초점 영역만 바뀐 경우 평균에 묻힐 수 있습니다. 스택이 바뀌면 결과는 버려집니다. 제안
프레임과 기준 프레임이 모두 포함된 경우에만 표시되며, 체크박스를 바꾸면 즉시 갱신됩니다.

### 확대/축소 및 이동

- **확대/축소**: 이미지 위에서 마우스 휠을 사용합니다
- **미세 확대/축소**: `Ctrl` + 마우스 휠로 더 작은 단위로 조정합니다
- **창에 맞추기**: 이미지를 더블클릭해 창에 맞춤과 100% 보기 사이를 전환합니다
- **이동**: 클릭한 채 끌어 패널 안에서 이미지를 옮깁니다

### 동기화 탐색

원본 패널에서 탐색하면 결과 패널에 해당 결과 프레임이 있으면 함께 표시됩니다.

## 6. 와이프 비교 보기

와이프 보기는 두 이미지를 하나의 프레임에 포개고 세로 구분선을 끌어 나누어,
어긋남과 품질 차이를 분할 경계에서 바로 확인할 수 있게 합니다.

### 와이프 보기 열기

1. 결과(합성 또는 정합)를 하나 이상 렌더링합니다
2. 결과 패널 제목 표시줄 오른쪽 위의 **와이프** 토글을 누릅니다
3. 결과 영역이 비교 보기로 바뀝니다. 되돌리려면 **와이프**를 다시 누릅니다

### 보기 읽기

- **A 쪽(구분선 왼쪽)**: 원본 프레임이며, 기본적으로 원본 패널 슬라이더를 따릅니다
- **B 쪽(구분선 오른쪽)**: 가장 최근 렌더링 결과입니다
- **흰 구분선 + 둥근 핸들**: 가로로 끌어 분할 위치를 옮깁니다
- 구분선을 넘나들며 끌면 나란히 보기에서는 잘 보이지 않던 정합 오류가 드러납니다

### 비교 대상 선택

비교 보기 아래쪽 막대에는 양쪽에 하나씩 그룹이 있습니다.

- **A 쪽** — **원본 따라가기**(기본값)를 선택하면 원본 패널 슬라이더를 추적하고,
  해제하면 자체 슬라이더로 A 쪽을 원하는 프레임에 고정합니다
- **B 쪽** — **최신 결과**(기본값)를 선택하면 항상 가장 새 렌더링을 보여 주고,
  해제하면 자체 슬라이더로 출력 기록을 훑어볼 수 있습니다

양쪽 모두 실시간으로 갱신됩니다. 새 렌더링, 원본 슬라이더 이동, 프레임 삭제가
즉시 반영됩니다.

### 확대/축소 및 이동

비교 보기는 두 이미지에 하나의 변환을 함께 적용합니다.

- **확대/축소**: 마우스 휠(커서 위치를 중심으로 확대)
- **이동**: 구분선을 제외한 아무 곳이나 클릭해 끕니다
- **초기화**: 더블클릭

와이프 모드와 ROI 모드는 같은 결과 패널을 사용하므로 한쪽에 들어가면 다른
쪽은 종료됩니다. 스택을 비우면 와이프 모드도 종료됩니다.

## 7. 이미지 정합

이미지 정합은 이미지 스택에서 프레임 사이의 공간적 어긋남을 보정합니다. 이미지가
약간 이동했거나 원근이 달라졌을 때 반드시 필요합니다.

### 정합 방식

#### ECC (향상된 상관 계수)

- 상관 관계를 기준으로 최적 정렬을 찾는 최적화를 사용합니다
- 미세한 어긋남에 적합합니다
- 서브픽셀 정밀도를 제공합니다
- 호모그래피보다 느리지만 더 정밀합니다

#### 호모그래피

- 특징점 매칭(SIFT/ORB 특징)을 기반으로 합니다
- 더 큰 기하 변환을 처리합니다
- 초기 정렬에서는 ECC보다 빠릅니다
- 원근 변화가 큰 이미지에 적합합니다

#### OpenFocus (고속)

- 제한된 유사 변환 정렬(이동 + 회전 + 크기)에 프레임별 밝기 균등화와
  자동 자르기를 더했습니다
- 샘플링한 이미지 차이로 탐색을 평가하고 Lanczos 보간으로 변환합니다
- **프레임 크기의 8%를 넘게 이동한 프레임은 부분 보정 대신 정렬하지 않은 채로
  둡니다**. CLI의 `--align-shift-limit`으로 이 값을 바꿀 수 있습니다
- 비강체나 극단적인 기하에는 대신 ECC나 호모그래피를 선택하세요
- **거부 프레임 처리**는 기본적으로 정렬되지 않은 프레임으로 계속합니다.
  **거부 프레임에서 중지**를 선택하면 검출 품질이 0.06 미만이거나 추정 움직임이 설정된
  이동 한도(기본 8%), 회전 8°, 크기 변화 5%를 넘을 때 결과를 만들기 전에 렌더링이나
  배치 항목을 실패시킵니다. 프레임 번호는 처리 스택 순서의 1부터입니다. 기하 기준은
  기본적으로 첫 프레임이며, 직접 일치가 약하면 기준에 가까운 인접 프레임으로 다시
  시도합니다. 이 정책은 거부된 추정을 찾을 뿐 모든 잘못된 일치를 막지는 못합니다.
  낮은 텍스처, 반복 패턴, 가림, 큰 움직임, 초점 변화는 여전히 정합을 방해할 수 있으니
  결과를 확인하세요.
- CLI에서는 `--align openfocus --align-param 'failure_policy="fail"'`로 같은 정책을
  선택합니다(셸에 맞게 인용). 기본값은 `"continue"`이며 배치 항목은 각자 이 정책을
  독립적으로 사용합니다.
- **기준 프레임**은 포함된 처리 대상 스택의 1부터 시작하는 번호로 지정해 기하를
  고정합니다. 프레임 순서는 유지되고 밝기 균등화는 자체 기준을 씁니다. 배치의 각
  스택에 해당 번호가 있어야 하며 없으면 항목이 실패합니다. CLI 예:
  `--align openfocus --align-param reference_frame=3`. 기준을 골라도 시차나 잘못된
  일치를 바로잡지는 못합니다. 결과를 확인하세요.

#### 호모그래피 → ECC

호모그래피로 거칠게 맞춘 뒤 ECC로 정교화합니다. 가장 느리지만 어려운 기하에 가장
관대한 조합이며, 이것도 드롭다운의 한 항목입니다(두 방식을 동시에 켜는 것이 아님).

정합 보고서는 기준 프레임과 각 프레임의 결과를 보여 줍니다. 폴백은 방식이 정합을
세우지 못했거나 이전의 실패한 추정에 의존한다는 뜻이며, 알 수 있으면 약한 추정과 한도
밖 움직임을 구분합니다. 품질 값은 방식마다 다르며 정확도를 보장하지 않습니다. 변환은
소스 좌표를 정합 단계의 기준 캔버스로 보낸 뒤 공통 자르기를 수행하고, 복합 방식은
단계별로 보고합니다. 호모그래피와 ECC도 `failure_policy="fail"`을 받아들이며 기본값은
`"continue"`입니다.

렌더링을 점검하려면 **설정 → 고급 설정 → 정합**에서 **정합 진단 수집**을 켜고 다시
렌더링하세요. 캐시를 재사용하지 않고 정합을 다시 계산합니다. 완료 상태가 폴백을
강조하며, **설정 → 고급 설정 → 정합 → 정합 진단**에서 프레임별 보고서를 엽니다. 실패 이유, 방식별 점수,
일치 수, 기준 프레임, 변환이 표시됩니다. 기준 번호와 이름은 제외된 프레임을 포함한 원본
소스 목록을 따릅니다. 배치와 그룹 렌더링은 이 보고서를 제공하지 않습니다.

### 정합 사용 설정

1. 오른쪽 패널에서 **정합** 그룹을 찾습니다
2. 드롭다운에서 방식을 **하나만** 고릅니다: **정렬 안 함**, **호모그래피**, **ECC**,
   **OpenFocus (고속)**, 또는 조합인 **호모그래피 → ECC**(기본값 ECC)
3. OpenFocus(고속)에서는 기준 프레임을 지정합니다. 거부 프레임 처리는 **설정 → 고급 설정 → 정합**에서 선택하며, 변경하면 각 방식에 적용됩니다
4. **정합 진단 수집**은 고급 설정에 있습니다(위 참조). 렌더링 전에 켜야 프레임별 보고서가
   만들어집니다

### 정합이 필요한 경우

- 이미지에 눈에 띄는 어긋남이 있을 때
- 손으로 들고 촬영했을 때
- 장면에 시차가 있을 때(가까운 물체가 프레임 사이에서 이동)
- 결과에 잔상이나 이중 상이 나타날 때

### 정합 설정

**설정 → 고급 설정 → 정합**에서 추가 설정에 접근합니다.
- **축소 폭**: 전처리 해상도를 제어합니다(기본값: 1024px)
- 값이 작을수록 빠르지만 정확도가 떨어질 수 있습니다
- 값이 클수록 느리지만 정확도가 높아질 수 있습니다
- **정합 진단 수집**과 **정합 캐시**도 같은 섹션에 있습니다

## 8. 이미지 합성 방식

OpenFocus는 열 가지 합성 알고리즘과 정렬 전용 모드를 제공합니다. 각각 특성이
달라 다양한 이미지 유형에 맞게 쓸 수 있습니다. 새 프로필은 **StackMFF V3**와
**ECC** 정합으로 시작합니다. 드롭다운의 첫 항목은 **정합만**이고
기본 선택은 **AI(StackMFF V3)**입니다. 그 뒤에 StackMFF V2/V1, OpenFocus A/B,
가이드 필터, GFG-FGF, OpenFocus C, DCT, DTCWT가 이어집니다.

### 가이드 필터

- **알고리즘**: 에지 보존 합성을 위해 가이드 필터링을 사용합니다
- **적합한 용도**: 범용, 속도와 품질의 균형
- **장점**: 우수한 에지 보존, 빠른 처리
- **매개변수**: 커널 크기(1-51 조정 가능, 홀수만)
  - 커널이 작을수록 국소 디테일이 많아지고 노이즈가 늘 수 있습니다
  - 커널이 클수록 결과가 부드러워지고 노이즈 억제가 좋아집니다

### DCT (이산 코사인 변환)

- **알고리즘**: DCT 계수를 이용한 주파수 영역 합성
- **적합한 용도**: 텍스처가 풍부한 이미지, 과학 이미지
- **장점**: 미세 텍스처를 유지하고 수학적으로 견고합니다
- **매개변수**: 커널 크기가 처리 창을 결정합니다

### DTCWT (이중 트리 복소 웨이블릿 변환)

- **알고리즘**: 다중 스케일 웨이블릿 영역 합성
- **적합한 용도**: 디테일 수준이 여러 단계인 복잡한 장면
- **장점**: 뛰어난 다중 스케일 분석, 우수한 방향성
- **합성 규칙**: 픽셀과 레벨마다 모든 방향과 색상 채널에 대해 단일 판단을
  내립니다(N개 후보, 다수 일관성 검사). 저주파 대역은 모든 프레임을 평균하지
  않고 가장 거친 레벨의 판단을 따릅니다
- **매개변수**: 오른쪽 패널의 웨이블릿 단계(1–6, 기본 4)입니다. 공간 커널을 쓰지
  않으므로 이 방식에서는 커널 슬라이더가 숨겨집니다.

### GFG-FGF (가우시안형 4이웃 기울기 + 고속 가이드 필터)

- **알고리즘**: Fu 등의 구현(*Laser & Optoelectronics Progress*, 2024)으로,
  블러 차이 초점 맵 |I − mean(I)|을 가우시안형 4이웃 기울기(GFG) 연산자로
  보강하고 고속 가이드 필터로 정련한 뒤 픽셀별로 판단하며(동률은 3×3 Sobel
  소영역 척도로 해소), 가중 혼합 전에 이진 판단 맵을 다시 고속 가이드 필터로
  스무딩합니다.
- **적합한 용도**: 현미경 이미지, 초점 영역이 뚜렷한 이미지
- **장점**: 빠르고 초점 영역 경계가 선명하며 메모리가 프레임 수에 따라 늘지
  않습니다
- **매개변수**: 커널 = 거친 초점 맵의 평균 필터 크기

### StackMFF(V1, 딥러닝)

- **알고리즘**: 스택 전체의 융합 휘도를 한 번에 예측하는 3D U-Net.
  Cb/Cr은 휘도가 가장 가까운 원본 프레임에서 가져옵니다
- **적합한 경우**: 초점 스택 전체의 신경망 합성
- **장점**: 매개변수가 없고 색이 색역 안에 유지됩니다. 프레임 순서가 결과에 영향을 줄 수 있습니다
- **참고**: 약 6M 매개변수. 큰 스택은 GPU가 유리합니다

### StackMFF V2(딥러닝)

- **알고리즘**: 레이어별 초점 추정을 양방향 순환 레이어로 정교화하고 초점면
  인덱스를 회귀해 스택에서 샘플링합니다. **프레임은 원래 초점 순서를 유지해야
  하며** 역순은 비활성화됩니다
- **깊이 맵**: 지원. 선택된 초점 레이어를 보고합니다
- **적합한 경우**: 매우 작고 빠른 모델이 필요한 연속 초점 스캔
- **요구 사항**: PyTorch, 약 0.05M 매개변수, 설정 없음
### StackMFF V3 (딥러닝)

- **알고리즘**: 픽셀 단위 원본 분류(PyTorch 필요). 신경망이 픽셀마다 어느 입력
  프레임에서 왔는지를 예측한 뒤, 그 확률로 프레임을 혼합하거나 한 프레임을
  고릅니다
- **AI 출력 모드**(오른쪽 패널, 이 방식에서만 표시):
  - **부드러운 혼합 (가중)** — 기본값. 각 픽셀이 확률 가중치로 프레임을 혼합한
    결과입니다. 전환이 부드럽고 이음매가 없으며 논문의 보고 설정과 같습니다
  - **단일 선택 (한 프레임)** — 각 픽셀을 가장 확률이 높은 프레임에서
    복사합니다. 프레임 간 보간이 없어 선택이 더 선명하지만, 두 프레임이
    비슷한 곳에서 픽셀 단위 이음매가 나타날 수 있습니다
- **적합한 용도**: GPU가 있을 때 최고 품질
- **장점**: 순서 무관(프레임 순서가 결과를 바꾸지 않음), 스택 길이 제한 없음,
  방식별 조정 불필요, 자동 최적화
- **요구 사항**: PyTorch 설치, 선택적 CUDA GPU(torchvision 불필요)
- **참고**: PyTorch가 설치되어 있지 않으면 사용할 수 없습니다

### OpenFocus A / B / C

- **OpenFocus A**: 다중 스케일 초점 응답으로 초점이 맞은 픽셀을 선택합니다.
- **OpenFocus B**: 스무딩한 깊이 맵을 기준으로 이웃 프레임을 혼합합니다.
- **OpenFocus C**: 스무딩한 깊이 맵을 기준으로 다중 스케일 대역을 재구성합니다.
- **매개변수**: A와 B의 커널은 초점 응답의 스케일을 조절하며 C에는 반경이 없습니다.

**스무딩**(0–8, 단계 0.2)의 효과는 방식에 따라 다릅니다.

| 방식 | 매개변수 | 기본값 | 효과 |
|---|---|---|---|
| OpenFocus A | 혼합 스무딩 | 2.0 | 픽셀을 선택하기 전에 초점 응답 맵을 스무딩합니다 |
| OpenFocus B | 깊이 스무딩 | 1.2 | 깊이 맵 스무딩과 프레임 간 전환을 조절합니다 |
| OpenFocus C | 혼합 스무딩 | 3.0 | 대역 재구성에 쓰는 깊이 맵을 조절합니다 |

각 방식의 값은 세션 간 저장되며 배치 처리에도 적용됩니다.

CLI: `--depth-smoothing VALUE`(B), `--blend-smoothing VALUE`(A, C).

**밝기 옵션은 방식별로 저장됩니다.** *합성 전 노출 맞추기*와 *밝기 드리프트
제거*는 전역 기본 설정이 아니라 스택별 판단이므로 합성 방식마다 따로
기억됩니다. OpenFocus A/B/C는 자체 노출 보정이 없으므로 둘 다 기본적으로
켜져 있고, 다른 방식은 지금까지의 기본값(노출 맞추기 켜짐, 드리프트 제거
꺼짐)을 유지합니다. 방식을 바꾸면 그 방식의 값이 표시되며 재시작 후에도 유지됩니다.
**초기화**는 모든 방식에 대해 기억된 밝기, 스무딩, 반경 값을 지웁니다.

**합성 결과 선명하게**는 합성 후 결과를 출력 비트 심도로 변환하기 전에 가벼운
언샤프 마스크를 적용합니다. 기본값은 꺼져 있으며 메인 합성 옵션이나 배치 옵션에서
켤 수 있고 CLI에서는 `--sharpen-output`입니다. 정합된 프레임이나 깊이 맵에는
영향을 주지 않으며, 에지를 또렷하게 하지만 노이즈와 할로를 키울 수 있습니다.
프로젝트에 저장되고 세션 간 기억됩니다.

### 정합만 (합성 안 함)

방식으로 **정합만 (합성 안 함)**을 선택하면 스택을 정합한 뒤 출력 목록에 스택 항목
하나를 추가합니다. 프레임은 내보낼 때까지 메모리에 남고, 정합 전용 캐시를 따로 만들거나
소스 파일 옆에 쓰지 않습니다. 항목을 저장하면 선택한 대상 안에 폴더 하나가 생깁니다.
원래 파일 이름 줄기를 유지하며 확장자는 선택한 형식을 씁니다.

### 합성 방식 선택

1. 오른쪽 패널에서 **합성** 그룹을 찾습니다
2. **드롭다운**에서 방식을 고릅니다(항상 정확히 하나가 선택되며 기본값은
   AI(StackMFF V3)입니다. 정합 전용 모드도 같은 목록에 있습니다)
3. 해당되는 경우 커널 크기를 조정합니다. 레이블에 선택한 방식에서 커널이
   무엇을 뜻하는지 표시됩니다
4. **렌더 시작**을 클릭해 처리합니다

### 알고리즘 비교 가이드

| 알고리즘 | 속도 | 품질 | 적합한 용도 |
|-----------|-------|---------|----------|
| 가이드 필터 | 빠름 | 좋음 | 범용 |
| DCT | 보통 | 좋음 | 텍스처 |
| DTCWT | 보통 | 매우 좋음 | 복잡한 장면 |
| GFG-FGF | 빠름 | 좋음 | 초점 영역 |
| StackMFF(V1) | 느림 (GPU) | 여기서는 미측정 | 전체 스택 신경망 합성, 순서가 결과에 영향을 줄 수 있음 |
| StackMFF V2 | 빠름 (GPU) | 여기서는 미측정 | 작은 모델을 쓰는 연속 스윕 |
| AI 합성 (StackMFF V3) | 느림 (GPU) | 최고 | 최고 품질 |
| OpenFocus A | — | — | 초점 픽셀 선택 |
| OpenFocus B | — | — | 깊이 맵 기반 혼합 |
| OpenFocus C | — | — | 깊이 맵 기반 대역 재구성 |

**도구 → 방법 비교**에서는 여러 방식을 각각 조정할 수 있습니다. 창이 좁아져도 각 방식의
이름, 매개변수 레이블, 입력란이 함께 줄바꿈됩니다. 변경하면 미리보기가 자동으로
갱신됩니다. **ROI 미리보기(고속)**는 선택 영역과 주변을 합성하고, **전체 이미지 합성**은
전체 결과를 확인한 뒤 다시 렌더링하지 않고 다른 영역을 살펴볼 수 있습니다. 노출 통계와
일부 알고리즘은 이미지 범위에 의존하므로 ROI 결과가 전체 이미지 결과와 다를 수 있습니다.
기본 계산 방식은 **전체 이미지 합성**입니다.

오른쪽 미리보기 위의 **미리보기 크기(px)**는 슬라이더나 숫자 입력으로 160–960픽셀의
정사각형 크기를 고릅니다. 모든 방식이 같은 크기를 쓰고 사용 가능한 너비에 맞춰
줄바꿈됩니다. 크기는 다음에 열 때도 기억됩니다. 크기를 바꿔도 현재 배율은 유지되고
검사 사각형이 중심을 기준으로 조정되며 이미지 경계에서 제한됩니다.

**F11** 또는 **전체 화면(F11)** 버튼으로 화면 전체를 쓸 수 있고 버튼은 **전체 화면
종료(F11)**로 바뀝니다. 제목 표시줄을 최대화해도 됩니다. **Esc**는 먼저 전체 화면을
나가고 한 번 더 눌러야 대화상자를 닫습니다. 전체 화면에서 돌아오면 이전 창 크기가
복원되고 결과 그리드는 어느 경우든 사용 가능한 너비에 맞춰 재배치됩니다.

작업 공간에 선택 방법이 표시됩니다. 결과를 클릭하거나 `Tab`으로 포커스를 이동한 뒤 `Enter` 또는
`Space`를 누르면 선택하거나 선택을 해제할 수 있습니다.

소스 이미지를 왼쪽으로 끌어 흰 검사 사각형을 옮기고 버튼을 놓으면 그 자리에 고정됩니다.
오른쪽 창들은 같은 정합 스택의 정확히 그 영역을 보여 줍니다. 휠로 영역 배율을 바꾸고,
오른쪽 끌기로 소스를 이동하고, **Ctrl+휠**로 소스를 확대하고, **F**로 맞춥니다. 소스
프레임을 바꾸거나 창 크기를 조정해도 선택이 유지됩니다. 취소는 이후 작업을 멈추고,
닫기는 현재 네이티브 작업이 안전하게 돌아올 때까지 기다립니다.

### 빠른 미리보기 (초안 렌더링)

큰 스택에서 전체 해상도로 매개변수를 조정하면 느립니다. **렌더 설정**을 열고
**빠른 미리보기**를 선택하면 OpenFocus가 먼저 선형 크기의 절반(긴 변 최소 320px)으로
초안을 렌더링합니다. 정합을 포함해 보통 몇 배 빠릅니다. 완료 메시지(및 최신 결과의
툴팁)에는 **품질: 미리보기**가 표시되며 초안은 **출력 기록에 추가되지 않습니다**. 상자를
해제하고 다시 렌더링하면 전체 해상도 결과가 만들어집니다. 미리보기 모드는 ROI
렌더링에는 적용되지 않고 전체 해상도 정합 캐시를 오염시키지도 않습니다.

## 9. 이미지 변환

### 회전

1. **편집 → 회전**으로 이동합니다
2. 회전 유형을 선택합니다:
   - **시계 방향 90°**: 모든 이미지를 오른쪽으로 90도 회전
   - **반시계 방향 90°**: 모든 이미지를 왼쪽으로 90도 회전
   - **180°**: 이미지를 위아래로 뒤집음

### 뒤집기

1. **편집 → 뒤집기**로 이동합니다
2. 뒤집기 유형을 선택합니다:
   - **가로 뒤집기**: 좌우로 반전
   - **세로 뒤집기**: 상하로 반전

### 크기 조정

1. **편집 → 크기 조정**으로 이동합니다
2. 크기 조정 옵션 대화상자가 나타납니다
3. 새 크기나 배율(%)을 입력합니다
4. 스택의 모든 이미지가 비례하여 조정됩니다

### 변환 순서

변환은 이미지 스택 전체에 적용되며 프레임 간 정렬이 유지됩니다.

## 10. 리터치, 레이블 및 주석

### 결과 리터치 (편집 → 결과 리터치…, `Ctrl+T`)

합성을 해도 국소 결함이 남을 수 있습니다. 고대비 에지 주변의 할로, 잘못된 프레임에서
가져온 털, 평탄한 영역의 노이즈 같은 것입니다. 작업 공간은 선택한 결과를 실제로 만든
프레임에서 픽셀을 복사합니다.

1. 출력 목록에서 결과 하나를 고르고(오른쪽 클릭 → *결과 리터치…*도 가능) `Ctrl+T`를
   누릅니다. 선택이 없으면 모든 결과와 소스 기록 여부를 보여 주는 선택 창이 열립니다.
2. 왼쪽은 소스 프레임, 오른쪽은 결과입니다. 둘은 배율과 위치를 공유합니다. 휠로
   확대/축소, 오른쪽/가운데 끌기(또는 Space+끌기)로 이동, `F`로 맞춤, `1`로 100%입니다.
3. 썸네일을 고르거나 프레임 슬라이더를 움직이거나 `,` / `.`를 누릅니다. 한 획은 그때의
   프레임과 브러시 설정에 고정되며 획이 끝날 때까지 프레임을 바꿀 수 없습니다.
4. **원본 브러시**(`B`) 또는 **복원 브러시**(`E`)를 고릅니다. 지름, 경도, 불투명도는
   슬라이더와 숫자 입력으로 조정하고 `[` / `]`로 지름을 바꿉니다. `Ctrl`을 누른 채 휠을
   위로 돌리면 지름이 커지고 아래로 돌리면 작아집니다. 휠만 돌리면 확대/축소합니다.
   복원 브러시는 연 시점의 이미지로 되돌리며 이전 출력에서 가져오지 않습니다.
5. `Tab`을 누르는 동안 이번 세션 전 결과를, `Alt`로 소스 프레임을 볼 수 있습니다. 선명도
   참조는 선택 사항이며 소스 캔버스만 덮고 모든 프레임에 같은 배율을 씁니다.
6. `Ctrl+Z` / `Ctrl+Y`는 획 단위 실행 취소/다시 실행입니다. **모두 복원…**도 한 번의
   실행 취소 가능한 작업입니다. **새 출력으로 적용**은 "<이름> · 리터치 N" 항목을 추가하고
   선택합니다. 원래 출력은 그대로이며, 새 항목은 내보낼 때까지 *내보내지 않음*으로 표시되고
   기록 자동 제거와 저장하지 않은 채 종료하는 동작에서 보호됩니다.

새 출력으로 적용한 뒤 메인 창에서 그 출력을 오른쪽 클릭하고 **레이어 TIFF 내보내기**를
선택하면 소스 프레임과 함께 저장할 수 있습니다. 라이브 레이블과 스케일 바는 포함되지
않고, 저장하지 않은 주석 변경은 계속 보호됩니다. 소스 기하와 유효 마스크는 유지됩니다.
결과와 각 소스는 크기가 같은 불투명 RGB 또는 회색조 이미지여야 하고 8비트/16비트 깊이가
같아야 하며, 각 소스 사각형은 결과 안에 들어와야 합니다. 소스는 최대 128개이고 소스
이름은 255자까지이며 NUL이나 기본 다국어 평면 밖 문자(많은 이모지 등)를 쓸 수 없습니다. 안전하지 않은
상황이나 512MiB를 넘을 것으로 예상되는 작업은 불완전한 파일을 쓰지 않고 거부합니다.
Windows의 GIMP 3.2.6은 오프셋과 투명 정합 여백을 포함한 8비트/16비트 레이어를 엽니다.
결과가 보이고 소스 레이어는 숨겨지며 GIMP가 보이는 배경 레이어를 추가합니다. 다른
편집기는 검증되지 않았습니다.

국소 밝기 보정에는 **노출 브러시**를 씁니다. 값은 1/100 스톱 단위이며(100은 픽셀 값 2배,
-100은 절반) 결과 위에 칠합니다. 미리보기는 칠하는 동안 갱신됩니다. 한 획은 겹친 부분도
포함해 현재 결과를 한 번만 조정하고 다음 획은 그 위에 쌓입니다. 브러시 불투명도와 경도로
혼합을 조절하며 밝게 할 때 하이라이트가 잘릴 수 있습니다. **Before**를 누르는 동안 연
시점 결과와 비교하고, 획 중 Esc로 취소하거나 획 후 실행 취소/다시 실행을 쓸 수 있습니다.
이는 조정 가능한 레이어가 아닌 픽셀 편집입니다. 새 출력으로 적용하고 그 항목을 내보내야
픽셀이 저장되며 프로젝트는 이 픽셀을 저장하지 않습니다.

**결과 조정…**은 현재 리터치 결과 전체를 바꿉니다. 노출과 대비를 바꾸면 샘플링 미리보기가
갱신되고 **Before**로 조정 전 결과와 비교할 수 있습니다. 둘 다 1/100 스톱 단위이며 노출이
픽셀 값을 곱한 뒤 대비가 중간 회색에서의 거리를 조정합니다. 극단값은 하이라이트나 섀도를
자를 수 있습니다. **확인**은 한 번의 실행 취소 가능한 편집으로 적용하고 **취소**는 결과를
바꾸지 않습니다. 처리 중 취소하면 롤백을 요청합니다. 전체 이미지 조정은 리터치 기록의
메모리 한도 안에 들어와야 합니다. 이후 위 방법으로 결과를 공개하고 내보냅니다.

출처는 출력과 함께 이동합니다. 정합된 프레임, ROI 자르기/붙이기 오프셋, DCT 가장자리
처리, 비트 깊이가 렌더링 시 기록됩니다. 배치 파일, 이전 결과, 정합 전용 폴더 항목에는
소스 기록이 없으므로 현재 스택에서 추측하지 않고 사용할 수 없음으로 표시합니다. 적용하지
않은 획과 실행 취소 기록은 세션에만 있으며 프로젝트를 저장해도 저장되지 않습니다.

**편집 → 이미지 파일 리터치…**에서는 기존 결과와 하나 이상의 소스 이미지를 따로 고를 수
있습니다. 소스는 결과와 같은 픽셀 그리드에서 이미 정합되어 있어야 하며 크기가 같다는
것만으로는 정합을 증명할 수 없습니다. 크기, 채널, 8비트/16비트 깊이가 같은 단일 페이지
PNG, TIFF, JPEG, BMP를 받고 불러올 때 EXIF 방향을 적용합니다. 알파와 다중 페이지 이미지는
지원하지 않습니다. 고른 프레임은 사용자가 제공한 것이며 렌더링 출처 기록이 아닙니다.
적용하면 별도의 내보내지 않은 출력이 생기고 출력 목록에서 저장해야 합니다. 고른 파일은
이 세션 동안 깊이 맵과 3D 메시 내보내기를 포함해 덮어쓰기에서 보호됩니다. 다른 결과와
마찬가지로 프로젝트 파일은 이 픽셀이나 브러시 기록을 저장하지 않습니다.

리터치 체크포인트를 저장할 때 첫 저장이나 불러오기는 베이스와 처리된 소스를 취소 가능한
백그라운드 작업에서 검증합니다. 저장은 기록된 편집도 재생하고 공개 전에 현재 이미지와
실행 취소/다시 실행 상태를 확인합니다. 소스가 바뀌어 재생이 더 이상 맞지 않으면 저장이
실패하고 편집은 유지됩니다. 저장이나 불러오기를 취소해도 현재 편집은 남습니다. 검증이나
재생에 메모리가 부족하면 현재 편집과 기존 체크포인트를 그대로 두고 멈춥니다. 기록 한도에
도달해 더 편집할 수 없으면 현재 편집을 적용하고 새 리터치 세션을 시작하세요.

체크포인트는 편집과 지문을 기록하며 픽셀은 기록하지 않습니다. 원래 베이스 이미지와 세션에
실제 사용한 처리된 소스 프레임을 같은 순서로 지정해 재생합니다.

```bash
openfocus retouch replay edits.json --base fused.png --sources frame1.png frame2.png --output retouched.tif
```

정합과 ROI 자르기 등 처리를 마친 뒤의 원래 픽셀 값과 비트 깊이를 가진 프레임을 쓰세요. 재생은
기록된 프레임 오프셋과 정합 동작을 재구성하고 베이스, 순서 있는 프레임, 유효 마스크를
검증합니다. 픽셀, 기하, 마스크가 맞지 않으면 거부됩니다. 각 경로에는 이미지 하나만 있어야
하고 출력은 PNG 또는 TIFF로 베이스 비트 깊이를 유지하며 체크포인트와 입력 이미지를 출력으로
쓸 수 없습니다.

### 레이블

이미지를 불러오거나 결과를 만든 뒤 **도구 → 레이블 → 레이블 관리…**를 엽니다. 각
레이블에는 대상(소스 스택, 정합된 스택, 출력 결과)이 있습니다. 출력 레이블은 모든 결과에
적용하거나 이름으로 선택한 결과에 연결할 수 있으며, 그 결과의 이름을 바꾸거나 순서를
바꿔도 연결이 유지됩니다.

**추가**로 새 레이블을 만들고 항목을 골라 편집하며 체크박스로 켜거나 끕니다. 고정 텍스트
또는 `{value}`로 프레임 번호를 넣을 수 있습니다. 번호는 시작값 + 0부터 시작하는 프레임
번호 × 간격이며 단일 출력은 항상 시작값을 씁니다.

모든 프레임, 현재 프레임, 또는 `3-5,8` 같은 사용자 지정 범위를 고릅니다. 잘못되었거나
사용할 수 없는 프레임 번호가 있으면 초안을 적용할 수 없습니다. 현재/사용자 지정 범위는
스택 순서가 바뀌어도 선택한 소스의 정체성을 따르고, 모든 프레임 레이블은 나중에 추가한
프레임에도 적용됩니다. 대상이 없으면 명시적으로 새 대상을 고를 때까지 원래 정체성과의
연결을 유지합니다.

미리보기는 실제 대상을 씁니다. 이전/다음 또는 프레임 번호 입력으로 이동하고 **맞춤**이나
**100%**를 고르며 100%에서는 이미지를 끌어 이동합니다. 위치와 글꼴 크기는 이미지 픽셀
단위입니다. 대체 글꼴 사용이나 그리기 실패는 알려 줍니다. PNG 또는 TIFF로 내보낼 때 원래
비트 깊이를 유지합니다.

**적용하고 닫기**는 초안 전체를 한 번의 실행 취소 가능한 변경으로 확정합니다. 취소, Esc,
대화상자 닫기는 초안을 버립니다. 다른 레이블을 골라도 확정하지 않은 편집은 남습니다.
**삭제**는 마지막 항목을 포함해 선택한 항목만 제거합니다. 메뉴의 제거 작업은 소스,
정합된 스택, 출력, 모든 레이블을 각각 지울 수 있고 역시 실행 취소할 수 있습니다. 레이블
적용은 세션 표시만 바꾸므로 파일에 쓰려면 이미지를 내보내야 합니다.

## 11. 설정 및 구성

**설정 → 고급 설정**에서 성능, 정합, 센서 보정, 출력 이름, StackMFF AI, 시작 설정을
편집합니다. **확인**을 누를 때까지 변경은 초안이며 취소, Esc, 창 닫기에서는 버려집니다.
타일 크기를 줄이면 표시되는 겹침 상한이 즉시 타일 절반으로 갱신됩니다. AI 섹션의 저장된
배치 상한은 유지되지만 현재 추론은 호출당 타일 하나입니다. 정합 폭은 정합 정확도에
영향을 주며, 정합 진단 수집은 정합 섹션의 체크박스입니다.

자동 업데이트 다운로드는 유휴 시간에 실행되며 자동으로 설치되지 않습니다. 다운로드가
끝나면 **재시작 후 업데이트**를 직접 선택할 때까지 준비된 상태로 남습니다. 재시작은
활성 편집과 저장하지 않은 작업을 보호하고 복구 데이터를 쓴 뒤 교체 빌드를 실행합니다.
다운로드나 준비를 취소하면 현재 안전 경계까지 기다립니다. 완전하고 더 새로운 스테이징
빌드가 있으면 오프라인에서도 설치할 수 있습니다.

상태 패널은 운영 체제가 둘 다 제공할 때 사용/전체 물리 메모리를 표시하며, 가져올 수
없으면 `N/A`를 표시합니다.

### 타일 설정 (메모리 최적화)

큰 이미지의 경우 OpenFocus는 메모리 문제를 피하기 위해 타일 기반 처리를
사용합니다.

**설정 → 고급 설정 → 성능**에서 접근합니다.

- **타일 처리 사용**: 끄면 전체 이미지를 강제로 처리합니다(큰 이미지는 메모리가 부족할 수 있음)
- **타일 블록 크기**: 각 처리 타일의 크기(기본값: 1024px)
- **타일 겹침**: 이음매 없는 혼합을 위한 타일 간 겹침(기본값: 256px)
- **타일 임계값**: 이 크기를 넘는 이미지에 타일을 사용(기본값: 2048px)

**권장 사항**:
- 블록 크기가 작을수록 메모리 사용량이 적고 처리가 느립니다
- 블록 크기가 클수록 메모리 사용량이 많고 처리가 빠릅니다
- 결과에 이음매가 보이면 겹침을 늘리세요

### 정합 설정

**설정 → 고급 설정 → 정합**에서 접근합니다.

- **축소 폭**: 정합을 위한 전처리 해상도
  - 기본값: 1024px
  - 속도를 원하면 낮추고, 정확도를 원하면 높입니다

### 성능 참고

큰 실제 스택에서 측정한 처리량과 메모리 수치, 깊은 스택과 고해상도 입력에 대한
실용적인 지침은 [PERFORMANCE.md](./PERFORMANCE.md)를 참고하세요.

### 스레드 수 설정

CPU 병렬 처리를 제어합니다.

**설정 → 고급 설정 → 성능 → 스레드 수**에서 접근합니다.

- `0`은 자동 조절이며 새 설정의 기본값입니다.
- 양수는 스레드 수의 상한이며 저장된 상한은 유지됩니다.
- CPU 용량, 리소스 모드 및 사용 가능한 메모리에 따라 동시 작업 수가 줄어들 수 있습니다.

### 리소스 모드

**설정 → 고급 설정 → 성능 → 리소스 모드**는 한 번의 렌더링이 시스템을 얼마나 쓸지
정합니다. 합성 결과 자체는 바꾸지 않습니다.

| 모드 | 동작 |
|---|---|
| 균형(기본값) | 물리 코어의 약 20%와 메모리 여유를 데스크톱용으로 남깁니다 |
| 반응 우선 | 코어의 약 절반과 더 작은 처리 창을 씁니다. 렌더링은 느리지만 시스템이 가장 쾌적합니다 |
| 최대 | 메모리 예산이 허용하는 모든 물리 코어를 씁니다 |

계획기는 물리 코어, CPU affinity, 할당량을 고려하고 한 번에 하나의 병렬 계층만
실행합니다. 무거운 작업은 준비부터 게시까지 같은 admission을 공유하고, 취소는 실행 중인
네이티브 호출이 끝날 때까지 기다립니다. 메모리를 알 수 없거나 부족하면 리소스 오류가
납니다. 선택한 타일 그리드는 그대로이며, 타일을 직접 작게 고르면 출력 픽셀이 달라질 수
있습니다.

### GPU 가속 토글

OpenFocus는 AI 신경망 모델(StackMFF V1/V2/V3)에만 GPU(CUDA/MPS)를 사용하며, 고전
알고리즘은 항상 CPU에서 실행됩니다.

- **설정 → GPU 가속**에서 전환합니다
- 선택을 해제하면 AI 방식이 CPU로 강제됩니다. GPU 드라이버가 문제를 일으킬 때
  유용합니다
- 가속기를 쓸 수 없거나 사용하지 않으면 상태 패널에 `N/A`, 가속기는 있지만 선택한
  방식이 CPU 전용이면 `CPU*`가 표시됩니다
- 선택은 다음 렌더링부터 적용되며 기억됩니다

### AI 배치 크기

**설정 → 고급 설정 → AI**에서 접근합니다.

- 저장되는 배치 상한의 기본값은 2이지만 현재 모든 장치에서 호출당 타일 하나를 추론합니다.
- 상한을 늘려도 GPU 병렬 배치 처리는 활성화되지 않습니다.

### 테마

인터페이스 테마는 **밝게(기본값)** 와 **어둡게** 두 가지입니다.
**설정 → 테마**에서 전환하며, 선택은 즉시 적용되고(Windows 제목 표시줄도 함께
따릅니다) 기억됩니다. 처음 실행하는 사용자는 시작 대화상자에서 테마를
선택합니다.

### 포터블 모드

`OpenFocus.exe` 옆에 `OpenFocus.portable`이라는 빈 파일을 만들면(포터블 zip에
하나 들어 있습니다) 설정, 로그, 최근 파일 등 모든 사용자 데이터가 사용자
프로필 대신 앱 옆의 `OpenFocusData` 폴더에 저장됩니다. 따라서 설치본을 USB
드라이브에 담아 이동할 수 있습니다. 표식 파일을 삭제하면 일반 프로필로
돌아갑니다.

### EXIF 메타데이터

원본 메타데이터(카메라 모델, 노출, 방향 등)는 유지됩니다. 방향은 불러올 때
적용되고, PNG/TIFF/WebP 내보내기에는 원본 EXIF가 자동으로 포함됩니다. JPG/BMP
내보내기는 전체 EXIF를 저장할 수 없어 EXIF 없이 기록됩니다.

### HEIC/HEIF 입력

iPhone 사진을 바로 불러올 수 있습니다. 선택적 `pillow-heif` 패키지가 필요하며
(`pip install pillow-heif`), 패키지 빌드에는 포함되어 있습니다.

### 센서 보정과 플랫 필드

플랫 필드 보정은 세션 작업 픽셀을 바꾸지만 소스 파일을 덮어쓰지 않습니다. 화이트 기준
이미지와 미리보기 프레임을 고르고 소스나 배율을 바꾸면 미리보기를 다시 생성하세요. 기준과
작업/베이스 이미지는 같은 좌표 영역과 크기여야 합니다. 적용은 두 스택을 준비한 뒤
확정하며 선택적인 기준 프레임 제거도 같은 실행 취소 단계에 속합니다. 세션 밖에 픽셀을
남기려면 보정된 소스 이미지를 내보내세요.

배치 처리에서도 처리 옵션으로 선택적 화이트 필드 이미지를 고를 수 있습니다. 원본 프레임
해상도의 초점이 나간 기준을 고르면 입력 스택에 맞춰 축소되고 기본 더스트 크기로 정합
전에 적용됩니다. 읽을 수 없는 기준이나 크기 불일치는 해당 스택을 분명히 실패시킵니다.
기준은 폴더 입력(그룹 처리 포함)에서 제외되며 합성에는 소스 프레임이 최소 두 개 남아야
합니다. 비워 두면 보정 없이 처리합니다. CLI에서도 `--dust-map WHITE`로 지정할 수
있습니다. 플랫 필드 보정은 투명 입력과 함께 쓸 수 없습니다.

센서 보정은 선택 사항이며 정합 전에 원래 센서 좌표 프레임에 실행됩니다. 데스크톱에서는
**설정 → 고급 설정 → 센서 보정**에 있고 배치 대화상자에도 같은 컨트롤이 있습니다.
알려진 핫/데드 픽셀을 고치려면 명시적인 결함 마스크를 고르세요. OpenFocus는 시편
이미지에서 마스크를 추측하지 않습니다. 마스크는 소스와 같은 크기의 단일 채널
8비트 또는 16비트 이미지여야 하며 0은 정상, 1 또는 채널 최댓값은 결함입니다. 처리 전에 범위를 확인하세요. 화면의 10%를
넘는 마스크나 마스크되지 않은 이웃이 없는 결함은 거부됩니다. 마스크는 원래 해상도로
두고 소스 이미지로 선택하지 마세요. GUI에서 결함 마스크를 쓰면 소스 프레임을 원본
배율로 불러옵니다. 마스크는 절대 축소되지 않습니다. GUI 스택에서 회전, 뒤집기, 플랫
필드 보정 등 소스를 바꾼 뒤에는 센서 보정(노이즈 제거 포함)을 적용할 수 없습니다. 원본
프레임을 다시 불러오거나 보정을 끄세요. 이런 소스 이력을 가진 복원 프로젝트도 같습니다.
사전 정합 ROI 처리와 함께 쓸 수 없습니다. 보정 설정은 현재 세션과 저장 프로젝트에
속하며 전역 환경 설정이 아닙니다. 배치와 CLI는 원래 입력을 따로 처리하고 센서 보정,
플랫 필드 보정, 정합 순서로 실행합니다. 결함 마스크는 중립 EXIF 방향의 소스 파일을
요구합니다. 방향이 있는 파일, 카메라 RAW, 방향을 확정할 수 없는 소스는 디코딩 픽셀이
센서 좌표와 맞지 않을 수 있어 거부됩니다.

선택적인 센서 노이즈 제거는 결함 마스크와 별개이며 기본적으로 꺼져 있습니다. 원래
크기로 결과를 확인해 평활화가 시편에 적합한지 판단하세요. 센서 보정은 소스 파일과
8비트/16비트 깊이를 보존하며 플랫 필드 보정과는 별개입니다. CLI는
`--defect-mask-path MASK`와 `--sensor-denoise`를 쓰고 레시피와 Python 레시피 API도 이
옵션을 기록합니다. 레시피는 마스크 지문을 저장하고 없거나 바뀐 마스크를 거부합니다.
CLI 보정은 투명 입력과 함께 쓸 수 없습니다. 그룹 처리는 중간 그룹 결과가 아니라 원래
프레임에만 보정을 적용합니다.

레시피는 출력 위치가 모든 입력 폴더 밖에 있어야 하며 명시적으로 선택한 입력을 출력으로
쓸 수 없습니다. 소스 이미지를 보호하고 다시 실행할 때 이전 결과가 입력에 섞이지 않게
하기 위해서입니다. 프로젝트의 처리 설정은 원본 소스가 이동했더라도 템플릿이나 레시피로
재사용할 수 있습니다. **파일 → 처리 템플릿 저장…**은 소스 경로 없이 설정을 저장하고
**파일 → 처리 템플릿 적용…**은 불러온 스택에 적용합니다.
`openfocus recipe create --project`가 쓰는 헤드리스 레시피에는 여전히 명시적 `--input`이
필요합니다. 템플릿은 센서 노이즈 제거 플래그를 담지만 결함 마스크 경로는 저장하지 않고,
레시피는 마스크 경로와 지문을 저장합니다. 프로젝트 자체를 열려면 소스와 기록된 플랫 필드
기준이 필요합니다.

**도구 → 더스트 맵(플랫 필드)**에서 스택의 베이스 배율일 때 파일 기준을 적용하면 저장된
프로젝트가 절대 경로, 내용 해시, 더스트 크기를 기록하고 열 때 원본 소스에 한 번 다시
적용합니다. 기준 파일은 바꾸지 말고 같은 위치에 두세요. 기준이 없거나 바뀌면 프로젝트를
열 수 없습니다. 스택에서 고른 기준이나 작업/베이스 배율이 다른 보정은 프로젝트를 저장하기
전에 보정된 소스 스택을 내보내야 합니다. 보정 후 작업 배율을 바꿨다면 저장 전에 보정
배율로 되돌리거나 보정된 스택을 내보내세요.

**도움말 → 피드백 보내기**는 로컬 로그를 엽니다. "복사"는 표시 중인 세션 로그만 복사하며,
피드백 ZIP에는 세션/전체 애플리케이션 로그와 환경 정보가 들어갑니다. 제출 전에 내용을
확인하세요. GitHub 열기는 트래커만 엽니다. 내보내기 취소는 파일을 바꾸지 않고, 오류가
나면 이전 대상 파일을 남기고 실패한 경로를 표시합니다.

각 실행은 자체 순환 로그를 쓰므로 동시에 도는 GUI/CLI 기록이 분리됩니다. 작업 ID는
매개변수, 경과 시간, 완료/취소/실패 결과를 연결하며 예기치 않은 오류에는 전체 스택
트레이스가 포함됩니다. 피드백 ZIP에는 현재 충돌 보고서와 종속성 버전도 들어갑니다.
**도움말 → 로그 폴더 열기** 또는 피드백 화면에 표시되는 경로에서 파일을 찾으세요.
로그는 프로세스당 1MB에서 순환하며 백업 세 개를 유지합니다. 14일이 지난 비활성 세션
로그는 삭제됩니다. 자세한 지원 로그가 필요하면 실행 전에
`OPENFOCUS_LOG_LEVEL=DEBUG`를 설정하세요. `OPENFOCUS_LOG_DIR`로 다른 로그 폴더를
지정할 수 있습니다.

### 업데이트

도움말 → 업데이트 확인은 현재 버전을 `openfocus.top`의 릴리스 정보와 비교합니다. 새 릴리스는
앱이 유휴 상태일 때 같은 사이트에서 백그라운드로 내려받습니다. 빌드가 스테이징되면 배너와 상태 영역에
**재시작 후 업데이트**가 나타나며 오프라인에서 적용할 수 있습니다. 자체 업데이트를 할 수
없는 빌드는 웹사이트 다운로드 페이지를 엽니다. 자동 확인은 하루에 최대 한 번 조용히 실행됩니다.

### 정합 캐시

OpenFocus는 정합 결과를 원본 스택 옆의 `.openfocus_cache` 폴더에 저장할 수
있습니다. 그러면 같은 스택을 다시 열 때(파일이 바뀌지 않았다면) 정렬을 완전히
건너뜁니다. **설정 → 고급 설정 → 정합 → 정합 캐시**에서 전환하며, 오래된 항목은 자동으로
교체됩니다.

### 출력 이름

**설정 → 고급 설정 → 출력 이름**에서 새로 렌더링한 결과를 식별할 선택적 파일 이름
접두사를 정할 수 있습니다. 입력하면 예시가 갱신됩니다. 최대 40자의 영문, 숫자,
밑줄, 하이픈을 쓸 수 있으며 비워 두면 원래 이름을 유지합니다. **확인**을 누르면
기억하고 취소하면 변경을 버립니다. 접두사는 새 출력 목록 이름과 추천 내보내기 이름의
일부가 되고 기존 결과는 원래 이름을 유지합니다. 저장 대화상자에서 이름을 고칠 수
있습니다. 이 설정은 소스 파일이나 배치 출력 이름을 바꾸지 않습니다.

### 저장되는 설정

다음 항목은 애플리케이션을 재시작해도 자동으로 유지됩니다. 스레드 수, 리소스 모드,
타일 매개변수, 정합 축소 폭, AI 합성(StackMFF V3) 배치 크기, GPU 가속 토글, 정합
캐시와 정합 진단 토글, 인터페이스 언어, 창 크기/패널 배치, 끌어내기 내보내기 형식,
방식별 밝기 옵션, 스무딩과 반경 값, 최근에 연 스택. 설정 대화상자는 확인하는 순간
저장되며, 애플리케이션이 닫힐 때도 모두 저장됩니다. 기본 설정은 사용자별로
`OpenFocus/OpenFocus.ini`(QSettings INI 형식)에 보관됩니다.

### 인터페이스 언어

**설정 → 언어**에서 언제든지 12개 언어(English, 中文, 日本語, Español, Deutsch, Français,
Русский, 한국어, Português, Italiano, Nederlands, Polski)를 전환합니다. 변경은 즉시
적용되고 이후 세션에서도 유지됩니다. 새 언어 팩은 `locales/<code>.py` 파일 하나를
추가하면 메뉴와 자동 감지에 포함됩니다.

### 자동 업데이트 확인

OpenFocus는 하루에 한 번, 실행 후 몇 초 뒤에 `openfocus.top`에 새 릴리스가 있는지
조용히 확인합니다. 릴리스 노트도 같은 사이트에서 가져옵니다. 새 버전이 있으면 이미지 패널 위에 배너가 나타나 버전,
**지금 업데이트**(스테이징된 빌드 적용 또는 다운로드 시작), **새 기능**(릴리스 노트),
닫기 버튼을 보여 줍니다. 닫으면 해당 버전에 대해서만 배너가 숨겨지고, 다음
릴리스에서 다시 나타납니다. **도움말 → 업데이트 확인**으로 즉시 다시 표시할
수도 있습니다.

다운로드가 백그라운드에서 진행되는 동안 상태 표시줄에 진행률이 표시됩니다.
**도움말 → 업데이트 확인**으로 언제든 직접 확인할 수도 있습니다.

## 12. 배치 처리

여러 폴더를 자동으로 처리합니다.

1. **도구 → 배치 처리**로 이동합니다
2. 배치 대화상자에서:
   - **폴더 추가**: 이미지 시퀀스가 들어 있는 폴더를 선택합니다
   - **폴더 끌어놓기**: 하나 이상의 스택 폴더를 대화상자(또는 폴더 목록) 어디에나
     놓으면 한 번에 추가됩니다. 놓으면 다중 폴더 모드로 바뀌고 디코딩되는 대로
     썸네일이 나타납니다
   - **선택 항목 제거**: 선택한 폴더를 목록에서 제거합니다
3. 출력 설정을 구성합니다:
   - **원본 폴더에 하위 폴더 만들기**: 각 입력 폴더에 결과를 만듭니다
   - **원본 폴더와 같게**: 기존 파일을 보존한 채 입력 옆에 저장합니다
   - **출력 폴더 지정**: 출력 위치를 직접 지정합니다
4. 현재 합성/정합 설정을 검토합니다
5. **배치 처리 시작**을 클릭해 시작합니다

배치 대화상자는 실시간 진행률을 보여 줍니다. 언제든지 처리를 취소할 수 있습니다.

### 배치 처리 참고

- 시작 시점의 메인 창 설정 스냅샷을 기본값으로 쓰고 배치 설정으로 덮어쓸 수 있습니다
- 각 폴더 또는 분할 그룹은 같은 파이프라인으로 독립 처리됩니다
- **그룹 합성**은 다중 폴더 모드에서만 쓸 수 있고 **큰 스택을 그룹으로 처리** 체크박스로
  켭니다. 끄면 그룹 크기와 겹침이 숨겨집니다. 켜면 그룹 크기는 2 이상, 겹침은 0부터
  그룹 크기−2까지입니다. 데스크톱 겹침은 1에서 시작하고 크기를 바꾸면 허용 범위로
  제한됩니다. 그룹은 임시 디스크를 써서 라운드별로 합성하며 진행 표시에 각 라운드가
  나옵니다. 합성, 노출 맞추기, 베이스 보정, 정합은 각 그룹의 프레임과 기준을 쓰므로
  결과는 스택 전체를 한 번에 처리한 결과의 근사치입니다. 합성 방식이 필요하고 원본
  프레임 깊이, 출처, 정합된 프레임 내보내기는 쓸 수 없습니다. 분할 폴더 모드는 지원하지
  않습니다. 정합하는 그룹은 자기 첫 프레임을 좌표 기준으로 씁니다. 각 정합은 보간용으로
  보수적인 경계를 잘라내고 이후 라운드는 남은 사각형의 교집합을 취하므로 최종 이미지가
  잘릴 수 있습니다. 각 그룹은 양쪽 8픽셀보다 커야 하며 어려운 회전이나 투영 변환은
  안전한 사각형을 얻지 못해 오류가 날 수 있습니다. 그럴 때는 정합 없이 미리 정렬한
  입력을 쓰거나 그룹화를 끄세요.
- 그룹 입력은 방향이 같은 동일 크기의 단일 프레임 파일이어야 하고 Pillow가 읽는 헤더가
  있어야 합니다. 카메라 RAW, 다중 페이지 파일, 알파 채널이나 투명 이미지(투명 PNG 포함)는
  지원하지 않습니다. 알파를 제거하거나 그룹화를 끄세요. CLI dry-run도 이 제한을
  확인합니다. 명령 예:
  `python main.py --input stack --output fused.png --group-size 8 --group-overlap 1`.
  CLI 그룹 입력은 폴더여야 하고 `--depth-map`과 함께 쓸 수 없습니다. 스택 전체에 다른
  OpenFocus 정합 기준을 지정하는 경우에도 함께 쓸 수 없습니다. 플랫 필드 기준은 정합 전
  원본 프레임에 적용되고 출력 선명화는 최종 그룹 뒤에 한 번만 적용됩니다.
- **파일 → 처리 템플릿 저장**은 소스 경로가 없는 처리 설정을 저장합니다.
  **처리 템플릿 적용**은 템플릿, 프로젝트 또는 프로젝트 기반 레시피를 현재 스택에
  적용하며 입력, 변환, 제외, 레이블을 바꾸지 않습니다. 템플릿 자체는 실행 가능한
  레시피가 아닙니다. CLI에서는 `openfocus recipe create`와 `openfocus recipe run`으로
  처리 레시피를 저장하고 다시 실행할 수 있습니다. 프로젝트의 소스 변환은 CLI 레시피로
  바로 캡처할 수 없으므로 먼저 처리된 소스 스택을 내보내세요.
- **모드별 출력 위치**: **정합만**이면 선택한 대상 아래에 스택마다 `<stack>_aligned`
  폴더가 생기고 출력 패널에 그 폴더가 표시됩니다. **합성 + 정합된 스택 저장**이면
  합성 이미지를 `<stack>.<ext>`로 대상에 쓰고 정렬된 프레임을 옆의 `<stack>_aligned`에
  둡니다. 출력 패널에는 합성 결과만 표시됩니다. **합성만**이면 합성 이미지만 씁니다.
  출력 패널의 폴더 이름은 디스크의 이름과 같습니다.
- 정렬된 프레임은 원래 파일 이름 줄기를 유지합니다. 중복 이름과 기존 폴더에는 번호가
  붙고 소스 파일은 절대 대체되지 않습니다.
- 같은 폴더에 원본 파일이 있으면 이전 빌드가 남긴 `*_registered*` 복사본을 프레임으로
  불러오지 않으며, 불러오기 메시지에 건너뛴 수가 표시됩니다.
- PNG/TIFF는 16비트를 유지하고 JPG/BMP를 명시하면 8비트로 변환합니다.
- 취소는 워커가 멈출 때까지 기다립니다. 확정된 파일은 남고 부분 성공, 실패, 취소,
  시작하지 않은 작업은 따로 집계됩니다.

## 13. 결과 내보내기

### 단일 결과 저장

1. 출력 목록에서 저장할 결과를 선택합니다
2. **파일 → 저장**으로 이동하거나 `Ctrl+S`를 누릅니다
3. 형식과 위치를 선택합니다
4. 저장을 클릭합니다

### 레이어 TIFF 저장

리터치한 출력을 오른쪽 클릭하고 **레이어 TIFF 내보내기…**를 선택하면 결과와 기록된
소스 프레임을 하나의 레이어 TIFF로 저장합니다. 라이브 레이블과 스케일 바는 포함되지
않고 저장하지 않은 주석 변경은 보호됩니다. 소스 기하와 유효 마스크는 유지됩니다. 결과와
각 소스는 크기가 같은 불투명 RGB 또는 회색조 이미지여야 하고 8비트/16비트 깊이가 같아야
하며 각 소스 사각형은 결과 안에 들어와야 합니다. 소스는 최대 128개이고 소스 이름은 255자까지이며
NUL이나 기본 다국어 평면 밖 문자(많은 이모지 등)를 쓸 수 없습니다. 안전하지 않은 상황이나
512MiB를 넘을 것으로 예상되는 작업은 불완전한 파일을 쓰지 않고 거부합니다. Windows의
GIMP 3.2.6은 오프셋과 투명 정합 여백을 포함한 레이어를 열 수 있습니다. 결과가 보이고
소스 레이어는 숨겨지며 GIMP가 보이는 배경 레이어를 추가합니다. 다른 편집기는 검증되지
않았습니다.

### 끌어내기 내보내기 형식

출력 목록에서 결과를 끌어내면 출력 목록의 컨텍스트 메뉴에서 고른 형식
(**끌어내기 형식**: JPG, PNG, WebP, TIFF)으로 이미지 파일이 만들어집니다. 선택은
기억됩니다.

### 정합된 스택 저장

1. **파일 → 스택 저장 → 정합된 스택**으로 이동합니다
2. 저장 형식을 선택합니다:
   - **폴더로 저장**: 정렬된 각 프레임을 별도 이미지 파일로 저장합니다
   - **다중 페이지 TIFF로 저장**: 스택 전체를 16비트 깊이를 유지한 채 하나의 `.tif`로 씁니다
   - **GIF로 저장**: 정렬된 시퀀스의 애니메이션 GIF를 만듭니다

### 입력 스택 저장

1. **파일 → 스택 저장 → 입력 스택**으로 이동합니다
2. 저장 형식을 선택합니다:
   - **폴더로 저장**: 원본 프레임을 별도 이미지로 저장합니다
   - **다중 페이지 TIFF로 저장**: 입력 스택을 16비트 깊이를 유지한 채 하나의 `.tif`로 씁니다
   - **GIF로 저장**: 입력 시퀀스의 애니메이션 GIF를 만듭니다

### 내보내기 형식

- **JPG**: 손실 압축 8비트 형식, 품질 대비 용량이 좋습니다
- **PNG**: 무손실, 8비트/16비트 데이터 유지
- **BMP**: 비압축, 16비트 데이터는 8비트로 변환
- **TIFF**: 8비트/16비트 유지, 다중 페이지 내보내기는 스택 전체를 한 파일로 저장
- **GIF**: 8비트 팔레트 애니메이션, 취소해도 기존 대상 파일은 유지

## 14. 명령줄 인터페이스

`pip install openfocus`에는 AI 모델과 가중치, HEIC와 카메라 RAW 디코딩이 포함됩니다. Python 3.13 이상에서는 `dtcwt`가 생략되며 DTCWT 항목은 안내와 함께 비활성화됩니다.

OpenFocus는 GUI 없이도 실행할 수 있어 스크립트 파이프라인과 CI에 유용합니다. pip
패키지를 설치하면 `openfocus` 명령을 바로 쓸 수 있고, 소스에서 실행할 때는 `openfocus`를
`python main.py`로 바꾸면 됩니다. 주요 하위 명령은 다음과 같으며 합성 옵션은 두 진입점
모두에서 같습니다.

```bash
openfocus version                       # 버전 출력
openfocus describe                      # JSON: 방식, 매개변수, 기능, 제어 명령
openfocus gui [--control] [--socket NAME] [경로…]   # 데스크톱 앱 시작
openfocus ctl <command> [flags]          # 실행 중인 창 제어(AGENT_CONTROL_SPEC.md)
openfocus recipe create FILE --input … --output … [처리 옵션]
openfocus recipe run FILE [--dry-run]    # 저장된 헤드리스 레시피 재생
openfocus retouch replay CHECKPOINT --base BASE --sources … --output RESULT
```

`openfocus gui`는 분리되어 시작합니다. `--control`은 제어 채널이 준비될 때까지 기다린 뒤
연결 JSON을 출력합니다. `openfocus describe`와 `version`은 입력이 필요 없습니다. Agent
워크플로는 [AGENT_CONTROL_SPEC.md](./AGENT_CONTROL_SPEC.md)와
`skills/openfocus-control/SKILL.md`에 있습니다. 데스크톱 앱은 시작할 때 토큰으로 보호된
로컬 Agent 채널도 자동으로 엽니다.

```bash
pip install openfocus
openfocus -i ./stack_folder -o ./result/fused.png
```

```bash
# 기본 AI(StackMFF V3)로 폴더 합성
python main.py --input ./stack_folder --output ./result/fused.png

# DTCWT + ECC 정합, 8스레드
python main.py -i ./stack_folder -o ./result/fused.png -m dtcwt -a ecc -t 8

# StackMFF V3를 CPU로 강제하고 사용자 지정 타일 크기 사용
python main.py -i ./stack_folder -o ./result/fused.png -m stackmffv3 --cpu --tile-size 512

# 파일을 명시적으로 나열. 동영상 파일도 입력으로 받습니다
python main.py -i img1.jpg img2.jpg img3.jpg -o fused.png -m gfgfgf

# 메타데이터에서 보정한 스케일 바가 있는 단일 다중 페이지 TIFF Z-스택
python main.py -i ./zstack.tif -o fused.png -m dtcwt --scale-bar

# 합성하거나 입력을 바꾸지 않고 인접한 유사 프레임만 확인
python main.py -i ./stack_folder --suggest-duplicates
```

`--suggest-duplicates`는 폴더 또는 순서가 있는 단일 프레임 이미지 목록을 받아 `files`와
`suggestions` 배열을 가진 JSON 객체를 출력합니다. `index`와 `reference_index`는 `files`의
0부터 시작하는 위치이고 `difference`는 정규화한 샘플 차이의 평균입니다.
`--json report.json`을 더하면 같은 객체를 저장합니다. 이 검토 모드는 `--output`,
`--output-dir`, `--json-progress`, `--dry-run`과 함께 쓸 수 없습니다. 보고서는 주어진
입력 순서에서 인접 파일만 비교하며 나중에 제외할 프레임을 알지 못합니다. 기준 프레임을
제외한다면 그 다음 프레임을 다시 고려하거나 의도한 순서로 다시 검토하세요.

한 번의 렌더링에 `--align openfocus --alignment-report alignment.json`을 더하면 프레임별
정합 결과를 저장합니다. JSON에는 `method`, `input`, `frame_count`, `entries`가 있고
`frame_index`는 합성 정렬 전의 디코딩 입력 순서로 0부터 시작합니다. 다중 페이지 이미지는
페이지 순서, 동영상은 디코딩 순서로 펼쳐집니다. 복합 방식은 단계별 항목을 따로 가집니다.
보고서는 성공 후 원자적으로 쓰이며 입력이나 다른 출력을 대체할 수 없습니다. 배치, 그룹,
dry-run에서는 이 옵션을 쓸 수 없습니다.

### 처리 레시피

처리 레시피는 헤드리스 설정을 저장해 재사용하고 옮길 수 있습니다.

```bash
openfocus recipe create workflow.json -i ./stack_folder -o ./result/fused.png -m dct --cpu
openfocus recipe run workflow.json --dry-run
openfocus recipe run workflow.json
```

레시피 JSON 버전 1은 `version`, `input` 배열, `output` 또는 `output_dir`, `options`
객체를 담습니다. 경로는 레시피 파일 기준 상대 경로이므로 옮길 때 입력도 함께 옮기세요.
생성은 CLI 설정과 확인된 알고리즘 매개변수를 기록하고 알 수 없는 필드, 잘못된 값,
지원하지 않는 버전을 거부합니다. `--dry-run`, `--resume`, `--json`, `--config` 같은
일시적 제어 항목은 레시피에 기록되지 않습니다. dry-run은 입력만 확인하고 결과 파일을
쓰지 않습니다. 기존 `.ofproj`에서 설정을 추출할 수도 있습니다.

```bash
openfocus recipe create workflow.json --project session.ofproj -i ./new_stack -o ./result/fused.png
```

합성, 정합, 밝기, 순서, 선명화, 타일 설정을 옮기고 GUI용 처리 설정도 넣습니다. 프레임
제외, 로딩 배율, 레이블, 편집은 옮기지 않습니다. 소스 변환(적용한 플랫 필드 보정 포함)이
있는 프로젝트는 먼저 보정된 소스 스택을 내보내야 합니다. 레시피 출력은 입력 폴더 밖에
있어야 하고 입력 파일을 출력으로 쓸 수 없습니다. 그룹 옵션은 CLI 인수에서 캡처할 수
있습니다. GUI의 **파일 → 처리 템플릿 저장**은 소스 경로 없이 설정을 저장하고,
**처리 템플릿 적용**은 템플릿, 프로젝트, 프로젝트 기반 레시피를 현재 스택에 적용합니다
(입력, 변환, 제외, 레이블은 바꾸지 않음). 템플릿 자체는 실행 가능한 레시피가 아닙니다.
레시피에 내장된 GUI 설정과 CLI 옵션은 서로 독립적이므로 JSON을 고칠 때 둘을 일치시키세요.

PyQt를 가져오지 않고도 Python에서 같은 헤드리스 API를 사용할 수 있습니다. 실제로 처리하려면 `dry_run=False`를 사용하세요.

```python
from core.recipes import capture_project_recipe, capture_recipe, load_recipe, save_recipe, run_recipe

capture_recipe("workflow.json", ["-i", "stack_folder", "-o", "result/fused.png", "-m", "dct"])
capture_project_recipe("from-project.json", "session.ofproj",
                       ["-i", "new_stack", "-o", "result/fused.png"])
recipe = load_recipe("workflow.json")
save_recipe("workflow.json", recipe)
exit_code = run_recipe("workflow.json", dry_run=True)
```

`capture_recipe` 인수의 경로는 현재 디렉터리를 기준으로, `save_recipe`에 저장된 경로는 레시피를 기준으로 해석됩니다. 레시피는 설정과 참조 및 명시적으로 선택한 센서 결함 마스크의 콘텐츠 지문을 기록하지만, 입력 픽셀, 소프트웨어 버전, 하드웨어 또는 원본 스택의 체크섬은 기록하지 않습니다. 출처가 중요하면 이를 별도로 보관하세요. 같은 설정이라도 소프트웨어 버전, 드라이버, 장치에 따라 픽셀이 같다는 보장은 없으며 GPU 신경망 연산은 비결정적일 수 있습니다. CPU 실행이 필요하면 `--cpu`를 사용하고 설치된 소프트웨어와 입력을 보관하세요.

### 리터치 체크포인트 재생

리터치 체크포인트는 헤드리스로 재생할 수 있습니다.

```bash
openfocus retouch replay edits.json --base fused.png --sources frame1.png frame2.png --output retouched.tif
```

실제 리터치에 쓴, 정합과 ROI 자르기 등 처리를 마친 소스 프레임을 원래 픽셀 값과 비트
깊이로 지정하세요. 체크포인트는 편집과 지문을 기록하며 픽셀은 기록하지 않습니다. 각
경로에는 이미지 하나만 있어야 하고 출력은 PNG 또는 TIFF로 베이스 비트 깊이를 유지하며
체크포인트나 입력을 덮어쓸 수 없습니다.

| 옵션 | 설명 |
|--------|-------------|
| `--input, -i` | 이미지 폴더, 동영상 파일, 하나 이상의 이미지 파일, 또는 다중 페이지 TIFF |
| `--output, -o` | 단일 스택 출력 경로(확장자가 형식 결정). `--output-dir`이 없으면 필수 |
| `--output-dir, -d` | 배치 모드: 각 입력 폴더를 처리하고 스택마다 `<folder>.png` 기록 |
| `--method, -m` | `stackmffv3`(기본값), `stackmffv2`, `stackmff`, `openfocus_a/b/c`, `guided_filter`, `dct`, `dtcwt`, `gfgfgf` |
| `--param KEY=JSON_VALUE` | 합성 매개변수. 여러 번 지정할 수 있고 기존 전용 플래그보다 우선 |
| `--align, -a` | `none`(기본값), `homography`, `ecc`, `openfocus`, `both` |
| `--align-param KEY=JSON_VALUE` | 정합 매개변수. 예: `failure_policy="fail"`, `reference_frame=3` |
| `--align-shift-limit` | `openfocus` 정합 전용: 허용하는 최대 이동량(프레임 크기 비율, 기본값 0.08) |
| `--alignment-report PATH` | 정합을 켠 단일·비그룹 렌더링의 프레임별 결과를 JSON으로 저장. 배치/그룹 불가 |
| `--suggest-duplicates` | 인접한 유사 프레임을 JSON으로 제안. 합성하거나 제외하지 않음. 출력·진행·dry-run·센서 보정 옵션과 함께 쓸 수 없음 |
| `--exposure-match` | 합성 전에 모든 프레임의 평균을 마지막 프레임에 맞춥니다(기본값: 켜짐, `--no-exposure-match`로 끔). 스택 전체 게인을 쓰므로 타일 출력도 이음매가 없고, 모든 방식과 OpenFocus 정합의 밝기 기준에 적용됩니다 |
| `--base-frame` | 선택적 후처리 단계: 출력의 저주파를 `last`/`first` 프레임에 맞춥니다(기본값 `none`) |
| `--sharpen-output` | 합성 후 양자화 전에 가벼운 언샤프 마스크 적용. 기본값 꺼짐 |
| `--sort` | `openfocus_a/b/c`의 프레임 순서: `asc`(기본값, 파일 순서), `desc`(원경→근경 스윕 반전), `off` |
| `--dust-map WHITE` | 초점이 나간 화이트 필드 촬영본으로 플랫 필드(더스트 맵) 보정 |
| `--defect-mask-path MASK` | 센서 좌표 결함 마스크. 0이 아닌 픽셀을 정합 전에 복구 |
| `--sensor-denoise` | 정합 전에 보수적인 센서 노이즈 제거 적용 |
| `--kernel, -k` | 커널 크기(홀수로 강제; OpenFocus A/B의 초점 응답 스케일을 조절하며 C에는 적용되지 않음) |
| `--depth-smoothing VALUE` | `openfocus_b` 전용: 깊이 스무딩 강도(기본 1.2) |
| `--blend-smoothing VALUE` | `openfocus_a` / `openfocus_c` 전용: 혼합 스무딩 강도(A 기본 2.0, C 기본 3.0) |
| `--threads, -t` | 스레드 수 상한. `0`은 자동(기본값), 양수는 동시 작업 수를 제한 |
| `--resource-preference` | 리소스 모드: `balanced`(기본값), `responsive`, `maximum` |
| `--batch-size` | AI 타일 배치 상한(기본값 2). 현재 호출당 타일 하나를 추론 |
| `--ai-mode` | StackMFF V3 출력: `soft`(기본값, 확률 혼합) 또는 `hard`(픽셀별 가장 확률 높은 프레임) |
| `--cpu` | GPU가 있어도 CPU를 강제로 사용 |
| `--downscale` | 정합 특징 검출용 축소 폭 |
| `--tile-size` | 큰 이미지의 타일 블록 크기 |
| `--tile-enabled` / `--no-tile-enabled` | 필요할 때 타일 처리 활성/비활성(기본 활성) |
| `--tile-overlap` | 타일 겹침 픽셀 수 |
| `--tile-threshold` | 타일 처리를 시작하는 최소 이미지 크기 |
| `--group-size` | 그룹 합성의 그룹당 프레임 수. `0`이면 끔(기본값), 켜면 2 이상. 폴더 입력 전용이며 `--depth-map`, RAW/알파/다중 페이지 입력, 기본이 아닌 OpenFocus 기준 프레임과 함께 쓸 수 없음 |
| `--group-overlap` | 연속 그룹이 공유하는 프레임 수. 기본값 `0`, 최대 그룹 크기−2 |
| `--scale-bar` | 스케일 바 그리기(TIFF 메타데이터에서 보정 자동 감지) |
| `--depth-map [path]` | 색상 깊이(초점 위치) 맵도 저장(기본값: `<output>_depth.png`). 지원 방식 전용, 그룹/투명 입력 거부. 배치에서는 기본 경로만 허용 |
| `--depth-colormap` | `--depth-map`의 색상 맵: turbo, viridis, jet, gray 등(기본값 turbo) |
| `--scale-um` | 픽셀 크기를 µm/px로 지정해 메타데이터를 덮어씀(`--scale-bar`를 포함함) |
| `--dry-run` | 매개변수와 입력만 확인하고 결과 파일을 쓰지 않음 |
| `--resume` | 배치의 완료되지 않은 작업 재개 |
| `--json FILE` | 결과 요약을 JSON으로 저장 |
| `--json-progress` | 진행률을 JSON 줄(NDJSON)로 출력. 일반 텍스트는 stderr로 |
| `--config FILE` | 배치 모드: 폴더별 덮어쓰기를 JSON으로 지정(예 `{"stackA": {"method": "dct"}}`) |

`--method none`은 없습니다. CLI는 항상 합성을 수행합니다. 정합 전용 출력은
데스크톱 앱을 사용하세요.

종료 코드: `0` 성공, `1` 처리 오류, `2` 사용법 오류.
`python main.py --help`는 모든 옵션을 출력합니다. 경로만 주어 실행하면
(`python main.py C:\stack`) 해당 폴더를 불러온 GUI가 열립니다.

## 16. 문제 해결

### 일반적인 문제

#### "이미지를 불러오지 않음"

- 이미지 폴더나 동영상을 먼저 가져왔는지 확인하세요
- 폴더에 지원되는 이미지 형식이 있는지 확인하세요

#### 합성 결과가 흐리거나 잔상이 보임

- 이미지 정합을 켜세요(드롭다운에서 호모그래피 / ECC / OpenFocus 고속 중 하나 선택)
- 합성 전에 이미지가 제대로 정렬되었는지 확인하세요
- 다른 합성 알고리즘을 시도하세요
- 더 부드러운 결과를 원하면 커널 크기를 늘리세요

#### AI를 사용할 수 없음

- PyTorch 설치: `pip install torch`(torchvision 불필요)
- GPU 지원이 필요하면 CUDA 버전 PyTorch를 설치하세요
- **도움말 → 환경 정보**에서 확인하세요

#### 메모리 부족 오류

- **설정 → 고급 설정 → 성능**에서 타일 처리를 켜세요
- 타일 블록 크기를 줄이세요
- 더 작은 커널 크기를 사용하세요
- 이미지 크기를 줄이세요

#### 정합 실패

- 제한된 강체 운동에는 **OpenFocus (고속)**을 쓰거나 **거부 프레임에서 중지**를 켜서
  정렬되지 않은 프레임을 받아들이지 않고 일찍 실패하게 하세요
- **설정 → 고급 설정 → 정합**에서 축소 폭을 줄이세요
- 이미지에 충분한 대비와 특징이 있는지 확인하세요
- **정합 진단 수집**을 켜고 다시 렌더링한 뒤 **설정 → 고급 설정 → 정합 → 정합 진단**에서 실패한 프레임을
  확인하세요

#### 처리 속도가 느림

- 스레드 수는 자동(`0`)으로 두세요. CPU 용량, 리소스 모드, 메모리 여유가 이미 동시
  작업 수를 제한합니다
- 무인 배치에는 **최대** 리소스 모드를 쓰거나 AI 방식 대신 가이드 필터 / GFG-FGF를
  사용하세요
- 이미지 해상도를 낮추거나 조정 중에는 **빠른 미리보기**를 사용하세요

#### Windows 첫 실행 시 SmartScreen 경고

Windows 빌드의 서명 여부는 릴리스에 따라 다릅니다(릴리스 노트 참조). 서명은
보장되지 않습니다. **https://openfocus.top**에서 내려받고(제3자
미러는 피하세요) SmartScreen 경고가 나오면 **추가 정보 → 그래도 실행**을 클릭하세요.
압축을 푼 뒤 처음 실행할 때는 30–60초 정도 걸릴 수 있습니다.

#### macOS에서 앱을 "열 수 없음" 또는 "손상됨"으로 표시됨

macOS 빌드는 공증되지 않았습니다. **https://openfocus.top**에서 Apple Silicon용
빌드를 내려받으세요. DMG에서 `OpenFocus.app`을 응용 프로그램 폴더로 옮겨
설치했다면 다음을 실행하세요.

```bash
xattr -cr /Applications/OpenFocus.app
```

터미널에서 `install.sh`로 설치했다면 앱이 `~/Applications`에 있습니다. 이 경우
`xattr -cr ~/Applications/OpenFocus.app`을 실행하세요.

또는 앱을 마우스 오른쪽 버튼으로 클릭하고 **열기**를 선택하세요. 배포되는
macOS 빌드는 Apple Silicon(M1/M2/M3/M4)용이며, Intel Mac은 소스에서 실행할 수
있습니다.

### 도움말 얻기

1. **환경 정보**: **도움말 → 환경 정보**로 이동해 설치 상태를 확인합니다
2. **지원 문의**: **도움말 → 문의하기**로 이동해 지원 정보를 확인합니다

## 부록: 합성 알고리즘 세부 정보

### 가이드 필터

가이드 필터는 가이드 이미지를 사용해 에지를 보존하는 스무딩을 수행합니다. 가이드
이미지와 입력 이미지 사이의 국소 선형 변환을 계산한 뒤 이를 적용해 출력을
만듭니다. 노이즈를 줄이면서 에지를 보존하는 데 뛰어난 방식입니다.

### DCT (이산 코사인 변환)

DCT는 이미지를 주파수 영역으로 변환하고 계수 크기에 따라 합성을 결정합니다.
고주파 성분(디테일)은 보존하고, 저주파 성분(평탄한 영역)은 국소 에너지를 기준으로
병합합니다.

### DTCWT (이중 트리 복소 웨이블릿 변환)

DTCWT는 이미지를 다중 스케일, 다중 방향으로 분해합니다. 서로 다른 스케일과
방향에서 특징을 포착하므로 텍스처와 구조 정보를 모두 보존하는 정교한 합성
규칙을 쓸 수 있습니다.

### GFG-FGF

Fu 등(2024)의 방식을 구현했습니다. 거친 초점 맵 |I − mean(I)|을 가우시안형
4이웃 기울기로 보강합니다. 3×3 템플릿 T = [1 2 1; 2 4 2; 1 2 1]/16으로
P = I⊗T를 구하고, G = (|I(x±1,y) − P|)/2 + (|I(x,y±1) − P|)/2를 계산하며
T0 = 0.005보다 작은 값은 버립니다. 그다음 고속 가이드 필터로 정련합니다.
픽셀은 초점 값이 가장 큰 프레임을 선택하고(동률은 3×3 Sobel 소영역 척도),
가중 혼합 전에 이진 판단 맵을 고속 가이드 필터로 스무딩합니다.

### AI 합성 (StackMFF V3)

대규모 다초점 이미지 쌍 데이터셋으로 학습한 신경망을 사용하는 딥러닝
방식입니다. 네트워크가 최적 합성 전략을 스스로 학습하므로, 제대로 구성하면
최첨단 결과를 냅니다.
