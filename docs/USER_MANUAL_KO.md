## 1. 소개

OpenFocus는 연구자, 엔지니어, 이미지 처리 전문가를 위해 만든 전문가용 다초점 이미지 합성 데스크톱 애플리케이션입니다. 고급 정합 및 합성 알고리즘으로 다초점 이미지 시퀀스를 처리해 피사계 심도가 완전한 올인포커스 이미지를 만들어 냅니다.

### 주요 기능

- **다초점 이미지 합성**: 초점이 각기 다른 여러 이미지를 하나의 완전히 초점이 맞은 이미지로 결합합니다
- **다양한 합성 알고리즘**: 가이드 필터, DCT, DTCWT, GFG-FGF, AI 합성(딥러닝) 중에서 선택할 수 있습니다
- **이미지 정합**: ECC 또는 호모그래피 방식으로 어긋난 이미지 시퀀스를 정렬합니다
- **와이프 비교 보기**: A/B 구분선 보기로 정렬 상태를 확인하고 결과를 비교합니다
- **프로젝트 파일**: 작업 세션 전체를 저장하고 복원합니다
- **다중 페이지 TIFF**: 단일 파일 Z-스택을 페이지별로 불러오고 다시 하나의 파일로 내보냅니다
- **깊이 맵**: 사용자 지정 의사 색상 체계를 지원하는 픽셀별 초점 위치 맵입니다
- **스케일 바**: µm/px 자동 보정을 지원하는 논문용 스케일 바입니다
- **충돌 자동 복구**: 충돌이 발생하면 마지막 작업 세션을 복원하도록 제안합니다
- **다국어 지원**: English, 中文, 日本語, Español 및 자동 시스템 언어 감지
- **헤드리스 CLI**: 자동화와 CI를 위해 명령줄에서 OpenFocus를 스크립트로 실행합니다
- **유연한 내보내기**: 결과를 개별 이미지, 폴더, GIF 애니메이션으로 저장합니다
- **이미지 변환**: 이미지 스택을 회전, 뒤집기, 크기 조정합니다
- **레이블 추가**: 정합된 스택과 입력 스택에 텍스트 레이블을 추가합니다
- **설정 유지**: 기본 설정, 언어, 최근에 연 스택이 재시작 후에도 그대로 남습니다

### 지원하는 입력 형식

- 이미지 파일: JPG/JPEG, PNG, BMP, TIFF, WebP 및 기타 일반적인 형식
- 동영상 파일: MP4 형식(자동으로 이미지 시퀀스로 디코딩)
- 번호가 붙은 이미지 시퀀스가 들어 있는 폴더
- 카메라 RAW 파일(DNG, CR2/CR3, NEF, ARW, RAF, ORF, RW2 및 기타 일반적인
  RAW 형식). 디코딩에는 `rawpy`(LibRaw)를 사용하며, `pip install openfocus`
  로 설치하거나 Windows/macOS 빌드에 함께 포함되어 있습니다

### 지원하는 출력 형식

- 개별 이미지: JPG, PNG, BMP, TIFF, WebP
- 이미지 시퀀스: 폴더로 저장
- 애니메이션: GIF 형식

## 2. 시작하기

### 애플리케이션 실행

설치 후 다음과 같이 OpenFocus를 실행합니다.

1. **Windows(실행 파일)**: OpenFocus 바로 가기나 실행 파일을 더블클릭합니다
2. **Python 소스**: 활성화된 conda 환경에서 `python main.py`를 실행합니다

실행하면 어두운 테마의 기본 애플리케이션 창이 나타납니다.

### 빠른 시작 워크플로

1. 이미지 시퀀스를 가져옵니다(파일 → 폴더 열기 또는 끌어다 놓기)
2. 오른쪽 패널에서 합성 설정을 구성합니다
3. 필요하면 정합을 켜서 정렬합니다
4. 필요에 따라 커널 크기를 조정합니다
5. *(선택 사항)* **빠른 미리보기**를 선택해 축소된 초안으로 매개변수를 먼저 시험합니다
6. **렌더 시작**을 클릭해 처리를 시작합니다
7. 결과를 내보냅니다

## 3. 기본 인터페이스 개요

OpenFocus 인터페이스는 크게 세 영역으로 구성됩니다.

### 왼쪽 패널: 이미지 표시 영역

창의 왼쪽 부분은 분할 보기로 이미지를 표시합니다.

- **원본 이미지 패널(위)**: 입력 이미지 시퀀스를 표시합니다
- **결과 이미지 패널(아래)**: 합성 또는 정합 결과를 표시합니다
- **탐색 슬라이더**: 각 패널 아래의 슬라이더로 이미지 프레임을 넘겨 봅니다
- **이미지 정보 레이블**: 현재 프레임 위치와 이미지 크기를 표시합니다

두 패널 사이의 분할선 핸들을 끌어 패널 크기를 조절할 수 있습니다.

### 오른쪽 패널: 제어 패널

오른쪽 패널에는 모든 구성 옵션이 세로로 정리되어 있습니다.

1. **합성 설정**: 합성 알고리즘과 커널 크기를 선택합니다
2. **정합 설정**: 정렬 방식을 켜거나 끕니다
3. **작업 버튼**: 기본값으로 초기화, 렌더 시작
4. **원본 이미지 목록**: 불러온 모든 이미지의 파일 이름을 보여 줍니다
5. **출력 목록**: 생성된 결과를 보여 줍니다

### 메뉴 막대

상단 메뉴 막대에서 모든 기능에 접근할 수 있습니다.

- **파일**: 가져오기/내보내기 작업과 최근 파일 목록
- **편집**: 이미지 변환과 레이블
- **배치**: 배치 처리
- **설정**: GPU 가속, 언어, 타일, 정합, 스레드 구성
- **도움말**: 환경 정보, 문의 정보, 업데이트 확인, 로그 폴더

## 4. 이미지와 동영상 가져오기

### 이미지 폴더 열기

1. **파일 → 폴더 열기**로 이동하거나 `Ctrl+O`를 누릅니다
2. 이미지 시퀀스가 들어 있는 폴더를 선택합니다
3. 로딩 배율 대화상자가 나타나면 배율을 선택합니다(100% = 전체 해상도)
4. 확인을 클릭해 이미지를 불러옵니다

대화상자에서 **다시 묻지 않고 항상 이 배율로 불러오기**를 선택하면 이후에는
묻지 않고 항상 선택한 배율로 불러옵니다. **설정 → 가져올 때 로딩 배율 묻기**를
켜면 다시 묻습니다. 이미 불러온 스택도 나중에 **편집 → 크기 조정**으로 축소할
수 있습니다.

애플리케이션이 자동으로 다음을 수행합니다.
- 이미지 파일을 검출해 파일 이름 순으로 정렬
- 첫 이미지를 원본 패널에 표시
- 원본 이미지 목록을 모든 프레임으로 채움

### 동영상 파일 열기

1. **파일 → 동영상 열기**로 이동하거나 `Ctrl+Shift+O`를 누릅니다
2. 동영상 파일을 선택합니다(MP4, AVI, MOV, MKV, WMV, FLV, WEBM)
3. 동영상이 자동으로 개별 프레임으로 디코딩됩니다
4. 각 프레임이 이미지 스택의 일부가 됩니다

### 프로젝트 파일

파일 → 프로젝트 저장은 작업 세션 전체를 `.ofproj` 파일로 저장합니다. 여기에는
정확한 원본 파일 목록(순서 포함), 로딩 배율, 합성 방식, 정합 옵션, 커널 크기,
타일/스레드/정합 설정, 레이블 구성, 현재 프레임이 들어갑니다. 파일 → 프로젝트
열기는 그 세션을 그대로 재구성합니다(원본 이미지는 복사되지 않고 참조되므로
원래 위치에 두어야 합니다). 창 제목에 열려 있는 프로젝트가 표시됩니다.

### 데모 스택

시작 대화상자에서 **데모 스택 불러오기**를 선택할 수 있습니다. 실제 초점
스택에서 가져온 샘플 사진 여섯 장이 함께 제공되므로, 직접 찍은 이미지가 없어도
전체 워크플로를 바로 시험해 볼 수 있습니다. 설치 확인에도 유용합니다.

### 선명도 곡선

원본 탐색 슬라이더 위의 작은 곡선이 프레임별 선명도(정규화됨)를 보여 줍니다.
초점이 나간 프레임은 빨간 점으로 표시된 골짜기로 나타납니다. 곡선의 아무
곳이나 클릭하면 해당 프레임으로 이동하고, 마우스를 올리면 프레임 번호가
표시됩니다.

### 다중 페이지 TIFF 스택

현미경 소프트웨어(ZEN, NIS-Elements, ImageJ/Fiji)는 Z-스택 전체를 하나의 다중
페이지 TIFF 파일로 내보내는 경우가 많습니다. OpenFocus는 그런 파일의 모든
페이지를 이미지 스택의 개별 프레임으로 읽습니다. 파일을 떨어뜨리거나 열면
스택이 완전한 상태로 나타납니다(프레임 이름은 `<file>_page_001` 형식입니다).
단일 페이지 TIFF는 예전과 똑같이 동작합니다. 반대 방향도 가능합니다.
**파일 → 스택 저장 → (정합된 스택 / 입력 스택) → 다중 페이지 TIFF로 저장**을
실행하면 스택 전체를 16비트 심도를 유지한 채 하나의 `.tif`로 다시 씁니다.

### 스케일 바 (논문용 그림)

설정 → 스케일 바…에서 내보낸 이미지에 새겨 넣을 스케일 바를 구성합니다. 픽셀
크기(µm/px)는 TIFF 메타데이터에서 자동으로 감지합니다. ImageJ의
`unit=micron` 규칙, OME-TIFF의 `PhysicalSizeX`, 또는 명시적인 센티미터 해상도
단위를 사용하므로, 다중 페이지 TIFF를 포함한 현미경 스택은 스스로 보정됩니다.
프린터 해상도(72/300 dpi 등)는 일부러 보정 정보로 취급하지 않으며, 직접 입력한
값은 항상 감지된 메타데이터보다 우선합니다. 그럴듯해 보이지만 틀린 스케일
바가 들어간 그림은 아예 없는 것만 못하기 때문입니다. 모서리와 색상(자동은
배경의 반대색으로 표시)을 고르면 대화상자에 실시간 미리보기가 나타납니다.
스케일 바를 켜 두면 모든 내보내기(단일 이미지, 폴더 스택, 다중 페이지 TIFF,
GIF, 전체 내보내기, 배치)에 논문용 스타일의 스케일 바가 함께 들어갑니다. 길이는
1-2-5 눈금(이미지 폭의 약 12%)으로 반올림되며, 읽기 쉽도록 외곽선을 넣은
텍스트가 표시됩니다. CLI에서는 `--scale-bar`(자동 보정)와
`--scale-um <um/px>`로 지원합니다.

### 깊이 맵 (초점 위치)

**도구 → 깊이 맵…**은 선택한 방식(DCT, DTCWT, GFG-FGF, StackMFF V3, OpenFocus B/C)의
활동 척도로 초점 위치를 추정합니다. 측정된 표면이나 합성 이미지 픽셀의 정확한 출처가
아닙니다. 현재 체크한 프레임 또는 선택한 출력에 기록된 소스를 선택할 수 있습니다.
출처 기록이 없다고 현재 스택으로 대신하지 않습니다. 계산, 텍스처, 내보내기는 같은
소스 스냅샷에 연결됩니다.

여섯 방식 모두 **계산**을 직접 눌러야 합니다. 창 열기, 측정 방식·소스·정합 변경,
매개변수 편집만으로는 계산이 시작되지 않습니다. 편집기는 측정 방식 선택기 바로 아래에
있습니다. DCT 중앙값 커널과 GFG 초기 커널은 1–51의 홀수(기본 7), B의 분산 창과 C의
대역 통과 에너지 창은 1–21 px의 홀수(기본 11)입니다. DTCWT 분해 단계는 소스 매개변수로
초기화되는 이 창의 편집값으로 변경할 수 있습니다. StackMFF V3는 숫자 커널 대신
자체 AI 출력 모드(기본 소프트 혼합 또는 하드 선택)와 설명을 표시합니다. 소프트 혼합은
확률로 가중한 연속 프레임 위치를, 하드 선택은 픽셀별로 가장 확률이 높은 프레임을
사용합니다. 둘 다 물리적 거리가 아닙니다. 초깃값은 일치하는 출력의 매개변수 또는 기본 창에 저장된
방식별 값에서 가져옵니다. 편집값은 이 창이 열려 있는 동안 소스와 방식별로 기억하며,
기본 창, 프로젝트 또는 기록된 출력의 설정을 변경하지 않습니다.

계산 설정을 바꾸면 이전 2D 맵에 **현재 결과가 아님**을 계속 표시하고 3D 표면을 지웁니다.
컬러, 원본 데이터, 물리 깊이, OBJ를 포함한 모든 내보내기는 새 계산이 성공할 때까지
차단됩니다. 실행 중인 작업은 협력적으로 취소됩니다. 종료 후 **계산**을 다시 눌러야 하며,
후속 계산은 예약하거나 자동 재개하지 않습니다. 계산 버튼은 항상 표시되며 계산, 취소,
모델 내보내기 중에는 비활성화됩니다.

- **색상 맵**: 회색조(논문 표준)에 15가지 과학용 팔레트(Turbo, Viridis, Magma
  등)와 직접 만든 색상표를 더했습니다. *새 사용자 색상표…*는 원하는 수의 색상
  지점으로 그라디언트를 만듭니다(지점을 더블클릭해 위치와 색상 편집). 사용자
  색상표는 저장되어 드롭다운에 나타납니다.
- **반전 / 감마 / 스무딩**: 깊이 축을 뒤집고, 톤을 다시 맞추고
  (감마 < 1은 낮은 인덱스를 밝게 함), 에지 보존 처리를 적용해 얼룩을 없앱니다.
- **오버레이**: 좌표 영역이 일치하는 연결 출력에만 2D 맵을 원하는 불투명도로
  겹쳐 표시할 수 있습니다.
- **내보내기**: 컬러 버전은 PNG/JPEG/TIFF/BMP를 지원합니다. 원본 16비트 TIFF는
  정규화된 초점 인덱스를 0–65535로 인코딩하며, 무손실 부동소수점 데이터나 물리적 거리가
  아닙니다. 원본 데이터에는 JPEG/BMP를 사용할 수 없습니다.
- **3D 모델 / 3D 텍스처**: 메시 긴 변의 정점 수는 기본 600입니다. 새로 열 때마다
  **자동(실제 색상)**을 선택합니다. 연결된 출력의 식별 정보와 좌표 영역/ROI가 완료된
  맵과 일치할 때만 해당 출력을 사용하며, 그렇지 않으면 완료된 계산에 참여한 첫 프레임을
  정합 후 실제 순서에 따라 사용합니다. 사용한 출력 또는 프레임 이름을 표시합니다.
  일치하는 출력, 지정한 참여 프레임 또는 **깊이 의사 색상**을 직접 선택할 수도 있습니다.
  사용할 이미지가 없으면 안내합니다. 3D 미리보기와 OBJ 텍스처 PNG는 같은 이미지를 씁니다.
  2D 맵은 자체 색상 맵과 오버레이 설정을 유지하므로 팔레트나 감마를 바꿔도 실제 사진의
  색상은 변하지 않습니다. 의사 색상 텍스처를 선택했을 때만 팔레트, 감마, 반전을 반영합니다.
  정지 미리보기와 내보내기는 같은 샘플링된 높이 필드를 쓰며 숨겨진 추가 스무딩을 하지
  않습니다. 상대 요철은 이미지 단위의 시각화입니다.

계산은 진행률과 취소를 지원하며 백그라운드에서 실행됩니다. AI 방식은 AI 합성과
동일한 메모리 안전 타일링을 재사용하므로 깊은 스택도 처리됩니다. CLI에서는
`--depth-map [path]`와 `--depth-colormap`이 같은 기능입니다.

### 충돌 자동 복구

OpenFocus는 작업 세션(스택, 설정, 레이블, 현재 프레임)의 스냅샷을 계속
보관합니다. 충돌, 전원 차단, 강제 종료처럼 애플리케이션이 예기치 않게 닫히면
다음 실행 시 이를 감지하고 **세션 복원**을 제안해 작업하던 위치로 정확히
돌아가게 합니다. 정상 종료에서는 이 안내가 나타나지 않습니다. 복구 데이터는
설정과 같은 위치에 저장됩니다(포터블 설치에서는 실행 파일 옆에 보관되므로
함께 이동합니다).

### 최근 항목

연 스택은 모두 **파일 → 최근 항목 열기**에 기억됩니다(최대 8개). `Alt+1`–`Alt+8`
을 눌러 항목을 바로 다시 열 수 있습니다. 같은 스택을 다시 열면 목록 맨 위로
올라가고, 파일이 더 이상 없는 항목은 안내를 거쳐 제거할 수 있으며,
**최근 목록 지우기**는 메뉴를 비웁니다.

### 끌어다 놓기

폴더를 애플리케이션 창으로 직접 끌어다 놓아 이미지를 가져올 수도 있습니다.
이미 있는 스택에 파일을 더 떨어뜨리면 크기를 확인한 뒤 뒤에 덧붙입니다.

### EXIF 방향

EXIF Orientation 태그가 있는 카메라 JPEG/TIFF 파일은 가져오기 과정에서 자동으로
회전/뒤집기 보정되므로 세로 사진도 올바른 방향으로 불러옵니다.

### 16비트 원본

16비트 PNG/TIFF 입력은 자동으로 감지되고 끝까지 그대로 유지됩니다. 합성은 전체
심도로 실행되며 결과도 16비트 PNG/TIFF로 다시 저장할 수 있습니다. JPG/BMP
내보내기는 이 형식들이 16비트를 저장할 수 없으므로 8비트로 변환됩니다.

카메라 RAW 파일은 16비트로 현상되며(카메라 화이트 밸런스, sRGB 감마), 자동
밝기 보정은 꺼져 있습니다. 그래서 스택의 모든 프레임이 같은 노출 매핑을
받습니다. 프레임마다 자동 노출을 적용하면 프레임 사이에서 밝기가 깜빡이게
됩니다. 16비트 데이터를 유지하려면 TIFF나 PNG로 저장하세요.

### 스택 비우기

불러온 이미지를 모두 제거하려면 **파일 → 스택 비우기**로 이동하거나 `Ctrl+W`를
누릅니다.

## 5. 이미지 보기 및 탐색

### 이미지 스택 탐색

- **슬라이더**: 원본 패널 아래의 슬라이더를 끌어 프레임을 넘깁니다
- **파일 목록**: 오른쪽 패널의 원본 이미지 목록에서 파일 이름을 클릭합니다
- **키보드**: 화살표 키(왼쪽/오른쪽)로 이동합니다

### 확대/축소 및 이동

- **확대/축소**: 이미지 위에서 마우스 휠을 사용합니다
- **미세 확대/축소**: `Ctrl` + 마우스 휠로 더 작은 단위로 조정합니다
- **창에 맞추기**: 이미지를 더블클릭해 창에 맞춤과 100% 보기 사이를 전환합니다
- **이동**: 클릭한 채 끌어 패널 안에서 이미지를 옮깁니다

### 동기화 탐색

원본 패널에서 탐색하면 결과 패널에 해당 결과 프레임이 있으면 함께 표시됩니다.

## 6. 와이프 비교 보기

와이프 보기는 두 이미지를 하나의 프레임에 포개고 세로 구분선을 끌어 나누어,
어긋남과 품질 차이를 분할 경계에서 바로 확인할 수 있게 합니다.

### 와이프 보기 열기

1. 결과(합성 또는 정합)를 하나 이상 렌더링합니다
2. 결과 패널 제목 표시줄 오른쪽 위의 **와이프** 토글을 누릅니다
3. 결과 영역이 비교 보기로 바뀝니다. 되돌리려면 **와이프**를 다시 누릅니다

### 보기 읽기

- **A 쪽(구분선 왼쪽)**: 원본 프레임이며, 기본적으로 원본 패널 슬라이더를 따릅니다
- **B 쪽(구분선 오른쪽)**: 가장 최근 렌더링 결과입니다
- **흰 구분선 + 둥근 핸들**: 가로로 끌어 분할 위치를 옮깁니다
- 구분선을 넘나들며 끌면 나란히 보기에서는 잘 보이지 않던 정합 오류가 드러납니다

### 비교 대상 선택

비교 보기 아래쪽 막대에는 양쪽에 하나씩 그룹이 있습니다.

- **A 쪽** — **원본 따라가기**(기본값)를 선택하면 원본 패널 슬라이더를 추적하고,
  해제하면 자체 슬라이더로 A 쪽을 원하는 프레임에 고정합니다
- **B 쪽** — **최신 결과**(기본값)를 선택하면 항상 가장 새 렌더링을 보여 주고,
  해제하면 자체 슬라이더로 출력 기록을 훑어볼 수 있습니다

양쪽 모두 실시간으로 갱신됩니다. 새 렌더링, 원본 슬라이더 이동, 프레임 삭제가
즉시 반영됩니다.

### 확대/축소 및 이동

비교 보기는 두 이미지에 하나의 변환을 함께 적용합니다.

- **확대/축소**: 마우스 휠(커서 위치를 중심으로 확대)
- **이동**: 구분선을 제외한 아무 곳이나 클릭해 끕니다
- **초기화**: 더블클릭

와이프 모드와 ROI 모드는 같은 결과 패널을 사용하므로 한쪽에 들어가면 다른
쪽은 종료됩니다. 스택을 비우면 와이프 모드도 종료됩니다.

## 7. 이미지 정합

이미지 정합은 이미지 스택에서 프레임 사이의 공간적 어긋남을 보정합니다. 이미지가
약간 이동했거나 원근이 달라졌을 때 반드시 필요합니다.

### 정합 방식

#### ECC (향상된 상관 계수)

- 상관 관계를 기준으로 최적 정렬을 찾는 최적화를 사용합니다
- 미세한 어긋남에 적합합니다
- 서브픽셀 정밀도를 제공합니다
- 호모그래피보다 느리지만 더 정밀합니다

#### 호모그래피

- 특징점 매칭(SIFT/ORB 특징)을 기반으로 합니다
- 더 큰 기하 변환을 처리합니다
- 초기 정렬에서는 ECC보다 빠릅니다
- 원근 변화가 큰 이미지에 적합합니다

#### OpenFocus (고속)

- 제한된 유사 변환 정렬(이동 + 회전 + 크기)에 프레임별 밝기 균등화와
  자동 자르기를 더했습니다
- 프레임당 1초 미만으로 ECC나 호모그래피보다 훨씬 빠릅니다
- **프레임 크기의 8%를 넘게 이동한 프레임은 부분 보정 대신 정렬하지 않은 채로
  둡니다**. CLI의 `--align-shift-limit`으로 이 값을 바꿀 수 있습니다
- 비강체나 극단적인 기하에는 대신 ECC나 호모그래피를 선택하세요

### 정합 사용 설정

1. 오른쪽 패널에서 **정합** 그룹을 찾습니다
2. 드롭다운에서 방식을 하나 고릅니다: **정렬 안 함**, **OpenFocus (고속)**,
   **ECC**, **호모그래피**
3. OpenFocus 고속 정렬은 ECC나 호모그래피 앞에 연결할 수도 있습니다(먼저 전역
   거친 패스, 다음으로 정밀한 국소 패스)

### 정합이 필요한 경우

- 이미지에 눈에 띄는 어긋남이 있을 때
- 손으로 들고 촬영했을 때
- 장면에 시차가 있을 때(가까운 물체가 프레임 사이에서 이동)
- 결과에 잔상이나 이중 상이 나타날 때

### 정합 설정

**설정 → 정합 설정**에서 추가 설정에 접근합니다.
- **축소 폭**: 전처리 해상도를 제어합니다(기본값: 1024px)
- 값이 작을수록 빠르지만 정확도가 떨어질 수 있습니다
- 값이 클수록 느리지만 정확도가 높아질 수 있습니다

## 8. 이미지 합성 방식

OpenFocus는 열 가지 합성 알고리즘과 정렬 전용 모드를 제공합니다. 각각 특성이
달라 다양한 이미지 유형에 맞게 쓸 수 있습니다.

### 가이드 필터 (기본)

- **알고리즘**: 에지 보존 합성을 위해 가이드 필터링을 사용합니다
- **적합한 용도**: 범용, 속도와 품질의 균형
- **장점**: 우수한 에지 보존, 빠른 처리
- **매개변수**: 커널 크기(1-51 조정 가능, 홀수만)
  - 커널이 작을수록 국소 디테일이 많아지고 노이즈가 늘 수 있습니다
  - 커널이 클수록 결과가 부드러워지고 노이즈 억제가 좋아집니다

### DCT (이산 코사인 변환)

- **알고리즘**: DCT 계수를 이용한 주파수 영역 합성
- **적합한 용도**: 텍스처가 풍부한 이미지, 과학 이미지
- **장점**: 미세 텍스처를 유지하고 수학적으로 견고합니다
- **매개변수**: 커널 크기가 처리 창을 결정합니다

### DTCWT (이중 트리 복소 웨이블릿 변환)

- **알고리즘**: 다중 스케일 웨이블릿 영역 합성
- **적합한 용도**: 디테일 수준이 여러 단계인 복잡한 장면
- **장점**: 뛰어난 다중 스케일 분석, 우수한 방향성
- **합성 규칙**: 픽셀과 레벨마다 모든 방향과 색상 채널에 대해 단일 판단을
  내립니다(N개 후보, 다수 일관성 검사). 저주파 대역은 모든 프레임을 평균하지
  않고 가장 거친 레벨의 판단을 따릅니다
- **매개변수**: 오른쪽 패널의 웨이블릿 단계(1–6, 기본 4)입니다. 공간 커널을 쓰지
  않으므로 이 방식에서는 커널 슬라이더가 숨겨집니다.

### GFG-FGF (가우시안형 4이웃 기울기 + 고속 가이드 필터)

- **알고리즘**: Fu 등의 구현(*Laser & Optoelectronics Progress*, 2024)으로,
  블러 차이 초점 맵 |I − mean(I)|을 가우시안형 4이웃 기울기(GFG) 연산자로
  보강하고 고속 가이드 필터로 정련한 뒤 픽셀별로 판단하며(동률은 3×3 Sobel
  소영역 척도로 해소), 가중 혼합 전에 이진 판단 맵을 다시 고속 가이드 필터로
  스무딩합니다.
- **적합한 용도**: 현미경 이미지, 초점 영역이 뚜렷한 이미지
- **장점**: 빠르고 초점 영역 경계가 선명하며 메모리가 프레임 수에 따라 늘지
  않습니다
- **매개변수**: 커널 = 거친 초점 맵의 평균 필터 크기

### StackMFF(V1, 딥러닝)

- **알고리즘**: 스택 전체의 융합 휘도를 한 번에 예측하는 3D U-Net.
  Cb/Cr은 휘도가 가장 가까운 원본 프레임에서 가져옵니다
- **적합한 경우**: 초점 순서가 일정하지 않거나 연속 촬영열이 아닌 스택
- **장점**: 순서에 무관하고 매개변수가 없으며 색이 색역 안에 유지됩니다
- **참고**: 약 6M 매개변수. 큰 스택은 GPU가 유리합니다

### StackMFF V2(딥러닝)

- **알고리즘**: 레이어별 초점 추정을 양방향 순환 레이어로 정교화하고 초점면
  인덱스를 회귀해 스택에서 샘플링합니다. **프레임은 원래 초점 순서를 유지해야
  하며** 역순은 비활성화됩니다
- **AI 출력**: 하드(기본, 논문 융합 규칙) 또는 소프트(확률 가중 혼합)
- **깊이 맵**: 지원. 소프트는 기대 레이어, 하드는 선택 레이어를 보고합니다
- **적합한 경우**: 매우 작고 빠른 모델이 필요한 연속 초점 스캔
- **요구 사항**: PyTorch, 약 0.05M 매개변수

### StackMFF-V3 (딥러닝)

- **알고리즘**: 픽셀 단위 원본 분류(PyTorch 필요). 신경망이 픽셀마다 어느 입력
  프레임에서 왔는지를 예측한 뒤, 그 확률로 프레임을 혼합하거나 한 프레임을
  고릅니다
- **AI 출력 모드**(오른쪽 패널, 이 방식에서만 표시):
  - **부드러운 혼합 (가중)** — 기본값. 각 픽셀이 확률 가중치로 프레임을 혼합한
    결과입니다. 전환이 부드럽고 이음매가 없으며 논문의 보고 설정과 같습니다
  - **단일 선택 (한 프레임)** — 각 픽셀을 가장 확률이 높은 프레임에서
    복사합니다. 프레임 간 보간이 없어 선택이 더 선명하지만, 두 프레임이
    비슷한 곳에서 픽셀 단위 이음매가 나타날 수 있습니다
- **적합한 용도**: GPU가 있을 때 최고 품질
- **장점**: 순서 무관(프레임 순서가 결과를 바꾸지 않음), 스택 길이 제한 없음,
  방식별 조정 불필요, 자동 최적화
- **요구 사항**: PyTorch 설치, 선택적 CUDA GPU(torchvision 불필요)
- **참고**: PyTorch가 설치되어 있지 않으면 사용할 수 없습니다

### OpenFocus A / B / C

- **알고리즘**: 분산 가중 평균, 분산 깊이 맵 선택, 라플라시안 피라미드 합성
- **OpenFocus A**: 마지막 프레임 사전 확률을 쓰는 분산 가중 평균 — 빠르고 짧은
  스택에서 색상이 안정적입니다
- **OpenFocus B**: 분산 깊이 맵 선택 — 픽셀마다 가장 선명한 프레임을 고르며
  매끄러운 표면과 현미경 이미지에 가장 적합합니다
- **OpenFocus C**: 라플라시안 피라미드 대역별 혼합 — 텍스처가 있는 피사체에서
  자연스럽고 국소 대비를 높입니다
- **매개변수**: A와 B는 분산 창(커널 슬라이더)을 사용하고, C에는 반경이
  없습니다. 세 방식 모두 스무딩 시그마를 사용합니다.

**스무딩**: 커널 슬라이더 아래의 스핀 상자 하나이며 선택한 방식에 따라 의미가
달라집니다(범위 0–8, 단계 0.2).

| 방식 | 레이블 | 기본값 | 효과 |
|---|---|---|---|
| OpenFocus A | 혼합 스무딩 (σ) | 2.0 | 프레임별 가중치 맵의 가우시안 스무딩 — 이웃 프레임의 선명 영역이 얼마나 넓게 혼합되는지 |
| OpenFocus B | 깊이 스무딩 (σ) | 1.2 | 깊이 맵의 가우시안 스무딩 — 프레임 사이 전환 폭 |
| OpenFocus C | 혼합 스무딩 (σ) | 3.0 | 각 피라미드 대역 가중치 맵의 가우시안 스무딩 |

0은 픽셀별로 가장 선명한 선택을 유지하지만(디테일은 최상이나 노이즈가 많은
스택에서는 얼룩이 생김) 값이 클수록 전환과 할로가 부드러워집니다. 각 방식은
세션이 바뀌어도 자기 값을 기억하며, 배치 처리도 같은 규칙을 따릅니다.

C에는 반경이 없습니다. Helicon의 Method C는 스무딩만 제공하므로, 아무 효과도
없는 커널 슬라이더를 조용히 두는 대신 C에서는 숨깁니다.

CLI: `--depth-smoothing SIGMA`(B), `--blend-smoothing SIGMA`(A, C).

**밝기 옵션은 방식별로 저장됩니다.** *합성 전 노출 맞추기*와 *밝기 드리프트
제거*는 전역 기본 설정이 아니라 스택별 판단이므로 합성 방식마다 따로
기억됩니다. OpenFocus A/B/C는 자체 노출 보정이 없으므로 둘 다 기본적으로
켜져 있고, 다른 방식은 지금까지의 기본값(노출 맞추기 켜짐, 드리프트 제거
꺼짐)을 유지합니다. 방식을 바꾸면 그 방식의 값이 표시됩니다.

### 정합만 (합성 안 함)

방식으로 **정합만 (합성 안 함)**을 선택하면 스택을 정합한 뒤 합성하지 않고
정렬된 프레임을 출력 목록으로 보냅니다. 정합 품질을 확인하거나 정렬된 프레임을
내보낼 때 편리합니다.

### 합성 방식 선택

1. 오른쪽 패널에서 **합성** 그룹을 찾습니다
2. **드롭다운**에서 방식을 고릅니다(항상 정확히 하나가 선택되어 있으며, 첫
   항목은 합성하지 않고 정합만 합니다)
3. 해당되는 경우 커널 크기를 조정합니다. 레이블에 선택한 방식에서 커널이
   무엇을 뜻하는지 표시됩니다
4. **렌더 시작**을 클릭해 처리합니다

### 알고리즘 비교 가이드

| 알고리즘 | 속도 | 품질 | 적합한 용도 |
|-----------|-------|---------|----------|
| 가이드 필터 | 빠름 | 좋음 | 범용 |
| DCT | 보통 | 좋음 | 텍스처 |
| DTCWT | 보통 | 매우 좋음 | 복잡한 장면 |
| GFG-FGF | 빠름 | 좋음 | 초점 영역 |
| AI 합성 (StackMFF-V3) | 느림 (GPU) | 최고 | 최고 품질 |
| OpenFocus A | 매우 빠름 | 매우 좋음 | 짧은 스택, 색상 안정성 |
| OpenFocus B | 매우 빠름 | 매우 좋음 | 매끄러운 표면, 현미경 |
| OpenFocus C | 빠름 | 매우 좋음 | 텍스처 피사체, 자연스러운 결과 |

### 빠른 미리보기 (초안 렌더링)

큰 스택에서 전체 해상도로 매개변수를 조정하면 느립니다. 렌더 버튼 위의
**빠른 미리보기**를 선택하면 OpenFocus가 먼저 축소된 초안(긴 변 1200px)을
렌더링합니다. 정합을 포함해 보통 몇 배 빠릅니다. 미리보기는 렌더링 후 상태 표시줄
요약에 "Preview" 표시와 함께 나타나며 **출력 기록에 추가되지 않습니다**. 상자를
해제하고 다시 렌더링하면 전체 해상도 결과가 만들어집니다. 미리보기 모드는 ROI
렌더링에는 적용되지 않고 전체 해상도 정합 캐시를 오염시키지도 않습니다.

## 9. 이미지 변환

### 회전

1. **편집 → 회전**으로 이동합니다
2. 회전 유형을 선택합니다:
   - **시계 방향 90°**: 모든 이미지를 오른쪽으로 90도 회전
   - **반시계 방향 90°**: 모든 이미지를 왼쪽으로 90도 회전
   - **180°**: 이미지를 위아래로 뒤집음

### 뒤집기

1. **편집 → 뒤집기**로 이동합니다
2. 뒤집기 유형을 선택합니다:
   - **가로 뒤집기**: 좌우로 반전
   - **세로 뒤집기**: 상하로 반전

### 크기 조정

1. **편집 → 크기 조정**으로 이동합니다
2. 크기 조정 옵션 대화상자가 나타납니다
3. 새 크기나 배율(%)을 입력합니다
4. 스택의 모든 이미지가 비례하여 조정됩니다

### 변환 순서

변환은 이미지 스택 전체에 적용되며 프레임 간 정렬이 유지됩니다.

## 10. 리터치, 레이블 및 주석

### 결과 리터치 (편집 → 결과 리터치…, `Ctrl+T`)

합성을 해도 국소 결함이 남을 수 있습니다. 고대비 에지 주변의 할로, 잘못된
프레임에서 가져온 털, 평탄한 영역의 노이즈 같은 것입니다. 리터치 브러시는 원본
프레임의 픽셀을 결과 위에 복사합니다.

1. 결과를 렌더링하거나(또는 출력 목록에서 결과를 선택한 뒤 마우스 오른쪽 버튼 →
   *결과 리터치…*도 가능) `Ctrl+T`를 누릅니다.
2. 왼쪽 마우스 버튼으로 결함 위를 칠합니다. **획마다 가장 선명한 프레임 자동
   선택**이 켜져 있으면(기본값) 획을 시작할 때마다 브러시 아래에서 디테일이 가장
   많은 프레임이 선택됩니다. 할로 수정은 보통 한 번 끌면 끝납니다. 이 기능을
   끄면 슬라이더나 `,` / `.`로 프레임을 직접 고릅니다.
3. **반경**(`[` / `]`), **경도**(부드러운 가장자리는 이음매를 감춥니다),
   **불투명도**를 조정합니다. 한 획 안에서 겹친 자국은 누적되지 않습니다.
4. **원본 프레임 보기**(`Tab`)로 칠해 오는 프레임을 미리 봅니다. 휠은 확대,
   오른쪽/가운데 드래그는 이동, `F`는 이미지에 맞춥니다.
5. `Ctrl+Z` / `Ctrl+Y`로 획 단위 실행 취소와 다시 실행을 합니다. **새 출력으로
   적용**은 리터치한 이미지를 출력 목록에 추가하며(접미사 `_Retouched`), 원래
   출력은 그대로 남습니다.

브러시는 결과를 만든 정렬된 프레임을 사용하므로 결과와 정확히 겹칩니다. 16비트
결과는 16비트로 유지됩니다. ROI 렌더링과 크기를 조정한 스택은 프레임이 결과의
기하와 더 이상 맞지 않으므로 리터치할 수 없습니다.

### 레이블 추가

1. 렌더링한 결과나 불러온 이미지가 있는지 확인합니다
2. **편집 → 레이블 추가**로 이동합니다
3. 대화상자에 레이블 텍스트를 입력합니다
4. 레이블이 정합된 스택과 입력 스택 모두에 추가됩니다

### 레이블 삭제

- **정합된 스택 레이블 삭제**: 정렬된 이미지에서 레이블을 제거합니다
- **입력 스택 레이블 삭제**: 원본 이미지에서 레이블을 제거합니다

이 옵션은 **편집 → 레이블 삭제** 하위 메뉴에서 접근합니다.

## 11. 설정 및 구성

### 타일 설정 (메모리 최적화)

큰 이미지의 경우 OpenFocus는 메모리 문제를 피하기 위해 타일 기반 처리를
사용합니다.

**설정 → 타일 설정**에서 접근합니다.

- **타일 블록 크기**: 각 처리 타일의 크기(기본값: 1024px)
- **타일 겹침**: 이음매 없는 혼합을 위한 타일 간 겹침(기본값: 256px)
- **타일 임계값**: 이 크기를 넘는 이미지에 타일을 사용(기본값: 2048px)

**권장 사항**:
- 블록 크기가 작을수록 메모리 사용량이 적고 처리가 느립니다
- 블록 크기가 클수록 메모리 사용량이 많고 처리가 빠릅니다
- 결과에 이음매가 보이면 겹침을 늘리세요

### 정합 설정

**설정 → 정합 설정**에서 접근합니다.

- **축소 폭**: 정합을 위한 전처리 해상도
  - 기본값: 1024px
  - 속도를 원하면 낮추고, 정확도를 원하면 높입니다

### 성능 참고

큰 실제 스택에서 측정한 처리량과 메모리 수치, 깊은 스택과 고해상도 입력에 대한
실용적인 지침은 [PERFORMANCE.md](./PERFORMANCE.md)를 참고하세요.

### 스레드 수 설정

CPU 병렬 처리를 제어합니다.

**설정 → 스레드 설정**에서 접근합니다.

- `0`은 자동 조절이며 새 설정의 기본값입니다.
- 양수는 스레드 수의 상한이며 저장된 상한은 유지됩니다.
- CPU 용량, 리소스 모드 및 사용 가능한 메모리에 따라 동시 작업 수가 줄어들 수 있습니다.

### GPU 가속 토글

OpenFocus는 AI 신경망 모델(StackMFF-V3)에만 GPU(CUDA/MPS)를 사용하며, 고전
알고리즘은 항상 CPU에서 실행됩니다.

- **설정 → GPU 가속**에서 전환합니다
- 선택을 해제하면 모든 처리가 CPU로 강제됩니다. GPU 드라이버가 문제를 일으킬 때
  유용합니다
- GPU가 비활성화된 동안 상태 패널에 `CPU*`가 표시됩니다
- 선택은 다음 렌더링부터 적용되며 기억됩니다

### AI 배치 크기

**설정 → AI 배치 크기**에서 접근합니다.

- 저장되는 배치 상한의 기본값은 2이지만 현재 모든 장치에서 호출당 타일 하나를 추론합니다.
- 상한을 늘려도 GPU 병렬 배치 처리는 활성화되지 않습니다.

### 테마

인터페이스 테마는 **어둡게(기본값)** 와 **밝게** 두 가지입니다.
**설정 → 테마**에서 전환하며, 선택은 즉시 적용되고(Windows 제목 표시줄도 함께
따릅니다) 기억됩니다. 처음 실행하는 사용자는 시작 대화상자에서 테마를
선택합니다.

### 포터블 모드

`OpenFocus.exe` 옆에 `OpenFocus.portable`이라는 빈 파일을 만들면(포터블 zip에
하나 들어 있습니다) 설정, 로그, 최근 파일 등 모든 사용자 데이터가 사용자
프로필 대신 앱 옆의 `OpenFocusData` 폴더에 저장됩니다. 따라서 설치본을 USB
드라이브에 담아 이동할 수 있습니다. 표식 파일을 삭제하면 일반 프로필로
돌아갑니다.

### EXIF 메타데이터

원본 메타데이터(카메라 모델, 노출, 방향 등)는 유지됩니다. 방향은 불러올 때
적용되고, PNG/TIFF/WebP 내보내기에는 원본 EXIF가 자동으로 포함됩니다. JPG/BMP
내보내기는 전체 EXIF를 저장할 수 없어 EXIF 없이 기록됩니다.

### HEIC/HEIF 입력

iPhone 사진을 바로 불러올 수 있습니다. 선택적 `pillow-heif` 패키지가 필요하며
(`pip install pillow-heif`), 패키지 빌드에는 포함되어 있습니다.

### 업데이트

프로젝트 파일(`.ofproj`)은 문서처럼 동작합니다. 저장하지 않은 변경 사항이 있는
동안 제목 표시줄에 프로젝트 이름과 `*`가 표시되며, 앱을 닫거나 다른 프로젝트를
열면 변경 사항을 버릴지 먼저 묻습니다. 프로젝트에는 프레임 목록, 로딩 배율, 모든
렌더링 옵션, 레이블, 현재 프레임이 저장됩니다. 이미지 자체는 복사되지 않고
참조됩니다.

도움말 → 업데이트 확인은 현재 버전을 GitHub Releases와 비교합니다. **다운로드 및
설치**는 새 설치 프로그램을 앱 안에서(진행률과 함께) 내려받아 실행합니다.
다운로드 페이지 열기는 Releases 목록으로 이동합니다. 확인은 하루에 한 번,
조용히 실행됩니다.

### 정합 캐시

OpenFocus는 정합 결과를 원본 스택 옆의 `.openfocus_cache` 폴더에 저장할 수
있습니다. 그러면 같은 스택을 다시 열 때(파일이 바뀌지 않았다면) 정렬을 완전히
건너뜁니다. **설정 → 정합 캐시**에서 전환하며, 오래된 항목은 자동으로
교체됩니다.

### 저장되는 설정

다음 항목은 애플리케이션을 재시작해도 자동으로 유지됩니다. 스레드 수, 타일
매개변수, 정합 축소 폭, AI 합성(StackMFF-V3) 배치 크기, GPU 가속 토글, 정합
캐시 토글, 인터페이스 언어, 창 크기/패널 배치, 끌어내기 내보내기 형식, 최근에 연
스택. 설정 대화상자는 확인하는 순간 저장되며, 애플리케이션이 닫힐 때도 모두
저장됩니다. 기본 설정은 사용자별로 `OpenFocus/OpenFocus.ini`(QSettings INI
형식)에 보관됩니다.

### 인터페이스 언어

**설정 → 언어**에서 언제든지 전환합니다. 변경은 즉시 적용되고 이후 세션에서도
유지됩니다.

### 자동 업데이트 확인

OpenFocus는 하루에 한 번, 실행 후 몇 초 뒤에 GitHub에 새 릴리스가 있는지
조용히 확인합니다. 새 버전이 있으면 이미지 패널 위에 배너가 나타나 버전,
**지금 업데이트**(내려받아 한 번에 재시작), **새 기능**(릴리스 노트),
닫기 버튼을 보여 줍니다. 닫으면 해당 버전에 대해서만 배너가 숨겨지고, 다음
릴리스에서 다시 나타납니다. **도움말 → 업데이트 확인**으로 즉시 다시 표시할
수도 있습니다.

다운로드가 백그라운드에서 진행되는 동안 상태 표시줄에 진행률이 표시됩니다.
**도움말 → 업데이트 확인**으로 언제든 직접 확인할 수도 있습니다.

## 12. 배치 처리

여러 폴더를 자동으로 처리합니다.

1. **배치 → 배치 처리**로 이동하거나 배치 옵션을 클릭합니다
2. 배치 대화상자에서:
   - **폴더 추가**: 이미지 시퀀스가 들어 있는 폴더를 선택합니다
   - **선택 항목 제거**: 선택한 폴더를 목록에서 제거합니다
   - **모두 지우기**: 모든 폴더를 제거합니다
3. 출력 설정을 구성합니다:
   - **원본 폴더에 하위 폴더 만들기**: 각 입력 폴더에 결과를 만듭니다
   - **원본 폴더와 같게**: 덮어쓰거나 입력 옆에 저장합니다
   - **출력 폴더 지정**: 출력 위치를 직접 지정합니다
4. 현재 합성/정합 설정을 검토합니다
5. **배치 처리 시작**을 클릭해 시작합니다

배치 대화상자는 실시간 진행률을 보여 줍니다. 언제든지 처리를 취소할 수 있습니다.

### 배치 처리 참고

- 수동 처리와 동일한 합성 및 정합 설정을 사용합니다
- 각 폴더는 독립적으로 처리됩니다
- 식별을 위해 파일 이름에 타임스탬프와 매개변수가 포함됩니다

## 13. 결과 내보내기

### 단일 결과 저장

1. 출력 목록에서 저장할 결과를 선택합니다
2. **파일 → 저장**으로 이동하거나 `Ctrl+S`를 누릅니다
3. 형식과 위치를 선택합니다
4. 저장을 클릭합니다

### 끌어내기 내보내기 형식

출력 목록에서 결과를 끌어내면 출력 목록의 컨텍스트 메뉴에서 고른 형식
(**끌어내기 형식**: JPG, PNG, TIFF)으로 이미지 파일이 만들어집니다. 선택은
기억됩니다.

### 정합된 스택 저장

1. **파일 → 스택 저장 → 정합된 스택**으로 이동합니다
2. 저장 형식을 선택합니다:
   - **폴더로 저장**: 정렬된 각 프레임을 별도 이미지 파일로 저장합니다
   - **GIF로 저장**: 정렬된 시퀀스의 애니메이션 GIF를 만듭니다

### 입력 스택 저장

1. **파일 → 스택 저장 → 입력 스택**으로 이동합니다
2. 저장 형식을 선택합니다:
   - **폴더로 저장**: 원본 프레임을 별도 이미지로 저장합니다
   - **GIF로 저장**: 입력 시퀀스의 애니메이션 GIF를 만듭니다

### 내보내기 형식

- **JPG**: 압축 형식, 품질 대비 용량이 좋습니다
- **PNG**: 무손실, 투명도 지원
- **BMP**: 비압축, 최고 품질
- **TIFF**: 고품질, 레이어 지원
- **GIF**: 애니메이션 형식

## 14. 명령줄 인터페이스

OpenFocus는 GUI 없이도 실행할 수 있어 스크립트 파이프라인과 CI에 유용합니다.
Python 환경(또는 패키지 실행 파일 옆)에서 실행합니다.

```bash
# Fuse a folder with the default Guided Filter
python main.py --input ./stack_folder --output ./result/fused.png

# DTCWT with ECC registration, 8 threads
python main.py -i ./stack_folder -o ./result/fused.png -m dtcwt -a ecc -t 8

# StackMFF-V3 forced to CPU with a custom tile size
python main.py -i ./stack_folder -o ./result/fused.png -m stackmffv3 --cpu --tile-size 512

# Explicit file list; video files are also accepted as input
python main.py -i img1.jpg img2.jpg img3.jpg -o fused.png -m gfgfgf

# Single multi-page TIFF Z-stack with a metadata-calibrated scale bar
python main.py -i ./zstack.tif -o fused.png -m dtcwt --scale-bar
```

| 옵션 | 설명 |
|--------|-------------|
| `--input, -i` | 이미지 폴더, 동영상 파일, 또는 하나 이상의 이미지 파일 |
| `--output, -o` | 출력 이미지 경로(확장자가 형식을 결정) |
| `--method, -m` | `stackmffv3`(기본값), `none`, `openfocus_a`, `openfocus_b`, `openfocus_c`, `guided_filter`, `dct`, `dtcwt`, `gfgfgf` |
| `--align, -a` | `none`(기본값), `homography`, `ecc`, `both`, `openfocus` |
| `--align-shift-limit` | `openfocus` 정렬 전용: 허용하는 최대 이동량(프레임 크기에 대한 비율, 기본값 0.08). 이 값을 넘는 프레임은 정렬하지 않고 둡니다 |
| `--exposure-match` | 합성 전에 모든 프레임의 평균을 마지막 프레임에 맞춥니다(기본값: 켜짐, `--no-exposure-match`로 끔). 스택 전체 게인을 쓰므로 타일 출력도 이음매가 없고, 모든 방식과 OpenFocus 정렬의 밝기 기준에 적용됩니다 |
| `--base-frame` | 선택적 후처리 단계: 출력의 저주파를 `last`/`first` 프레임에 맞춥니다(기본값 `none`) |
| `--sort` | `openfocus_a/b/c`의 프레임 순서: `asc`(기본값, 파일 순서), `desc`(원경→근경 스윕 반전), `off` |
| `--dust-map WHITE` | 초점이 나간 화이트 필드 촬영본으로 플랫 필드(더스트 맵) 보정 |
| `--kernel, -k` | 커널 크기(홀수로 강제. openfocus 계열에서는 분산 창 반경의 기준) |
| `--depth-smoothing SIGMA` | `openfocus_b` 전용: 프레임 간 깊이 전환의 가우시안 시그마(기본값 1.2, 0은 가장 미세한 디테일 유지) |
| `--blend-smoothing SIGMA` | `openfocus_a` / `openfocus_c` 전용: 프레임별 가중치 맵의 가우시안 시그마(A는 기본값 2.0, C는 3.0, 0은 픽셀별로 가장 선명한 선택 유지) |
| `--threads, -t` | 스레드 수 상한. `0`은 자동(기본값), 양수는 동시 작업 수를 제한 |
| `--resource-preference` | 리소스 모드: `balanced`(기본값), `responsive`, `maximum` |
| `--batch-size` | AI 타일 배치 상한(기본값 2). 현재 호출당 타일 하나를 추론 |
| `--cpu` | GPU가 있어도 CPU를 강제로 사용 |
| `--downscale` | 정합 특징 검출용 축소 폭 |
| `--tile-size` | 큰 이미지의 타일 블록 크기 |
| `--output-dir, -d` | 배치 모드: 입력 폴더를 모두 합성하고 스택마다 `<folder>.png`로 기록 |
| `--scale-bar` | 스케일 바 그리기(TIFF 메타데이터에서 보정 자동 감지) |
| `--depth-map [path]` | 색상 깊이(초점 위치) 맵도 저장(기본값: `<output>_depth.png`) |
| `--depth-colormap` | `--depth-map`의 색상 맵: turbo, viridis, jet, gray 등(기본값 turbo) |
| `--scale-um` | 픽셀 크기를 µm/px로 지정해 메타데이터를 덮어씀(`--scale-bar`를 포함함) |

종료 코드: `0` 성공, `1` 처리 오류, `2` 사용법 오류.
`python main.py --help`는 모든 옵션을 출력합니다. 경로만 주어 실행하면
(`python main.py C:\stack`) 해당 폴더를 불러온 GUI가 열립니다.

## 16. 문제 해결

### 일반적인 문제

#### "이미지를 불러오지 않음"

- 이미지 폴더나 동영상을 먼저 가져왔는지 확인하세요
- 폴더에 지원되는 이미지 형식이 있는지 확인하세요

#### 합성 결과가 흐리거나 잔상이 보임

- 이미지 정합을 켜세요(드롭다운에서 호모그래피 / ECC / OpenFocus 고속 중 하나 선택)
- 합성 전에 이미지가 제대로 정렬되었는지 확인하세요
- 다른 합성 알고리즘을 시도하세요
- 더 부드러운 결과를 원하면 커널 크기를 늘리세요

#### AI를 사용할 수 없음

- PyTorch 설치: `pip install torch torchvision`
- GPU 지원이 필요하면 CUDA 버전 PyTorch를 설치하세요
- **도움말 → 환경 정보**에서 확인하세요

#### 메모리 부족 오류

- **설정 → 타일 설정**에서 타일 처리를 켜세요
- 타일 블록 크기를 줄이세요
- 더 작은 커널 크기를 사용하세요
- 이미지 크기를 줄이세요

#### 정합 실패

- 한 번에 하나의 정합 방식만 시도하세요
- **설정 → 정합 설정**에서 축소 폭을 줄이세요
- 이미지에 충분한 대비와 특징이 있는지 확인하세요

#### 처리 속도가 느림

- **설정 → 스레드 설정**에서 스레드 수를 늘리세요
- 더 강력한 CPU를 사용하세요
- 이미지 해상도를 낮추세요
- 더 단순한 합성 알고리즘을 사용하세요(AI 합성 대신 가이드 필터)

#### Windows 첫 실행 시 SmartScreen 경고

배포된 바이너리는 서명되지 않았습니다. **추가 정보 → 그래도 실행**을
클릭하세요. 압축을 푼 뒤 처음 실행할 때는 30–60초 정도 걸릴 수 있습니다.

#### macOS에서 앱을 "열 수 없음" 또는 "손상됨"으로 표시됨

앱이 서명되지 않았고 공증도 받지 않았습니다. `OpenFocus.app`을 응용 프로그램
폴더로 옮긴 뒤 다음을 실행하세요.

```bash
xattr -cr /Applications/OpenFocus.app
```

또는 앱을 마우스 오른쪽 버튼으로 클릭하고 **열기**를 선택하세요. 배포되는
macOS 빌드는 Apple Silicon(M1/M2/M3/M4)용이며, Intel Mac은 소스에서 실행할 수
있습니다.

### 도움말 얻기

1. **환경 정보**: **도움말 → 환경 정보**로 이동해 설치 상태를 확인합니다
2. **지원 문의**: **도움말 → 문의하기**로 이동해 지원 정보를 확인합니다

## 부록: 합성 알고리즘 세부 정보

### 가이드 필터

가이드 필터는 가이드 이미지를 사용해 에지를 보존하는 스무딩을 수행합니다. 가이드
이미지와 입력 이미지 사이의 국소 선형 변환을 계산한 뒤 이를 적용해 출력을
만듭니다. 노이즈를 줄이면서 에지를 보존하는 데 뛰어난 방식입니다.

### DCT (이산 코사인 변환)

DCT는 이미지를 주파수 영역으로 변환하고 계수 크기에 따라 합성을 결정합니다.
고주파 성분(디테일)은 보존하고, 저주파 성분(평탄한 영역)은 국소 에너지를 기준으로
병합합니다.

### DTCWT (이중 트리 복소 웨이블릿 변환)

DTCWT는 이미지를 다중 스케일, 다중 방향으로 분해합니다. 서로 다른 스케일과
방향에서 특징을 포착하므로 텍스처와 구조 정보를 모두 보존하는 정교한 합성
규칙을 쓸 수 있습니다.

### GFG-FGF

Fu 등(2024)의 방식을 구현했습니다. 거친 초점 맵 |I − mean(I)|을 가우시안형
4이웃 기울기로 보강합니다. 3×3 템플릿 T = [1 2 1; 2 4 2; 1 2 1]/16으로
P = I⊗T를 구하고, G = (|I(x±1,y) − P|)/2 + (|I(x,y±1) − P|)/2를 계산하며
T0 = 0.005보다 작은 값은 버립니다. 그다음 고속 가이드 필터로 정련합니다.
픽셀은 초점 값이 가장 큰 프레임을 선택하고(동률은 3×3 Sobel 소영역 척도),
가중 혼합 전에 이진 판단 맵을 고속 가이드 필터로 스무딩합니다.
